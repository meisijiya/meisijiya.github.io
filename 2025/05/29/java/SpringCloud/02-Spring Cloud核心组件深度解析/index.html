Eureka服务注册与发现

1.1 Eureka概述 📍

Eureka是Netflix开源的服务注册与发现组件，采用AP模型（高可用性），是Spring Cloud Netflix的核心组件之一。

核心概念：

  • Eureka Server：服务端，注册中心
  • Eureka Client：客户端，服务提供者/消费者
  • 服务注册：服务启动时向Eureka Server注册
  • 服务续约：服务定期发送心跳
  • 服务发现：客户端从Eureka Server获取服务列表
  • 服务下线：服务停止时注销

Ribbon客户端负载均衡

2.1 Ribbon概述 ⚖️

Ribbon是Netflix开源的客户端负载均衡器，提供多种负载均衡策略，是Spring Cloud Netflix的核心组件之一。

核心功能：

  • 负载均衡：将请求均匀分配到多个服务实例
  • 服务发现：集成Eureka获取服务列表
  • 故障容错：支持重试机制
  • 多种策略：轮询、随机、加权等

Feign声明式REST调用

3.1 Feign概述 📝

Feign是Netflix开源的声明式HTTP客户端，通过接口和注解的方式定义HTTP请求，简化HTTP客户端的开发。

核心特性：

  • 声明式调用：通过接口定义HTTP请求
  • 集成Ribbon：自动集成负载均衡
  • 集成Hystrix：自动集成熔断器
  • 请求压缩：支持GZIP压缩
  • 日志记录：支持请求日志

Hystrix服务熔断与降级

4.1 Hystrix概述 🔥

Hystrix是Netflix开源的延迟和容错库，用于隔离访问远程系统、服务或第三方库的请求，防止级联失败。

核心功能：

  • 服务熔断：防止服务雪崩
  • 服务降级：提供降级响应
  • 服务限流：控制请求速率
  • 请求缓存：缓存请求结果
  • 请求合并：合并多个请求

Spring Cloud Gateway网关

5.1 Gateway概述 🚪

Spring Cloud Gateway是Spring Cloud官方提供的API网关，基于WebFlux构建，提供路由转发、负载均衡、安全认证、限流熔断等功能。

核心特性：

  • 路由转发：根据路径转发到不同服务
  • 负载均衡：集成Ribbon/LoadBalancer
  • 过滤器链：请求和响应过滤
  • 限流熔断：集成Sentinel/Hystrix
  • 安全认证：JWT、OAuth2

Spring Cloud Config配置中心

6.1 Config概述 ⚙️

Spring Cloud Config是Spring Cloud官方提供的配置中心，支持将配置文件存储在Git、SVN等版本控制系统中，实现配置的集中管理和动态刷新。

核心功能：

  • 集中管理：所有服务的配置集中存储
  • 版本管理：配置文件版本控制
  • 动态刷新：配置变更后自动刷新
  • 环境隔离：支持多环境配置

面试常见问题与答案

Q1：Eureka的工作原理是什么？

答案：

Eureka工作原理：

  1. 服务注册：

    • 服务启动时，Eureka Client向Eureka Server发送注册请求
    • Eureka Server将服务信息保存到注册表
    • 服务信息包括：服务名、IP地址、端口、健康状态等

  2. 服务续约：

    • Eureka Client定期（默认30秒）发送心跳
    • Eureka Server接收心跳，更新服务状态
    • 如果90秒没有收到心跳，服务将被移除

  3. 服务发现：

    • Eureka Client启动时，从Eureka Server获取注册表
    • Eureka Client缓存注册表到本地
    • Eureka Client定期（默认30秒）更新注册表

  4. 自我保护机制：

    • 当Eureka Server在短时间内丢失过多客户端时
    • Eureka Server进入自我保护模式
    • 不再移除服务实例，防止网络分区导致的服务误删

Q2：Ribbon的负载均衡策略有哪些？

答案：

Ribbon内置负载均衡策略：

  1. RoundRobinRule（轮询策略）：

    • 按顺序轮流选择服务实例
    • 默认策略，简单公平

  2. RandomRule（随机策略）：

    • 随机选择服务实例
    • 适合实例性能相近的场景

  3. RetryRule（重试策略）：

    • 在一定时间内重试选择可用实例
    • 适合实例不稳定的场景

  4. WeightedResponseTimeRule（加权响应时间策略）：

    • 根据响应时间分配权重
    • 响应时间短的实例获得更多请求

  5. BestAvailableRule（最少连接数策略）：

    • 选择并发请求最少的实例
    • 适合长连接场景

  6. AvailabilityFilteringRule（可用性过滤策略）：

    • 过滤掉故障实例
    • 适合实例不稳定的场景

  7. ZoneAvoidanceRule（区域感知策略）：

    • 避免选择不可用区域
    • 适合多区域部署场景

Q3：Feign和RestTemplate有什么区别？

答案：

对比维度 Feign RestTemplate
调用方式 声明式，接口+注解 编程式，代码调用
可读性 高，接口定义清晰 低，代码冗余
维护性 高，接口统一管理 低，代码分散
负载均衡 自动集成Ribbon 需要手动配置
熔断降级 自动集成Hystrix 需要手动配置
代码量 少，只需定义接口 多，需要编写调用代码

Feign优势：

  • 声明式调用，代码简洁
  • 自动集成负载均衡和熔断器
  • 接口统一管理，易于维护
  • 支持请求压缩和日志记录

Q4：Hystrix的熔断原理是什么？

答案：

Hystrix熔断原理：

  1. 熔断器状态：

    • 关闭状态：正常调用，统计失败率
    • 开启状态：快速失败，不调用服务
    • 半开状态：允许部分请求通过，测试服务是否恢复

  2. 熔断触发条件：

    • 请求量超过阈值（默认20个）
    • 错误率超过阈值（默认50%）
    • 统计时间窗口内（默认10秒）

  3. 熔断恢复机制：

    • 熔断器开启后，经过休眠时间窗口（默认5秒）
    • 进入半开状态，允许一个请求通过
    • 如果请求成功，关闭熔断器
    • 如果请求失败，保持熔断器开启

  4. 降级策略：

    • 熔断器开启时，调用降级方法
    • 降级方法返回默认值或缓存数据
    • 防止服务雪崩

Q5：Spring Cloud Gateway和Zuul有什么区别？

答案：

对比维度 Spring Cloud Gateway Zuul
开发公司 Spring Cloud官方 Netflix
底层框架 WebFlux（Reactor） Servlet
性能 高，非阻塞IO 低，阻塞IO
长连接 支持WebSocket 不支持
限流 集成Sentinel/Redis 需要额外实现
过滤器 GatewayFilter ZuulFilter
维护状态 活跃维护 已停止维护

Gateway优势：

  • 性能更高，非阻塞IO
  • 支持WebSocket长连接
  • 官方推荐，持续维护
  • 与Spring Cloud生态集成更好

总结 📝

Spring Cloud核心组件要点：

  1. Eureka：服务注册与发现，AP模型，自我保护机制
  2. Ribbon：客户端负载均衡，多种策略，集成Eureka
  3. Feign：声明式HTTP客户端，集成Ribbon和Hystrix
  4. Hystrix：服务熔断与降级，防止服务雪崩
  5. Gateway：API网关，路由转发，过滤器链
  6. Config：配置中心，集中管理，动态刷新

面试关键点：

  • 理解每个组件的核心原理
