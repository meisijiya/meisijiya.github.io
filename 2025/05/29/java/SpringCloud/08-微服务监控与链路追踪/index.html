微服务监控指标与体系

1.1 为什么需要微服务监控 🎯

微服务监控的必要性：

  1. 服务数量多：

    • 微服务架构中服务数量众多
    • 服务间调用关系复杂
    • 难以掌握系统整体状态

  2. 故障定位困难：

    • 请求经过多个服务
    • 故障可能发生在任何环节
    • 缺乏有效的故障定位手段

  3. 性能瓶颈难发现：

    • 性能问题可能出现在任何服务
    • 缺乏性能监控数据
    • 难以发现性能瓶颈

  4. 容量规划困难：

    • 不了解系统资源使用情况
    • 难以进行容量规划
    • 容易出现资源不足或浪费

分布式链路追踪原理

3.1 链路追踪概述 🔍

分布式链路追踪是一种监控和诊断分布式系统的方法，用于追踪请求在多个服务间的调用链路。

核心概念：

  • Trace：一次完整的请求链路
  • Span：一次服务调用
  • TraceId：追踪ID，贯穿整个请求链路
  • SpanId：跨度ID，标识一次服务调用
  • ParentSpanId：父跨度ID，标识调用关系

3.3 链路追踪实现方式 🛠️

1. 埋点方式：

  • 代码埋点：在代码中手动添加追踪代码
  • 字节码埋点：通过字节码增强自动添加追踪代码
  • 日志埋点：通过日志框架添加追踪信息

2. 传播方式：

  • HTTP头传播：通过HTTP请求头传播追踪信息
  • 消息头传播：通过消息队列消息头传播追踪信息
  • RPC上下文传播：通过RPC上下文传播追踪信息

3. 采样方式：

  • 全量采样：采集所有请求的追踪数据
  • 采样率采样：按采样率采集追踪数据
  • 自适应采样：根据系统负载动态调整采样率

Sleuth与Zipkin集成

4.1 Sleuth概述 📦

Spring Cloud Sleuth是Spring Cloud提供的分布式链路追踪组件，用于生成追踪ID和跨度ID。

核心功能：

  • 生成追踪ID：为每个请求生成唯一的追踪ID

  • 传播追踪信息：通过HTTP头传播追踪信息

Zipkin是Twitter开源的分布式链路追踪系统，用于收集、存储和展示链路追踪数据。

核心功能：

  • 数据收集：收集链路追踪数据
  • 数据存储：存储链路追踪数据
  • 数据展示：展示链路追踪数据

Q3：什么是分布式链路追踪？

答案：

分布式链路追踪是一种监控和诊断分布式系统的方法，用于追踪请求在多个服务间的调用链路。

核心概念：

  • Trace：一次完整的请求链路
  • Span：一次服务调用
  • TraceId：追踪ID，贯穿整个请求链路
  • SpanId：跨度ID，标识一次服务调用
  • ParentSpanId：父跨度ID，标识调用关系

工作原理：

  1. 为每个请求生成唯一的TraceId
  2. 为每次服务调用生成唯一的SpanId
  3. 通过HTTP头传播追踪信息
  4. 收集和存储追踪数据
  5. 展示和分析追踪数据

Q4：Sleuth和Zipkin有什么区别？

答案：

对比维度 Sleuth Zipkin
功能 生成追踪ID和跨度ID 收集、存储和展示追踪数据
角色 追踪数据生成器 追踪数据收集器和展示器
集成 集成Zipkin 提供存储和展示
依赖 依赖Zipkin 独立部署

关系：

  • Sleuth负责生成追踪数据
  • Zipkin负责收集、存储和展示追踪数据
  • 两者配合使用，实现完整的链路追踪

Q5：SkyWalking和Zipkin有什么区别？

答案：

对比维度 SkyWalking Zipkin
开发公司 Apache Twitter
功能 链路追踪、性能监控、告警 链路追踪
性能 高 中等
存储 H2/MySQL/Elasticsearch 内存/MySQL/Elasticsearch
UI 功能完善 功能简单
维护状态 活跃维护 活跃维护

选择建议：

  • 需要完整的APM功能选择SkyWalking
  • 只需要链路追踪选择Zipkin
  • 已有ELK Stack选择Zipkin
