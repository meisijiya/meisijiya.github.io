三、九学王 · 软件测试实习生（11-09）

Q1：你们这个岗位要做的功能测试、接口测试、回归测试，分别测什么？

功能测试从界面点，验的是”点下去结果对不对”，比如登录成功进首页、下单后订单状态变成待发货。接口测试绕过界面直接对服务发请求，验的是参数校验、鉴权、状态码、返回体字段和业务链路，能在界面做好之前就发现问题。回归测试是改完之后重跑，确认没把别的功能改坏，范围按改动的影响面定，不是每次都全量。

面试可补一句：三者的执行顺序是先跑冒烟确认主干通，再执行功能用例，接口用例跟着开发提测节奏走，回归跟着每次修复走。

Q2：等价类与边界值怎么用？给我一个例子。

等价类是把输入分成”结果相同”的几堆，每堆挑代表测。以密码长度 8–20 位为例，有效等价类是 8 到 20 位，无效等价类有”少于 8 位”和”多于 20 位”两类。边界值专挑分界线，取 7、8、20、21 四个点。这两者常一起用：先分堆，再补边界。

再往上一层，多个条件组合决定结果时用判定表（如优惠券是否可用：门槛、会员等级、有效期），串业务链路时用场景法，凭经验猜哪里容易坏时用错误推测。

Q3：给我一个登录页面，你怎么设计用例？

先澄清：Web 还是客户端、支持手机号还是邮箱还是账号、有没有验证码与第三方登录、密码错几次锁定。然后分四类铺。

输入校验：账号或密码为空、全空格、长度边界、特殊字符、中文、超长粘贴、SQL 注入串 ' or 1=1、XSS 串。业务规则：账号不存在、密码错误、连续错误锁定、验证码错误与过期、明文密文切换。交互状态：未填时按钮是否禁用、连点是否重复提交、回车能否提交、登录后是否回跳原页面、token 过期是否回登录页、多端登录是否互踢。界面兼容：提示文案是否明确、Tab 顺序、密码可见性图标、缩放 125% 是否错位。

答完补一句优先级：P0 是登录成功与失败主干加安全项，P1 是切换账号、忘记密码这类隐藏入口，P2 是兼容与文案。

Q4：HTTP 和 HTTPS 有什么区别？常见状态码说几个。

HTTP 明文传输，HTTPS 在 HTTP 下面加了 TLS，提供加密、完整性校验和身份认证，默认端口从 80 变成 443。测试视角关心的点是：敏感信息必须走 HTTPS，证书过期或域名不匹配会导致请求失败。

状态码按类记：2xx 成功（200），3xx 重定向（301 永久、302 临时、304 命中缓存），4xx 客户端问题（400 参数错、401 未认证、403 无权限、404 找不到、405 方法不允许、429 限流），5xx 服务端问题（500 内部错误、502 网关收到无效响应、504 网关超时）。

Q5：MySQL 你写过哪些 SQL？

按用途记四类。条件查询 SELECT name FROM employee WHERE dept='测试' AND salary>8000；分组统计 SELECT dept, COUNT(*) FROM employee GROUP BY dept HAVING COUNT(*)>2；关联 SELECT o.id,u.name FROM orders o JOIN users u ON o.user_id=u.id WHERE o.status='PAID'；造数据 INSERT INTO users(name) VALUES('边界用户')。

两个常问细节：WHERE 在分组前过滤、HAVING 在分组后过滤；COUNT(*) 统计行数包含空行，COUNT(col) 不统计 NULL。

Q6：Postman 你怎么用的？

建集合分组管理接口；每个请求写断言，至少断状态码和关键业务字段，比如 pm.test("code 为 0", () => pm.expect(pm.response.json().code).to.eql(0))；登录拿到的 token 存进环境变量，后续请求在 header 里引用，这叫请求关联；多组账号放 CSV 做数据驱动；最后用 Collection Runner 批量跑并导出报告。

变量优先级从高到低是局部变量、数据文件、环境变量、集合变量、全局变量。

Q7：pytest 你写过什么？

fixture 负责造数和清理，scope 控制共享范围；用例参数化用 @pytest.mark.parametrize，一组数据一条用例；用 marker 给用例分组，比如冒烟、慢用例；断言直接用 assert。原则是用例之间不依赖执行顺序，需要的数据自己造、自己清。

Q8：大模型产品怎么做评测？这个岗位要测对话准确性、幻觉、知识库召回。

拆成三类。对话准确性看回答是否答到问题上，用固定问题集逐条比对期望要点。幻觉看它有没有编造资料里没有的事实，做法是给一个知识库里没有的问题，看它拒答还是瞎编，以及答案里的事实能否在原文找到对应片段。知识库召回看”该出现的资料有没有被检索出来”，准备”问题—应命中片段”的对照集，统计命中率与排名。

回答时补一句边界：这几类都靠人工评审与固定集回归，没有自动化一把梭的方案。

Q9：AI 工具你平时怎么用？Prompt / RAG / Agent 说人话。

AI 工具主要用来铺测试点和写脚本初稿：给角色、给上下文（需求与接口定义）、给输出格式约束，让它列用例，然后人工评审补业务场景。RAG 是”先检索再回答”，把文档切块进向量库，提问时召回相关片段再让模型作答，好处是减少瞎编、答案能指回原文。Agent 是”模型加工具加循环”，自己决定调哪个工具、拿结果继续做。

最容易翻车的答法是只报工具名。面试官要听的是你怎么验证 AI 的输出、哪些活不给它干。

Q10：简历上写 Linux，你说说常用命令。

按四层答。看日志用 tail -f、grep -n -C 3、less；查服务端口用 ps -ef | grep java、ss -lntp | grep 8080、curl -i 探活；看资源用 df -h、du -sh *、free -m、top；改文件用 ls -al、chmod 755、chown、find。

追问”接口报 500 怎么定位”，就串成一条：先看应用日志的报错栈，再查进程与端口，然后排除磁盘与内存，最后看依赖服务通不通。

Q11：发现一个缺陷，从提单到关闭怎么做？

先确认能稳定复现，把范围缩到最小（是前端还是接口、必现还是偶现），然后提单：标题写清现象、复现步骤、预期结果、实际结果、环境与版本、日志截图，补上复现概率和影响面。分级按影响定严重度，按排期定优先级。开发修完按影响面回归，通过就关闭，不通过就打回重开。

Q12：你怎么对接产品、开发、运维？

版本按需求评审、用例设计评审、提测冒烟、执行与缺陷跟踪、回归、上线前冒烟、上线后观察、复盘补用例推进。对产品确认验收口径与边界，对开发对齐接口契约并在提单时给复现步骤与日志，对运维给上线冒烟清单和回滚判据。手头多任务时按线上问题、阻塞提测、版本 P0、普通需求排序，每天同步阻塞项。

四、指数科技 · 测试实习生（AI 应用 / 接口 / AI 硬件）

Q1：这个岗要”能读代码、能写简单自动化”，你的 Python 到什么程度？

按能做的事说：能读懂 FastAPI 或 Flask 的路由与模型定义，知道请求参数在哪校验；能写脚本调接口、读 JSON、写断言、用 pytest 组织用例；能用 fixture 造数清数、参数化跑多组数据。说不出来的部分直接说不熟，比如装饰器原理、异步编程细节。

Q2：pytest 里 fixture 和普通函数的区别？

fixture 由 pytest 管理生命周期，可以在用例前准备数据、用例后清理，能通过 scope 控制共享范围（function、class、module、session），还能通过参数依赖其他 fixture。普通函数要被显式调用，清理逻辑得自己写 try/finally。测试里用它做登录拿 token、建临时库、造边界数据。

Q3：接口自动化的断言，你会怎么写才算有效？

只断状态码 200 不够，接口返回 200 但业务失败时用例照样绿。要断三样：状态码、业务码或关键字段值、以及数据结构（字段是否存在、类型对不对）。写完还要自查断言能不能抓住一次真实改动，改坏一处逻辑看用例会不会红。

Q4：Linux 你都用在哪？

用在三处：看服务日志定位报错、确认服务与端口是否在跑、清理或查看磁盘占用。远程连服务器用 SSH，传文件用 scp 或 rsync。

Q5：RAG 的基本链路是什么？测试要关注哪两段？

链路是文档切块、向量化入库、提问时检索相关片段、把片段拼进提示词让模型作答。测试关注两段：召回的准不准（该出现的片段有没有被检索出来、排名如何），以及回答的忠实性（答案是否真出自召回片段，有没有加料）。

Q6：大模型输出不稳定，你怎么做回归？

用固定问题集当回归集，每次改完重跑，比对这次与上次的差异；对确定性要求高的功能，把模型输出接到结构化校验上（必填字段、枚举值、长度），不满足就拒答或降级。这和普通接口回归的区别在于断言要基于”要点覆盖”而不是逐字相等。

Q7：AI 硬件方向你了解吗？

不了解。可以说明自己能迁移的部分：AI 硬件测试里常见的固件版本管理、串口日志、升级与回滚流程，我都没实操过；但测试方法（边界、异常、回归）与接口测试思路是通用的，上手要先看设备日志与升级文档。

诚实说不会，比编一个”我很感兴趣”更安全。

Q8：JD 里写”整理测试文档、缺陷回归、协助复现”，你做过类似的事吗？

做过：用例按模块整理成表，缺陷按现象、复现、根因线索、影响面写清楚，回归按影响面挑用例。文档这块我习惯把”怎么复现”和”怎么验证修好了”写在同一张表里，交给别人能照着做。

五、海客智能 · 全栈开发实习生（TikTok 一级代理）

Q1：React 里状态和渲染的关系怎么讲？

状态变化触发重新渲染，组件函数重新执行，返回新的元素树，React 用 diff 找你改了哪些节点再更新真实 DOM。所以不要在渲染过程中改状态，也不要把派生数据再存一份到 state 里，容易不一致。

Q2：Next.js 的 SSR、SSG、ISR 区别？

SSR 每次请求服务端渲染，适合个性化数据；SSG 构建时生成静态页，适合文档与营销页；ISR 是静态生成加定时或按需再生，兼顾速度与更新。App Router 里还可以用 Server Component 在服务端取数，客户端组件负责交互。

Q3：TypeScript 的类型系统解决什么问题？

在编译期发现字段拼错、可空值没判、联合类型没穷尽这类问题。常用手段是接口定义、联合类型加穷尽检查、泛型约束、unknown 配合类型收窄，避免滥用 any。

Q4：Go 的 goroutine 和线程什么区别？

goroutine 由 Go 运行时调度，初始栈很小、按需增长，创建成本远低于系统线程；多个 goroutine 复用到少量系统线程上，通过 channel 或互斥锁通信协调。面试常追问 GMP 模型：G 是 goroutine，M 是系统线程，P 是处理器上下文，调度器把 G 分配到 P 上再交给 M 执行。

Q5：PostgreSQL 的索引与关联查询要注意什么？

索引用 B-tree 应对等值与范围查询，联合索引要按最左前缀匹配；EXPLAIN ANALYZE 看是否走索引、有没有全表扫描。关联查询注意 JOIN 的驱动表选择与连接字段是否有索引，LEFT JOIN 保留左表全部行、INNER JOIN 只留匹配行。

Q6：多币种对账要注意什么？

金额不用浮点，用整数最小单位或 Decimal，并明确币种精度（日元没有小数位）；汇率要存快照，不能事后用当前汇率重算历史；对账按渠道账单逐笔比，差异分本地有渠道无、渠道有本地无、金额不一致三类，分别处理。

Q7：CSV 导入与数据对账你做过吗？

没做过生产级，但知道要点：编码与分隔符要先确认，字段做类型与长度校验，导入要幂等（按业务唯一键去重），失败行要留错误原因，支持重跑不重复插入。对账就是拿导入结果与渠道账单逐笔比。

Q8：Docker 你了解多少？

会写简单 Dockerfile 与 docker-compose 起服务，知道镜像与容器的区别、端口映射、数据卷持久化。没做过 K8s 与 CI 流水线，明确说不会。

六、绮丝丽贸易 · AI 自动化工程师（RPA / Python）

Q1：RPA 是什么，和接口自动化有什么区别？

RPA 是让机器人模拟人在界面上的操作，点按钮、填表单、读表格；接口自动化是直接对服务发请求。界面没法直接调接口、或者系统不开放 API 时只能用 RPA，代价是慢、脆、受界面改版影响。能用接口解决的场景优先用接口。

Q2：RPA 流程不稳定怎么处理？

三个方向：元素定位加容错（优先稳定属性、加显式等待、失败重试并截图留证），流程加断点续跑（记录已处理到哪一条，失败不从头跑），失败要能报警并留下现场（日志、截图、当时的数据行）。

Q3：Python 你会哪些？这个岗主要写脚本。

文件读写、CSV 与 JSON 处理、requests 调接口、异常处理、函数与类的基本写法、用 logging 打日志、用 argparse 或配置文件传参。面试常考的是”读一个脚本并说它在干什么”，所以能读懂别人的代码比会炫技重要。

Q4：跨部门沟通怎么处理？

先把对方的需求翻译成可执行的动作（要什么数据、从哪个系统取、多久跑一次），再确认验收标准；做不了的部分当场说清原因与替代方案，别拖到最后一天再说。这条在 RPA 岗被问得比技术还多，因为流程要落给业务人员用。

Q5：英语四级写进 JD 了，你怎么看？

跨境电商场景要看英文后台与英文文档，四级是筛人门槛。能说的是：读英文界面与报错没问题，写英文邮件需要借助工具。

Q6：AI 工具在这个岗怎么用？

三类用法：写脚本初稿（描述输入输出让它生成骨架）、排查报错（贴日志让它分析可能原因，再自己验证）、写文档（把流程整理成操作手册）。判定和验收还是自己做，尤其是涉及账号、金额、批量写的脚本不给它直接跑。

七、知识总结：六块能力各五句话

测试基础

  1. 测试的目的是尽早发现问题，不是证明没问题。
  2. 用例必须有预期结果，否则无法判定对错。
  3. 等价类分堆取代表，边界值专挑分界线，判定表管组合，场景法管链路。
  4. 冒烟判断能不能测，回归确认有没有改坏，验收由用户判断能不能交付。
  5. 缺陷严重度看影响，优先级看排期，两者不是一回事。

接口测试

  1. 单接口看六要素：URL、方法、请求头、入参、状态码、返回体。
  2. 业务链路看串联与依赖，token 与前置数据要能传递。
  3. 参数校验必测：缺失、类型错、长度越界、特殊字符。
  4. 鉴权必测：无 token、过期 token、别人的 token。
  5. 幂等必测：重复提交与超时重试只应生效一次。

性能测试

  1. 线程数不等于并发数，并发靠 ramp-up 与思考时间控制。
  2. 看 P95、P99 与错误率，不看平均响应时间。
  3. 压测环境要与生产同规格，否则数字没有参考价值。
  4. 瓶颈定位顺序：应用、连接池、数据库、缓存、网络、下游。
  5. 没压过就直说没压过，用本机小规模数据说明口径，别报编造的数字。

AI 与评测

  1. 大模型输出按准确性、忠实性、逻辑性三类问题设计测试点。
  2. 幻觉的测法是给它知识库里没有的问题，看拒答还是编。
  3. 召回看”该出现的片段有没有被检索到”，用固定问题集统计。
  4. 回归用固定集比对差异，断言基于要点覆盖而非逐字相等。
  5. Prompt 按角色、上下文、约束、输出格式四段写，人工评审补业务场景。

RPA 与自动化

  1. 能调接口的优先调接口，界面自动化是兜底。
  2. 元素定位要稳，等待要显式，失败要截图。
  3. 流程要能断点续跑，失败不从头来。
  4. 导入与写库要幂等，按业务唯一键去重。
  5. 涉及账号、金额、批量写的操作，AI 只出稿，人执行。

全栈与数据

  1. 状态驱动渲染，派生数据不再存一份。
  2. SSR 看个性化、SSG 看静态、ISR 折中。
  3. 类型系统在编译期拦错，别用 any 兜。
  4. goroutine 便宜，但共享状态仍要锁或 channel。
  5. 金额用整数或 Decimal，汇率存快照。

九、面试前的 20 分钟

  1. 时间线背一遍：课程实战 → 商城后端验证 → AI 功能测试 → 自研平台自动化。
  2. 每个项目准备三句骨架加一个只有做过的人才知道的细节。
  3. 四份 JD 的必会项各挑一条，用一句话说清你会什么、边界在哪。
  4. 准备好三个反问：团队怎么分工、回归靠手工还是自动化、实习期跟哪个模块。
  5. 想清楚哪些不能吹：没压测过、没上线用户、没做过埋点校验。

十、合并时保留下来的最小必要知识

旧的四篇速通里，与四份 JD 无关的大段语言教程、框架罗列已经剔除，删掉的部分在各自专题文章里有更完整的版本（Java、Go、Python、Redis 等）。这里是删不掉的底线内容，笔试与面试都够用。

Go 最小必要（海客智能 JD 点名）

变量与零值、slice 与 map 的区别（map 非并发安全，多 goroutine 写要么加锁要么用 sync.Map）、goroutine 起协程与 channel 传值、defer 执行顺序、error 作为返回值显式处理而不是抛异常。

Python 最小必要（四份 JD 都写）

数据类型与容器、函数与作用域、异常处理、文件与 JSON、requests 调接口、pytest 组织用例。能读懂别人的脚本比会炫技重要，面试常给一段代码问”它在干什么”。

Java 最小必要（九学王写”Python 或 Java”）

集合（List/Map/Set 的选择）、String 与 StringBuilder 区别、异常体系、线程基础。是备选项，不用比 Python 更熟。

前端最小必要（海客智能写 React / Next / TS）

组件与状态、props 与 state 的边界、事件绑定、路由、TS 的 interface 与联合类型。Next.js 会讲 SSR 与 SSG 的区别就够，别硬答 App Router 的缓存细节。

笔试主观题模板

问”怎么设计用例”：先说方法（等价类、边界值、场景法），再给一个具体例子，最后说优先级。
问”怎么保证质量”：需求评审提前介入、用例评审、缺陷闭环、回归与上线前冒烟、复盘补用例。
问”发现缺陷怎么处理”：确认复现、缩小范围、提单、跟踪修复、按影响面回归、关闭或打回。
逻辑推理题（数列、图形、真假话）不靠刷题库，先把题目翻译成约束条件再推，时间不够先跳过。

业务认知（海客智能与绮丝丽贸易会问）

TikTok 一级代理商是帮商家在海外短视频平台开店和投广告，收入来自服务费或佣金。所以钱有两个方向：商家充值投广告，平台结算回来再分给商家，两边都要对账，多币种还要处理汇率与精度。

RPA 在跨境电商的典型场景：批量上架商品、订单与库存同步、报表下载与汇总、多店铺切换。这类活的共同点是重复、有固定界面、系统不开放接口。

四个项目的追问链（问到第二层时用）

iHRM：用例怎么组织（按模块 × 五个方向）、断言为什么不能只断 200、Runner 报告怎么看。
Vapor：幂等怎么验（连点、同标识重发、超时重试三条路径）、缓存不一致怎么人为复现。
踏浪：AI 输出怎么判对错（三类问题各自的判法）、召回怎么量化（固定问题集看命中）。
VidDigest：契约漂移怎么防（重导出后比 diff）、断言有效性怎么自查（改坏实现看红不红）、流式怎么断（分帧与事件序列）。

十一、这篇怎么用

四份 JD 的问答不要求全背，按投递方向挑：投测试岗看第二、三节，投全栈看第四节，投 RPA 看第五节，第六节当睡前速览。每一条答法都留了”边界那半句”，那半句比前面的知识点更能让面试官信你。

这篇由原来的四篇速通合并而来，重复的测试基础只保留一处，口径统一到基线提交那一版。以后 JD 变了只改对应小节，不再新开一篇。
