一、Linux：查日志、看进程、查磁盘、传文件、改权限

定位：测试在 Linux 上干三件事——搭环境、看服务日志、查资源，占用全部 Linux 场景。面试按「查日志 / 看进程端口 / 查磁盘 / 传文件 / 权限」五组答，比报一串命令有层次。

装什么 / 在哪用：Windows 装 XShell 或 MobaXterm 远程连服务器；Mac/Linux 直接用终端。本地演练用虚拟机或 WSL。服务日志一般在 /var/log 或应用自己的 logs 目录，Tomcat 在 $CATALINA_HOME/logs。

命令分五组记，共 20 条：查日志看服务报了什么错，看进程端口确认服务起没起，查磁盘确认机器还撑得住，传文件把包送上去，改权限把脚本跑起来。

1.1 查日志（4 条）

步骤 命令 预期结果
跟日志 tail -f app.log 终端持续输出新日志，Ctrl+C 退出
找报错 tail -n 5000 app.log | grep -n -C 3 "ERROR" 打印 ERROR 在 tail 输出里的行号与前后 3 行上下文；要看原文件行号用 grep -n -C 3 "ERROR" app.log
看开头 head -n 100 app.log 打印前 100 行，确认服务启动顺序
数次数 grep -c "NullPointerException" app.log 输出匹配行数，同一行多次出现只计 1 行

1.2 看进程与端口（4 条）

步骤 命令 预期结果
找进程 ps -ef | grep java | grep -v grep 只列出 java 进程行
看端口占用 ss -lntp 列出监听端口与进程 PID；非 root 只能看到自己进程的 PID，看别人进程需 sudo
连通性 curl -i http://<主机>:<端口>/health 返回状态码与响应体，判断服务是否活着
看资源 top -p <PID> 实时显示该进程的 CPU 与内存

1.3 查磁盘（4 条）

步骤 命令 预期结果
看分区 df -h 各挂载点已用/可用百分比
找大文件 du -sh /var/log/* | sort -h | tail 列出最大的 10 个日志目录
看内存 free -m 输出内存与 swap 使用量（MB）
看磁盘 IO iostat -x 1 3 每 1 秒输出一次共 3 次；首次是开机以来累计值，看瞬时 IO 取后两次或加 -y

1.4 传文件（4 条）

步骤 命令 预期结果
拷一个 scp app.jar user@host:/opt/app/ 远端出现该文件
传目录 rsync -avz --delete ./dist/ user@host:/opt/dist/ 目录同步，远端与本地一致
打包 tar -czf logs.tar.gz logs/ 生成压缩包 logs.tar.gz
解压 tar -xzf logs.tar.gz -C /opt/ 解出 logs 目录

1.5 改权限（4 条）

步骤 命令 预期结果
看权限 ls -al app.sh 显示 -rwxr-xr-x 与属主
改执行权 chmod +x app.sh 文件多出 x 权限
改属主 chown appuser:appgroup app.sh 属主属组变为指定值
看当前用户 id 输出当前 uid、gid 与所属组

面试三问：Linux 在测试里干什么？（查日志定位问题、看进程端口确认服务起没起、看磁盘内存定位资源瓶颈、传包部署）；日志怎么看？（先 tail 看尾部，再用 grep 带上下文筛关键字，配合 grep -c 统计匹配行数）；权限命令有哪些？（ls -al 看、chmod 改、chown 改属主、id 看当前用户）。

二、MySQL：6 类必会查询

定位：MySQL 是测试的「验数据」工具——接口返回对不对，最终要看库里那行数据；造数据、查库比对、统计口径全靠它。

装什么 / 在哪用：装 MySQL 5.7/8.0 客户端，命令行 mysql -h <主机> -P <端口> -u <用户> -p，或用 Navicat、DataGrip 图形化连库。本篇示例表：students（学号、姓名、性别、年龄、班级）和 scores（学号、科目、分数）。

2.1 六类查询与可跑 SQL

类别 目的 可跑 SQL
单表条件 按条件筛行 SELECT * FROM students WHERE sex='男' AND age BETWEEN 18 AND 20;
聚合分组 统计口径 SELECT class, COUNT(*) AS cnt, AVG(score) AS avg_score FROM students s JOIN scores sc ON s.student_no=sc.student_no GROUP BY class HAVING cnt>1;
关联 多表拼信息 SELECT st.name, sc.score FROM students st INNER JOIN scores sc ON st.student_no=sc.student_no;
子查询 嵌套条件 SELECT name FROM students WHERE student_no IN (SELECT student_no FROM scores WHERE score < 60);
更新校验 改数据再核对 UPDATE students SET age = age + 1 WHERE student_no = 'S001'; 然后 SELECT age FROM students WHERE student_no='S001';
看索引 排查慢查询 EXPLAIN SELECT * FROM students WHERE student_no='S001';

2.2 分页、去重与五个易错点

易错点 说明
where 与 having where 筛行（聚合前），having 筛分组（聚合后）
NULL 比较 用 IS NULL，不能用 = NULL；空串与 NULL 不同
update 忘 where 全表更新先跑一遍 SELECT 确认命中行数，再执行 UPDATE
分页与去重 LIMIT 0,10 取第 1 页 10 条；DISTINCT 去重，和 GROUP BY 选一个
排序稳定性 ORDER BY 多字段时把唯一字段放最后，防止同值行顺序漂移

面试三问：怎么用 SQL 验证接口返回？（按业务主键查那一行，比对关键字段和状态）；**group by 后怎么筛？（用 having，不能用 where）；怎么看一条 SQL 有没有走索引？**（EXPLAIN 看 type、key、rows，type 到 range 以上、key 非 NULL 才算走到索引）。

三、抓包：浏览器 F12 与 Charles

定位：抓包是在客户端与服务端之间设代理，把请求和响应截下来看。测试用它做三件事：定位前后端 bug、模拟弱网、绕过界面直接测接口。

装什么 / 在哪用：浏览器 F12 零成本，优先用它。Charles 需要装并装根证书，能抓 HTTPS 和手机流量。Charles 本身收费，试用期有限；Fiddler 是同类替代。

3.1 浏览器 F12 抓一个接口（5 步）

步骤 操作 预期结果
打开面板 浏览器按 F12，切到 Network 标签 下方出现请求列表
清空并录制 点清空图标，勾选 Preserve log，再操作页面 新请求实时出现在列表
看细节 点目标请求 → Headers / Payload / Response 看到请求行、请求体、响应体
看耗时 看 Timing 里的 Duration 与各阶段耗时 判断慢在排队还是服务端
看响应 切 Response 标签看 Body，切 Headers 看响应头 和数据库值比对，判断责任方

3.2 Charles 抓 HTTPS（6 步）

步骤 操作 预期结果
开代理 启动 Charles，Proxy → Proxy Settings → 勾选 HTTP Proxy 状态栏显示代理已开
设浏览器 浏览器/系统代理指向本机 Charles 默认监听端口 浏览器能正常上网，Charles 出现数据
装证书 Help → SSL Proxying → Install Charles Root Certificate，再开 SSL Proxying 原本灰白的 HTTPS 请求变可读
抓手机 手机与电脑同一 WiFi，手机 WiFi 代理填电脑地址与端口；HTTPS 需手机装同一证书 Charles 出现手机请求
筛包 用 Structure 按域名分组，右键域名设 Focus 列表只剩目标域名流量
筛域名 用 Structure 或 Filter 只留目标域名 列表只剩目标接口

3.3 改请求与模拟弱网（3 步）

步骤 操作 预期结果
改参数重放 右键请求 → Edit → 改参数或 body → 重新发送 服务端按新参数返回，用来测后端边界
模拟弱网 Proxy → Throttle Settings → 选 3G 或自定义延时/带宽 页面加载明显变慢，接口 Duration 变长
定位前后端 请求错 → 前端；响应与库不一致 → 后端；请求响应都对但页面错 → 前端 给出归属结论而不是「前端好像有问题」

面试三问：抓包能解决什么问题？（定位前后端 bug、模拟弱网、绕过界面做接口测试）；怎么判断是前端还是后端的锅？（看请求参数对不对，再看响应与库是否一致，页面显示再对一次）；F12 和 Charles 怎么选？（F12 零成本查接口，Charles 能改请求、能模拟弱网、能抓手机流量）。

四、ADB：8 条命令

定位：ADB 是 Android 调试桥，测试用它装包、启应用、抓日志、看内存、做稳定性压测。

装什么 / 在哪用：装 Android SDK Platform-Tools，把 platform-tools 加进 PATH，命令行 adb 可用。真机需在开发者选项里打开 USB 调试并信任本机；模拟器用 adb connect <设备地址> 连。

# 命令 用途 预期结果
1 adb devices 查连接的设备 列出设备号与状态（device 表示正常）
2 adb connect <设备地址> 连无线设备或模拟器 输出 connected to
3 adb install -r app.apk / adb uninstall <包名> 装包与卸包 装包输出 Success；卸包输出 Success
4 adb shell am start -n <包名>/<启动页> 启动应用 应用被拉起
5 adb shell screencap -p /sdcard/s.png 截屏 手机相册出现截图
6 adb logcat -c → adb logcat > log.txt 清日志并保存 log.txt 持续写入崩溃信息
7 adb shell monkey -p <包名> -v 3000 随机操作做稳定性压测 输出事件注入统计（3000 是事件数，-v 是日志详细度，可叠加 -v -v）
8 adb shell dumpsys meminfo <包名> 看应用内存占用 输出 PSS、Java Heap 等分项

稳定性排查链：monkey 压测 → grep -E "CRASH|ANR|Exception|timeout" log.txt 找关键词 → 用日志里的堆栈定位到具体代码行。

面试三问：ADB 是干什么的？（连接设备、装卸包、拉起应用、抓日志看内存，做黑盒专项测试）；APP 崩溃怎么定位？（logcat 抓日志找 CRASH/ANR 关键字，看堆栈定位代码行）；怎么做 APP 稳定性测试？（monkey 随机操作几千次，同时抓 logcat 看有没有崩溃和 ANR）。

定位：Postman 是接口测试的事实标准工具，用来做接口用例的组织、断言、关联和批量执行。

装什么 / 在哪用：官网下载桌面版，装完直接登录账号即可用；也可装 Apifox 做类似的事。下面示例环境统一用 {{base_url}} 变量。

# 步骤 操作 预期结果
1 建环境 Environments → New，写 base_url 指向测试环境 环境列表出现该环境，可切换
2 建请求 Collections → New Collection → Add Request，URL 写 {{base_url}}/api/user/login 请求保存进集合
3 配方法与体 选 POST，Body → raw → JSON，填账号密码字段 Send 后返回响应体

六、JMeter：8 步做性能

定位：JMeter 是压测工具，模拟大量虚拟用户并发请求，看响应时间、错误率和吞吐量，找出瓶颈。

装什么 / 在哪用：装 JDK 并配好 JAVA_HOME，再解压 JMeter（安装路径避免空格——官方原文：路径含空格可能出问题，尤其 client-server 模式；中文路径非官方警告但同样建议避开），运行 bin/jmeter 启动。命令行模式 jmeter -n -t test.jmx -l result.jtl -e -o report 跑 GUI 不开，减小压测自身开销。

6.1 八步操作表

# 步骤 操作 预期结果
1 建线程组 右键测试计划 → 添加 → 线程组，设线程数、Ramp-Up、循环次数 出现线程组节点
2 加 HTTP 请求 线程组下添加 HTTP 请求，填协议/域名/端口/路径与参数 请求节点出现
3 加断言 请求上右键 → 添加 → 断言 → 响应断言，填期望字符串 断言节点挂在请求下
4 加监听器 添加 → 监听器 → 聚合报告 跑完出统计表
5 参数化 添加 → 配置元件 → CSV Data Set Config，请求里用 ${变量名} 每线程读到不同数据行
6 关联 添加 → 后置处理器 → 正则提取器，下个请求引用 ${变量名} 提取值传给后续请求
7 定时器 添加 → 定时器 → 固定/同步定时器，模拟思考时间或集合点 请求节奏变慢或并发集中
8 出报告 跑完看聚合报告；命令行加 -e -o report 生成 HTML 报告 得到可归档报告

6.2 参数化与关联片段

元件执行顺序（同一作用域）：配置元件 → 前置处理器 → 定时器 → 取样器 → 后置处理器 → 断言 → 监听器。

作用域规则：取样器本身没有作用域；逻辑控制器只对子节点生效；父节点是取样器时，元件只作用于这个父取样器；父节点不是取样器时，作用于其下所有后代。

面试三问：JMeter 的线程数是什么？（虚拟用户数，越多负载越大，Ramp-Up 决定多久起完）；聚合报告看哪几个字段？（Samples 样本数、Average/Median 平均与中位响应时间、90% Line/99% Line 分位（99% 才是尾延迟）、Error% 错误率、Throughput 吞吐）；为什么压测要关掉查看结果树？（监听器本身耗资源，会压低测出来的性能数据）。

七、Selenium / Playwright：定位、等待与 PO 模式

定位：Web UI 自动化靠两件事——找得到元素（定位）、等得到元素（等待）；再用 PO 模式把页面元素和操作封装起来，改页面不改用例。

装什么 / 在哪用：Selenium 需浏览器驱动（ChromeDriver），Selenium 4.6+ 自带 Selenium Manager，会自动发现并下载匹配浏览器版本的驱动；驱动版本需与浏览器大版本一致这条仍然成立，但一般不用手动下载和配 PATH。Playwright 装 pip install playwright 后执行 playwright install 下载浏览器，省去驱动匹配问题。

7.1 八种定位与优先级

常见经验排序（非官方结论）：ID > Name > CSS Selector > XPath > Class Name > Link Text > Partial Link Text > Tag Name。ID 唯一最快最稳。绝对 XPath 脆且慢，别写 /html/body/div[1]/...；动态 ID 用 starts-with()、contains() 匹配。

方式 语法示例 适用
ID find_element(By.ID, "username") 元素有唯一 ID，首选
Name find_element(By.NAME, "password") 表单 name 属性
CSS find_element(By.CSS_SELECTOR, "input[name='email']") 结构化、性能高
XPath find_element(By.XPATH, "//button[contains(text(),'提交')]") 复杂层级、动态元素
Class Name find_element(By.CLASS_NAME, "btn-primary") 类名有辨识度
Link Text find_element(By.LINK_TEXT, "登录") 超链接完整文本
Partial Link Text find_element(By.PARTIAL_LINK_TEXT, "注册") 超链接部分文本
Tag Name find_elements(By.TAG_NAME, "input") 批量取同类元素

7.2 三种等待与显式等待写法

等待 写法 特点
隐式等待 driver.implicitly_wait(10) 全局设置，作用于每次元素定位；超时内轮询查找，找到即返回，超时才报错
显式等待 WebDriverWait(driver, 10).until(EC.visibility_of_element_located((By.ID, "x"))) 按条件精准等待，推荐
强制等待 time.sleep(2) 固定卡秒，慢且不稳，只在排查时临时用

7.3 PO 模式三步

  1. Page 类抽元素（定义实例属性）和业务操作（定义方法）。
  2. Base 类做公共动作：找元素、显式等待、截图、日志。
  3. 用例脚本只调方法，不直接写定位。

分层目录通常是 base / page / data / script / report / log 加 config.py 和 pytest.ini：页面一改，只动 page 层，用例和报告不用动。

7.4 Playwright 的两个差异

Playwright 自带浏览器管理，省掉「驱动版本和浏览器版本不匹配」这个坑；等待是默认自动的，通常不用手写等待。

取舍：Selenium 生态成熟、企业存量脚本多；Playwright 写新脚本更省心，自带等待让脚本更稳。面试说「都会，Selenium 为主」即可，别硬说自己精通。

面试三问：元素定位有哪些方式？（八种：id、name、class_name、tag_name、link_text、partial_link_text、xpath、css_selector）；为什么用显式等待不用隐式等待？（隐式是全局设置，每次元素定位都轮询等待，显式按条件轮询更准更稳）；PO 模式好处？（页面元素和业务操作封装在 Page 层，用例只调方法，改页面不用改用例）。

八、pytest：6 个装饰器

定位：pytest 是 Python 测试框架，装饰器用来管前置后置、数据驱动、跳过和分类标记。这 6 个是笔试高频。

装什么 / 在哪用：pip install pytest；项目根目录建 pytest.ini 放配置，conftest.py 放共享 fixture（放在测试目录同级或子目录会被自动发现，不用 import）。

# 装饰器 作用 关键点
1 @pytest.fixture 定义前置/后置与共享数据 scope 可取 function/class/module/package/session，最常用前四个；autouse=True 自动生效；yield 之前是前置、之后是后置
2 @pytest.mark.parametrize 同一逻辑多组数据 参数名与数据列表对应，减少重复代码
3 @pytest.mark.skip 无条件跳过 建议填 reason 说明原因（可选）
4 @pytest.mark.skipif 条件满足才跳过 按版本、环境跳过；条件在测试收集阶段求值
5 @pytest.mark.xfail 已知问题，预期失败 默认失败记 XFAIL 不影响套件结果；意外通过记 XPASS；开 strict 后 XPASS 算失败
6 @pytest.mark.<自定义> 分类标记，配合 -m 筛选执行 在 pytest.ini 里注册减少告警

conftest.py 是共享 fixture 的落点：放在测试目录同级或其子目录会被自动发现，测试文件按参数名直接注入，不用 import。pytest.ini 里注册自定义 mark 后，用 pytest -m smoke 就能只跑冒烟用例。

面试三问：fixture 是什么？（pytest 的依赖注入机制，定义前置后置与共享数据，按名字注入）；scope 有哪几种？（function、class、module、package、session，越大复用越高但状态隔离要注意）；skip、skipif、xfail 有什么区别？（skip 无条件不跑，skipif 条件不跑，xfail 预期失败、跑了失败也不算挂）。

九、Git：5 条命令

定位：Git 是版本控制工具。测试用它管理用例和脚本、留痕变更、跑分支还能回滚。

装什么 / 在哪用：装 Git 本地客户端，配置 user.name 与 user.email；远端用 Gitee 或 GitHub 托管。

# 命令 用途 预期结果
1 git status 看当前改动 列出已改未跟踪文件
2 git add <文件> → git commit -m "说明" 提交改动 生成一个 commit
3 git branch / git switch -c feature/login 看分支 / 建分支 分支列表出现新分支
4 git pull 拉取远端更新 出现 Fast-forward 或合并信息
5 git revert <commit> 回滚一个已提交改动 生成一条新的撤销提交，历史不丢

push 被拒怎么办：提示 push rejected 时，先 git pull 把远端改动合进来再推。git 2.27+ 遇到分叉默认不再自动合并，需显式选 git pull --no-rebase（merge）或 --rebase；可用 git config pull.rebase false 固化为 merge 默认，不要直接覆盖别人的提交。

面试三问：git 的三个区是什么？（工作区、暂存区、仓库区，add 把改动放进暂存区，commit 提交进仓库）；怎么撤销修改？（未提交用 git checkout -- 文件 或 git restore，已提交用 git revert 生成反向提交）；push 冲突了怎么办？（先 pull 合并解决冲突再 push，默认 merge 不覆盖）。

十、Allure 与 Jenkins：报告与持续集成

定位：Allure 把测试结果渲染成可读 HTML 报告；Jenkins 负责在代码提交后自动跑测试并归档报告。两者合起来就是持续集成（CI，频繁合并代码并自动验证）。

装什么 / 在哪用：Allure 装命令行工具并配进 PATH，另装 allure-pytest 插件；Jenkins 装好后进 Manage Jenkins → System Configuration → Global Tool Configuration 配 Allure 工具路径。

10.1 Allure 三步

步骤 命令/操作 预期结果
1 pip install allure-pytest 插件装好，pytest 跑完自动产出结果文件
2 pytest --alluredir=./report -q 生成 report 目录，里面是结果 JSON
3 allure generate ./report -o ./new_report --clean 后 allure open ./new_report 浏览器打开 HTML 报告

10.2 Jenkins 三步

步骤 操作 预期结果
1 Global Tool Configuration 里配 Allure 路径 任务里可选该工具
2 新建 Freestyle 项目，添加构建步骤执行 pytest 命令 点构建后自动跑测试
3 构建后操作里填 Allure 报告路径（结果 JSON 目录） 构建页面出现报告链接

执行链路：代码拉取 → 装依赖与环境 → pytest 执行 → 产出结果 → Allure 生成报告 → Jenkins 归档展示。

面试三问：Allure 有什么用？（把 pytest 等框架的结果渲染成带分类、图表、失败详情的 HTML 报告）；CI 是什么？（持续集成，代码一提交就自动构建和跑测试，尽早发现问题）；Jenkins 里一般配哪几步？（配工具路径、配置构建命令跑测试、构建后归档报告）。

🗣️ 面试怎么说

  1. 「Linux 我按五组用：查日志 tail -f 加 grep -n -C 3 定位报错、看进程端口 ps -ef 和 ss -lntp、看磁盘内存 df -h 和 free -m、传文件用 scp 和 rsync、权限用 ls -al 和 chmod。」
  2. 「MySQL 我用六类查询：单表条件、聚合分组、关联、子查询、更新后校验、EXPLAIN 看索引；where 筛行、having 筛分组，update 一定先 select 确认命中行数。」
  3. 「抓包优先用浏览器 F12 看请求响应，要改请求或模拟弱网才用 Charles；定位前后端 bug 就三步：请求有没有问题、响应和库是否一致、页面显示对不对。」
  4. 「ADB 我常用八条：devices 看连接、connect 连无线设备、install 装包、am start 启动、screencap 截图、logcat 抓日志、monkey 压测、dumpsys meminfo 看内存。」
  5. 「Postman 我按八步走：建环境变量、写请求、Tests 写断言、前置脚本造数据、关联提取 token、参数化批量、Runner 跑、出报告。」
  6. 「UI 自动化我用 Selenium 的八种定位，优先 ID 再 CSS，XPath 只在必要时用；等待一律用显式等待；页面按 PO 模式封装，用例只调方法。」
  7. 「pytest 我重点掌握 fixture、parametrize、skip、skipif、xfail 和自定义 mark 六个装饰器，共享数据放 conftest.py。」

✅ 自测 5 题

  1. Linux 查日志定位报错的命令链是什么？
    tail -f app.log 跟日志，grep -n -C 3 "ERROR" 找上下文，grep -c "Exception" app.log 统计匹配行数。
  2. where 和 having 的区别？
    where 在聚合前筛行，having 在聚合后筛分组。
  3. Postman 里怎么把登录接口的 token 传给下一个接口？
    登录接口 Tests 里 pm.environment.set("token", j.data.token)，下一个请求 Header 写 Bearer {{token}}。
  4. 隐式等待和显式等待的区别？
    隐式是全局设置，每次元素定位都在超时时间内轮询查找，找到即返回；显式用 WebDriverWait 按条件轮询，更准更稳，推荐用显式。
  5. pytest 里 skip、skipif、xfail 的区别？
    skip 无条件跳过，skipif 条件满足才跳过，xfail 标记预期失败（已知缺陷），跑了失败也不算用例挂。
