软件测试与语言基础--面试速通宝典

Hi，我是 meisijiya ，也是 老江湖 ，感谢你的阅读，我们一起进步。

这份笔记按简历和一条具体的 JD 写出来。基础部分给的是能直接答出口的版本，语言基础按「看懂代码、写简单脚本」这条线收窄，项目部分走六问骨架，最后是简历讲法的边界与进门前的清单。全篇不报没有出处的数字，项目细节只写到简历写过的机制为止。

零、这条 JD 在考什么

这家公司做在线教育，产品线里有面向学生的大模型问答。测试实习生这条线的活很具体，跟着需求走完整流程，功能、接口和回归都做，还要给大模型问答产品做评测。五条职责拆开，对应五种现场验法。

JD 职责 现场怎么验 本文位置
参与需求评审，按需求与交互稿设计功能、边界、异常用例 给一个小功能，让你当场拆用例 一章、二章
执行功能、接口、回归测试，用 AI 工具辅助用例编写与日志分析 问你怎么用 AI 提效，边界在哪 四章 4.9、七章
提交跟踪验证缺陷，配合研发产品算法推进闭环 问缺陷怎么写、研发说不是 bug 怎么办 1.5、1.6
参与大模型评测：对话准确性、幻觉、知识库召回、多轮体验 问一次回答「算不算错」怎么判 四章
维护用例库与测试资产，参与测试报告与线上复盘 问测试报告有哪些内容、复盘找什么 1.6

必备项里唯一能当场扣分的是三样：等价类边界值这些基础说不清、代码看不懂、SQL 写不出来。加分项里的 Prompt 与 RAG 概念，教育公司的面试官问得比大厂细，因为他们的产品就架在上面。

简历上的三个项目是答辩主战场。面试官不会问「你做了什么功能」，会问「你怎么证明它是对的」。第五章按「是什么、怎么做、做了什么、难点、落地、未来」六问把三个项目各讲一遍，第六章讲哪些经历可以补、补到什么边界。

一、软件测试基础

1.1 一条线讲完测试流程

阶段 产物 一句话要害
需求评审 需求疑问清单、可测性意见 需求阶段问出来的问题最便宜
测试计划 范围、人力、进度、风险、准入准出 计划回答「测什么、谁测、什么时候结束」
用例设计 用例库、测试数据 用等价类边界值把无限输入压到有限条
执行与缺陷跟踪 执行记录、缺陷单 缺陷要能重现，重不出来的先补日志
回归与准出 回归报告、测试报告 回归范围由改动影响面决定，不是全量重跑
线上复盘 复盘纪要、改进项 复盘找的是漏测环节，不是找责任人

我的流程是需求评审时同步拆用例，提测后先跑冒烟确认主链路通，再按优先级铺开，缺陷按严重程度分流，最后按改动影响面圈回归范围，出报告前确认准出条件是否满足。

追问： 需求评审你一般问什么 ／ 提测质量不达标怎么处理 ／ 准出条件谁定

1.2 四个模型，一句话一个

模型 一句话 什么时候提
V 模型 开发每阶段对应一个测试阶段，测试左移的雏形 问测试与开发的对应关系
W 模型 开发与测试并行，测试从需求阶段就介入 问测试什么时候开始
H 模型 测试流程独立成一条线贯穿全周期，与其他流程并发，测试点就绪就执行 问多版本并行怎么管
敏捷 短迭代，用例轻量化，自动化兜回归 问迭代快来不及写用例怎么办

我用得最多的是 W 模型的思路，需求评审阶段就开始拆用例，等到提测时用例已经过了一轮自检，测试执行期只补数据。

追问： V 和 W 差在哪 ／ 敏捷下还要写用例吗 ／ 你们团队用哪个模型

1.3 用例设计四法，加一个演练

方法 适用 一句话
等价类 输入域大、取值可分类 每类取一个代表值，有效无效都取
边界值 有范围、长度、数量限制 取上点、离点、内点，边界最容易错
判定表 多个条件组合决定结果 条件桩配动作桩，把组合穷举成规则
场景法 有业务流程与分支 画基本流与备选流，每条流一条用例

演练对象换成教育产品的一个功能：课程搜索框，输入关键词返回课程列表，支持筛选年级与学科。

维度 用例要点
等价类 正常关键词、超长关键词、纯空格、纯 emoji、特殊字符 % _ '
边界值 关键词长度 0／1／上限／上限+1；结果条数 0／1／一页满／超过一页
判定表 年级已选未选 × 学科已选未选 × 有无结果，四种组合各一条
场景法 搜索→筛选→翻页→点进详情→返回，返回后筛选条件是否保留
异常 断网、接口 500、接口超时、返回空数组、返回字段缺字段

我会先按等价类和边界值把输入压成几条，再用判定表覆盖筛选组合，最后用场景法串起主流程，异常场景单独列一组，因为教育产品的搜索空结果是常态，不是异常。

追问： 只给一天时间你怎么取舍 ／ 用例写到什么颗粒度 ／ 怎么判断用例写全了

1.4 用例要素与写作硬要求

要素 要求
标题 动宾结构，一条用例只验一个点
前置条件 数据与账号状态写清，别人拿到能复现
步骤 可执行，不写「正常操作」这类含糊动作
预期 可观测，落到页面元素、接口字段、数据库值
优先级 与业务重要度挂钩，冒烟集只放 P0

我写用例的硬要求是预期必须能被别人验，看到「显示正常」这种写法我会退回去改成具体字段值。

追问： 用例和测试点区别 ／ 用例怎么维护 ／ 冗余用例怎么处理

1.5 缺陷：生命周期、严重程度与优先级

状态 含义
新建 提交后待确认
已确认 研发认可，进入修复
已拒绝 研发认为非缺陷或重复，需给出理由
已修复 待验证
已关闭 / 重开 验证通过关闭，不通过重开并补证据

不同缺陷系统的叫法不一致，研发侧常把「拒绝」写成解决结果而不是状态，面试时说清你用的是哪一套就够。

项 判据
严重程度 影响系统可用性与数据的算致命/严重，界面与文案算轻微
优先级 看业务影响与修复成本，严重但低频可以后修，轻微但挡主流程必须马上修

缺陷单我按四段写：现象、复现步骤与最小条件、根因线索（日志、请求、报错栈）、影响面（影响哪些用户与哪些功能），再附上截图和抓包。

追问： 研发说这不是 bug 你怎么处理 ／ 严重程度和优先级会冲突吗 ／ 偶现缺陷怎么提

1.6 测试报告与线上复盘

报告模块 写什么
测试范围与环境 版本、模块、环境、数据
用例执行情况 计划数、执行数、通过率、未执行原因
缺陷统计 按严重程度与模块分布，遗留缺陷与规避方案
结论与风险 是否建议上线，遗留风险与监控建议

报告的结论我写建议而不是判断，附上遗留缺陷清单和上线后要盯的指标，让评审的人自己决定发不发。

追问： 遗留缺陷怎么定 ／ 线上出问题你怎么复盘 ／ 复盘要产出的东西是什么

二、接口测试基础

2.1 为什么先做接口

理由 说明
早 接口在页面之前就绪，能提前发现后端问题
稳 不依赖前端渲染，用例不易因改版失效
快 一条用例一个请求，回归成本低
深 能直接构造边界与异常，绕开前端限制

我的顺序是先接口后页面，接口能把参数校验、鉴权、幂等这些逻辑先钉住，页面层只补交互与展示问题。

追问： 接口测试和功能测试的边界 ／ 什么功能只做接口就够

2.2 HTTP 报文与状态码

部分 关键点
请求行 方法 + 路径 + 版本，路径带查询参数
请求头 Content-Type、Authorization、Cookie、自定义 traceId
请求体 JSON 为主，注意字段类型与嵌套
响应 状态码 + 响应头 + 响应体，业务码常藏在响应体里
状态码 含义 常见测试点
200 / 201 成功 / 已创建 响应体字段与类型
301 / 302 重定向 跳转目标与循环跳转
400 参数错误 缺字段、类型错、超长
401 / 403 缺有效凭据 / 服务器拒绝履行 无 token、过期 token、越权访问他人资源，403 也可能与凭据无关
404 路径不存在 资源 id 不存在
429 限流 并发上限与 Retry-After
500 / 502 / 504 服务端异常 / 网关错误 / 超时 依赖故障时的降级行为

接口用例我一定覆盖四类：正常、参数异常、鉴权异常、依赖异常，状态码和业务码都要断言，只看 200 等于没测。

追问： HTTPS 和 HTTP 在测试上差什么 ／ 401 和 403 怎么区分 ／ 幂等接口怎么做用例

2.3 接口用例的十要素

项 内容
接口信息 方法、URL、鉴权方式
前置 登录态、依赖数据、库存或额度
入参 必填、选填、类型、长度、枚举
断言 状态码、业务码、字段值、字段类型、耗时上限
后置 数据清理或补偿

十要素里我最常被人漏的是后置清理，用例之间互相污染是回归误报的主要来源。

追问： 用例之间怎么保证独立 ／ 测试数据怎么造 ／ 怎么断言列表接口

2.4 Postman 与 Charles 的分工

工具 用来做什么
Postman 用例沉淀成集合，环境变量切环境，Tests 写断言，Runner 配 CSV 做数据驱动
Charles 抓真实客户端请求，定位「前端传了什么、后端回了什么」，把线上问题复现成一条可重放的请求

页面问题我先抓包，把请求复制成 curl，确认是前端传错还是后端回错，再决定缺陷提给谁。

追问： 环境和全局变量区别 ／ CSV 数据驱动怎么配 ／ 手机端怎么抓 HTTPS

2.5 鉴权、幂等与并发

主题 测法
鉴权 无 token、伪造 token、过期 token、他人资源 id，四种都要试
幂等 同一请求重复提交两次，断言只落一条数据
并发 多线程同一时刻打同一接口，断言不超卖、不重复、不死锁
限流 短时间超阈值请求，断言返回 429 且恢复后可正常访问

幂等我用同一份请求体重放两次，再看数据库条数与返回的 id 是否一致，只看返回成功会漏掉重复落库。

追问： 并发用例用什么工具写 ／ 唯一索引和幂等键的区别 ／ 限流测试怎么定阈值

三、语言基础

3.1 这一章为什么必考

岗位写的是「Python/Java 任一，能看懂基础代码、写简单脚本」。落到面试就是三件事：给一段代码说出它做什么、指出哪里会出错、现场写十几行解决一个小问题。

层级 会怎么问 准备到什么程度
读 这段代码输出什么、有什么坑 能逐行走一遍
改 这里有个 bug 怎么修 说得清原因再动手
写 写个函数把日志里的报错提出来 能跑，边界写清

我的准备顺序是先会读，再会改，最后才写。读代码考的是基本功，答得利索比写得漂亮更重要。

追问： 你平时用哪个语言多 ／ 为什么不精通也能上手测试脚本 ／ 现场写一个判空函数

3.2 Python 必会的最小集

主题 必须能说清的点
可变与不可变 list/dict/set 可变，str/tuple 不可变；函数默认参数不要用可变对象
切片与推导 a[::-1]、a[1:3]、列表推导带条件，字典推导
异常 try/except/else/finally，只捕能处理的异常，不要裸 except
文件与 json with open(...) as f，json.load/loads 与 dump/dumps 的区别
装饰器与生成器 一句话：装饰器不改函数体就加行为，生成器用 yield 逐个产出、省内存

默认参数在函数定义时只求值一次，所以可变默认值会在多次调用之间共享，我写函数一律用 None 占位再新建。

追问： 深浅拷贝差在哪 ／ 生成器和列表推导什么时候用哪个 ／ 上下文管理器怎么自己实现

3.3 Python 读代码题

题一，浅拷贝。

内层列表还是同一个对象，copy() 只复制了外层。要真正独立用 copy.deepcopy。

题二，闭包延迟绑定。

lambda 里取的是变量 i 本身，等调用时循环已经结束。要固定值就写成 lambda i=i: i。

题三，遍历中改字典。

改成遍历 list(d.items()) 再删。

题四，is 与 ==。

is 比身份，== 比值。判断 None 用 is None。

读代码题我不会急着算输出，先找可变对象、闭包、循环里改集合这三类，坑基本都在这。

追问： 为什么小整数 is 是 True ／ 什么场景必须用 is ／ 字符串拼接什么时候用 join

3.4 Java 必会的最小集

对着 SpringBoot 项目能读就够，不需要会写业务。

主题 必须能说清的点
类与接口 implements 与 extends 的区别，接口默认方法
集合 ArrayList 查快、LinkedList 插删快；HashMap 用 hashCode 定位桶、equals 判等
Stream filter/map/collect 一条链读下来等价于 for 循环加判断
资源关闭 try-with-resources 自动关闭实现 AutoCloseable 的对象
注解 @Service、@Transactional 这类由框架扫描后加行为，不是语法糖

读后端代码我先找入参校验和事务边界，这两处出问题在测试里表现为「有时成功有时失败」。

追问： == 和 equals 差在哪 ／ 为什么重写 equals 要重写 hashCode ／ 事务不生效常见原因

3.5 Java 读代码题

题一，空指针。

get 返回 null 不等于键不存在，取值后要先判空。

题二，字符串比较。

== 比引用，equals 比值。

我读 Java 代码先扫三个地方：可能为 null 的返回值、== 用在字符串上、集合在多线程里被共享。

追问： 怎么防 NPE ／ 哪些集合是线程安全的 ／ 循环里拼字符串为什么慢

3.6 SQL 基础

岗位只要基础 SQL，但测试岗用得多：造数、对账，查一条数据的状态对不对。

主题 写法要点
条件与排序 WHERE 过滤行，ORDER BY 排序，LIMIT 分页
分组 GROUP BY 后只能选分组列与聚合函数，过滤聚合结果用 HAVING
连接 INNER JOIN 取交集，LEFT JOIN 保左表，连接条件写 ON
子查询 先写出子查询能单独跑的结果，再嵌进外层
索引 复合索引按最左前缀生效，EXPLAIN 看 type、key、rows

对账我会两边各写一条 SQL 出条数，再写第三条查差集，只看两条数字是否相等容易把漏数据看成对上了。

追问： where 和 having 有什么区别 ／ 为什么这条查询不走索引 ／ 怎么造一万条测试数据

3.7 pytest 速通

主题 要点
用例 文件名 test_*.py，函数名 test_* 才会被收集
断言 直接用 assert，失败时会打印中间值
fixture @pytest.fixture 提供数据，scope 取 function/class/module/package/session
参数化 @pytest.mark.parametrize 一行数据一条用例，失败能定位到哪组参数
内置夹具 tmp_path 给临时目录，monkeypatch 临时改环境变量或替换函数
共享 conftest.py 放公共 fixture，同级与子目录自动可见

SSE 怎么断言。 流式接口不能只断言 200，要按契约逐帧看字段与顺序。

写接口用例我先把断言写死到字段，状态码 200 只是入场券，业务码、字段类型、关键值三样缺一条都算没断言。

追问： fixture 的 scope 怎么选 ／ 参数化和循环调用的区别 ／ 假实现怎么注入进去

3.8 语言题追问链

问题 30 秒答法 会被怎么追问
可变默认参数有什么坑 定义时求值一次，多次调用共享同一个对象 怎么改，为什么用 None 占位
深拷贝浅拷贝 浅拷贝只复制一层，内层还是同一个对象 什么时候必须深拷贝
闭包为什么都取到最后一个值 变量在调用时才取值，循环结束时已经定格 怎么固定住当前值
Python 和 Java 你更熟哪个 写脚本用 Python，读后端用 Java 举一段你读过的 Java 代码
SQL 会不会写 会条件、分组、连接、子查询，也会看 explain 这条为什么没走索引
pytest 和 unittest 差别 断言直接写 assert，fixture 比 setUp 灵活 参数化怎么传多组数据

四、AI 大模型产品评测

4.1 这条职责到底在测什么

评测项 对应缺陷 测什么
对话准确性 答非所问、事实错误、答错题 回答是否切题、事实是否正确、步骤是否可执行
幻觉 编造知识、编造引用、过度推断 回答里 unsupported 的内容有多少
知识库召回 召回不到、召回到错块 该答的资料有没有进上下文
多轮体验 遗忘上下文、指代错、话题混乱 连续追问下体验是否稳定

我把 AI 评测理解成四层：先看召回有没有把资料拿进来，再看生成有没有把资料用对，再看多轮里上下文能不能保住，最后看整体回答对不对。这四层任何一层出问题，用户都会觉得「答错了」。

追问： 四项里哪项最难量化 ／ 对话准确性怎么定义「对」 ／ 幻觉和事实错误区别在哪

4.2 幻觉怎么分类怎么测

类型 定义 典型表现
事实性幻觉 回答与世界事实不符 编造年份、公式、人物、事件
忠实性幻觉 回答与给定资料不符 资料里没写的结论却说「资料里提到」
逻辑性幻觉 推理链断裂或自相矛盾 前后结论矛盾、步骤跳步

学术综述通常把幻觉分成事实性与忠实性两类，逻辑不一致算忠实性下面的一个子类型。面试时我会先说两类根，再补一句「按表现还能拆出逻辑不一致这一类，因为它的修法不同」。

用例写法（事实性，2 条）：

  • 提问一个有唯一正确答案的问题，期望关键词必须出现，禁止词必须不出现。例如问「Python 里 list.append 的返回值是什么」，期望「None」，禁止「返回新列表」。
  • 提问一个资料里明确写过的事实，把正确答案拆成 3-5 个必须命中的短语，全部命中才算过。

用例写法（忠实性，2 条）：

  • 给一段短资料，问一个资料里没答的问题，期望回答里出现「资料未提及」或等价拒答，禁止编造细节。
  • 给两段互相矛盾的资料，问结论，期望回答指出矛盾或说明无法判断，禁止直接选一边。

用例写法（逻辑性，2 条）：

  • 给一个多步推理题，要求回答写出每步，断言最终结论与中间步骤一致。
  • 给一个否定条件（「除了 X 之外」），断言回答没有把 X 当作合法选项。

判分口径：

  • 命中率 = 命中必须短语数 / 必须短语总数。
  • 幻觉率 = 含禁止词或编造内容的样本数 / 总样本数。
  • 拒答正确率 = 正确拒答数 / 应拒答样本数。

我把幻觉拆成事实性、忠实性、逻辑性三类，因为三类的修法不同：事实性靠知识库与事实校验，忠实性靠资料约束与引用，逻辑性靠推理链与步骤断言。混在一起打分，修的时候不知道该动哪层。

追问： 三类幻觉哪个最难自动判 ／ 忠实性怎么判「资料支持」 ／ 拒答算不算幻觉

4.3 知识库召回评测

环节 故障表现 隔离方法
语料切块 块太长稀释、块太短断句 对比不同块大小下的命中率
向量化 同义词召回不到 同义问法集测召回
Top-k 检索 k 太小漏召、k 太大噪声 固定问题集扫 k 值
重排 相关块排在后面 看命中块的排名分布
生成 召回到但没用 召回正确时回答仍错

口径差别：

  • 命中率 = 至少一个相关块被召回到 / 提问总数。看「有没有拿到」。
  • 召回率 = 被召回到的相关块数 / 全部相关块数。看「拿全了没有」。
  • 精确率 = 召回块中相关块数 / 召回块总数。看「噪声多少」。

判断错在检索还是生成：把召回到的块直接喂给模型，如果回答对了，错在检索前的链路；如果回答仍错，错在生成或 Prompt。这是最常用的二分法。

我的排查顺序是先看召回：把召回到的块打印出来，人工判断相关块在不在、排第几。召回对了回答还错，再查 Prompt 和生成；召回错了，再查切块、向量和 k 值。这样不会把检索问题误诊成模型问题。

追问： Top-k 怎么选 ／ 命中率和召回率哪个更重要 ／ 怎么判断切块粒度合适

4.4 多轮对话体验评测

维度 测什么 用例写法
上下文保持 前轮信息能否被后轮继承 第一轮给条件，第二轮直接追问细节
指代消解 「它」「这个」「上面那个」指向正确 用代词追问，断言指向对象正确
改口与否定 用户纠正后模型能否切换 先说 A 再说「不对，是 B」，断言最终按 B
话题切换 切换后不串旧话题 问完数学切到英语，断言不混入数学内容

回归方法：把「同一问题隔轮再问」作为固定回归项，第一轮正常回答，中间插 3-5 轮无关问题，最后一轮重问原题，断言答案与第一轮一致或明确说明变化原因。这个方法来自踏浪 AI 中心的分层会话记忆实践，同题隔轮再问就是回归的最小单元。

多轮评测我最怕「答第一轮对，第三轮忘」，所以回归集里固定放一组「同一问题隔轮再问」的用例，每次改 Prompt 或切块策略都跑一遍，防止改好单轮却破坏多轮。

追问： 上下文窗口满了怎么办 ／ 指代消解失败怎么定位 ／ 多轮回归集多大合适

4.5 评测集怎么建

环节 做法
分层抽样 按题型、难度、场景分层，每层按比例抽样，避免只测简单题
难度分级 简单（直接查）、中等（需推理）、困难（多跳、模糊、矛盾）
标注规范 每题写标准答案、必须短语、禁止词、拒答条件，四者齐全
双人标注 两人独立标，分歧处第三方仲裁，分歧率作为质量指标
回归集 只增不减，修过的缺陷对应用例必须入库

评测集不是题越多越好，关键是有分层、有标注规范、有回归纪律。我建集的顺序是先定标注规范再收题，否则后面标不齐，分数不可比。

追问： 评测集多大合适 ／ 标注分歧怎么处理 ／ 回归集只增不减会不会膨胀

4.6 评分方式

方式 适用 偏差与边界
人工打分 主观题、体验题 成本高，需打分 rubric 和校准
成对比较 两个版本优劣 只能比相对优劣，不能给绝对分
规则判定 有明确期望的题 快、稳定，覆盖不了开放题
LLM 当裁判 开放题、规模大 有位置偏差、长度偏差、自恋偏差

LLM 当裁判的边界：裁判模型不能与被评模型相同家族；必须给 rubric 和 few-shot；裁判输出要结构化（分数 + 理由 + 引用）；对裁判本身做一致性校验（同一题多次裁判分数方差）。偏差来源：先看 A 后看 B 时 A 分数偏高（位置偏差），长答案偏高（长度偏差），裁判倾向给自己的家族高分（自恋偏差）。

代码骨架（pytest 风格）：

评分方式我按题型选：有明确期望的用规则判定保证稳定，开放题用 LLM 当裁判但必须配 rubric 与一致性校验，版本对比用成对比较。人工打分只做校准与抽检，不作为主流程。

追问： LLM 裁判怎么避免偏差 ／ 成对比较和单点评分哪个更稳 ／ 规则判定覆盖不了什么

4.7 Prompt、RAG、Agent 的面试口径

概念 是什么 测试关注点
Prompt 给模型的指令与上下文模板 指令是否歧义、上下文是否溢出、输出格式是否稳定
RAG 检索外部资料再生成回答 召回质量、资料利用率、引用忠实性
Agent 模型调用工具完成任务 工具选择正确性、参数正确性、多步收敛、失败重试

Prompt 测的是指令与格式的稳定性，RAG 测的是资料链路的准确性，Agent 测的是工具调用与任务完成。三者测试对象不同，不能用同一套用例评三者。

追问： 三者在产品里怎么组合 ／ Prompt 改动怎么回归 ／ Agent 失败怎么定位

4.9 用 AI 工具辅助测试

用途 做法 边界

追问： AI 生成的用例怎么筛 ／ 日志脱敏脱到什么程度 ／ 什么任务不适合交给 AI

4.10 埋点与数据校验

埋点四要素：事件名、触发时机、属性字段、用户标识。常见错埋与漏埋：事件名不统一、触发时机错（页面加载时触发而非动作完成时）、属性缺失或类型不对、漏埋关键路径、重复埋点导致重复计数。

核验方法：用日志或数据库查事件记录，按「事件名 + 时间窗口 + 用户」对账，对比前端触发次数与后端接收次数；数据测试与业务数据对账时，以业务库为准，埋点计数允许误差范围由埋点规范定义，但误差来源必须能解释。

埋点校验我按四要素过一遍，再用数据库对账：前端埋点计数与后端落库计数差的那部分，就是埋点丢失或重复的位置。

追问： 埋点四要素缺一不可吗 ／ 数据对账允许的误差怎么定 ／ 埋点和业务日志区别在哪

五、项目实战：六问骨架

5.0 先记骨架，再记内容

面试官问项目只有六种问法，顺序也基本固定。把六问的答案按顺序压成一条线，讲的时候就不会被带跑。

问法 他要确认的 答的长度
这个项目是什么 你懂不懂业务 一句话到两句
你怎么做的 技术选型有没有理由 三句，讲链路
你具体做了什么 你在这项目里占多少 三到五句，只讲自己动过的部分
难点是什么 你有没有真的踩过坑 一到两个，讲透一个
落地到什么程度 是真项目还是练手 诚实给现状
未来怎么改 有没有想过演进 一句方向 + 一句原因

三个项目我按「是什么、怎么做、做了什么、难点、落地、未来」这个顺序讲，讲难点时只讲一个，讲完等对方追问。

追问： 你在团队里什么角色 ／ 项目上线了吗 ／ 这个项目你觉得自己做得最差的地方

5.1 踏浪工作室 AI 中心

是什么。 工作室内部用的 AI 研发效能工具，一半是开发侧的辅助，帮人写单测、做代码评审；一半是知识库问答，把内部文档接进去让人能查。

怎么做的。 后端 Python 与 FastAPI，会话与缓存放 Redis，向量存 PGVector，整套用 DockerCompose 起。

做了什么。 我是开发组长，负责技术选型和攻坚，具体干了四件：单测有效性、评审清单、分层记忆、混合召回。

难点 解法 一句话话术
AI 生成的单测看着通过，把实现改坏也不报错 逐条判断断言能不能抓住一次真实改动，抓不住的退回重写，最后沉淀成单测提示词模板 我拿改坏实现的变异去反向验证断言，只有断言变红才算用例有用
评审意见太笼统，说了等于没说 把项目规范整理成固定检查清单，覆盖空值、边界、错误吞没、共享状态的数据竞争，再由人按误报条目反向收窄清单 清单是被误报率削出来的，不是一开始就列全的
多轮对话上文断裂 短期摘要配长期记忆的分层会话，用「同一问题隔轮再问」做回归场景 记忆有没有生效不看一次回答，看隔一轮还能不能取回
检索命中不稳 长文按语义边界切块，再和关键字检索混合召回，自建固定问题集按命中与召回两个口径比较 换方案之前先有尺子，不然只能靠感觉

落地。 工作室内部在跑，服务日常开发和内部检索，没有对外。

未来。 想把固定问题集扩成带难度分层的回归集，每次改检索策略都自动跑一遍，把「凭感觉调参」换成「有基线可比」。

这个项目对我最大的改变是知道「测试通过」这四个字不可信，我开始用改坏实现的方式去验证断言本身。

追问： 分层会话的摘要什么时候生成 ／ 混合召回怎么定权重 ／ 组长怎么分活和验收

5.2 VidDigest

是什么。 用户贴一个视频链接，系统解析出字幕与元信息，生成摘要和思维导图，还能针对视频内容追问。

怎么做的。 后端 Python 与 FastAPI，数据落 SQLite，摘要与追问走 SSE 流式返回，前端 Vue 加 TypeScript 与 Pinia，Vite 构建，DockerCompose 部署。

做了什么。 独立开发，从解析链路到前端到部署全自己写。测试这块做得最重，因为只有一条解析链路，改一处就回归一遍。

难点 解法 一句话话术
一条链路，改动就要全量回归 pytest 分库建用例：每例独立临时库，老库缺列单独起一条升级回归，SSE 帧按契约逐字段断言 用例之间不共享库，回归才敢天天跑
外部模型不可控，测试没法重复 把模型调用抽成可替换接缝，测试用假实现固定输出，只断言我方的解析与降级行为 我不测模型输出，我测模型出错时我怎么退
用例通过不代表能发现问题 写完断言再用变异脚本改坏实现，确认对应用例真的转红，只破坏一条不变量的变异才算有效 变不红的用例等于没写
密钥泄露与越权 敏感内容扫描覆盖全部提交历史，管理员权限改成每次请求回查，公开接口用 429 与 Retry-After 断言并发上限 权限不在登录时判一次，每次请求都回查

落地。 本地与容器里能完整跑通，还没对外开公网，解析依赖第三方站点，登录态拿不到时会明确报错而不是静默失败。

未来。 想加一层解析结果缓存，同一个视频解析过一次就不再打第三方，把重复请求与限流风险一起降下来。

这个项目让我把「测试」从跑用例变成设计接缝，先让代码可测，再谈用例怎么写。

追问： SSE 怎么断言一帧 ／ 假实现怎么保证和真实现契约一致 ／ 升级迁移用例为什么单独一条

5.3 Vapor 优选

是什么。 商品查询加秒杀优惠券，商家侧能投放优惠信息。

怎么做的。 SpringBoot 加 MySQL 与 Redis，秒杀资格校验与扣减用 Lua 脚本，异步补偿走 Kafka，本地缓存用 Caffeine，持久层 MyBatisPlus。

做了什么。 后端开发，主要盯秒杀链路与缓存一致性。

难点 解法 一句话话术
并发下重复落库与超卖 Redis 加 Lua 把资格校验与库存扣减压成一次原子执行，再用重复提交与超时重试验证只生成一单 判定和扣减不能在两条命令里做，中间那一步就是超卖的窗口
缓存与数据库不一致 改成先更库后删缓存，配消息队列补偿与 TTL 兜底，把复现路径固定成「写库成功、删缓存失败」 先修哪一边取决于谁更怕脏数据

落地。 课程项目性质的系统，按生产思路做的设计与验证。

未来。 想把秒杀链路的压测口径固定下来，把并发数与吞吐量分开报，避免把施压机的极限当成系统的极限。

秒杀这条链路我最大的收获是知道并发缺陷不能靠运气复现，得先把「重复提交成功但只落一单」写成断言。

追问： Lua 脚本怎么保证原子 ／ 为什么先更库后删缓存 ／ 补偿失败怎么办

5.4 换个角度：给自己项目设计测试方案

面试官常在讲完项目后追加一句「你会怎么测这个项目」。这是把前面的内容翻过来问，答案结构反过来走。

层 要测什么 用什么
单元与契约 解析、降级、切块、断言是否抓得住改动 pytest 加变异验证
接口 参数、鉴权、幂等、限流、依赖故障 Postman 集合加 pytest 脚本
流式 SSE 帧顺序、字段完整、断流与超时 契约断言加超时用例
端到端 主流程与异常分支 手工用例加浏览器
非功能 并发上限、响应时间、资源占用 JMeter 加日志观察

我会先测最容易坏又最难发现的，也就是契约和降级，这两块坏了用户看不出原因，日志里也只剩一句 500。

追问： 手里只有一天先测哪层 ／ 怎么定哪些用自动化 ／ 回归范围怎么算

5.5 落地与未来期许怎么答

问法 答法
上线了吗 直接给现状，内部在用 / 本地跑通 / 未对外，再补一句原因
有什么用 讲谁在用、解决了谁的什么麻烦，不讲功能列表
以后怎么改 一句方向 + 一句原因，方向要能对上现在的缺陷

未来我最想补的是回归集和基线，每次改动都能自动跑一遍，这样方案比较才不是凭感觉。

追问： 为什么现在没做 ／ 要多少成本 ／ 你打算怎么排优先级

六、简历讲法：把已有能力讲透

同一份简历，讲出来的密度可以差很多。目标是在面试官心里立一个形象：做过真实工程、习惯用证据说话、清楚自己的边界。做法只有三种：补细节，补方法，补选择理由，都不离开简历写过的东西。

6.1 先做能力盘点

简历已有 能撑住的问法深度
三个项目与四条测试相关技能条 技术选型理由、验证方式、失败路径
开发组长与社团职务 沟通、分工、推进
软考、蓝桥杯、奖学金 基础扎实、学习节奏

缺口在规模与场景：没有多人在团队里协作测试的经历，没有和产品、算法对齐口径的经历，没有线上问题复盘的经历。这三块是实习岗最想看的东西，也是可以补的部分。

6.2 三类可补内容与补法

类型 补什么 例子 边界
项目内补细节 把已写机制往下一层讲，补上当时的选择与被否掉的方案 分层会话为什么用摘要不用全量上下文 机制必须真在这项目里
课程与课设补实践 把课程作业讲成一次完整的测试实践，有需求、有用例、有缺陷、有结论 数据库课设里做过一次造数与对账 课程确实做过才行
场景补经验 用「如果让我做」的方式讲方法，不冒充做过 让我接一个问答产品，我会先建回归集 用假设语气，别说成做过

我没做过大规模线上复盘，但我知道复盘要看的是漏测环节，比如需求阶段漏了一个异常分支，那复盘就要改用例检查项，不是改测试同学的态度。

追问： 你带过几个人 ／ 怎么和产品对齐口径 ／ 线上出过问题吗

6.3 三个可用的补强讲法

讲法一，用例库维护。 简历没写这一条，可以在项目后面补讲，说清这是做法而不是既有产出。我会这样讲：用例按「解析、摘要、追问、鉴权」分四组，每组标进入条件，改动哪块就只跑那组，跑之前先看这组用例上次有没有跟着逻辑一起改。

讲法二，缺陷推进。 缺陷被判定为非 bug 时，我不争对错，先把复现条件和影响面发过去，让对方判断优先级；如果是设计如此，就把这条写进用例的备注，避免下次重复提。

讲法三，和算法同学对齐口径。 评测问答产品最怕的是「我觉得答错了」这种描述。我会先约定判错的三条标准：和知识库冲突、答案里出现库里没有的内容、答非所问，三条之外的分歧先挂起，攒够样本再谈。

讲法 能撑住的追问 撑不住就照实说
用例库维护 分组依据、进入条件怎么定 没做过跨项目用例库
缺陷推进 判定分歧怎么落地 没做过缺陷度量
对齐口径 判错标准怎么定 没参与过标注规范制定

6.4 三条防线

防线 什么意思
机制防线 讲的每个机制都要能指到代码或文档，追问两层还能答
数字防线 不报没有出处的数字，需要报数就报口径，例如「按命中与召回两个口径比」
身份防线 不虚构公司与实习，虚构的雇主经不起背调与社保核对，问到就崩

我讲项目时数字只给口径，因为面试官追一句「怎么测出来的」就能分出真假。

追问： 这数字怎么来的 ／ 你在里面具体是哪部分 ／ 这个方案是团队定的还是你定的

6.5 一句话立形象

我是计算机专业在读，做过三个有完整链路的后端项目，其中一个独立开发到能容器化跑通。我最擅长的是把「测试通过」这句话拆开，用变异和契约断言去看它到底靠不靠得住。

七、工具与环境速通

7.1 Linux 查日志与进程排查

考点 一句话答法
看日志与翻页 tail -n 200 app.log 看尾部，tail -f 实时跟随，less +F 边翻页边追新日志
时间窗与 traceId grep '2026-11-08 10:' app.log 缩到分钟再 grep traceId，journalctl -u nginx --since '10 min ago' 同理
进程与端口 ss -lntp 看监听对应进程，ps -ef 看完整参数，lsof -i:8080 交叉确认
磁盘与负载 df -h 看分区占用，uptime 看 1/5/15 分钟负载，top -bn1 看瞬时占用

线上问题我先按时间窗把日志缩到出错那一分钟，再用 traceId 串起一次请求的全部日志，最后用 ss 和 ps 确认是哪个进程在报错。

追问： less 里怎么边翻页边看新日志 ／ grep 找不到日志先查什么（日志路径与轮转） ／ 磁盘告警先跑哪条命令

7.2 Git 最小集

考点 一句话答法
分支与提交 git checkout -b fix/login 建分支并切换，git add 后 git commit -m 落提交
回滚 本地未推送用 git reset --hard HEAD~1 抹掉，已推送用 git revert <commit> 追加反向提交
stash 与历史 stash push/pop 暂存取回，log -S"关键词" --oneline 找字符串增删，blame -L 10,20 文件 定位改动人
冲突处理 git status 找冲突文件，打开删掉 <<<<<<< 标记行，git add 后提交

reset 和 revert 的取舍看分支状态，本地没推送的提交用 reset 直接抹掉，已经推送的用 revert 追加反向提交，历史留痕方便别人对账。

追问： reset --hard 会不会丢未提交的改动 ／ revert 之后那笔改动还怎么合回来 ／ 冲突改完要不要再跑一遍测试

7.3 MySQL 客户端与造数

考点 一句话答法
连库与表结构 mysql -h127.0.0.1 -uroot -p -D shop 进客户端，SHOW CREATE TABLE orders\G 看建表语句
explain 读法 看 type 是否落到 const/ref、key 是否命中、rows 估算行数、Extra 有无 filesort/temporary
造数与清理 INSERT ... SELECT 从 information_schema.columns 取行配 LIMIT，清理用 DELETE 或 TRUNCATE TABLE
事务与锁 InnoDB 默认可重复读，行锁加在索引上，SELECT ... FOR UPDATE 拿排他行锁

我看 explain 只盯四列，type 说明走了什么访问方式，key 说明用没用上索引，rows 是扫描行数估算，Extra 里出现 filesort 或 temporary 就要去看排序和临时表开销。

追问： 加了索引但 key 仍为空常见原因（隐式类型转换、函数包字段、最左前缀断了） ／ 行锁没加在索引上会发生什么 ／ 造数 1000 条够不够用例跑

7.4 Postman 进阶

考点 一句话答法
环境变量 环境里放 base_url，请求地址写 {{base_url}}/login，切环境只换变量
关联与断言 上一请求 Tests 里 pm.environment.set 存 token，下一请求用 {{token}} 引用，pm.test 配 pm.expect 写断言
数据驱动 Collection Runner 选 CSV，首行表头即变量名，每行跑一轮
给 CI 导出 collection 与 environment 两个 JSON，命令行用 newman 跑同一份用例

我做接口关联就两步，登录请求的 Tests 把 token 存进环境变量，后续请求用双花括号引用，换测试环境时只改 base_url，一套用例跑多套环境。

追问： token 过期了 Runner 怎么办 ／ CSV 里某行字段缺失会怎样 ／ 断言写在哪一层（单请求 Tests 与整体脚本）

7.5 Charles 抓包

考点 一句话答法
手机代理与证书 手机与电脑同一 Wi-Fi，手机 Wi-Fi 设置填电脑 IP 与端口 8888，装证书后在系统设置里启用完全信任
过滤与查看 SSL Proxying Settings 加目标域名，Sequence 的 Filter 输关键字，请求响应看 Headers、Body、Preview
重写与断点 Rewrite 改 header 或参数做模拟，Breakpoints 拦下请求改完再 Execute
可分享复现 右键请求 Copy as cURL，贴出前把 cookie 与 token 打码

线上问题要交给研发，我把那条请求 Copy as cURL 发过去，对方粘到终端就能原样重放，比口头描述路径和参数快得多。

追问： 抓不到手机包先查哪三处（同网段、代理指向、证书信任） ／ HTTPS 页面一片红叉说明什么 ／ 断点改了请求怎么验证后端影响

7.6 JMeter 性能口径

考点 一句话答法
线程数与并发 线程数即虚拟用户数，并发是同一时刻在途的请求数，并发约等于 RPS 乘平均响应时间（秒）
聚合报告 Average 与 Median 看典型延迟，90% Line 看长尾，Throughput 是吞吐量，Errors 是错误率
施压机瓶颈 施压机的 CPU、网卡、JVM 堆先打满时数据会失真，压测前先看它自身的资源占用
结论口径 结论写成某并发档位下的 P90 响应时间与错误率，不直接外推成线上容量

报压测结果我给档位和口径，某并发下 P90 响应时间与错误率是多少，线上容量还受缓存命中、数据量和下游依赖影响，这两件事我会分开说。

追问： 线程数 100 是不是等于 100 并发 ／ 怎么判断是接口慢还是施压机先扛不住 ／ 响应时间正常但 RPS 上不去查什么

7.7 浏览器 DevTools 用法

考点 一句话答法
状态码与耗时 Network 看 Status 与 Time 分解，Stalled 高查连接排队，TTFB 高查服务端处理
过滤与复制 Filter 输关键字并切 Fetch/XHR 只看接口，右键 Copy as cURL 粘到终端重放
控制台断点 Sources 面板点行号与条件断点，看 Call Stack 与 Watch 里的变量实际值
报错定位 Console 先看报错堆栈定位到文件行号，再决定找前端还是后端

排查页面报错我先看 Network 的状态码和 TTFB，确认是请求没发对还是后端慢，再用断点在可疑分支停下来看变量实际值。

追问： 同一接口浏览器能通、脚本 403 差在哪（header 与 cookie） ／ 断点打进闭包内部怎么操作 ／ 长任务卡住主线程在哪个面板看

7.8 工具题的追问链

问题 30 秒答法 会怎么被追问
Linux 怎么查一次线上报错 按时间窗 grep 缩小范围，用 traceId 串完整条链路，再用 ss 与 ps 确认进程 grep 找不到日志查路径与轮转 ／ traceId 从哪来
reset 和 revert 怎么选 本地未推送用 reset –hard 抹掉，已推送用 revert 追加反向提交 reset 会不会丢改动 ／ revert 后如何再合回
explain 显示全表扫描怎么办 看 type、key、rows、Extra 四列，补索引后对比四列变化 加了索引为什么不生效 ／ 为什么不建议盲目加索引
线程数 100 是不是 100 并发 线程数是虚拟用户，并发是在途请求数，两者用响应时间换算 并发怎么估 ／ 施压机打满了怎么发现

工具题我按固定顺序答，先说命令或入口，再说判断依据，最后补一句边界，追问往哪深都能接得住。

追问： 让你现场演示会先演示哪个 ／ 工具拿到手第一步做什么 ／ 哪些问题你会直接去查文档而不是硬答

八、进门前 30 分钟与反问

8.1 三十分钟清单

分钟 做什么
0-5 把三个项目的一句话简介各念一遍，出声
5-12 每个项目挑一个难点讲一遍，讲完给自己补一句「怎么验证的」
12-18 等价类与边界值各举一个自己的例子，别背定义
18-24 过一遍 SQL 四件套：条件、分组、连接、子查询，各写一条
24-30 想好三个反问，确认要问的业务问题

8.2 反问怎么问

反问 想知道的
实习生进来主要接哪一块，功能、接口还是评测 岗位真实分工
测试用例库现在大概什么规模，维护节奏怎么样 资产成熟度
大模型评测这块目前是人工判还是有规则与脚本 技术水位
团队里实习生和正式员工怎么配合 协作方式

8.3 不会的时候怎么说

这块我没做过，我的理解是……如果是我，我会先确认……再动手。回去我把这块补上。

不装懂，也不空手。给一个方向，说明你会怎么查，比硬答一行错误答案安全得多。

8.4 诚实边界

项目机制部分按简历写过的内容讲，机制之外的延伸一律用「如果让我做」的假设语气。面试时守同一条线，讲过的每一句都要能追到代码或文档。
