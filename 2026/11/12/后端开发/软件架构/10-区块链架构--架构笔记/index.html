建材集团一批特种钢材出了质量问题要追责。采购方掏出电子合同，写的是国标。供应商也掏出一份，写的是按样品交付，两份都有电子签章，都说自己才是原件。物流方说温控记录完好，但系统是自建的、数据自己存自己管，这话在追责现场没人认。质检方说报告确实出过，可它在几个渠道里转了好几手，说不清哪份没改过。最后打到鉴定机构，鉴定机构能证明文件现在的哈希值是多少，证明不了它从签的那天起就没被改过。

🔹 这个事故浓缩成一句话：四个相关方，四份数据库，零份共识。每一次对峙问的都是同一句——你那份我凭什么信。

10.1 引言与本课定位

🔹 视频是《软件架构》系列的继续，开场先划边界：不需要懂密码学，不需要研究过比特币，连区块链这三个字是什么意思都不要求。门槛只有一条——会 Java 这样的语言，用过 Spring Boot，做过哪怕很小的项目，知道 Controller、Service 怎么一层层调。

🔹 第二个边界：不聊投资，一个字都不聊，只讲技术本身——区块链这个框架在什么场景下有价值、架构长什么样、代价是什么，最后怎么装进熟悉的 Spring Boot 项目里。

🔹 课程路线四段。第一段从每天写的代码说起，从数据库的 insert 出发一步步把区块链拼出来。第二段是术语，账本、共识、智能合约这些词要列一张表扫清。第三段是实战，从一个 Spring Boot 加 MySQL 的存证系统升级成区块链架构。第四段从 demo 到生产，给工程化的答案。

10.2 为什么需要区块链

🔹 第一章的四个问题：你每天写的 insert 离区块链差几步。账本抄给所有人为什么就改不动了。区块链和比特币、发币是什么关系。什么代价，什么时候不该用。

🔹 先替 MySQL 说句公道话。中心化数据库有四个好处：快，一次主键查询毫秒级返回，吞吐上万是家常便饭。能改数据，一个 update 搞定，错了还能事务回滚。权限、备份、审计都在自家运维手里。便宜，一台八核 16G 就能撑起日活百万的业务。这四条区块链都给不了，链比数据库慢得多、贵得多、还不能改。

🔹 数据库在四种场景里就是最优解。数据只在一家机构内部流转。参与方愿意认一个共同的担保人，比如平台、银行、监管。业务要求可修正可修改，比如用户注销、错账冲正。只是单纯想让日志不可改——这种情况在数据库审计日志加一次写入多读的 WORM 存储就够，又便宜又合规。

⚠️ 把区块链用在这四类场景上，视频的说法是杀鸡用牛刀。区块链的价值只有一个出口：多方互不信任，又没有人有资格当担保人的时候。

📌 考点：区块链慢、贵、不能改，这三条在单机构场景全是缺点。数据库在这些场景是最优解。

🔹 什么时候互信会变成刚需？视频给了中心化世界的三道坎。第一道是多方不信任，跨机构各存各的账，同一批货四份记录四个版本，只能靠对账人工对比，出错就开始扯皮。第二道是自证清白，账在立方手里，签章能证明文件是谁签的，证明不了签完之后有没有被改过，数据躺在利害相关方的服务器上，日志记得再全也是自己证明自己。第三道是历史追责，找中立平台记账听着不错，但平台收费要吃掉交易额的 1% 到 3%，平台需要授权还可能跑路，本身仍是单点，接着就是谁来监督这个担保人——无限套娃。

🔹 三道坎的共同点：问题出在信任对象没有架构层面的答案。数据库解决的是记得准，解决不了大家信。还有两笔隐形成本：跨机构对账的时间差，两边财务每月兑一次账差一笔就要拉群打电话翻存证，好几天，这笔钱不在任何报表上却真实发生。跨机构共享数据还牵涉谁能看谁的什么东西，一旦集中就等于全部可见，中心化架构在这点上无解。

🔹 解法第一步，把账抄给所有人。正式名字叫分布式账本：四家每家存一份全量，新增一笔记录就立刻广播给所有人，谁手里都是全量，谁也不比谁多一份原始数据。落到工程上就是每一方部署一个记录服务，一个 Spring Boot 加一张表，业务发生一笔就同步调用所有参与方的服务，各自插一条，相当于把数据库的 log 全量互推给对方，还要立下铁规矩——这张表只允许 insert，没有 update 没有 delete，写错了追加一条更正记录。这个形态像 git，人人都有一份完整克隆，谁在本地改了什么一眼就能看出来。

🔹 光抄账本不够，每一份副本还要可验证，工具是哈希。定义：把任意内容压缩成一个固定长度的指纹，比如 SHA-256，输入一部电影还是一个字，输出永远是 64 个 16 进制字符，内容变一点点指纹面目全非。视频的说法是内容定指纹、指纹验内容。三条性质：确定性，同样输入永远同样输出。雪崩效应，改一个字输出的 64 位整个变掉，与原来毫无关联。单向，由内容算指纹瞬间完成，指纹反推内容数学上做不到，比作能通过指纹认出一个人，却没法通过指纹长出一个人。

🔹 怎么发现有人偷偷改了副本？存指纹。每条重要记录额外存一份哈希，对峙时把双方账本重新算一遍指纹，跟当初存的一比，一样就是没改过。

🔹 账本那么长，逐条核对太琐碎。工程上的做法是攒一批打个包，像批量提交一样，一万条 insert 攒成一批一起提交省成本，这个包就叫区块。区块有四个字段：本块的数据 data、上一块的指纹 previous hash、本块自己的指纹 hash，以及出块时间 time。其中 previous hash 是整个设计的灵魂。链就是这些包按指纹首尾相扣排成一串：块一的 hash 是 AAA，块二存着 previous hash 等于 AAA，算出自己 BBB，块三存 BBB。有人偷偷改块二里的一个字，块二的 hash 就变了，块三的 previous hash 对不上，块三连着块四，后面所有块连环失效——改一个字等于同时伪造后面所有块的指纹，还要瞒过所有人手里的副本，理论上可能，工程上不可能。

🔹 完整定义：多方各存一份全量账本、只允许追加、页与页之间用哈希相扣的账本，改任何一条历史记录都会被全体立刻发现。回到事故：正确做法是签署合同的瞬间就把文件的哈希值写入多方共同维护的链，原文各自留存，日后任何一方拿出原文重算哈希跟链上记录对比，相等就证明从签下那一刻起一个字都没改过。这个证明依赖数学，司法存证平台底层就有类似结构。

🔹 视频接着泼两盆冷水。区块链比不过中心化数据库，查询、统计、事务样样不如 MySQL。它也不是防泄密的保险箱，链上数据人人有份大家都看得见，敏感数据放上去等于公开。它也不是万能的，只保证记上去的没被改，不保证记上去的是真的，塞进假的垃圾，取出来的还是垃圾。

🔹 代价有四个。慢：写一条数据要经过全网广播、共识确认、多节点落盘，比 MySQL 只需本机事务提交慢很多，MySQL 轻松上万 TPS，区块链大多数情况是上千级别。膨胀：每个节点都存全量账本，历史只增不减，不能像普通数据库那样清理归档，图片视频这类大文件绝对不要上链，只存哈希。隐私：账本人人一份，采购价与成本价这类数据不能让对手和利益相关方看到，客户名单也一样，谁能看到多少要在架构层重新设计，要考虑群组隔离、权限和加密。改不了：这是最容易被低估的一条，业务写错了怎么办，用户想行使删除权怎么办，链上没有 update 没有 delete，纠错只能追加更正记录，旧数据永远躺在那里，所以上链前要严格把关，纠错靠冲正记录。

📌 考点：课件把三件事分开了——区块链是多方记账的架构，是中性工具；比特币是区块链的第一个应用，2009 年诞生；虚拟货币是链上的激励代币，波动极大。企业用的链可以一分钱的代币都没有，激励靠联盟规则，不靠挖矿发币。

10.3 区块链架构基础

🔹 术语先扫清。共识机制的定义：两个节点的账不一样时，按什么规则定输赢。它回答两个问题：谁来记账，几个节点同意才算数。

机制 怎么定输赢 性能与能耗 视频给的定位
POW 工作量证明 全网算力竞赛，谁先解出难题谁拿到记账权，其余只做验证 TPS 个位数到十几，能耗很高 比特币的选择，为完全匿名的陌生公网设计
POS 权益证明 按质押权益加随机选记账人，作恶被发现罚没质押 公链方案 公网上用，企业场景基本碰不到
PBFT 实用拜占庭容错 点名投票一个提案，2/3 以上同意才通过 上千到上万级 TPS（视频口径），能耗低 企业级联盟链首选
Raft 及其变体 领导者选举加日志复制 上万级 TPS（视频口径） Nacos、etcd 底层都是这一组协议

🔹 拜占庭的来历是几个将军围城靠传令兵沟通，其中可能有叛徒传假消息，翻译到计算机状态就是有的节点作恶账还能不能记对。PBFT 的答案很朴素：2/3 以上同意才通过。四方里叛徒不超过一个就拦不住其他三家把账记对，也就是能容忍 1/3 的坏节点。

🔹 挖矿到底在挖什么。每一块账本只能由一个节点来记，这个名额叫记账权，挖矿就是抢这个名额，不同共识机制是不同的抢法。POW 的想法是一道算术题：找一个数，让块内容加上它进行哈希之后，开头指定的位数全是零，前 N 位为零。哈希没有规律，只能一个数一个数地试，举个例：普通电脑算几十毫秒，要求前六位都是零可能要秒级，比特币全网平均 10 分钟才解出来一次，还要烧掉巨额电费。挖矿的真相就是用电费换记账权，比拼算力，谁先找到这个数谁拿到记账权。

🔹 公链可以想成一个完全开放的公共广场，有电脑有网络随时加入，下载数据、发起交易，记账权人人可争，比特币挖矿和以太坊质押都是这样。它是任何人都能提交写操作的超级大型公共数据库，数据公开透明，效率非常低。比特币的难度按视频说法是找前十几位都是零的数（实际难度约是前 20 位十六进制零），全网矿机一起算，平均 10 分钟一块，电费真金白银在烧。公链慢是故意的，用出块速度换作恶成本——十分钟出一块意味着要篡改历史就得在十分钟内追平全网算力重挖后面所有块，几乎不可能。

🔹 私链是企业内部的闭门会议室，准入需要许可，完全由某一个组织控制，外人进不来，记账权高度集中，只有指定节点能记账，本质上也是中心化的，写入速度非常快，隐私性很强，跟 MySQL 集群这类传统分布式数据库没太大区别，只是多了一个防篡改的链式账本结构。

🔹 联盟链是行业俱乐部，准入半开放，由多个企业或机构组成联盟，成员审批才能加入，记账权由联盟内指定节点共同参与，比如十家银行里五家作为节点共同确认交易。特点是多中心化，兼顾隐私、效率和一定的去中心化信任，TPS 远高于公链。

🔹 智能合约就是一段部署在链上的公共代码，所有节点共同执行，规则提前写死谁都改不了，相当于 MySQL 的存储过程，区别是它跑在每家机构的节点上，而不是某一家的数据库里。还可以类比自动售货机：规则印在机器上人人可见，投币就出货，没有人能暗箱操作，因为机器不偏心。四家机构调同一个合约，不用互相写接口也不用互相信任。什么时候才需要真写合约：多方的业务规则经常变，又都要认账。合约一旦上线改不了，业务规则经常变就要特别小心，可变的参数做成链外配置，或者干脆别放合约。

🔹 剩下的词一并过一遍。节点是跑着账本的一台服务器，或者一个 Spring Boot 实例。钱包是管密钥的工具，里面装的是钥匙不是钱。签名是用私钥给数据盖章，证明这笔确实是我发的。分叉是两份账对不上。出块是打包一批记录成一块。gas 是公链上执行代码的手续费，联盟链保留计量但不收费，企业级场景基本不用管。

📌 考点：公链谁都能进，用的是抢答赛那套，慢但关不掉。联盟链是机构实名准入，投票那套，快能追责，所以企业落地几乎都选联盟链。私链一家公司自己玩，本质是带审计的高级数据库，视频的建议是别浪费这个钱。

10.4 区块链实战

🔹 实战章节只有两小段代码加一堆图和流程：一段 14 行的迷你链，一段 18 行的 Spring Boot 接口，每行都带中文翻译。

🔹 起点是存证系统：本质是一套防篡改的电子证据保管箱，用密码学和区块链把易被修改、易丢失的电子数据固定下来，合同、交易日志这类数据固定后具备法律效力，能在纠纷中当证据用。普通电子数据存在硬盘或中心化服务器里容易被篡改、伪造、删除，一旦发生纠纷，自己提供的截图或后台数据对方可以不信。存证系统的核心任务是解决自证清白。

🔹 传统流程先看清楚：用户上传合同，后台算出文件的 SHA-256 指纹，原文存对象存储，指纹存到存证表，返回一个回执——你的文件我收到了。每个项目都是这个结构，没有一行你不了解的东西。它有两个致命缺口：数据库在你手里，别人凭什么信，DBA、运维甚至一个工单都能改这行记录，对手方要的是你没改过的证明，你自己说了不算。只有你一家存，历史说不清，中间有没有被替换过没有任何机制能回答。升级成链补的就是这两条：账本各方各存一份谁也改不了，指纹连成链互相验证，改一处就全线报警。这两个缺口也是很多存证平台招标文件里的需求，比如第三方可验证、历史可追溯。

🔹 迷你链的三个关键点：previous hash 是灵魂，没有它你只是个列表。出生就算指纹，篡改立刻暴露。只追加不修改，没有 update 也没有 delete，这个限制换来的是互相取得信任的来源。视频给的是带中文注释的片段，下面按它的结构整理，完整实现留给自己补。

🔹 往链上追加一个块，新块的 previousHash 填当前末尾块的 hash，这一行就把所有块串成一条链。

🔹 亲手弄坏一次，验证不可篡改是不是真的好。三步：偷偷改第一块的数据。重新算哈希，新的指纹和块里存的旧指纹对不上，第一块当场报警。第三块里记的 previous hash 对不上第一块，第三块和第四块全线报警。神不知鬼不觉地改就得把后面每一块全部重算一遍，改一块相当于重做整条链。公链还嫌不够，加一道工作量证明，重算每块都要做几亿次哈希运算，篡改成本从改一个字段变成烧几百万电费。POW 证明的是成本，企业链节点实名、作恶可以追责，用投票就够，这是联盟链快、公链慢的根本原因。

🔹 单机链有单点风险，一条链只在一个节点上和普通账本没区别，四家各跑一份互相通报才算分布式账本。流程五步：A 节点记 B 块，先校验，重算指纹对应 previous hash，对不上直接丢。广播给同伴节点，行话叫 peer，一个 HTTP 调用就能解决。收到的人再转给认识的人，像纯八卦，行话叫 gossip 协议，全网秒级同步。最后四家各存一份完整账本。用微服务的经验理解，每个节点就是一个 Spring Boot 实例，节点之间互相 HTTP 调用，没有 MQ 也没有注册中心。安全底线只有一条：先校验再转发，不校验就转发，一个坏块可能污染全网。

🔹 新问题随之出现：A 和 B 同时各写一块同时广播，有的节点收到 A 的有的收到 B 的，账本出现两个版本，分叉了。转发解决不了，必须有一条大家都服的裁决规则，那就是共识。真正的区块链把共识内置了，写代码的人不用操心这个问题。

🔹 18 行的接口代码把链包进熟悉的三层结构：一个 Controller，两个接口。存证接口收到文件算指纹，调用 addBlock 上链，把块哈希和时间戳当返回值返回。验证接口传一个哈希进来，链上查有没有、什么时候存的。加上按哈希回溯查询，三个接口构成一套最小的存证系统。下面是按视频描述整理的片段。

🔹 生产前必须补三件事，都是工程基本功，上链不能豁免：接口加鉴权限流。存证按文件指纹做幂等，重复上链直接返回原回执。每次调用写审计日志。

🔹 链挂在哪一层？把它当成一个特殊的持久层，以前背后是 MySQL，现在换成 chain service，背后的业务代码一行都不用改。换持久层不换业务，这是链能落地的一个关键。

🔹 业务规则老是要改的时候智能合约上场。存证合约两个按钮：store 登记一次存证并统一指纹，重复投币会被拒，机器替你做幂等。verify 查询谁什么时候存过。登记成功还会喊一嗓子通知链下系统，这叫事件。Java 侧对接四步：引官方 SDK 和客户端、配数据源。用合约地址加载出一个 Java 对象，之后调它像调本地 service 一样。写操作走共识大概几百毫秒，读操作本机毫秒级，跟读写分离是一个思路。监听事件、落库回执，私钥放到密钥管理服务里，不放进 git。什么时候才需要真写合约：多方规则常常都变，又互相认账。四步里最容易出事的是监听事件——它是异步的，服务一重启可能漏消息，生产上要配漏单补偿，定期拿本地待确认的记录去链上反查询。链给了事件，可靠性还得靠自己的工程兜底。

🔹 跨机构怎么搭联盟链，有现成开源轮子：FISCO BCOS，国产的、免费、文档比较全。就四步：一条命令生成四个节点的链，本机就能模拟四家机构，一键启动看到四个节点进程都在，链就活了。用官方控制台敲两行命令看块高、发一笔存证，几百毫秒就能出块。最后装一个网页控制台，点几下就能管链、发合约、看交易。

🔹 四个必须理解的概念。准入靠证书，谁能连这条链是机构们投票定的管理问题。群组是一条链上切出多个独立账本，像 MySQL 实例可以分多个库，不同合作圈不同群组的数据天然隔离。共识节点参与投票，观察节点只看不投，适合监管方接入。为什么至少四个节点：PBFT 只容忍 1/3 作恶，要容忍一个坏节点至少需要四个。可以自己演示，停掉一个节点链照常出块，停两个共识就停了。

🔹 什么东西放链上，什么放链下。链上慢、贵、改不了，就只放存在证明——文件指纹、谁、什么时候，就一条几十个字。链下是快的、便宜的、归你管的：合同原文放对象存储，业务数据放 MySQL 查统计，全在链下。个人信息删除权怎么办：链下原文可以删，链上的哈希追加一条失效记录，既遵守个人信息保护规则，又保证审计连续。

🔹 四步串起来：用户存合同原文进存储，指纹写上链几秒出块，拿到区块号和交易号。链上事件异步通知 Java，监听后把回执落库。再加一个每天凌晨的对账定时任务，逐条比对链下记录和链上的回执，漏记或篡改立刻暴露。

🔹 判断一个字段要不要上链，只问一句：将来争议的时候第三方需要验证它的什么？只要验证它存在过没改过，哈希上链就够。要频繁读内容就留链下，前端展示永远查库不上链，链每秒只能写上千这种 TPS，拿它当查询库会非常慢。

🔹 性能上，联盟链出块大概是百毫秒级别，每秒大概千笔交易（视频口径），够大多数多方业务用，前提是链上只放凭证，大文件和大字段一律放链下，写之前先做幂等，重复数据别浪费共识。安全上，私钥进密钥管理服务，绝不落代码库。证书定期轮换。合约代码能短则短，上限改不了，短就是安全。审计日志照常记，上链不能豁免工程纪律。

📌 考点：一条存证请求的落点判断只有一句——第三方将来要验证什么。存证系统两个致命缺口：库在自己手里、只有自己一家存。

10.5 从 demo 到生产

🔹 demo 能跑和生产之间隔着一堆工程问题：代码怎么分模块、一次请求怎么走完全程、哪些场景值得上、怎么部署运维落地、怎么排期。

🔹 分模块给了五个目录，四个模块加一个公共库。chain-core 是领域模型，Block、哈希工具这些不依赖 Spring 的纯 Java。chain-contract 是合约源码和部署脚本，独立构建，产物放到配置里。chain-api 是 Spring Boot 应用，REST 接口、鉴权、幂等这些。chain-sink 是事件监听、对账、回执落库。chain-common 是 DTO、异常、工具类，只被依赖，不依赖别人。

🔹 三条理由。chain-sink 独立成模块，因为事件监听和对账是长期运行的后台任务，伸缩节奏和 API 完全不一样——API 白天高峰晚上空闲，SINK 二十四小时匀速跑，放一个进程里扩容 API 时会顺手多起几个 SINK 重复消费事件，分开将来能拆成独立进程。chain-contract 独立发布，因为合约改一次要多方评审、重新部署、还要更新地址，节奏和 Java 服务完全不同。把合约版本化，地址进配置中心，不重启就能切到新合约，合约升级时不需要停业务。chain-core 不依赖 Spring，领域逻辑保持纯 Java，单元测试毫秒级就能跑完，前面那条迷你链就是它的一个雏形，不需要启动 Spring 容器就能测。

🔹 一次请求走完全程，视频给的是合同签署场景：甲公司、乙公司、公证处、监管方四方，签完存证，将来有纠纷能当证据。九步。第一步网关收请求，做三件事——鉴权确认是这家机构，限流防止有人刷流量，校验格式和大小，比如限制 20 兆以内、只收 PDF 和图片，这是上链前的第一道关，别把垃圾扔进链里。第二步服务端算 SHA-256 得到 64 位码，原文进对象存储，业务记录落数据库，记住的只有 key 没有原文。第三步幂等检查，拿哈希查是不是已经存过，同一份合同甲乙双方可能各传一次，已存在就直接返回原回执，不用重复上链。第四步签名发交易，SDK 从 KMS 里取这家机构的私钥签这笔交易，把哈希写进合约，私钥不在应用内存里在 KMS 里，应用只请求签名。第五步共识出块，交易广播到四个节点，视频说 PBFT 是两阶段投票，FISCO BCOS 官方流程是预准备、预投票、预提交三阶段，拿到 2/3 同意就出块，大概几百毫秒。第六步合约执行，四个节点各自执行同一份 store 函数，校验、写 mapping、emit 事件，注意各自执行不是一台机器算完广播结果，是每台机器都算一遍、算完对答案。第七步回执落库，chain-sink 监听到 store 事件，拿到区块号、交易哈希、合约地址和时间落进回执表，它是异步的，可能比第八步晚几秒。第八步返回给用户的回执编号在业务侧生成，不是在链上生成的，这张回执包含编号、时间、哈希、区块号。第九步日后验证，任何一方（甲公司、乙公司、公证处、法院）把手上的合同重新算一遍 SHA-256，和链上记录比对，一致就证明从签署那天到现在一个字都没改过。

🔹 场景不同的做法差很远，视频举了四个落地场景，每个都问三句：痛点是什么、链在其中扮演什么角色、是不是非链不可。

场景 痛点 链的角色 判断
司法存证 电子证据一改一失效，自己证明自己法院难采信 签署瞬间哈希上链加时间戳，法院认链上记录作为证据 非链莫属，同时满足多方与防篡改两个刚需
供应链溯源 批次信息各环节自己上报，出问题查不到源头 每环节把批次号加校验哈希上链，全程可回溯，责任可定位 可以做，但别承诺上链就保真——链只保证记录没被改过，不保证记录是真的
供应链金融 核心企业信用传不到二级三级供应商，中小企业融资贵融资难 应收账款凭证上链流转，可拆分，金融机构据此放款 多方互信加监管要求下非常合适，天生是联盟；链上唯一重复质押被杜绝
数字身份证书徽章 资质验证靠打电话靠发函，慢且不可靠 颁发机构把证书哈希上链，任何验证方秒级核验真伪，机构解散后证书依然可验 规模小时中心化发证系统更便宜，跨机构长生命周期才值得上链

🔹 衡量值不值得用区块链，视频给了三问：跨机构吗、需要防篡改背书吗、数据源头可信吗。三问下来会发现很多场景下不用区块链才是更正常的答案。

🔹 部署分环境。本地和测试环境用一条 docker 命令把几个组件全部起起来，测试链按脚本建，本地永远不能手工搭链，手工搭的链第二天自己都复现不出来，要用脚本一键重置。生产分两种：优先用云厂商的 BaaS，节点托管、证书轮换、监控告警都是现成的，能省下运维成本。必须自建就上 K8S，注意链节点是有状态服务，需要数据盘、需要稳定的网络标识，不要当成无状态服务让它到处漂移。业务应用 chain-api 和 chain-sink 才是无状态的，可以随便弹性伸缩扩容。原则是节点要稳，节点频繁重启会触发视图切换，出块间隔会抖动，严重时整条链卡住，所以链节点的副本数、调度策略、滚动升级都要按稳定需求设计，不能按弹性需求设计。

🔹 监控定四类指标。第一类出块：高度是否在增长，出块间隔抖不抖，高度不涨这条链就是死的。第二类节点：进程在不在，磁盘满没满，peers 数够不够。第三类交易：TPS、失败率、有没有积压队列。第四类业务：回执落库延迟、对账差异条数，这些从业务视角看链的健康度。

🔹 治理技术上解决不了，必须落到书面章程上：新成员准入流程谁来批准、要多久、要什么材料。作恶或违约怎么处置，罚多少、怎么退出。合约升级要有多方签名规则，需要几个人签、谁有否决权。这些都是通过章程约束人。

🔹 路线三段。第一阶段 03 个月，存证先行、单场景验证，挑一个最痛的场景，比如合同、检测报告、验收单，把哈希上链，起步可以用 BaaS 或者本机四节点小集群，产出一条有背书的完整链路。第二阶段 39 个月，多方扩源、立好规矩，让更多机构入网，群组划分、治理章程、WeBASE 运维体系和告警建起来，产出是一个能自我运转的联盟。第三阶段九个月以后，深化集成、治理净化，合约升级体系、隐私计算、跨链互认、和业务系统深度集成、数据产品化一步步来，到这里链才真正变成基础设施。

⚠️ 顺序反了会天天出事：一上来就让八家机构入网，章程还没签，结果一家想退一家作恶一家说数据不能给别人看，项目直接停摆。顺序是先证明单点价值，再扩源，再深化。

🔹 五个坑。第一个坑是为了链而链，老板说上就上，单机构场景硬上，维护成本全打水漂。解法是自查数据是不是只在内部流转、有没有共同担保人、业务要不要可删可改。第二个坑是原文上链，大文件直接塞到链上，存储爆炸、同步变慢、隐私全无。解法是哈希上链、原文入库。第三个坑是先搭链后立规矩，节点谁出钱、作恶怎么罚没说清楚就开张，后面的扯皮只是时间问题。解法是先签章程再搭链。第四个坑是密钥放到 git，开发密钥顺手提交，身份可以被冒用，事故不只自己出事整个联盟都出事。解法是 KMS 加 CI 私钥扫描。第五个坑是赌合约不会改，上线前发现有 bug，合约不可热修，业务被迫停摆。解法是数据逻辑分离加多方签名升级，而且要在第一版就设计进去，不能等出了事再补。

10.6 常见错误清单

🔹 前五条是视频点名的五个坑，后三条是其他章节顺带提到的坑。

⚠️ 为了链而链。单机构内部流转、有共同担保人、业务本身要可删可改的场景硬上链，慢、贵、还不能改，维护成本全打水漂。
⚠️ 把合同原文、大图片大文件直接塞上链。每个节点都存全量账本且只增不减，存储膨胀、同步变慢、隐私全无，只该把哈希上链。
⚠️ 先搭链后立规矩。节点谁出钱、作恶怎么罚、怎么退出都没写进章程就开张，后面的扯皮只是时间问题。
⚠️ 把私钥提交进 git。身份可以被冒用，事故不只自己出事，整个联盟一起出事，私钥必须进 KMS 并做 CI 私钥扫描。
⚠️ 赌合约不会改。合约上线即不可热修，上线前发现 bug 业务只能停摆，升级方案要在第一版就设计进去。
⚠️ 链上放原文和敏感字段。链上人人有份谁都看得见，采购价成本价客户名单上链等于公开给对手。
⚠️ 用链当查询库。前端展示也去链上查，链每秒只能写上千这种 TPS，查询会非常慢，展示永远查链下库。
⚠️ 忽略事件异步和消息丢失。监听事件服务一重启就可能漏消息，生产上不配漏单补偿机制，回执表会和链上对不上。

10.7 小结

🔹 先问多方互不信任，再问要不要链。没有多方的情况，区块链就是一个昂贵的摆设。

🔹 链上存共识，链下存业务。哈希上链是工程和法务的共同语言，在工程上是最省成本的证据，在法务上是可采信的凭证。

🔹 不可篡改是数学给的，信任是人管出来的。密钥、章程、治理一个都不能少，技术能保证改了会被发现，保证不了没人敢改。

🔹 让联盟活下来的是章程、准入和处置机制，链只是把规矩写成了代码。
