MyBatis--面试思维导图笔记

基础概念

框架定义

MyBatis是什么

  • 半ORM框架
  • 封装JDBC
  • 关注SQL语句本身
  • 无需处理驱动加载、连接创建、Statement创建等冗杂过程
  • 编写原生SQL，可严格控制执行性能
  • 使用XML或注解配置映射
  • 将POJO映射为数据库记录

为什么叫半ORM

  • 查询关联对象需手动编写SQL
  • 相比Hibernate全自动ORM，MyBatis需开发者编写SQL
  • Hibernate可根据对象关系模型直接获取关联对象

ORM概念

对象关系映射

  • 解决关系型数据库与Java对象映射问题
  • 通过描述对象和数据库映射的元数据
  • 将程序对象自动持久化到数据库

JDBC不足与MyBatis解决

连接频繁创建释放

  • MyBatis通过连接池统一管理
  • 配置数据源链接池

SQL写在代码中难维护

  • MyBatis将SQL配置在映射文件中
  • 实现SQL与Java代码分离

参数设置麻烦

  • MyBatis自动将Java对象映射至SQL语句
  • 自动处理占位符与参数对应

结果集解析复杂

  • MyBatis自动将SQL执行结果映射为Java对象
  • 封装为POJO对象

Hibernate与MyBatis对比

映射关系

  • MyBatis半自动映射
  • 配置Java对象与SQL执行结果对应
  • 多表关联简单
  • Hibernate全表映射
  • 配置Java对象与数据库表对应
  • 多表关联配置复杂

SQL优化与移植性

  • MyBatis手动编写SQL
  • 优化容易
  • 数据库无关性差
  • Hibernate封装SQL
  • 提供HQL操作数据库
  • 数据库无关性好
  • SQL优化困难

适用场景

  • MyBatis适合需求变化频繁、快速迭代项目
  • 如电商网站
  • Hibernate适合需求稳定、中小型项目
  • 如办公自动化系统

核心配置与使用

使用步骤

创建SqlSessionFactory

  • 从配置文件或直接编码创建
  • 读取mybatis-config.xml配置

创建SqlSession

  • 通过SqlSessionFactory创建
  • SqlSession代表程序和数据库之间桥梁

执行SQL或获取Mapper

  • 直接通过session.selectOne执行SQL
  • 通过session.getMapper获取Mapper接口
  • 通过Mapper接口方法执行SQL

提交事务

  • 更新、删除语句需提交事务
  • 调用session.commit()

关闭会话

  • 调用session.close()
  • 释放数据库资源

组件生命周期

SqlSessionFactoryBuilder

  • 方法级生命周期
  • 创建SqlSessionFactory后不再需要

SqlSessionFactory

  • 应用级生命周期
  • 应为单例
  • 是应用级的 SqlSession 工厂，连接池由 DataSource（POOLED）提供
  • 多次创建和销毁浪费资源

SqlSession

  • 请求或方法级生命周期
  • 非线程安全
  • 不能被共享
  • 每次请求创建新的实例

Mapper

  • 方法级生命周期
  • 从SqlSession中获取
  • 在事务方法内使用

传递多个参数方法

顺序传参法

  • #{0}、#{1}代表传入参数顺序
  • 不直观，顺序调整易出错
  • 不推荐使用

@Param注解传参法

  • #{名称}对应注解括号内名称
  • 参数不多时直观
  • 推荐使用

Map传参法

  • #{名称}对应Map中的key名称
  • 适合传递多个参数
  • 参数易变灵活传递

Java Bean传参法

  • #{名称}对应Bean类成员属性
  • 直观，可读性强
  • 业务逻辑处理方便
  • 推荐使用

实体类属性与字段名不一致处理

SQL别名方法

  • select order_id id, order_no orderno from orders
  • 字段名别名与实体类属性名一致

resultMap映射方法

  • 使用<result>映射字段名和属性名对应关系
  • property为实体类属性名
  • column为数据库表字段名
  • 主键使用<id>标签

枚举映射

MyBatis支持映射枚举类

自定义TypeHandler实现

完成javaType至jdbcType转换

完成jdbcType至javaType转换

体现为setParameter()和getResult()方法

#{}和${}区别

#{}预编译处理

  • 占位符替换为问号?
  • 使用参数值替代问号
  • 能有效防止SQL注入
  • 参数值被正确转义

${}字符串替换

  • 参数值直接替换到SQL语句
  • 不经过预处理
  • 存在SQL注入风险
  • 用于动态表名、列名、排序等
  • 需提前对参数进行安全性校验

模糊查询like写法

${}写法

  • 可能引起SQL注入
  • 不推荐

“#”{}写法

  • 占位符必须写在引号外面
  • ‘%#{q}%’ 会报 Parameter index out of range；’%’#{q}%’ 或 “%”#{q}”%” 都能用

CONCAT函数写法

  • CONCAT(‘%’, #{question}, ‘%’)
  • 推荐使用

bind标签写法

  • 官方支持，与 CONCAT 并列可用，不是不推荐

获取生成主键

新增标签中添加keyProperty=”ID”

使用useGeneratedKeys=”true”

插入完成后通过对象getId()获取主键

实现主键回填

全局配置settings

cacheEnabled

  • 全局开启二级缓存

lazyLoadingEnabled

  • 全局开启延迟加载

mapUnderscoreToCamelCase

  • 自动将下划线命名映射为驼峰属性
  • 如user_name映射为userName

useGeneratedKeys

  • 允许JDBC支持自动生成主键

logImpl

  • 指定日志实现
  • 支持SLF4J、LOG4J、LOG4J2、JDK_LOGGING、STDOUT_LOGGING

动态SQL

常用标签

if标签

  • 根据条件组成where子句
  • test属性编写判断条件
  • 如<if test=”title != null”>

choose when otherwise标签

  • 类似Java的switch语句
  • 按顺序匹配条件
  • 无匹配时执行otherwise

trim where set标签

  • <where>自动处理条件中的AND/OR
  • 适用于所有查询条件动态情况
  • <set>用于动态更新
  • 自动处理多余的逗号
  • <trim>可自定义前缀后缀
  • 覆盖处理多余连接词

foreach标签

  • 遍历集合
  • 用于构建IN条件
  • 用于批量插入

foreach属性详解

collection属性

  • 必须指定
  • 单参数List时值为list
  • 单参数Array时值为array
  • 多参数用 @Param 起的名字，或者 Map 的 key，作为 collection 的值
  • Map的key为参数名

item属性

  • 集合中元素迭代别名

index属性

  • index 在 List/数组里是序号，在 Map 里是键

open属性

  • 语句以什么开始
  • 常用(

separator属性

  • 迭代之间分隔符
  • 常用逗号

close属性

  • 语句以什么结束
  • 常用)

OGNL表达式

动态SQL基于OGNL计算表达式值

从SQL参数对象中获取属性

如<if test=”title != null”>

关联查询与延迟加载

一对一关联association

订单与支付一对一关系

实体类中定义关联对象属性

private Pay pay;

结果映射使用<association>标签

property指定关联属性

javaType指定关联对象类型

内联映射关联对象字段

一对多关联collection

商品分类与商品一对多关系

实体类中定义集合属性

List<Product> products;

结果映射使用<collection>标签

property指定集合属性

ofType指定集合元素类型

内联映射集合元素字段

多对多多对一

同样使用association和collection

通过适当的结果映射实现

思路与一对一、一对多一致

延迟加载原理

配置lazyLoadingEnabled=true

使用Javassist创建代理对象（MyBatis 3.3 起 proxyFactory 默认 Javassist，CGLIB 从 3.5.10 起废弃）

调用目标方法时进入拦截器

发现关联对象为null时

发送预先保存的关联查询SQL

查询到关联对象后调用set方法赋值

再完成目标方法调用

几乎所有的ORM框架延迟加载原理相同

嵌套查询与嵌套结果

嵌套查询

  • 关联通过select属性指定另一条SQL
  • 存在N+1查询问题
  • 每次查询关联都触发新SQL

嵌套结果

  • 关联对象通过一次SQL联表查询
  • 由resultMap内联映射
  • 性能更优

推荐使用嵌套结果

  • 配合延迟加载和fetchType

缓存机制

一级缓存

SqlSession级别

基于PerpetualCache的HashMap本地缓存

默认开启

各个SqlSession间缓存隔离

清空时机

  • Session执行flush时
  • Session执行close时
  • 执行更新操作后自动清空
  • 更新操作包括insert、update、delete

二级缓存

Mapper级别

在多个SqlSession间共享

默认不开启

开启方式

  • 映射文件中配置<cache/>标签
  • 实体类需实现Serializable接口
  • 用于保存对象状态

可自定义存储源

  • 如Ehcache

配置属性

  • flushInterval刷新间隔
  • size引用数目
  • readOnly只读状态
  • eviction回收策略
  • 如LRU最近最少使用

缓存共享与注意事项

跨namespace共享

  • 使用<cache-ref>标签
  • 引用其他namespace的缓存

适用场景

  • 读多写少
  • 数据不频繁修改
  • 不要求实时一致性

更新操作使缓存失效

  • 确保数据一致性
  • 需重新加载最新数据

插件与拦截器

插件原理

拦截四大核心对象

  • Executor执行器
  • StatementHandler数据库会话器
  • ParameterHandler参数处理器
  • ResultSetHandler结果处理器

使用JDK动态代理

  • 为目标对象生成代理对象
  • 提供工具类Plugin
  • 实现InvocationHandler接口

方法调用流程

  • 代理对象调用方法进入invoke
  • 存在签名拦截方法时调用intercept
  • 不存在签名方法时反射调用目标方法
  • 返回结果

编写步骤

实现Interceptor接口

  • 重写intercept()方法
  • 在方法中编写自定义逻辑
  • 调用invocation.proceed()执行目标方法
  • 可在调用前后执行额外操作

编写@Intercepts注解

  • 使用@Signature注解
  • 指定拦截对象type
  • 指定拦截方法method
  • 指定拦截方法参数args

配置plugin标签

  • 在mybatis-config.xml中配置
  • 指定interceptor全路径类名
  • 可设置property属性
  • 如数据库类型参数

常用场景

分页插件

  • 如PageHelper
  • 拦截Executor的query方法
  • 重写SQL实现物理分页

SQL性能监控

  • 统计SQL执行时间
  • 记录慢查询日志

权限控制

  • 拦截SQL执行
  • 根据用户权限过滤数据

日志记录

  • 记录SQL语句和参数
  • 便于调试和审计

分页机制

内存分页

使用RowBounds对象

针对ResultSet结果集执行

不推荐大数据量

  • 性能差
  • 消耗大量内存

物理分页

SQL中直接写分页参数

  • 如limit、offset
  • 数据库原生支持
  • 性能好

使用分页插件

  • 如PageHelper
  • 自动生成物理分页SQL
  • 支持多种数据库方言

分页插件原理

拦截Executor的query方法

在执行查询时拦截待执行SQL

根据方言dialect重写SQL

添加物理分页语句和参数

示例

  • select * from student
  • 重写为select t. from (select * from student) t limit 0,10*

工作原理

构建会话工厂

读取配置文件

  • 读取mybatis-config.xml基础配置
  • 读取映射文件映射器
  • 解析生成Configuration对象
  • 初始化别名、插件、映射器、ObjectFactory等
  • 初始化环境变量如数据源

构建SqlSessionFactory

  • 通过SqlSessionFactoryBuilder.build方法
  • 传入Configuration对象
  • 创建DefaultSqlSessionFactory实现类

会话运行

SqlSession门面接口

  • 对外提供API
  • 实际执行由Executor完成

Executor执行器

  • SimpleExecutor
  • 每次执行创建新Statement对象
  • 用完立刻关闭
  • ReuseExecutor
  • 以SQL为key查找Statement对象
  • 存在则复用，不存在则创建
  • 用完后不关闭，放入Map中
  • 供下次使用
  • BatchExecutor
  • 执行update语句
  • 将所有SQL添加到批处理中
  • 调用addBatch()方法
  • 等待统一执行executeBatch()
  • 缓存多个Statement对象
  • 特性严格限制在SqlSession生命周期内

StatementHandler

  • 处理数据库会话
  • 串起参数映射和结果映射处理
  • 预编译SQL语句
  • 执行SQL语句

ParameterHandler

  • 设置预编译SQL语句的参数
  • 使用TypeHandler类型处理器
  • 处理参数类型转换

ResultSetHandler

  • 处理执行结果
  • 包装结果集
  • 使用TypeHandler处理类型
  • 使用ObjectFactory组装对象
  • 返回目标对象

功能架构

API接口层

  • 提供给外部使用的接口API
  • 开发人员通过本地API操作数据库
  • 接收调用请求后调用数据处理层

数据处理层

  • 负责SQL查找
  • 负责SQL解析
  • 负责SQL执行
  • 负责执行结果映射处理
  • 完成一次数据库操作

基础支撑层

  • 连接管理
  • 事务管理
  • 配置加载
  • 缓存处理
  • 为上层提供最基础支撑

Mapper接口与动态代理

无需实现类原因

使用JDK动态代理

通过MapperProxyFactory生成MapperProxy

MapperProxy是Mapper代理对象

代理对象调用方法时进入invoke

调用过程

获取Mapper

  • session.getMapper(Class)
  • 获取MapperProxyFactory
  • 创建MapperProxy代理对象
  • 返回代理对象实例

执行方法

  • MapperProxy.invoke方法
  • 生成MapperMethod对象
  • 通过cachedMapperMethod初始化
  • 调用MapperMethod.execute方法
  • 根据命令类型执行操作

MapperMethod

命令模式

封装方法签名和SQL操作

最终通过SqlSession实例执行SQL

处理SELECT、INSERT、UPDATE、DELETE等类型

处理返回类型判断

  • 返回void
  • 返回List
  • 返回Map
  • 返回Cursor
  • 返回单个对象

Batch模式注意事项

  • addBatch方法只对更新语句有效
