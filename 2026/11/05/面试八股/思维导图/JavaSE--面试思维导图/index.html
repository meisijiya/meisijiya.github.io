基础

语言特点

Sun公司推出的面向对象编程语言，吸收C++优点并摒弃指针等易错特性
Java通过JVM实现“一次编译，处处运行”的跨平台能力，依赖不同操作系统上的JVM实现字节码到机器码的转换

核心特性

面向对象：支持封装、继承、多态三大特性，以对象为核心组织程序结构
平台无关性：基于JVM中间层屏蔽底层差异，源代码编译为字节码后可在任意安装JVM的平台上运行
内存自动管理：内置垃圾回收机制，无需手动调用malloc/free，降低内存泄漏风险
多线程支持：语言级提供线程创建、同步等API，无需依赖操作系统API实现并发

JVM、JDK和JRE区别

JDK是Java开发工具包，包含JRE及编译器（javac）、文档生成工具（javadoc）等开发工具
JRE是Java运行时环境，包含JVM和运行Java程序必需的核心类库
JVM是Java虚拟机，负责加载、验证、执行字节码，是实现跨平台的关键组件

面向对象

三大特性

封装

数据（属性）和操作数的方法捆绑在一起，形成独立的对象
把一个对象的属性私有化，同时提供一些可以被外界访问的方法
通过private修饰属性，提供publicgetter/setter方法控制访问，隐藏内部实现细节

继承

允许一个类继承现有类的属性和方法，提高代码复用性
子类通过extends复用父类属性和方法，建立”is-a”关系，支持方法重写实现多态

多态

允许不同类的对象对同一消息做出响应，但表现不同行为。执行一段代码，java运行时根据对象类型不同产生不同结果
满足继承、重写、父类引用指向子类对象三个条件，运行时根据实际类型动态绑定方法调用

  • 前置条件
    • 子类继承父类
    • 子类重写父类方法
    • 父类引用指向子类对象
  • 多态解决了什么问题
    目的是提高代码灵活性和可扩展性，是代码更容易维护和扩展，比如动态绑定，允许在程序在运行时再确定调用的是子类还是父类方法

this关键字

this是自身的一个对象，代表对象本身，理解为指向对象本身的一个指针
this指向当前对象本身，用于区分形参与成员变量，或调用本类其他构造方法

用法

  • 普通的直接引用
  • 形参与成员变量重名
  • 引用本类构造函数

重写和重载

如果一个类有多个名字相同但参数个数不同的方法，我们通常称这些方法为方法重载（overload）。如果方法的功能是一样的，但参数不同，使用相同的名字可以提高程序的可读性。
如果子类具有和父类一样的方法（参数相同、返回类型相同、方法名相同，但方法体可能不同），我们称之为方法重写（override）。方法重写用于提供父类已经声明的方法的特殊实现，是实现多态的基础条件。
方法重载发生在同一个类中，同名的方法如果有不同的参数（参数类型不同、参数个数不同或者二者都不同）。
方法重写发生在子类与父类之间，要求子类与父类的方法名和参数列表相同，返回类型可以相同，也可以是父类返回类型的子类型（协变返回），并且不能比父类的方法声明更多的异常。

抽象类和接口

一个类只能继承一个抽象类；但一个类可以实现多个接口。所以我们在新建线程类的时候一般推荐使用实现 Runnable 接口的方式，这样线程类还可以继承其他类，而不单单是 Thread 类。
抽象类符合 is-a 的关系，而接口更像是 has-a 的关系，比如说一个类可以序列化的时候，它只需要实现 Serializable 接口就可以了，不需要去继承一个序列化类。
抽象类更多地是用来为多个相关的类提供一个共同的基础框架，包括状态的初始化，而接口则是定义一套行为标准，让不同的类可以实现同一接口，提供行为的多样化实现。

深拷贝浅拷贝

浅拷贝：仅拷贝被拷贝对象的成员变量的值，也就是基本数据类型变量的值，和引用数据类型变量的地址值，而对于引用类型变量指向的堆中的对象不会拷贝。
深拷贝：完全拷贝一个对象，拷贝被拷贝对象的成员变量的值，堆中的对象也会拷贝一份。
深拷贝是安全的，浅拷贝的话如果有引用类型，那么拷贝后对象，引用类型变量修改，会影响原对象。
浅拷贝如何实现呢？
Object 类提供的 clone()方法可以非常简单地实现对象的浅拷贝。
深拷贝如何实现呢？
重写克隆方法：重写克隆方法，引用类型变量单独克隆，这里可能会涉及多层递归。
序列化：可以先将原对象序列化，再反序列化成拷贝对象。

hashCode与equals

hashCode方法

作用就是获取哈希码，返回一个int整数，定义在Object类中
通常用来获取对象的哈希码，可以用来作为键值对的键

为什么重写equals时必须重写hashCode

基于哈希的集合类（HashSet，HashMap等）通过对象的哈希码将其存储在不同桶中，如果重写了equals而不重写hashCode，那么被认为相等的对象可能有不同的哈希码

异常处理

Throwable

java语言所有错误和异常的基类，有两个主要子类

Error

表示严重的错误，程序无法处理，比如内存不足、栈溢出。通常与JVM运行状态有关

Exception

  • 编译时异常
    在编译时必须被显式处理（捕获或声明抛出）
  • 运行时异常
    运行时抛出，通常是程序逻辑错误导致比如空指针

异常处理方式

遇到异常不具体处理，抛给调用者

throw，throws

IO流

分类

按数据流方向划分

  • 输入流Input Stream
  • 输出流Output Stream

按处理数据单位划分

  • 字节流
    以字节为单位读取数据，处理二进制数据如音频、图像
  • 字符流
    以字符为单位读写数据，用于处理文本数据

按功能划分

  • 节点流
    直接与数据源或目的地相连
  • 处理流
    对一个已存在的流进行包装
  • 管道流
    用于线程之间数据传输

BIO、NIO、AIO

BIO（Blocking I/O）：采用阻塞式 I/O 模型，线程在执行 I/O 操作时被阻塞，无法处理其他任务，适用于连接数较少的场景。
NIO（New I/O 或 Non-blocking I/O）：采用非阻塞 I/O 模型，线程在等待 I/O 时可执行其他任务，通过 Selector 监控多个 Channel 上的事件，适用于连接数多但连接时间短的场景。
AIO（Asynchronous I/O）：使用异步 I/O 模型，线程发起 I/O 请求后立即返回，当 I/O 操作完成时通过回调函数通知线程，适用于连接数多且连接时间长的场景。

Stream流

使用stream流对一个包含一个或多个元素的集合做各种操作，这些操作可能是中间操作，也可能是终端操作
中间操作返回一个Stream流，终端操作返回一个结果

高级语法

序列化与反序列化

序列化（Serialization）是指将对象转换为字节流的过程，以便能够将该对象保存到文件、数据库，或者进行网络传输。
反序列化（Deserialization）就是将字节流转换回对象的过程，以便构建原始对象。

Java序列化方式

Java 对象序列化 ：Java 原生序列化方法即通过 Java 原生流(InputStream 和 OutputStream 之间的转化)的方式进行转化，一般是对象输出流 ObjectOutputStream和对象输入流ObjectInputStream。
Json 序列化：这个可能是我们最常用的序列化方式，Json 序列化的选择很多，一般会使用 jackson 包，通过 ObjectMapper 类来进行一些操作，比如将对象转化为 byte 数组或者将 json 串转化为对象。
ProtoBuff 序列化：ProtocolBuffer 是一种轻便高效的结构化数据存储格式，ProtoBuff 序列化对象可以很大程度上将其压缩，可以大大减少数据传输大小，提高系统性能。

泛型

本质是参数化类型，所操作的数据类型被指定为一个参数

反射

反射原理

Java程序执行分为编译和运行，编译后生成字节码.class文件，JVM进行类加载时，会加载字节码文件，将类型相关所有信息加载进方法区，反射就是获取这些信息再进行其他操作

网络编程-socket

Socket 是网络通信的基础，表示两台设备之间通信的一个端点。Socket 通常用于建立 TCP 或 UDP 连接，实现进程间的网络通信。

RPC框架

RPC是一种协议，允许程序调用位于远程服务器上的方法，就像调用本地方法一样。RPC 通常基于 Socket 通信实现。
RPC 框架支持高效的序列化（如 Protocol Buffers）和通信协议（如 HTTP/2），屏蔽了底层网络通信的细节，开发者只需关注业务逻辑即可。
常见框架
gRPC：基于 HTTP/2 和 Protocol Buffers。
Dubbo：阿里开源的分布式 RPC 框架，适合微服务场景。
Spring Cloud OpenFeign：基于 REST 的轻量级 RPC 框架。
Thrift：Apache 的跨语言 RPC 框架，支持多语言代码生成。

String

String、StringBuilder、StringBuffer

都是用来处理字符串的，但String不可变，遇到大量字符串连接可以用StringBuilder（不会生成很多新的对象），StringBuffer和SB类似，但每个方法都加了synchronized关键字，线程安全
