AI 核心概念--面试思维导图笔记

作者: 老江湖
日期: 十一月 5, 2026  12:00:00
分类: 面试八股 思维导图

Hi，我是 meisijiya ，也是 老江湖 ，感谢你的阅读，我们一起进步。

原始资料：B 站 UP 主 程序员小Dan 的面试思维导图（合集·计算机专业面试总结），XMind 文件转录为 Markdown。标题层级沿用导图结构，导图备注里的答案按段落排到对应标题下，原图的说法尽量保留，只补了必要的连词；个别与官方文档不符的技术说法已按规范改正，其余保持原样。本篇是我学习整理的复习笔记，内容以他的导图为准，感谢他的导图与资料。

大模型基础

运行机制

自回归生成
自回归生成指模型根据已有上下文逐Token预测下一个Token的生成方式

Token与子词切分

📌 考点：Token 是模型处理文本的最小单位，用 BPE 或 Unigram 切成子词碎片。

Token是模型处理文本的最小单位通过BPE或Unigram算法将文本切分为子词碎片

上下文窗口
上下文窗口是一次调用中模型可处理的总Token上限决定对话连续性与单次处理能力

采样参数
采样参数通过Temperature控制随机性Top-p和Top-k缩小候选池Penalty防止重复

Prompt工程

四要素框架
四要素框架包括角色设定明确任务提供上下文和指定输出格式

结构化输出
结构化输出通过JSON Mode约束语法JSON Schema定义契约Structured Outputs强制生成阶段贴合结构

工具调用

模型生成调用意图
模型只生成调用意图包括工具名和参数而不直接执行后端代码

典型链路
典型链路从用户问题出发模型判断是否需要工具生成参数服务端校验执行结果回填模型生成最终回答

Transformer架构

自注意力机制
自注意力机制让模型在生成每个 Token 时关注已经生成的位置（含当前这个）；解码阶段有因果掩码，看不到后面的位置，只有编码器是看全序列的

多头注意力
多头注意力并行计算多个自注意力头捕捉不同子空间的特征

位置编码
位置编码为序列中每个位置添加位置信息弥补注意力机制无法感知顺序的缺陷

前馈网络与层归一化
前馈网络与层归一化对每个位置的表示进行非线性变换并稳定训练过程

预训练与微调

预训练学习通用知识
预训练通过大规模自监督学习（next-token prediction，标签由文本自己构造）让模型掌握通用语言知识

微调适配下游任务
微调使用监督数据适配下游任务使模型表现更精准

监督微调与RLHF
监督微调与RLHF分别通过有监督学习和人类反馈强化学习优化模型行为
SFT用标注数据直接优化，RLHF 通过人类反馈强化学习（如 PPO）进一步对齐人类偏好；DPO 是不训练奖励模型、也不做强化学习的直接偏好优化，和 RLHF 并列，不算 RLHF 的一种。

Agent

定义与公式

📌 考点：Agent = LLM + 规划 + 记忆 + 工具，会持续观察、判断、执行直到任务结束。

Agent等于LLM加规划加记忆加工具是一个能感知环境做决策执行动作的软件系统
Agent = LLM + Planning + Memory + Tools
Agent是能感知环境、做决策、执行动作的软件系统，与普通聊天机器人的区别在于它会持续观察、判断、执行直到任务结束。

核心架构

推理与规划
推理与规划使用思维链分析任务状态拆解目标决定下一步行动，是Agent的决策核心

记忆
记忆分为短期记忆保持对话连续性和长期记忆沉淀跨会话的个性化经验
短期记忆保持对话连续性，长期记忆沉淀跨会话的个性化经验（如用户偏好、历史决策）。

工具
通过Function Calling或MCP协议让模型操作外部世界如查数据调API执行代码

观察
将工具执行结果作为反馈放回上下文驱动下一轮，形成感知-决策-执行的闭环

运行循环

📌 考点：Agent 反复推理、调用工具、获取反馈，直到任务完成或触发停止条件。

推理行动观察循环指Agent反复执行推理调用工具获取反馈直到任务完成或触发停止条件
推理→行动→观察循环

Agent反复执行推理、调用工具、获取反馈，直到任务完成或触发停止条件（如最大轮次）。

工作模式

ReAct模式
ReAct模式让推理和行动交替进行模型每走一步就根据工具返回结果再判断下一步
Reasoning + Acting交替进行，模型每走一步就根据工具返回结果再判断下一步，减少幻觉，适合动态任务。

计划与执行模式
计划与执行模式先由LLM制定全局分步计划再由执行器按步骤完成适合长任务
先由LLM制定全局分步计划，再由执行器按步骤完成，适合步骤多、依赖关系明确的长期任务。

工作流与图

有向图节点边状态
AI工作流的数据结构，节点负责执行，边负责流转，状态在节点间共享上下文。

全局工作流与局部子循环
在全局工作流中嵌入Agent子循环，让模型在不确定节点中自行探索，兼具全局结构与局部活性。

上下文工程

有限窗口内管理信息
在上下文窗口限制内合理组织系统提示、用户输入、RAG结果、工具描述等，确保模型在合适时机获取正确信息。

记忆系统

事实记忆与经验记忆

📌 考点：事实记忆存用户偏好和显式事实，经验记忆存决策轨迹和成败教训。

事实记忆存储用户偏好和显式事实，经验记忆存储历史决策轨迹和成败教训。

工作记忆与长期记忆
工作记忆处理当前推理上下文和任务进展，长期记忆跨会话复用个性化经验，与RAG（外部知识库）有本质区别。

工程实践

系统工程

模型外整套系统

Harness Engineering指模型之外的整套系统，包括系统提示词、工具调用、文件系统、沙箱环境、反馈回路等，类比CPU和操作系统。

三层工程关系

📌 考点：提示工程把指令说清，上下文工程给对信息，执行工程管持续执行、纠偏和恢复。

提示工程
Prompt Engineering解决如何把指令说清楚，让模型理解意图。

上下文工程
Context Engineering解决该给Agent看什么信息，确保在合适时机提供正确且必要的信息。

执行工程
Harness Engineering解决系统如何持续执行、纠偏、观测和恢复，长链路任务中持续正确。

循环工程

设计可持续反馈循环

Loop Engineering围绕Agent设计触发、目标、上下文、行动、观察、状态、停止等机制，反复运行直到任务完成或需要人工接管。

常见面试考点

解决幻觉方法

📌 考点：RAG、外部知识源、可控生成、引用校验、拒答机制和人工反馈闭环。

RAG、外部知识源、可控生成、引用校验、拒答机制和人工反馈闭环等

可靠Agent设计

📌 考点：关注上下文管理、工具质量、错误处理、最大轮次限制和状态持久化。

关注上下文管理、工具质量、错误处理、最大轮次限制、状态持久化等

RAG系统评估
包括端到端评估、组件级评估（检索、生成）和A/B测试。

多模态与模型部署
涉及图文理解、语音交互、以及模型量化、蒸馏、推理加速等部署技术。

Skills

定义

任务说明与经验沉淀

Skill是一份可被Agent发现、按需加载的任务说明，沉淀某类任务的经验、约束和执行顺序，类似“老员工脑子里的规矩

与Prompt关系

不同分工的组件Prompt给任务Skill给方法Function Calling和MCP支撑工具执行四者分工明确

MCP

定义

标准化工具通信协议是MCP Client和MCP Server之间的标准协议让宿主发现和连接工具

三层关系

📌 考点：Agent 是任务编排层，MCP 是通信协议层，Function Calling 是模型能力层。

任务编排层
Agent负责如何完成任务，是任务编排层。

通信协议层
MCP负责工具怎么被发现和连接，是通信协议层。

模型能力层
Function Calling负责模型如何表达调用工具的意图，是模型能力层。

MCP Server

暴露具体能力

笔记：将文件系统、数据库、API等外部能力通过标准接口暴露给AI应用，是能力的具体提供者

RAG

定义与目标

📌 考点：先检索再生成，缓解知识时效和私有数据问题，检索不充分时幻觉仍会出现。

检索后生成弥补知识短板

系统先从知识库检索相关片段，再交由LLM生成答案，缓解知识时效性与私有数据访问的问题，并降低幻觉（检索不充分时模型照样编，根除不了）。

工作链路

离线索引

📌 考点：文档清洗、分块、向量化后存入向量数据库，变成可检索结构。

包括文档清洗分块嵌入向量化并存入向量数据库

文档清洗→Chunking（分块）→Embedding（向量化）→存入向量数据库，将原始文档变为可检索结构。

在线检索

📌 考点：查询改写、相似度检索、重排序、上下文构建，最后由 LLM 生成答案。

包括查询改写相似度检索重排序上下文构建和LLM生成
查询改写→相似度检索→Rerank/过滤→上下文构建→LLM生成答案，将用户问题变为可回答结果。

Embedding

文本映射语义向量
将文本转换为高维稠密向量，使语义相近的文本在向量空间中距离更近，是向量检索的基础。

向量检索与数据库

近似最近邻搜索
通过HNSW、IVF等算法在百万级甚至亿级向量中快速找到最相似的结果，平衡速度和精度。

常见产品
Milvus、Pinecone、Qdrant、pgvector等，提供元数据过滤、混合检索、增量写入等生产级能力。

文档处理与切分

切分策略
包括固定长度、递归切分、语义切分、结构切分、Parent-Child（父子分块）等，需根据文档类型和查询任务选择。

关键原则
兼顾语义完整性、Embedding模型输入长度和召回粒度，小块召回准但上下文易残缺，大块保留完整但噪声大。

混合检索

向量检索加关键词检索

📌 考点：向量检索管语义相似，BM25 管精确词匹配，用 RRF 合并结果。

向量检索擅长语义相似，BM25擅长精确词匹配，两者互补，通过RRF（倒数排名融合）合并结果。

查询改写

多种改写策略
包括规范化改写、Multi-Query（多查询）、Query Decomposition（分解）、Step-back（后退）、HyDE（假设文档嵌入）等。

重排序

精细打分提升相关性
使用Cross-Encoder对召回候选进行更细粒度的相关性判断，向量相似度看“像不像”，Rerank看“能不能回答”。

GraphRAG

检索实体关系路径
将文档中的实体、关系显式建模，查询时沿图关系收集证据，适合多跳推理和跨文档归纳，检索对象是节点、边、路径和社区摘要。

评估指标

召回率与命中率
衡量检索系统找到相关文档的能力，顶部排序质量可用MRR（平均倒数排名）评估。

答案质量指标
包括忠实度（Faithfulness，答案是否基于检索内容）和答案相关性（Answer Relevancy）等。
