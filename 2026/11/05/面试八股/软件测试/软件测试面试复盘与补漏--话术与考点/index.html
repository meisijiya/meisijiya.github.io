独立做过 VidDigest，视频链接进、AI 摘要出，FastAPI 加 SSE 流式，用 pytest 写分库用例和契约断言。

  • 团队人数按实际填，没带人就删掉”组长”以外的规模描述。

练习方法

掐表念三遍，第一遍 70 秒可以接受，第三遍要稳在 60–65 秒。宁可 65 秒也不要 15 秒：时间没用完，面试官会认为我没内容。

二、简历缺数据：补什么，怎么真测出来

我的简历现在写的是”逐条判断断言有效性””自建固定问题集对比策略”，全是方法没有结果。测试岗招人看的是我能不能让结论可复核，没有数字就等于没有结论。

可以在本地真实测出来的指标

指标 出处项目 怎么测 写法模板

参数化覆盖 VidDigest 数 parametrize 数据集总量 “单接口 1 个函数覆盖 M 组异常入参”

SSE 契约断言数 VidDigest 数帧级断言 “对首帧、结束帧、异常断流 3 类契约各写断言”

硬规则

  • 数字必须是本地跑出来的。写完在面试里会被追问”怎么数的””环境是什么”，答不上来比没写更糟。
  • 只写一个数字就够，别堆。一个站得住的 90% 检出率，胜过五个含糊的百分比。
  • 单位写全：条、个、次、ms、%。”提升明显”不是数据。

三、”项目做到什么程度”：把事实和现状分开

不要辩解”我上线了”。三句话拆开：

这一版是拆成端侧和云端的：端侧本地解析视频、能生成总结和思维导图，联网后把结果贡献给社区；云端负责社群、账号、额度和模型出口，不持有我的登录态。端侧我用 docker compose 起了全套跑通过一次完整解析，云端也能自部署。

现在的问题在数据源这一层：解析依赖目标站的登录态，不带登录态拿不到视频流，账号被风控就没数据源。

如果要把它做成公开服务，路径是三条：带用户 cookie 的登录态解析、限速加退避降低请求特征、把解析器做成可替换接缝，风控升级时切到备用通道。

这件事我有记录：解析失败会落日志，能区分是参数错、风控拦截还是源站变更。

技术点必须讲得出，才不算找借口：

现象 判断依据 处理
403 / 429 状态码 + 返回 HTML 而非媒体流 降速、加退避、带 cookie
空流 / 分段缺失 播放地址拿到但下载中断 重试 + 分段校验
源站改版 正则或字段缺失报错 解析器做成策略类，单独升级
需要登录内容 匿名请求一律失败 明确标为不支持，降级到官方字幕

**不要说”yt-dlp 不行”**：引擎没问题，是目标站的反爬策略；面试官关心的是你能不能定位到这一层。

四、运营催自动化测试代码、对时间不满意

这类题的评分点不是”你会不会妥协”，而是我有没有让需求方在信息完整的前提下做决定。

四步，按顺序说：

  1. 先接住，不要顶回去。 “这个需求我接了，我先把范围和时间说清楚。”
  2. 把不确定性量化成选项。 不说”做不完”，说”三个方案，代价不同”。
  3. 让运营选，并留记录。 选完在群里或需求单里确认一句，防止后面扯皮。
  4. 给一个能马上用的中间产物。 别让他空等两周。

逐句话术

我先确认一下你要覆盖哪几个流程，是每天手工回归的那几条，还是全量？范围定了我才能给准时间。

现在有两种做法：
A 方案，只覆盖主流程 5 条，两天能出，能进 CI，每轮回归省半小时；
B 方案，把异常分支也做进去，大概一周，覆盖更全，但这一周里你得继续手工点。

如果这周就要用，我建议先上 A，B 放到下个迭代补。你更在意上线时间还是覆盖率？

追问链准备：

追问 答法
他就说”明天必须给我” “明天我能给的是主流程 5 条的冒烟脚本，能跑通但异常分支没覆盖。这个限制我写在交付说明里，可以吗？”
“自动化跑挂了算谁的问题” “脚本挂了我第一时间看，是被测系统改了还是脚本过时。断言我按业务字段写，不按实现细节写，减少误报。”
“为什么不能边做边加需求” “可以加，但每加一条我要重跑一次回归。现在加进去会让主流程的交付往后推，你确认我就调整。”
“你觉得我这个需求优先级不高？” “不是高低的问题，是我手上任务的交付时间已经承诺给别人了。你这条如果更急，我需要你跟我上级确认一下调整顺序。”

最后一句是护栏：跨部门抢资源，永远不要自己拍板改优先级，要拉共同上级。

五、已有高优先级任务，运营又插一个

判断用两个维度，不要用”紧急/重要”四象限（太抽象，答出来像背的）：

判据 问自己 结论
影响面 这条不做，影响几个用户/几条业务线 影响面大优先
不可逆性 晚做的代价是延迟，还是数据丢失/资损 不可逆优先
阻塞性 别人是否在等我这条才能开工 阻塞别人的优先

动作四步：

  1. 不立刻答应，也不立刻拒绝。 先花两分钟问清截止时间和影响面。
  2. 列当前队列，把时间摊开。 “我现在手上三件事，A 今天下班前必须交，B 周四，C 在等后端接口。你这条如果插进来，会挤掉哪一个？”
  3. 给替代方案。 能不能拆一半先做、能不能临时手工顶一次、能不能找同组人接。
  4. 要决策，不要自己扛。 两条都急，就拉上级或需求方一起定，定完留文字记录。

完整话术

我先说下我现在的队列：A 今天 18 点前要交付，B 周四评审，C 卡在后端接口上等联调。你这个需求的截止时间是什么时候，影响的是哪条业务？

如果比 A 还急，我把 A 推半天，先把这条做掉，但需要你跟我组长说一声，我这边不能自己调。
如果不急，我排在 B 后面，周四给你。
还有一个办法，这条如果只是每周一次的例行，我可以先写个半自动脚本加手工确认，半小时能给你，等下周再补成全自动。

不要说

  • “好的我加班做”——不加条件地接，等于把排期风险全揽到自己身上。
  • “我做不完”——只说结论不给选项，等于拒绝协作。
  • 自己改优先级却不通知任何人——交付那天两个需求方都来找我。

六、团队协作：完成后跟谁沟通 / 组长怎么协调

项目完成后要跟哪些职位沟通（测试岗答法）

顺序按”交付链条”说，别说成名单：

阶段 对接人 说什么
提测前 开发、产品 需求验收标准是否一致、提测范围、已知缺陷
测试中 开发 缺陷单：现象、复现步骤、期望与实际、影响面、日志
上线前 运维、DBA 部署时间窗、回滚方案、数据库变更脚本
上线后 运营、客服 功能变化点、已知问题、话术口径
复盘 全员 漏测的原因与后续改进项

一句话版本：

我按交付链路对接：需求阶段对产品，开发阶段对后端前端，上线对运维和 DBA，上线后对运营和客服，最后一起复盘。 每一环我只交三样东西——范围、标准、已知风险。

开发组长怎么协调成员

组长不是分派任务，是做四件事：

  1. 切接口：先把模块边界和接口定死（字段、错误码），各人才能并行。
  2. 定验收标准：每个人交付前自己先跑通，标准写在任务卡里，不靠口头。
  3. 暴露进度：每天一句进展加一个阻塞点。阻塞点由我协调，不让人自己卡三天。
  4. 裁决冲突：两个人对实现有分歧，我按”谁的方案改起来影响面小”定，定完就执行，不再回头讨论。

用踏浪的真实例子讲：

我做过 AI 单测生成和知识库检索两条线。检索那条线依赖向量库，我先把索引字段和召回接口的返回结构定下来，做切块的人和做评测的人同时开工。评测那边要求每条问题都要有人工标注的正确文档，我就把这个标注工作前置，不然等他们写完发现标注口径不一致，整批数据要重做。

团队里最容易出问题的不是谁不会写，是两个人对”做完”的定义不一样。所以我在任务卡上写死验收条件：接口返回什么字段、错误码怎么给、用例跑通多少条。

追问准备：

追问 答法
成员不配合怎么办 “先问他卡在哪，是没时间还是不会。没时间就调排期，不会就拆小一点给他，或者我接。连续两次不交付，我才升级到上级。”
你怎么知道他们做得对不对 “看验收条件，不看态度。每人的任务卡上都有可检查的东西。”
有成员比你资深怎么办 “技术方案我听他的，排期和标准我来定。分工上按模块切，不按资历切。”
冲突时你凭什么定 “凭影响面：谁的方案让别的模块少改。定完就不再重开讨论。”

七、排序算法：会写一个，会讲全部

笔试只要求写得出一个。冒泡最短最不容易写错，优先写它；问快排再写分治。

Python 冒泡（带提前退出）

Python 快排（一行分治，最好背）

mid 单独拆出来，重复元素才不会死循环，这是面试官常抓的点。

Java 冒泡

Java 快排（原地，双指针）

复杂度与稳定性（必背）

算法 平均 最坏 额外空间 稳定 一句话
冒泡 O(n²) O(n²) O(1) 稳定 相邻交换，加 swapped 可提前退出
插入 O(n²) O(n²) O(1) 稳定 像摸牌，近乎有序时最快
选择 O(n²) O(n²) O(1) 不稳定 每轮选最小，交换次数最少
快排 O(n log n) O(n²) O(log n) 栈 不稳定 基准取中间；已排序且取端点会退化
归并 O(n log n) O(n log n) O(n) 稳定 分治合并，稳定但要额外空间
Timsort（内置） O(n log n) O(n log n) O(n) 稳定 归并加插入的混合

Java 常考：Arrays.sort 对基本类型用双轴快排（不稳定），对对象数组用 Timsort（稳定）。所以 Arrays.sort(int[]) 不稳定，Arrays.sort(Integer[]) 稳定。

写不出来时的兜底

先写冒泡骨架（两层循环加交换），确认能跑再优化。空数组、单元素、全相同、已排序四个边界必须说得出来——这四句比算法本身更像测试岗的答案：先用 []、[1]、[5,3,3,1]、[1,2,3,4,5] 验一遍。

八、黑盒测试：七种方法，一句话一种

笔试犹豫的根源是记不住”什么时候用哪个”。按输入形态记：

方法 一句话 什么时候用
等价类 把输入分成”结果必然相同”的若干类，每类取一个值 输入有取值范围，先分类再取点
边界值 取边界本身和边界前后各一个 等价类的搭档，长度/数值/日期必用
判定表 把条件组合和对应动作列成表 多条件交叉的业务规则（优惠、权限）
因果图 从原因到结果画约束关系，再转判定表 条件之间有”必须/不能同时”的约束
场景法 按用户操作路径写主流程与异常流程 有先后顺序的业务（下单、支付）
正交实验 用正交表挑最少的组合覆盖多因素 配置项多、组合爆炸（浏览器×系统×分辨率）
错误推测 凭经验列最容易出错的地方 补充手段，不能单独用

答题模板（被问”登录怎么测”）：

先按输入拆等价类：手机号合法/非法格式/空，密码正确/错误/长度越界；边界取长度 5、6、20、21；再用判定表覆盖”账号锁定与验证码”的组合；最后按场景走主流程和三条异常流程，比如连续错 5 次锁定、锁定期间正确密码也拒绝、解锁后恢复正常。

自测五题：

  1. 一个输入框允许 1–100 的整数，最少设计几条用例？→ 等价类 3 条（合法 1–100、小于 1、大于 100），边界 4 条（0、1、100、101），共 7 条；非整数输入归到等价类的非法项里，可另加 1 条。
  2. 为什么边界值常和等价类一起用？→ 等价类选代表值，边界是缺陷最密集的地方，两者互补。
  3. 判定表和因果图的区别？→ 因果图先建模约束，最终仍转成判定表。
  4. 正交实验解决什么问题？→ 多因素组合爆炸，用最少组合达到覆盖。
  5. 错误推测能单独用吗？→ 不能，只作补充。

九、Python 输出题（14 道，答案已实跑确认）

笔试给一段代码问输出，考的都是同一个东西：什么时候复制对象、什么时候共享引用。

1. 可变默认参数

输出 [1, 2, 3] [1, 2, 3] [1, 2, 3]——默认值只在定义时求值一次，三次共享同一个列表。

2. 闭包晚绑定

输出 [2, 2, 2]——循环结束时 i 才是 2，lambda 取的是变量不是值。要 lambda i=i: i。

3. 列表乘法是浅复制

输出 [[9, 0], [9, 0]]——外层两个元素指向同一个内层列表。

4. += 与 +

输出 [1, 2, 3, 4] [1, 2, 3, 4, 5]——+= 原地改，+ 造新对象。

5. sort() 返回 None

输出 [3, 2, 1] None [1, 2, 3]——sort 原地排序返回 None，写成 y = x.sort() 就丢数据。

6. try 里 return，finally 还执行

输出 ['try', 'finally']——返回值是同一个对象，finally 里的修改也会被带出去。

7. 生成器只能遍历一次

输出 [1, 2] []。

8. 整除与取模负数

输出 -4 -1 -4 -1 2 4——// 向下取整，% 符号跟除数，round 是银行家舍入（.5 取偶）。

9. 浅拷贝

输出 {'a': 1} {'a': 2}——只有一层，不会互相影响。

10. 字符串操作

输出 abcabc cba True True——in 对字符串做子串匹配。

11. nonlocal

输出 (2, 3)。

12. 解包与类型比较

输出 1 [2, 3]——带星号的那个永远是列表。

13. 浮点精度

输出 False True——浮点比较用误差范围，别用 ==。

14. 类属性是共享的

输出 [1]——B.x 没赋值时仍是 A.x 那个列表。

三条判断原则

  1. 赋值永远不复制对象，只复制引用。
  2. += 对列表原地改，+ 造新对象；对元组和字符串都不存在原地改。
  3. 默认参数、类属性、闭包变量都是”定义时绑定一次，全生命周期共享”。

十、pytest 笔试考点

能带多个参数的装饰器

写法 参数 说明
@pytest.mark.parametrize("a,b", [(1,2),(3,4)]) 多个参数名 参数名可写 "a,b" 或 ["a","b"]；每条数据是元组，个数要对上
多个 parametrize 叠加 是的 笛卡尔积，2×2 生成 4 条用例
@pytest.fixture(scope="module", params=[1,2], ids=["p1","p2"], autouse=True) 是的 参数用 request.param 取
@pytest.mark.skip(reason="…") 只一个 无条件跳过
@pytest.mark.skipif(cond, reason="…") 两个 条件跳过
@pytest.mark.xfail(raises=ValueError, reason="…", strict=True) 多个 预期失败，不是跳过

「哪个可以跳过测试方法」的准确答法：**skip 无条件跳过，skipif 满足条件跳过，xfail 是标记为预期失败仍会执行**。运行时还有 pytest.skip("原因") 在函数中间跳。

最小可跑示例（已实测：8 passed, 1 skipped, 1 xfailed）

测试类的三条规矩

  1. 类名必须 Test 开头，方法必须 test_ 开头，否则不收集。
  2. **测试类不能写 __init__**，写了 pytest 直接报错（会提示找不到 fixture 或无法实例化）。
  3. 类内 fixture 第一个参数是 self，autouse=True 时每个方法前自动执行。

装饰器本身怎么答（如果问的是 Python 装饰器）

一句话：不带参数的装饰器两层，带参数的装饰器三层；functools.wraps 必须加，否则函数名变成 wrapper。
