广州软件测试岗面试复盘（11-06 电话面）--表达与考点

作者: 老江湖
日期: 十一月 6, 2026  21:30:00
分类: 面试复盘 广州软件测试

Hi，我是 meisijiya ，也是 老江湖 ，感谢你的阅读，我们一起进步。

结论：技术没崩，表达崩了。 全程 17 分钟，面试官没有一次深挖技术细节，因为他拿不到可追问的抓手——每次回答都停在”我用了什么”，没给”我怎么判断它对不对”。测试岗招人买的就是判断力。

三个信号：花 2 分钟反复确认”你确定要走测试吗”；结尾问”怎么学测试”，对方答的是”先了解岗位、执行过才知道适不适合”——这是劝退式回答，不是培养式；反问环节说”没有了”。

文字稿是 ASR 转写，”大浪/2s API/SS流逝/open扣/NGX/play瓦特”这类是转写错字，不是失分点。失分点是内容停在名词、没有动作和判据。

零、问题判定

# 现场问题 现场答法 失分机制 改法
1 讲讲项目经历、学到什么 报了项目名，学到什么答”Java 和 Python 都学了” 问的是认知，答的是课程表 每个项目一句话”问题→我的动作→结果”
2 简历上那几个项目 直接跳到视频解析，一个没接 面试官手上那版简历与投递版不一致 先一句澄清，再把话题拉回自己项目
3 视频解析是怎么做的 “Python 加 FastAPI，加 SSE 流式” 只给栈名，没有链路 一条链路 + 一张服务表
4 现在做到什么程度 “单机部署了，上线也做了，但是要账号” 自相矛盾 事实与现状分开说
5 本机搭的是什么程序 “一个前后端全栈项目” 零信息量 进程、端口、中间件清单
6 设计时考虑资源和性能了吗 答成限流与退避 问的是资源预算，不是容错 四个数 + 一句兜底
7 测试开发和产品开发的区别 “开发偏业务，测试写脚本” 两边都没说对 用产出物和对谁负责讲
8 你自己那套系统怎么验证的 “借助 AI 跟 AI 对接测试点” 主语是 AI 主语换回自己
9 AI 工具和平台怎么连接 “我用我的 MCP，找到测试相关的” 讲不出链路 三段链路一句话
10 云端算力？什么模型？花多少钱 “DeepSeek，走的中转，平时稍微用一下” 没有数字 报单价与月用量
11 别人外化的 skill 怎么确认过程 OK “要按自己业务重新沟通” 方向对，没有验证手段 固定用例集 + 三个数
12 结合 AI，测试工程师要做什么 “设计用例，先冒烟，再 UI 自动化” 主动把答案收窄 生成 → 验收 → 平台化回归
13 AI 也能设计用例，测试人员还需要什么 “业务敏锐度 + 代码基础 + 不能放任 AI” 全场最好的一题 补上验收标准
14 自己发现并解决的实际问题 跨域只答一句，被追问”还有吗”就断了 单点回答且细节虚 同源差异 + 反代 + 流式三处
15 职业规划，要有个专注方向 “偏向跟新技术和代码打交道” 没给方向 一句话锚定
16 在校没有实习经验吧 “对的” 承认完就没了 用替代证据接一句
17 你还有什么问题 第二次”没有了” 收尾空白 备三个问题

打分（10 分制）：技术广度 6、项目深度 4、测试专业度 4、表达结构 4、岗位动机 3。

一、简历版本不一致：先核对事实

面试官念的是「分销平台、四层权限中后台、宠物领养平台」，而我手上这版简历里是踏浪 AI 中心、VidDigest、Vapor 优选，一个都对不上。

两种可能，都必须先确认：投的是早期那份 Java 简历，那三个项目在里面；或者 HR 传错了简历。

当场澄清话术（约 15 秒）：

您说的那几个项目是我早期做的，最近这版简历我把重点换成了 AI 中心和视频解析平台。我按最近这版讲，需要的话早期项目我也能展开。

动作：每投一家，文件名里带公司与岗位（如 简历-测试-<公司>-<日期>.pdf），投完把投递版存回本目录，跑一次项目名比对——本地版与投递版的项目列表必须一致，否则面试官问的项目自己都答不上。

二、项目讲解：一条链路 + 一张服务表

链路（20 秒讲完）：用户贴视频链接 → 端侧校验链接、拉元数据 → 有字幕就用平台字幕，没有就下载音轨转写 → 按语义边界切块 → 端侧调模型（自带密钥走本机，或走平台通道）出摘要与思维导图 → 结果落本地 SQLite 并流式推给端侧前端 → 联网时把可贡献产出上传，云端存成结果版本进社区，社区可搜索、可追问。

原则：入口是什么、中间几个环节、出口是什么。别从技术栈开始讲。补一句边界：登录态、cookie 和自带密钥只留在本机，云端只存贡献出来的产出。

服务清单表（回答”本机搭了什么程序”）

组件 形态 作用
端侧后端 FastAPI（uvicorn） 本地解析、下载、自带密钥调用
端侧前端与桌面壳 Vue3 + Vite 产物，PySide6 + QWebEngine 壳 页面、托盘常驻、单实例
本地库 SQLite 单文件 解析记录与本地结果
云端后端 FastAPI + PostgreSQL 社群、账号、额度、模型出口
反向代理 Nginx 同源入口、接口转发、流式不缓冲

话术：本机是一台机器起全套——桌面壳拉起本地后端，数据落 SQLite，外部的视频元数据与模型调用走 HTTPS 出去；联网时结果可贡献给社区，云端只存贡献出来的产出，不拿用户的登录态。

三、”做到什么程度”：事实与现状分开

三段式（40 秒）：

判断：端侧功能链路跑通了，单人可用；云端是社群与账号，不对外提供解析服务。
动作：本机全栈部署过，从零跑通过一次完整解析到摘要；云端用 docker compose 起 api + 数据库 + 代理。
兜底：对外不可用的原因是数据源依赖平台的登录态与风控，账号被封就没数据源。要做成公开服务，得换成自有账号池或者官方 API，这块我还没做。

承认边界并说出原因和下一步，比含糊的”上线了”得分高。

四、”资源和性能”：问的是预算，不是容错

要答的 说法
并发上限 云端官方模型出口按账号并发 1，超限返回 429 concurrency_limited 并带 Retry-After，错误码与速率限流分开
速率限流 按账号计数，超限返回 429 rate_limited（注册登录这类匿名入口才按来源 IP），云端请求都带鉴权，按 IP 分桶会在 NAT 后面误伤
超时预算 外部模型调用设总超时，超时降级返回部分结果；额度预扣带超时兜底，超时未结算按失败回滚
存储增长 摘要与思维导图落库并按用户和日期建索引；视频本体不存，只存链接和结果

话术：这套是端云分离的，端侧本地解析，云端负责社群、账号、额度和模型出口。限流是两道闸门：速率按账号计数，官方模型出口每账号并发 1，超限返回 429 带 Retry-After，两种错误码分开，因为语义不同——速率是”太频繁”，并发是”占着不放”。模型调用有总超时，超时降级返回部分结果；额度预扣还挂了一个超时兜底，断连后额度最多被占住一段时间才还，不会无限期挂着。存储只留结果与链接。要上量就得把解析改成任务队列加多 worker，这块我只做了设计没实现。

口径提醒：别说”我做了压测，QPS 多少”——没测就说清口径。本机回环、空响应体的压测数字没有参考价值，唯一作用是能讲清”线程数是虚拟用户数，不等于并发；P95 才反映长尾；错误率要和延迟一起看”。

五、测试开发 vs 产品开发：用产出物讲

差别不在会不会写代码，在交付物和对谁负责。产品开发交付功能，对需求负责，上线就算完；测试开发交付的是质量信号——用例、自动化、门禁、缺陷报告，对”问题能不能被提前发现”负责。所以测试开发要造工具，让别人也能跑，不是自己跑一遍就完。
我现在的经验偏”自己给自己做验证”，还没到给别人造平台的阶段。

最后那句是加分项：主动划边界，比吹成”我都做过”可信。

六、”你自己的系统怎么验证的”：主语必须是”我”

验证自己的东西最容易假通过，所以我先定”什么算失败”。
接口我按契约逐字段断言，流式按事件逐条读、逐条断言，不等全部返回；外部模型我抽成可替换接缝，测试里注入固定输出的假实现，只断言我这边的解析和降级；写完再用变异脚本改坏一条实现，用例不转红就说明断言是空的，退回重写。
UI 那层我只覆盖了主流程，没做全量回归。

关键词只有三个：契约断言、假实现接缝、变异验证。

七、MCP / 模型链路：三段话讲清

客户端按配置起一个 MCP server 子进程，双方用标准输入输出传 JSON 消息；server 把我这边的工具（读文件、跑命令、查库）暴露成工具列表，模型决定调哪个，客户端执行完把结果回给模型。

三句必备：传输是本地 stdio 传 JSON-RPC、远端是 Streamable HTTP；边界是模型不直接碰文件系统，只能调 server 暴露的工具；失败时 server 起不来就是”工具列表为空”，模型会退化成只会聊天，所以第一件事是确认工具数不为 0。

算力与成本：云端 API，主力 DeepSeek，走第三方中转网关，个人自费按量计费，一个月几十块。中转的好处是免注册多模型，坏处是限流和稳定性不由我控制，所以代码里做了 429 退避与超时降级。

八、”别人外化的 skill 怎么确认 OK”：这是主场

不能靠看，要靠跑。别人的 skill 是通用口径，落在我业务上一定偏。
我先准备一个固定用例集，每条写清”必须命中的词”和”绝对不能出现的词”，跑一遍算三个数：命中率、误报率、能不能跑通。命中率低是覆盖不够，误报高是判据太松，跑不通是链路断了。这三个数不达标就改，改完再跑同一批，数字不退化才算收敛。
这套只能测”有没有答到点”，测不了答得对不对，正确性还得人抽检。

配套脚本 skill_eval.py + cases.jsonl：

评测器自检（不是模型指标）：含糊回答（”这个要根据具体业务来定”）命中 0%、误报 0%、可执行 100%、退出码 1；期望答案命中 100%、误报 0%、可执行 100%、退出码 0。

这两个数字只证明评测器本身没坏，不代表任何模型的质量。真实模型跑出来的三个数要接 --cmd 跑一次才有。

写用例时踩到的坑：never 词用子串匹配会误伤正确答案。第一版把 never 写成”一直重试”，正确答案”不能无上限一直重试”被判成误报，误报率 20%。规则：**never 里只放具体错误做法**。

九、AI 时代测试工程师要做什么：补上”验收”这层

AI 能生成用例，但生成的东西默认不可信。分三段：生成阶段给 AI 业务上下文和边界清单；验收阶段人只看三件事——能不能跑通、断言是否指向具体字段、有没有覆盖到异常分支；沉淀阶段把跑通过的用例进回归集，跑不过的退回改提示词。
AI 最容易漏的是”状态跳变”和”并发交叉”，这两类我现在还是手写。

十、跨域：讲清”为什么本地没有、线上才有”

本地开发时前端跑在 dev server 上并配了代理，浏览器看到的请求地址和页面是同一个源，所以不触发跨域检查；上线后页面由反向代理托管，接口如果直连后端域名或端口就是跨源请求，浏览器先发预检，服务端没返回允许的头就被拦。我的做法是不让前端直连后端：反向代理把接口路径转发给后端，页面和接口同源，应用层就不用处理跨域。

追问 答
为什么配了 CORS 还要反向代理 CORS 要处理预检和凭据头，配置面大、易漏；同源反代一劳永逸，还能顺带做限流和日志
流式有什么额外配置 代理默认会缓冲响应，流式会被攒成一坨；要关缓冲与缓存，放大这条路径的读超时，必要时在响应头里告诉代理不要缓冲
还有什么线上才暴露 上传体积限制、请求头大小、超时；还有前端写死的本机地址

十一、职业方向 + 无实习：两句锚定

我确定走测试开发，不是”开发测试都行”。我做过的事里最有正反馈的是”让一个问题被提前发现”——变异验证、契约断言、门禁，都是这一类。所以我想先做业务测试把场景吃透，再往自动化平台走。
我现在缺的是真实业务系统的复杂度和线上问题的处理经验，这也是我来实习的原因。

无实习的接法：对，没有公司实习。替代的是我自己把一条链路从开发做到部署再做到测试，包括线上才暴露的跨域和流式问题——至少线上出问题时我知道从哪查。

十二、反问：备三个，按回答追问

面试官给过高价值信息：视频智能化业务（视频理解）、业务功能测试数据流、交付产品的工程化测试、正在自建自动化测试平台。

顺序 问题 追问方向
1 自动化测试平台现在到哪个阶段，实习生进去会负责哪一块 是补用例、修脚本，还是做平台功能
2 交付产品的工程化测试具体测什么，是打包、升级、兼容性还是现场部署 这类测试和业务测试技能栈差别很大
3 团队里做测试的有多少人，业务测试和测试开发的比例 判断是不是一个人扛

禁用”没有了”。第二次被问就说”我想确认一下实习的带教方式”。

十三、实测记录

验证项 方法 结果
评测器判漏能力（自检，非模型指标） 含糊回答跑 10 条用例 命中 0/10，未假通过
评测器判据正确性（自检，非模型指标） 期望答案跑 10 条用例 命中 10/10，误报 0
评测器退出码 两种模式各跑一次 期望答案 rc=0，含糊回答 rc=1
never 词子串误伤 第一版用例 误报 2/10（20%），已改为只放错误做法
本地压测脚本可跑 本地 HTTP 服务 + 子进程调用 400/400 成功；本机回环口径，不作模型指标
简历版本一致性 从 PDF 抽全文 grep 项目名 分销/宠物/权限三个项目均不在本版简历中

十四、三天补漏计划

天 内容 完成判据
第 1 天 第二节链路与服务清单、第三节现状、第十节跨域因果链，各录音一遍 三段话连续说完不卡，能主动说出流式的代理缓冲配置
第 2 天 第六节验证三件套、第七节 MCP 三段、第八节 skill 验收 能当场画出”客户端→server→工具”三段；能报出用例集的三个数
第 3 天 第四节性能四数、第五节测试开发区别、第十一节方向锚定、第十二节反问 全程不出现”两个方向都可以”；结尾不说”没有了”

优先级：第三节（现状）> 第十一节（方向锚定）> 第六节（验证三件套）> 第十节（跨域）> 其余。前两项决定生死，后三项决定分数。
