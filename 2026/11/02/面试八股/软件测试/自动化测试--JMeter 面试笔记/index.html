一、JMeter 是什么：定位、原理与线程组

1. 什么是 Apache JMeter？

🗣️ 回答重点

  • JMeter 是一款开源的性能测试工具，专门做负载和性能测试。
  • 它最拿手的是模拟多用户并发访问，帮开发和运维评估系统在高负载下的表现。
  • 它不只测 Web 应用，还能通过多种协议覆盖你几乎能想到的各类服务。

📈 拔高

  • 支持 HTTP/HTTPS、FTP、SMTP、POP3、IMAP、JDBC 数据库、LDAP 等多种协议。
  • 自带图形界面能拖拽设计测试计划，也支持命令行运行并与 CI/CD 管道集成。
  • 插件系统很丰富，社区和第三方插件能扩展报告、协议等能力。
  • 支持多实例分布式测试模拟海量用户，并可生成折线图、饼图、表格等报告定位瓶颈。

2. 软件测试中，JMeter 的作用以及优缺点是什么？

🗣️ 回答重点

  • JMeter 是一款开源软件测试工具，核心用途是性能测试和负载测试，能模拟大量用户并发请求。
  • 它的强项在于协议覆盖广、GUI 易上手、报表丰富，还能通过插件扩展功能。
  • 短板是 GUI 跑大规模测试占资源、复杂场景吃力、分布式配置麻烦。

📈 拔高

  • 优点：Apache 旗下完全免费开源，开发人员可按需二次开发。
  • 优点：支持 HTTP、HTTPS、FTP、SOAP、REST、JDBC、LDAP 等多种协议，报表可输出 HTML、CSV、XML。
  • 缺点：GUI 模式跑大规模测试会吃大量系统资源，影响测试性能。
  • 缺点：高度复杂的特殊测试场景可能力不从心，分布式测试配置略复杂需经验。
  • 测试计划由线程组、Sampler、监听器、定时器等元素组合，可通过 HTTP(S) Test Script Recorder 录制脚本，还可与 Jenkins 等 CI/CD 集成。

3. JMeter 的工作原理是什么？

🗣️ 回答重点

  • JMeter 的核心原理是创建虚拟用户来生成模拟负载，检测服务器的响应性能。
  • 线程组代表虚拟用户，多个线程按设定的并发量和时间间隔发送实际请求。
  • 它收集响应时间、吞吐量、并发用户数等数据，用图表和报表呈现，帮助分析系统表现。

📈 拔高

  • 线程组里的每个线程就是一个虚拟用户，会按预设时间间隔和并发量发请求。
  • 支持 HTTP、HTTPS、FTP、JDBC、SOAP、REST 等多种协议请求。
  • 测试计划可用图形界面或文本配置文件定义，可调线程数、循环次数、休息时间等参数。
  • 可通过 Java + JUnit、BeanShell 或 JSR223 脚本扩展功能。
  • 提供聚合报告、响应时间分布图、性能曲线等视图，帮助快速找出瓶颈。

4. JMeter 的基本使用场景有哪些？

🗣️ 回答重点

  • 最普遍的是性能测试，看不同条件下应用的性能表现。
  • 负载和压力测试通过模拟大量并发并逐步加压，探查系统在高负载下的行为与极限。
  • 还能做功能验证、回归测试、分布式测试，以及用 JDBC 测数据库。

📈 拔高

  • 负载测试模拟大量用户并发访问；压力测试逐步增加负载，找到系统最大承受能力和稳定性。
  • 功能测试可验证登录、注册、数据提交和查询等基础功能。
  • 分布式测试用多台机器共同生成负载，更真实模拟生产并发；回归测试自动执行保存的测试计划。
  • 数据库测试经 JDBC 模拟并发查询与更新，评估数据库性能与稳定性。
  • 最初由 Apache 软件基金会开发，支持 FTP、数据库、SOAP、RESTful Web 服务等多种协议。

5. 什么是 JMeter 的线程组？

🗣️ 回答重点

  • 线程组是测试计划里的基本元素，用来模拟用户请求。
  • 它决定有多少个虚拟用户并发压测目标服务器，每个线程就是一个虚拟用户。
  • 能配置线程数、启动时间和循环次数，灵活定义并发负载。

📈 拔高

  • 它是个容器，容纳并管理一批用户请求。10 个线程配 10 秒 Ramp-Up，就是每秒钟起一个线程，压力顺着曲线慢慢爬上去，不会一下打满。
  • 线程数（Number of Threads）决定虚拟用户数；Ramp-Up Period 是启动全部线程的总时间；Loop Count 是每个线程的执行次数。
  • 调度器可设开始/结束时间、持续时间（Duration）和启动延迟（Startup Delay）来精细控制。
  • 除基础线程组外，还有并发用户组（Concurrency Thread Group）和阶梯式线程组（Stepping Thread Group）做更细的控制，这两个都要另外装插件，不是内置元件。
  • 压力测试时逐步加大线程数直到系统崩溃，可找出承载极限；建议逐步加负载并结合服务器端监控。

二、请求实战：方法、报文、参数化与鉴权

6. 如何在 JMeter 中测试 GET 请求接口？

🗣️ 回答重点

  • 先建测试计划，加线程组设定用户数和循环次数，再在线程组下加 HTTP 请求。
  • 在 HTTP 请求里填协议、服务器名或 IP、端口和 GET 路径，就能发出请求。
  • 加个 View Results Tree 监听器，运行后就能在结果树里看响应数据。

📈 拔高

  • 右键测试计划选「添加 → Threads(Users) → Thread Group」，再右键线程组选「添加 → Sampler → HTTP Request」。
  • HTTP 请求配置窗口设协议（通常 http 或 https）、服务器名称或 IP、端口号与路径（GET 的具体路径）。
  • 需要校验响应可加响应断言（Response Assertion）或 JSON 断言；多组数据可用 CSV Data Set Config 做参数化。
  • 用 Aggregate Report 看累计结果，命令行非 GUI 模式适合接入 CI/CD 自动化。
  • 还可加 User Defined Variables 简化路径配置，分布式测试用主从模式模拟大量并发。

7. 如何使用 JMeter 进行 POST 请求测试？

🗣️ 回答重点

  • 先新建测试计划，加线程组模拟用户，再在线程组下加 HTTP 请求 Sampler。
  • 在 HTTP 请求里把方法选成 POST，填好服务器地址和具体 API 路径。
  • 在 Body Data 选项卡里填要传的 POST 参数，加个查看结果树监听器就能看到响应。

📈 拔高

  • 右键测试计划选「添加 → 线程(Users) → 线程组」，再右键线程组选「添加 → Sampler → HTTP 请求」。
  • HTTP 请求选 POST 方法，在 Server Name or IP 填目标服务器（如 api.example.com），在 Path 填 API 路径（如 /login）。
  • Body Data 选项卡直接写键值对参数，例如 username=admin&password=123456。
  • 右键 HTTP 请求加「监听器 → 查看结果树」，点工具栏绿色三角运行，可看到请求、响应数据、请求头等。
  • 进阶可用 CSV Data Set Config 模拟不同用户登录，或加 Assertions 校验响应内容。

8. 对于 POST 请求需要传递 JSON 格式数据，如何在 JMeter 中实现？

🗣️ 回答重点

  • 先建线程组、再在线程组下加 HTTP 请求取样器，这是所有接口测试的通用骨架。
  • HTTP 请求的方法选 POST，填好服务器名称或 IP、端口和具体路径。
  • JSON 数据放在“HTTP 请求主体数据”文本框里，要先勾选它再把 JSON 粘进去。
  • 必须加 HTTP Header 管理器，把 Content-Type 设成 application/json，否则服务器不认是 JSON。
  • 想看请求和响应细节就加个查看结果树监听器来调试。

📈 拔高

  • 校验响应可以加响应断言，检查返回里是否包含或等于预期值。
  • 动态值可用正则表达式提取器或 JSON 提取器从前一个响应里取值，后续请求用变量引用。
  • 要批量发不同数据，加 CSV 数据文件集，在主体数据里用变量引用 CSV 中的值。
  • 一次请求里也可以用 JMeter 的内置函数生成或引用参数值。

9. 如何在 JMeter 中测试 JSON 数据格式的接口？

🗣️ 回答重点

  • 先搭测试计划、加线程组，再在线程组下加 HTTP 请求采样器，这是测试 JSON 接口的基础骨架。
  • 在 HTTP 请求里配好 URL 和方法（GET 或 POST），如果是 POST 就把 JSON 写进 Body Data。
  • 必须加 HTTP Header Manager，把 Content-Type 设成 application/json，告诉服务器发的是 JSON。
  • 加 JSON 断言来验证返回里指定的 JSON 路径和值是否正确。
  • 运行脚本后在查看结果树里直观看请求和响应结果。

📈 拔高

  • POST 的 JSON 请求体示例是 {“name”: “John”, “age”: 30}。
  • 更细粒度解析和验证 JSON 响应可用 JSON Extractor，不少资料把它写成 JSON Path PostProcessor，指的都是同一个元件。
  • 需要换不同 JSON 输入测稳定性，可用 CSV Data Set Config 做参数化；JMeter 还支持分布式测试和接入 Jenkins 等 CI/CD。
  • 默认已创建新的测试计划，没有的话也可以手动新建。

10. 如何使用 JMeter 测试文件上传接口？

🗣️ 回答重点

  • 先建 Test Plan、加 Thread Group，再在 Thread Group 下加 HTTP Request 采样器。
  • HTTP 请求里填好上传接口 URL，方法通常选 POST。
  • 在 Body Data 部分勾选 “Use multipart/form-data for POST”，这样才走文件上传的格式。
  • 文件不是加在 Body Data 里：HTTP Request 下面有个「Files Upload」表格，在那里点 Add 加一行，填参数名和要上传的文件路径，Body Data 那一栏只放原始请求体。
  • 加个 View Results Tree 监听器，运行后就能看响应结果。

📈 拔高

  • 文件路径、文件名不固定时，可用 CSV Data Set Config 参数化，提升脚本复用性。
  • 想看性能就调多线程和调度策略做压力测试，高并发下观察接口表现。
  • 校验上传是否成功可加响应断言查状态码和响应内容。
  • 要取回的数据用 JSON Extractor 或 Regular Expression Extractor 后处理器。
  • 测试脚本可通过命令行运行，便于集成到 Jenkins 等 CI/CD 平台。

11. 如何在 JMeter 中添加 Header 信息？

🗣️ 回答重点

  • 加 Header 有两种路：用 HTTP Header Manager 统一管，或直接在某条 HTTP 请求里填。
  • HTTP Header Manager 是右键请求 → 添加 → 配置元件 → HTTP Header Manager，再点添加填名称和值。
  • 直接加就在 HTTP 请求的“头部信息”那块点添加，填关键字和值，只作用于这一条请求。
  • 多个请求要共享同一种 Header 时优先用 Manager，省得每条都填一遍。

📈 拔高

  • HTTP Header Manager 能配多个 Header（如 Content-Type、Authorization），还能设默认值，请求没单独指定就走默认。
  • 想动态设值可用变量和函数，比如 User Defined Variables 或 CSV Data Set Config 读进来。
  • 复杂逻辑用 BeanShell PreProcessor 或 JSR223 PreProcessor 写脚本，在请求前把 Header 动态塞进去。
  • 直接在 HTTP 请求里添加 Header 更适合单条请求的特定头部，更灵活。

12. 如何在 JMeter 中添加 Cookie？

🗣️ 回答重点

  • 加 Cookie 通常用 HTTP Cookie Manager，它管整个测试计划里的 Cookie。
  • 右键你的 HTTP 样本 → 添加 → 配置元件 → HTTP Cookie Manager。
  • 在管理器里点 Add，手动填 Cookie 的名称、值、域、路径等属性就行。
  • 配好运行后，HTTP 请求列表里所有请求都会自动带上这些 Cookie。

📈 拔高

  • HTTP Cookie Manager 默认自动处理服务器返回的 Set-Cookie，把 Cookie 补进后续请求，很适合模拟浏览器登录态。
  • 它还有 Clear Cookies each iteration（每次迭代清除 Cookie）和 Policy（默认标准浏览器行为）等选项可精细控制。
  • 除了 Cookie，JMeter 还有 HTTP Header Manager、HTTP Cache Manager 等管理组件配合定制请求。
  • Cookie 是服务器发给浏览器保存在本地的一小段文本，用于保存用户状态，如登录态和个性化设置。

13. 如何在 JMeter 中进行参数化？参数化类型有哪些？

🗣️ 回答重点

  • 参数化就是让脚本吃变量而不是写死，常用 CSV Data Set Config 把参数放 CSV 文件里调用。
  • User Defined Variables 用来定义全局或局部常量，比如 API 的 base URL。
  • Configuration Elements 像 HTTP Request Defaults 能设默认参数，子级请求自动引用。
  • 函数和变量能用内置函数（如 __Random 生成随机数）或自定义函数生成、引用参数值。

📈 拔高

  • CSV Data Set Config 适合用户名、密码这类大量数据，设好文件路径、变量名、分隔符就行。
  • 引用变量统一用 ${VAR_NAME} 格式，User Defined Variables 在 Test Plan 或线程组下加。
  • 验证参数化是否成功可用 Debug Sampler 看变量是否被正确读取替换。
  • 配置默认值用 HTTP Request Defaults 设服务器地址、端口号；大参数文件可分模块管理并用 Git 做版本管理。
  • 参数化能增强测试场景覆盖、提高用例重用性，使脚本维护更容易。

14. 如何在 JMeter 中跨线程组传输参数？

🗣️ 回答重点

  • 跨线程组传参靠网络变量（Properties），它是 JMeter 全局变量，任何线程组都能读写。
  • 发送方在 JSR223 PreProcessor 或 BeanShell PreProcessor 里用 props.put("名称", "值") 把变量存进 Properties。
  • 接收方在另一个线程组的预处理器里用 props.get("名称") 把值取出来用。

📈 拔高

  • 普通 JMeter 变量只在当前线程组有效，跨线程组必须走网络变量。
  • 用户定义的变量在测试计划级所有线程组可见，但执行中不能动态变化，要动态更新得结合 JSR223 和网络变量。
  • 也可配正则表达式提取器，把响应里的值存成网络变量，供别的线程组用。
  • 共享属性（Shared Properties）也是通过 props 对象实现，设置与读取方式类似。
  • 加载大量参数共享还可用 CSV Data Set Config，但不太适合单个参数的传递。

三、断言、加密与证书：结果怎么验

15. 如何在 JMeter 中进行断言？

🗣️ 回答重点

  • 打开 JMeter 加载测试计划，找到需要断言的请求节点，右键选“添加”->“断言”，再选断言类型。
  • 常用类型有“响应断言（Response Assertion）”和“响应时间断言（Duration Assertion）”等，按需选择。
  • 最后配置断言参数，比如匹配内容、模式、响应时间等，所有断言都通过该请求才算成功。

📈 拔高

  • 响应断言最常用，验证响应内容是否包含特定字符串、正则表达式或响应码，如 JSON 中是否包含某关键字。
  • JSON 断言可校验 JSON 响应中特定字段和值，XPath 断言用于校验 XML 响应，响应时间断言用于保证性能场景的响应时限。
  • 复杂校验可选用自定义断言（BeanShell Assertion 或 JSR223 Assertion），通过 Groovy、BeanShell、JavaScript 等脚本实现。
  • 同一请求节点下可加多个断言，它们之间是 AND 关系，全部通过请求才成功。

16. 如何在 JMeter 中处理需要加密的请求参数？

🗣️ 回答重点

  • 用 JSR223 Sampler 或 JSR223 PreProcessor 写 Groovy 脚本加密参数，把加密后的参数传给 HTTP 请求。
  • 先在 HTTP Request 里配好目标 URL 和请求方法，再给它加 JSR223 PreProcessor 选语言 Groovy。
  • 在 PreProcessor 里写加密逻辑，HTTP Request 中用 ${variableName} 引用加密后的参数。

📈 拔高

  • 例：Base64 编码，用 org.apache.commons.codec.binary.Base64，vars.get 取原始参数，Base64.encodeBase64String 编码后 vars.put 存为 JMeter 变量，HTTP Request 参数设为 ${encodedParameter}。
  • 更复杂的加密如 AES/RSA 可借助 javax.crypto 包；AES 示例用 Cipher.getInstance(“AES”)、SecretKeySpec，密钥需 16 字节。
  • 可把加密逻辑抽到公共函数或外部文件复用；对称与非对称加密都可用，非对称需公钥私钥配合签名验证。
  • 复杂脚本注意性能，避免每个请求重复创建加密对象，耗时操作可放测试计划开头只执行一次。

17. 如果接口返回的数据进行了加密，如何在 JMeter 中进行断言？

🗣️ 回答重点

  • 先用 BeanShell PostProcessor 或 JSR223 PostProcessor 执行解密脚本，把解密结果存到 JMeter 变量。
  • 然后用 Response Assertion，Apply to 选 JMeter Variable，填变量名 decryptedResponse（填名字本身，不要带 ${}），在 Pattern to Test 里写断言条件。

📈 拔高

  • JSR223 PostProcessor 支持 Groovy、JavaScript 等脚本语言；示例用 Cipher.getInstance(‘AES’)、SecretKeySpec 解密，encryptedData.decodeBase64() 后 vars.put(‘decryptedResponse’, decryptedData)。
  • 解密逻辑复杂时可写自定义类库，JSR223 PostProcessor 里 import 进来再调用，像 YourCustomDecryptor.decrypt(encryptedData) 这样用。
  • 调试可用 Debug Sampler 和 View Results Tree 检查中间变量值，确保解密正确。

18. 如果下一个接口需要使用上一个接口返回的加密数据，如何在 JMeter 中提取？

🗣️ 回答重点

  • 在上一个接口的 HTTP 请求后加“正则表达式提取器”（Regular Expression Extractor）。
  • 配置引用名、正则表达式、模板、匹配数字、默认值等规则，引用名即变量名。
  • 下一个接口的 HTTP 请求中用 ${引用名} 调用提取到的数据，如 ${encryptedData}。

📈 拔高

  • 示例：返回 {“encryptedData”: “abc123xyz”}，引用名 encryptedData，正则 “encryptedData”:\s*”([^”]+)”，模板 1，匹配数字 1，默认值 NOT_FOUND。
  • 除了正则表达式提取器，还可选 JSON Extractor（JSON 路径 $..encryptedData）或 XPath Extractor（//encryptedData/text()）。
  • 复杂嵌套数据可结合多个提取器逐层提取；用 Debug Sampler 和 View Results Tree 调试验证，规则写好注释方便维护。

19. 如何在 JMeter 中测试 SOAP 请求？

🗣️ 回答重点

  • 创建测试计划，加线程组设线程数与循环次数，线程组里加“SOAP/XML-RPC 请求”采样器。
  • 设置采样器 URL 为 SOAP 服务地址，把 SOAP 请求的 XML 粘贴到数据输入框。
  • 配置 HTTP Header Manager 添加 Content-Type: text/xml;charset=UTF-8，运行测试查看结果。

📈 拔高

  • 可用断言验证响应，如响应断言检查 HTTP 状态码或响应文本；定时器控制请求间隔模拟用户操作。
  • 前置处理器（如用户定义的变量）做请求前准备，后置处理器（如正则表达式提取器）处理响应数据。
  • 聚合报告和图形报告可实时监控性能结果；除 HTTP/HTTPS 外还支持 JDBC、JMS、LDAP 等协议。
  • 丰富的第三方插件可扩展协议支持和报告类型。

20. 如何在 JMeter 中处理 HTTPS 证书？

🗣️ 回答重点

  • 启动 HTTP(S) 测试脚本记录器，JMeter 自动生成 CA 证书用于捕获 HTTPS 流量。
  • 将生成的证书（通常 $JMETER_HOME/bin 下的 ApacheJMeterTemporaryRootCA.crt）导入浏览器的受信任根证书颁发机构存储区。
  • HTTPS 请求的 HTTP 请求采样器中协议设为 https，并准确设置目标服务器和端口。

📈 拔高

  • 自签名证书场景可配置系统属性 javax.net.ssl.trustStore 和 javax.net.ssl.trustStorePassword 指向可信存储。
  • 多证书链场景用不同别名和信任链管理，熟悉 keytool 可批量导入证书和管理密钥库。
  • 可指定 TLS 版本与加密算法，调节 https.default.protocol 和 https.socket.protocols 参数。
  • 证书过期会影响测试，执行前检查并更新证书或设置系统参数避免问题。

21. JMeter 测试完成后如何自动发送邮件？

🗣️ 回答重点

  • 使用 JMeter 内置的 SMTP Sampler，测试结束时自动发送邮件。
  • 测试计划里加“查看结果树”监听器方便调试；加 SMTP Sampler 填写 SMTP 服务器地址、用户名、密码、发件人、收件人等。
  • 确保能连通 SMTP 服务器，最后在目标侦听器设置条件，测试执行完毕时发送邮件。

📈 拔高

  • SMTP 配置要注意企业邮箱或严格安全策略，比如 Gmail 现在要开两步验证、再用应用专用密码登录，早年那个「低安全应用访问权限」开关 Google 已经关掉了。
  • 除发邮件外，JMeter 提供多种后置处理器与监听器，如聚合报告、图形结果收集统计，再用自定义脚本生成报告通过邮件发送，可由 BeanShell Sampler 或 JSR223 Sampler 实现。
  • 与 CI/CD（如 Jenkins）集成可自动触发测试并发送结果，提高效率；复杂邮件逻辑可用 JSR223 Sampler 中的 Groovy 或 BeanShell 编写。

22. 在 JMeter 中怎么使用函数和变量？

🗣️ 回答重点

  • 函数和变量能让测试脚本动态填数据，比写死值灵活得多。
  • 变量在脚本里用 ${variableName} 引用，先定义后随处取用。
  • 变量靠“用户定义的变量”或 CSV Data Set Config 这类配置元素来定义。
  • 函数以 __functionName(参数) 形式调用，能生成随机串、当前时间、UUID 等。
  • 函数和变量都能在函数助手对话框里查看并插入到测试计划。

📈 拔高

  • 定义变量：在测试计划右键“添加”→“配置元件”→“用户定义的变量”，用键值对填。
  • CSV Data Set Config 从 CSV 文件读数据并赋给变量，要配文件路径、变量名称、分隔符。
  • 函数助手在 Options 菜单下的 Function Helper Dialog 里打开，选好函数可直接插进测试计划。
  • 常用函数包括 __RandomString(length,charset,variable)、__time(format,variable)、__UUID()、__setProperty(name,value)、__groovy(expression)。
  • 实战例子：CSV 放 UserID（1001/1002/1003），CSV Data Set Config 设变量 userID，HTTP 请求里写 userID=${userID} 就能逐行换用户。

23. JMeter 的正则表达式是什么？

🗣️ 回答重点

  • 它是一种用 Java 正则语法从服务器响应里抓出指定内容的工具。
  • 最常用于提取会话 ID、令牌这类动态数据，方便后续请求复用。
  • 核心元件是 Regular Expression Extractor，配好就能把匹配结果存成变量。
  • 也能配合 Response Assertion 验证响应里到底有没有某个模式。

📈 拔高

  • 基本语法跟 Java 一致：. 任意单字符、* 零或多、+ 一或多、? 零或一、[] 任选其一、^ 和 $ 是字符串首尾。
  • Regular Expression Extractor 的配置项有：名称、正则表达式、模板、匹配编号、默认值。
  • 示例：从 <input type="hidden" name="sessionID" value="abc123"> 提取值，正则可写 <input type="hidden" name="sessionID" value="(.+?)">。
  • 调试可用 Regex101 这类在线工具先验证正则对不对，再贴进 JMeter。
  • 大规模数据提取时要注意性能，尽量少用贪婪匹配和重复计算。

24. JMeter 中处理器的类型有哪些？

🗣️ 回答重点

  • JMeter 的处理器分两大类：前置处理器（Pre-Processor）和后置处理器（Post-Processor）。
  • 前置处理器在请求发送前初始化数据或环境，比如设置 Cookies、修改 HTTP 请求。
  • 后置处理器在请求发送后处理响应数据，比如提取 JSON 数据、用正则表达式提取器取值。

📈 拔高

  • HTTP URL Re-writing Modifier：通过 URL 重写处理会话 ID，实现会话管理。
  • User Parameters：在请求之间设置或修改用户定义的参数。
  • HTML Link Parser：请求执行前提取 HTML 页面中的链接并处理。
  • Regular Expression Extractor：从响应中按正则表达式提取数据。
  • JSON Extractor：从 JSON 格式的响应中提取所需数据。
  • XPath Extractor：用 XPath 表达式从 XML 响应中提取数据。
  • BeanShell PostProcessor：高级用户用 BeanShell 脚本对响应做自定义处理。

25. JMeter 中的预置处理器元件是什么？请列出一些预置处理器元件。

🗣️ 回答重点

  • 预置处理器元件（Pre-Processor Elements）是一组在采样器执行之前执行的操作。
  • 它们通常用来修改采样器请求的设置，或为后续请求设置测试环境。
  • 常用的有：HTTP URL Re-writing Modifier、HTTP User Parameter、定时器（Timer）、Regular Expression User Parameters、User Defined Variables。

📈 拔高

  • HTTP URL Re-writing Modifier：在 HTTP 请求中重写 URL，例如测试 Web 应用时自动把会话 ID 加入 URL。
  • HTTP User Parameter：在 HTTP 请求中动态添加参数，可按请求替换不同用户参数。
  • Timer：可作为预处理器使用，在发送请求前执行，模拟用户行为之间的间隔时间。
  • Regular Expression User Parameters：从响应数据中提取信息并用作后续请求的参数，例如提取动态令牌。
  • User Defined Variables：测试计划开始执行前定义变量，整个测试计划中可用，便于切换测试场景。

26. JMeter 的后置处理器是什么？

🗣️ 回答重点

  • 后置处理器是在处理请求后应用的组件，主要用于处理服务器返回的响应数据。
  • 可在测试计划某一步执行后立即处理返回的数据，比如提取特定响应部分、处理数据供后续步骤使用。
  • 主要功能：提取数据、变量设置、后期处理。

📈 拔高

  • 提取数据：利用正则表达式、XPath、JSON Path 等从响应中提取所需数据；变量设置：把提取出的数据存到变量中供后续请求使用；后期处理：对响应数据进一步加工，例如解析 JSON、XML。
  • Regular Expression Extractor：用正则表达式从响应中提取信息。
  • JSON Extractor：用 JSON Path 从 JSON 格式的响应中提取数据。
  • XPath Extractor：用 XPath 表达式从 XML 或 HTML 响应中提取数据。
  • Boundary Extractor：用固定的左右边界提取响应中的部分数据。
  • BeanShell PostProcessor：用 BeanShell 脚本进行自定义后置操作。
  • 使用场景：测试登录时提取返回的 token 供后续请求使用；在一个复杂场景中把一个响应的数据传递到下一步操作。
  • 配置步骤：选择一个 HTTP 请求或其他测试元素；添加所需类型的后置处理器；在后置处理器中配置表达式、目标字段等参数。

27. JMeter 中测试元件的执行顺序是什么？

🗣️ 回答重点

  • JMeter 元件的执行顺序按测试计划中的位置和所属类别确定，通常为：配置元件、前置处理器、定时器、取样器、后置处理器、断言、监听器。
  • 配置元件在测试启动时初始化，每个线程组开始时执行一次；前置处理器在每个样本请求前运行；定时器让线程休眠一段时间。
  • 取样器是实际发出请求的地方，按顺序依次执行；后置处理器在每个样本请求后执行；断言验证响应是否符合预期；监听器记录或显示取样器结果。

📈 拔高

  • 配置元件如 HTTP Cookie 管理器、HTTP 请求默认值，可为取样器提供默认设置，例如 HTTP 请求默认值避免重复输入服务器名称。
  • 前置处理器常用于请求前的预备操作，例如用正则表达式提取器在一次请求中提取数据供后续使用。
  • 定时器可以让测试更接近真实用户操作，模拟用户在两个请求之间的思考时间，使负载更真实。
  • 断言类型包括响应断言、JSON 断言、XPath 断言等，用于验证系统在特定条件下的行为是否正确。
  • 监听器是获取测试结果的重要工具，例如查看树监听器查看每个请求的详细信息，汇总报告生成统计数据。

28. JMeter 中的配置元件是什么？

🗣️ 回答重点

  • 配置元件用于配置和提供运行时参数，与测试计划中的其他组件配合，增强测试的灵活性和可管理性。
  • 常见的配置元件包括 CSV Data Set Config、HTTP Request Defaults、User Defined Variables、Java Request Defaults。

📈 拔高

  • CSV Data Set Config：从 CSV 文件按行读取数据提供给线程，适合模拟多种测试场景，如不同登录名和密码。
  • HTTP Request Defaults：提供默认的 HTTP 请求参数，避免每个 HTTP 请求重复配置，保证请求一致性。
  • User Defined Variables：定义全局变量，可在测试计划任何地方使用，适合配置全局参数或常量。
  • Java Request Defaults：为 Java 请求提供默认配置，适用于通过 Java 代码模拟的请求。
  • 使用配置元件可减少重复工作、提高测试灵活性、增强可维护性；CSV Data Set Config 让测试数据管理方便，只需更换 CSV 文件即可切换测试情境。

29. JMeter 中的计时器是什么？计时器的类型有哪些？

🗣️ 回答重点

  • 计时器是在请求之间添加延时的组件，模拟用户在实际使用场景中的操作，避免所有请求在同一时间发送到服务器导致测试结果不真实。
  • 可为单个请求或整个线程组设置延时，具体取决于使用方式。
  • 常见类型：固定定时器、高斯随机定时器、恒定吞吐量定时器、统一随机定时器、服务时间定时器、同步定时器、自定义定时器（通过编写 JMeter 插件）。

📈 拔高

  • 固定定时器：添加固定延时值，适合每个请求之间有固定间隔时间。
  • 高斯随机定时器：按高斯分布添加随机延时，围绕平均值，模拟用户随机停顿如阅读网页或输入数据。
  • 恒定吞吐量定时器：控制吞吐量，使请求以恒定速率发出，适合达到固定吞吐量如每分钟多少请求。
  • 统一随机定时器：在指定最大值与最小值之间添加随机延时，模拟有上下边界的随机用户行为。
  • 服务时间定时器：模拟服务器处理时间，具体时间可按实际测量值设定。
  • 同步定时器：等待一定数量的线程达到某一点后同时释放，用于并发用户测试，模拟多用户同时执行操作。
  • 自定义定时器：通过编写自定义代码或使用第三方插件实现，适用于内置计时器无法满足的特殊业务需求。

30. JMeter 聚合报告里面的参数是什么意思？

🗣️ 回答重点

  • 聚合报告把性能结果汇总成一张表，帮我们快速看懂整体表现。
  • Label 是请求名，# Samples 是这个请求一共被执行了多少次。
  • Average、Min、Max 分别是平均、最快、最慢的响应时间。
  • Error % 是失败请求的比例。聚合报告里另外还有 Median 和 90%、95%、99% 线；想看响应时间的标准差 Std. Dev.，那是汇总报告（Summary Report）的列，聚合报告没有这一列。
  • Throughput 是每秒处理多少请求，KB/sec 是每秒传多少千字节，两者衡量系统处理能力。

📈 拔高

  • 响应时间指从发请求到收到响应的时长，高并发下是最该盯的指标。
  • 并发用户数是同一时刻发起请求的人数，增多可能让响应变慢、错误率上升。
  • 性能瓶颈常表现为并发上来后响应和错误率突增，根因可能是数据库锁争抢、CPU 过高、内存不足。
  • 负载测试在预期负载下看稳定，压力测试一直加压到崩溃看极限，基准测试则定下性能基线。
  • 瓶颈缓解可从优化数据库查询、增加硬件资源、做分布式部署这几条路入手。

31. JMeter 的监听器有哪些？

🗣️ 回答重点

  • JMeter 是开源负载测试工具，监听器负责查看和分析测试结果，常用的就是下面这几种。
  • 先用“查看结果树”调试验证脚本，大规模性能测试时避免重型监听器，多用“汇总报告”“聚合报告”这类轻量级的。
  • 结合后端监听器把结果发到 Graphite、InfluxDB 等后端做持久化分析，是企业级常用做法。

📈 拔高

  • 查看结果树：看每个请求的详细请求/响应内容，适合调试脚本，但高并发下占大量内存资源，需慎重。
  • 汇总报告：样本数、平均/最大/最小响应时间、吞吐量、错误率等基础统计，适合整体性能概况。
  • 聚合报告：类似汇总报告但结构化展示，额外提供 90%线、95%线、99%线等关键指标，便于细粒度分析。
  • 图形结果：图形化展示趋势和性能变化，适合长期监控系统性能。
  • 生成爬虫爬行记录：简短汇总，适合集成测试环境快速生成结果统计。
  • 后端监听器：把测试结果发送到后端数据库或存储系统，便于进一步分析和可视化。

32. 软件测试中，如何减少 JMeter 中的资源请求？

🗣️ 回答重点

  • 两条路：禁用 JMeter 的默认资源请求，以及精简测试计划、排除不必要的资源。
  • 禁用默认请求：打开测试计划，找到 HTTP Request 采样器，在配置界面取消勾选“Retrieve All Embedded Resources”，别让它自动去抓页面里的图片和脚本；更省事的做法是加一个 HTTP Cache Manager，让它按缓存头决定要不要重新拉。
  • 精简计划：移除图片、样式表、JavaScript 等静态资源请求，只测特定 HTTP 请求路径而非整页加载。

📈 拔高

  • 正则表达式提取器：加到 HTTP Request 采样器，只捕获关心的资源类型，在“Response Field to check”里填正则。
  • JMeter Plugins Manager：下载安装 Dummy Sampler 插件，模拟请求而不实际访问服务器资源。
  • 脚本化请求：用 BeanShell、Groovy 等动态控制和生成 HTTP 请求，精细控制测试逻辑。
  • 缓存和池化：在 HTTP Request 采样器“Advanced”选项卡启用“Use Cache-Control/Expires Header”，让 JMeter 缓存静态资源。

33. 如何在 JMeter 中执行尖峰测试（Spike Testing）？

🗣️ 回答重点

  • 新建测试计划，加线程组，设置用户数量、启动时间、持续时间，关键是配置用户负载突增情况。
  • 在线程组下加 HTTP Request 等采样器代表真实用户行为，再加“查看结果树”“聚合报告”等监听器记录结果。
  • 运行后观察监听器中的数据和图表，分析突增流量下的响应时间、错误率等指标。

📈 拔高

  • 尖峰测试模拟突然高负载，用于识别系统瓶颈，确保极端条件下正常运行。
  • 线程组阶梯配置：用定时器（Timer）和定时触发器（Scheduler）在不同时间点增加负载，步进线程组（Stepping Thread Group）插件可配置更复杂场景。
  • 深入分析生成的日志和报告：响应时间分布、吞吐量、错误分布，定位性能瓶颈。
  • 同时监控服务器端 CPU、内存、网络带宽等资源，可用 NewRelic、Grafana、Prometheus。
  • 发现表现不佳时根据结果优化：增加硬件、优化代码、调整数据库配置，提升鲁棒性和可扩展性。

34. 软件测试中，如何在 JMeter 中捕获身份验证窗口的脚本？

🗣️ 回答重点

  • 主要使用“HTTP Authorization Manager”组件，它会在 JMeter 访问需要身份验证的页面时自动提供认证信息。
  • 打开测试计划，在线程组下右键添加 -> 配置元件 -> HTTP Authorization Manager，填入域、路径、用户名和密码。
  • 若未启用 HTTPS，可通过修改 HTTP Request Defaults 提供默认协议信息。

📈 拔高

  • 不同用户名密码：用“CSV Data Set Config”管理数据文件，为每组请求提供不同认证信息。
  • 认证失败调试：用“查看结果树”监听器检查响应数据，确认用户名密码传输是否正确及服务器状态码。
  • 其他认证类型：Bearer Token 或 OAuth 可用“HTTP Header Manager”附加认证头，或写自定义 Java Sampler 处理复杂流程。
  • 客户端动态 Token 等复杂身份验证，可能需要更复杂脚本或用 Selenium 自动化模拟。

35. 软件测试中，在 JMeter 中是否有必要显式调用嵌入式资源？

🗣️ 回答重点

  • 大多数情况下不必显式调用，HttpSampler 可自动处理图片、CSS、JavaScript 等嵌入式资源。
  • 在 HTTP 请求中勾选“Retrieve All Embedded Resources”，JMeter 会自动下载页面所有嵌入式资源。

📈 拔高

  • 负载测试优化：模拟真实用户通常需加载全部嵌入式资源，但只关心主页面响应时间时可禁用自动加载。
  • 控制带宽：默认资源加载带宽与主请求不一致时，需手动对每个资源配置。
  • 过滤特定资源：页面含大文件或外部资源时，手动配置可精确控制加载与排除。
  • 调试定位：遇到特定性能问题时，显式调用嵌入式资源有助于逐步排查。
  • 显式调用做法：把每个嵌入式资源作为单独 HTTP 请求控件并设正确路径，大量资源可用自动化脚本或插件生成。

36. 如何使用 JMeter 进行性能测试？

🗣️ 回答重点

  • 先去官网下载 JMeter，解压后用 jmeter.bat 或 jmeter.sh 启动。
  • 建一个 Test Plan 测试计划，它是所有测试对象的容器。
  • 加 Thread Group 线程组定义用户行为，设线程数、Ramp-Up 时间、循环次数。
  • 加 Sampler 采样器，一般选 HTTP Request 来模拟访问网页、提交表单。
  • 配好 URL、请求方法 GET/POST、参数后，加 Listener 如 View Results Tree、Summary Report，点绿色按钮开跑。

📈 拔高

  • 跑完在监听器里能看到响应时间、吞吐量、错误率这些关键性能指标。
  • 想造更大压力可做分布式测试：一台当 Master、其余当 Slave 并行加压。
  • 不止 HTTP/HTTPS，还支持 JDBC、LDAP、SOAP、FTP、SMTP 等多种协议。
  • 用 Beanshell、Groovy 写复杂逻辑，用 CSV Data Set Config 做外部数据参数化。
  • 可集成进 CI/CD，比如 Jenkins 的 Job 自动跑性能测试并生成报告。

37. JMeter 为性能测试提供了哪些好处？

🗣️ 回答重点

  • 它开源免费，是 Apache 软件基金会的项目，能大幅降低测试成本。
  • 协议覆盖广，HTTP、HTTPS、SOAP、JDBC、LDAP 等都支持。
  • 图形界面简单直观，测试人员很快就能上手，学习曲线短。
  • 有插件机制和分布式测试，能扩到集群跑大量用户并发。
  • 能生成详细的测试报告和图表，方便分析各项性能指标。

📈 拔高

  • 测试脚本可跨项目复用，在不同测试间共享，减少重复劳动。
  • 作为开源项目有活跃社区，指南、教程、问题求助都好找。
  • 能和 AWS、Azure、Google Cloud 等云平台集成，免得自建大规模环境。
  • 可接 Jenkins、GitLab CI 等 CI/CD 工具，每次提交后自动跑性能测试。
  • 支持命令行和脚本执行，很适合非 UI 环境下的自动化测试。

面试前 10 分钟速查

JMeter 是什么

  • 定位：JMeter 是 Apache 旗下开源性能测试工具，专门做负载和性能测试，模拟多用户并发访问评估系统在高负载下的表现。

  • 协议覆盖：支持 HTTP/HTTPS、FTP、SMTP、POP3、IMAP、JDBC 数据库、LDAP、SOAP、REST 等多种协议。

  • 线程组：线程组是测试计划的基本元素，每个线程就是一个虚拟用户，决定并发压测目标服务器的用户数。

  • 线程参数：线程数（Number of Threads）决定虚拟用户数；Ramp-Up Period 是启动全部线程的总时间；Loop Count 是每个线程的执行次数。

  • 调度器：调度器可设开始/结束时间、持续时间（Duration）和启动延迟（Startup Delay）来精细控制负载。

  • 运行方式：自带图形界面可拖拽设计测试计划，也支持命令行运行并与 CI/CD 管道集成。

  • 报表：提供聚合报告、响应时间分布图、性能曲线等视图，支持输出 HTML、CSV、XML 报表。

  • 扩展：可通过 Java + JUnit、BeanShell 或 JSR223 脚本扩展功能，插件系统丰富。

  • 分布式：支持多实例分布式测试模拟海量用户；还有并发用户组（Concurrency Thread Group）和阶梯式线程组（Stepping Thread Group）。

  • 场景：可用于性能、负载、压力、功能验证、回归、分布式测试，以及经 JDBC 测数据库。
    请求实战

  • GET 请求：先建测试计划、加线程组设定用户数和循环次数，再在线程组下加 HTTP 请求，填协议、服务器名称或 IP、端口和 GET 路径就能发出请求，加 View Results Tree 监听器查看响应数据。

  • POST 请求：HTTP 请求方法选 POST，填 Server Name or IP 和 Path，Body Data 选项卡里写键值对参数（如 username=admin&password=123456），加查看结果树监听器运行查看请求、响应数据和请求头。

  • JSON POST：JSON 数据放在“HTTP 请求主体数据”文本框，先勾选它再把 JSON 粘进去，必须加 HTTP Header 管理器把 Content-Type 设成 application/json，否则服务器不认是 JSON。

  • JSON 接口：HTTP 请求里配好 URL 和方法（GET 或 POST），POST 把 JSON 写进 Body Data，加 JSON 断言验证返回里指定的 JSON 路径和值，POST 的 JSON 请求体示例是 {“name”: “John”, “age”: 30}，更细粒度解析可用 JSON Extractor（不少资料写成 JSON Path PostProcessor，指的是同一个元件）。

  • 文件上传：HTTP 请求方法通常选 POST，Body Data 部分勾选 “Use multipart/form-data for POST”，文件在 HTTP Request 的「Files Upload」表格点 Add 加一行，填参数名和文件路径，Body Data 只放原始请求体，加 View Results Tree 监听器看响应。

  • Header 添加：用 HTTP Header Manager（右键请求 → 添加 → 配置元件 → HTTP Header Manager）点添加填名称和值；也可直接在 HTTP 请求的“头部信息”块点添加，只作用于该条请求；Manager 可配多个 Header 并设默认值。

  • Cookie：用 HTTP Cookie Manager（右键 HTTP 样本 → 添加 → 配置元件 → HTTP Cookie Manager），点 Add 填 Cookie 的名称、值、域、路径等属性，运行后所有请求自动带上 Cookie；默认自动处理服务器返回的 Set-Cookie，还有 Clear Cookies each iteration 和 Policy 选项。

  • 参数化：常用 CSV Data Set Config 把参数放 CSV 文件里调用；User Defined Variables 定义全局或局部常量如 API 的 base URL；引用变量用 ${VAR_NAME} 格式；Debug Sampler 验证变量是否被正确读取替换。

  • 默认值：Configuration Elements 像 HTTP Request Defaults 能设默认参数，子级请求自动引用，可设服务器地址、端口号；多组数据可用 CSV Data Set Config 做参数化，动态值可用正则表达式提取器或 JSON 提取器从前一个响应取值。

  • 校验与断言：需要校验响应可加响应断言（Response Assertion）或 JSON 断言；想取回数据用 JSON Extractor 或 Regular Expression Extractor 后处理器；Aggregate Report 看累计结果，命令行非 GUI 模式适合接入 CI/CD 自动化。

  • 跨线程组传参：靠网络变量（Properties），发送方在 JSR223 PreProcessor 或 BeanShell PreProcessor 里用 props.put(“名称”, “值”) 存入，接收方在另一个线程组的预处理器里用 props.get(“名称”) 取出；普通 JMeter 变量只在当前线程组有效。

  • User Defined Variables 动态：用户定义的变量在测试计划级所有线程组可见，但执行中不能动态变化，要动态更新得结合 JSR223 和网络变量；加载大量参数共享还可用 CSV Data Set Config，但不太适合单个参数的传递。
    断言、加密与证书

  • 断言添加：右键请求节点「添加」→「断言」选类型，配置匹配内容、模式、响应时间，所有断言都通过该请求才算成功。

  • 响应断言：最常用，验证响应是否包含特定字符串、正则表达式或响应码，如 JSON 中包含某关键字。

  • 结构断言：JSON 断言校验 JSON 响应特定字段和值，XPath 断言校验 XML 响应，响应时间断言保证性能场景的响应时限。

  • 自定义断言：复杂校验用 BeanShell Assertion 或 JSR223 Assertion，通过 Groovy、BeanShell、JavaScript 脚本实现。

  • 多断言关系：同一请求节点下多个断言是 AND 关系，全部通过请求才成功。

  • 参数加密：JSR223 PreProcessor 选语言 Groovy 写加密逻辑，HTTP Request 参数设 ${encodedParameter} 引用加密后的参数。

  • 加密算法：Base64 用 org.apache.commons.codec.binary.Base64，vars.get 取原始参数、vars.put 存为 JMeter 变量；AES 用 Cipher.getInstance(“AES”) 与 SecretKeySpec，密钥需 16 字节。

  • 解密断言：先用 BeanShell PostProcessor 或 JSR223 PostProcessor 解密并 vars.put 存变量，Response Assertion 的 Apply to 选 JMeter Variable，填 ${decryptedResponse} 写断言条件。

  • 数据提取：上一接口后加正则表达式提取器，配引用名、正则表达式、模板、匹配数字、默认值，下一接口用 ${encryptedData} 调用；也可用 JSON Extractor 或 XPath Extractor。

  • SOAP 测试：SOAP/XML-RPC 请求采样器把 SOAP 请求的 XML 粘贴到数据输入框，HTTP Header Manager 设 Content-Type: text/xml;charset=UTF-8，响应断言检查 HTTP 状态码或响应文本。

  • 邮件报告：聚合报告和图形结果收集统计后，用自定义脚本生成报告，由 SMTP Sampler 或 BeanShell Sampler、JSR223 Sampler 发送，配合 Jenkins 自动触发测试并发送结果。

  • 证书导入：启动 HTTP(S) 测试脚本记录器生成 CA 证书 ApacheJMeterTemporaryRootCA.crt，导入浏览器的受信任根证书颁发机构存储区，采样器协议设 https。

  • 证书参数：自签名证书配 javax.net.ssl.trustStore 与 javax.net.ssl.trustStorePassword，keytool 管理密钥库，https.default.protocol 指定 TLS 版本与加密算法。
    元件与执行顺序

  • 变量定义：变量用 ${variableName} 引用，先定义后随处取用，靠“用户定义的变量”或 CSV Data Set Config 来定义。

  • 函数调用：以 __functionName(参数) 形式调用，函数助手在 Options 菜单的 Function Helper Dialog 里打开，选好函数可直接插进测试计划；常用 __RandomString(length,charset,variable)、__time(format,variable)、__UUID()、__setProperty(name,value)、__groovy(expression)。

  • CSV实战：CSV 放 UserID（1001/1002/1003），CSV Data Set Config 设变量 userID，HTTP 请求里写 userID=${userID} 就能逐行换用户。

  • 正则提取：核心元件是 Regular Expression Extractor，配置项为名称、正则表达式、模板、匹配编号、默认值，把匹配结果存成变量，最常用于提取会话 ID、令牌这类动态数据，示例正则 <input type="hidden" name="sessionID" value="(.+?)">。

  • 正则语法：基本语法跟 Java 一致，. 任意单字符、* 零或多、+ 一或多、? 零或一、[] 任选其一、^ 和 $ 是字符串首尾；可配合 Response Assertion 验证响应，Regex101 这类在线工具先验证正则，大规模提取注意性能、少用贪婪匹配。

  • 处理器两分：处理器分前置处理器（Pre-Processor）和后置处理器（Post-Processor），前置在请求发送前初始化数据或环境，比如设置 Cookies、修改 HTTP 请求，后置在请求发送后处理响应数据，比如提取 JSON 数据、用正则表达式提取器取值。

  • 预置元件：预置处理器元件在采样器执行之前执行，HTTP URL Re-writing Modifier 自动把会话 ID 加入 URL，HTTP User Parameter 动态添加参数，Timer 在发送请求前执行以模拟用户行为之间的间隔时间；Regular Expression User Parameters 从响应中提取动态令牌用作后续请求的参数，User Defined Variables 在测试计划开始执行前定义变量、整个测试计划可用。

  • 后置元件：在处理请求后应用，主要功能是提取数据、变量设置、后期处理；JSON Extractor 用 JSON Path 提取，XPath Extractor 从 XML 或 HTML 响应提取，Boundary Extractor 用固定左右边界提取，BeanShell PostProcessor 用 BeanShell 脚本自定义，测试登录时可提取返回的 token 供后续请求使用。

  • 执行顺序：测试元件按配置元件、前置处理器、定时器、取样器、后置处理器、断言、监听器执行；配置元件在测试启动时初始化，每个线程组开始时执行一次。

  • 顺序细节：前置处理器在每个样本请求前运行，定时器让线程休眠一段时间，取样器按顺序依次执行，后置处理器在每个样本请求后执行，断言验证响应是否符合预期，监听器记录或显示取样器结果，例如查看树监听器、汇总报告。

  • 配置元件：CSV Data Set Config 从 CSV 文件按行读取数据提供给线程，HTTP Request Defaults 提供默认的 HTTP 请求参数避免重复配置，User Defined Variables 定义全局变量，Java Request Defaults 为 Java 请求提供默认配置。

  • 计时器：在请求之间添加延时，模拟用户在实际使用场景中的操作，避免所有请求在同一时间发送到服务器导致测试结果不真实，可为单个请求或整个线程组设置延时。

  • 计时器类型：固定定时器添加固定延时值，高斯随机定时器按高斯分布围绕平均值添加随机延时，恒定吞吐量定时器让请求以恒定速率发出，统一随机定时器在最大值与最小值之间添加随机延时，服务时间定时器模拟服务器处理时间，同步定时器等一定数量的线程达到某点后同时释放，自定义定时器通过编写 JMeter 插件实现。
    结果解读与进阶配置

  • 聚合报告：Label 是请求名，# Samples 是执行次数，Average、Min、Max 是平均、最快、最慢的响应时间。

  • 报告波动：Error % 是失败请求比例；聚合报告还有 Median 和 90%、95%、99% 线；Throughput 是每秒请求数，KB/sec 是每秒千字节，衡量处理能力；响应时间的标准差 Std. Dev. 在汇总报告里，聚合报告没有这一列。

  • 监听器选型：先用「查看结果树」调试脚本，大规模性能测试时避免重型监听器，多用「汇总报告」「聚合报告」这类轻量级的。

  • 细粒度分析：聚合报告比汇总报告额外提供 90%线、95%线、99%线；后端监听器把结果发到 Graphite、InfluxDB 等后端做持久化分析。

  • 减少资源请求：测试计划的 HTTP Request 采样器取消勾选「Retrieve All Embedded Resources」，或者加 HTTP Cache Manager 按缓存头判断要不要重拉，移除图片、样式表、JavaScript 等静态资源请求，只测特定 HTTP 请求路径。

  • 请求精简手段：正则表达式提取器在 Response Field to check 填正则只捕获关心的资源；Dummy Sampler 插件模拟请求而不实际访问服务器；HTTP Request 采样器 Advanced 选项卡启用 Use Cache-Control/Expires Header 缓存静态资源。

  • 尖峰测试：线程组设用户数量、启动时间、持续时间，用定时器 Timer 和定时触发器 Scheduler 在不同时间点增加负载，Stepping Thread Group 插件可配置更复杂场景。

  • 尖峰监控：运行后在监听器观察响应时间、错误率，同时用 NewRelic、Grafana、Prometheus 监控服务器端 CPU、内存、网络带宽。

  • 身份验证捕获：线程组下右键添加 -> 配置元件 -> HTTP Authorization Manager，填入域、路径、用户名和密码，访问需认证页面时自动提供认证信息。

  • 认证进阶：不同用户名密码用 CSV Data Set Config 管理数据文件；Bearer Token 或 OAuth 用 HTTP Header Manager 附加认证头；复杂流程写自定义 Java Sampler 处理。

  • 嵌入式资源：多数情况不必显式调用，HTTP 请求勾选 Retrieve All Embedded Resources 由 HttpSampler 自动下载图片、CSS、JavaScript 等资源；只关心主页面响应时间时可禁用自动加载。

  • 测试步骤：用 jmeter.bat 启动，建 Test Plan 测试计划，加 Thread Group 设线程数、Ramp-Up 时间、循环次数，加 HTTP Request 采样器配 URL 与 GET/POST 方法，挂 View Results Tree、Summary Report 监听器后运行。

  • 工具优势：开源免费的 Apache 项目，支持 HTTP、HTTPS、SOAP、JDBC、LDAP 等协议，图形界面学习曲线短，支持命令行和脚本执行，可接 Jenkins、GitLab CI 等 CI/CD 工具自动跑测试。
