一、RPA 认知与工具

1.1 RPA 定义与适用边界

RPA（Robotic Process Automation，机器人流程自动化）是用软件机器人模拟人在电脑上的操作，自动执行规则明确、重复、跨系统界面或跨应用的业务流程。它在跨境电商里价值最高的是「人要在多个后台之间搬运数据」的活。

维度 适合上 RPA 不适合上 RPA
规则 稳定、可穷举的规则 频繁变化、需要主观判断
频率 高频、批量、每日定时 偶发、一次性的事
系统 有界面没 API，或 API 能力不足 有稳定 API 且字段开放
数据量 中小批量可逐条处理 海量、需流式计算
异常 异常路径可枚举、可兜底 异常发散、要临场决策

判断一句口诀：稳定规则 + 高频 + 有界面无 API，才最值钱。有 API 优先用 API，这是 1.3 的「API 优先、UI 兜底」原则。

问法 一句话答 追问
什么是 RPA 用软件机器人模拟人操作电脑，自动跑规则明确的重复流程 和写脚本有什么区别
什么时候不该用 RPA 有稳定 API 时优先 API；规则天天变、要人判断的不适合 那你怎么说服业务方
RPA 和自动化脚本区别 RPA 多聚焦界面操作、低代码、带调度控制台；脚本更底层灵活 你更想用哪种

1.2 影刀 RPA 具体能力

影刀是国产低代码 RPA，强在电商/桌面场景，流程面板里还能写 Python 模块。

能力点 事实要点（已核实）
版本 社区版免费但限非商业使用、有每日运行时长约 30 分钟；创业版按年付费限人数；企业版团队协作、合规、私有化，官网公开标准套餐约 59800 元/5 账号/年
支持系统 Windows、Mac、信创（统信 UOS、银河麒麟、Linux）、Android 手机自动化
元素拾取 提供元素捕获、元素锚点、AI 辅助定位、元素库、企业云元素库；支持网页/桌面/手机元素
指令库大类 网页自动化、桌面软件、鼠标键盘、数据表格、Excel/WPS、对话框、数据处理、操作系统、流程/应用、人工智能 AI、网络、工作队列、手机、自定义指令、SAP 扩展
内置 Python 流程面板可建 Python 模块，内置 xbot 与 package 两个包；第三方库可装可用、可定义调用函数
调度 控制台有调度中心、高级任务计划、机器人管理、任务监控；企业版原生定时触发；社区版定时要走系统计划任务曲线方案
异常/日志 有「错误列表」「运行日志」，流程可捕获异常、AI 辅助定位；异常捕获与重试属流程指令能力

xbot 包边界必须说清：**xbot 是影刀运行环境内置包，只能在影刀 Python 模块内调用，不是可 pip install 的独立 SDK**。它封装了软件自动化、数据表格、Excel、日志、AI 等能力。外部纯 Python 进程不能直接 import xbot。面试编 xbot.orders.download() 这种没公开的方法名会翻车，只讲已公开的大类能力。

问法 一句话答 追问
影刀用过哪些能力 元素捕获做网页/桌面拾取，内置 Python 模块跑 xbot 做 Excel 和日志，控制台定时调度 xbot 能 pip 装吗
社区版和企业版差在哪 社区版免费但非商业、有运行时长限制；企业版有控制台调度、多人多机器人、私有化 定时任务社区版怎么做
影刀 Python 和脚本 Python 区别 影刀里 Python 跑在它的运行环境，能用 xbot 调封装指令；外面普通脚本调不了 xbot 那你怎么单测影刀里的逻辑

1.2.1 录制与编码两种开发方式

方式 适用 优劣
录制 界面操作多、流程简单 上手快；但选择器脆弱、难维护、难单测
Python 模块编码 复杂逻辑、批量、要单测 灵活、可测；需会 Python
混合 多数真实项目 录制搭骨架，编码补解析/幂等/重试

1.2.2 指令库大类与跨境用途映射

指令大类 跨境 RPA 用途
网页自动化 卖家后台订单/库存抓取
Excel/WPS 表格 报表汇总、对账表生成
数据表格 中间数据暂存与清洗
人工智能 AI 调模型做单据抽取、异常分类
网络 直接调平台开放 API
工作队列 多店铺/多任务分发排队
操作系统 文件整理、命名、移动
流程/应用 分支、循环、子流程复用

1.2.3 影刀开发工作流（需求到上线）

  1. 需求澄清：平台、字段、去重键、频率、合规边界。
  2. 搭流程：优先查 API；无 API 才录制网页/桌面。
  3. 写逻辑：Python 模块做解析、幂等、重试，便于单测。
  4. 控制台调度：企业版定时触发，配机器人。
  5. 小批量验收：抽数据对核对输出。
  6. 灰度：单店铺先跑，再全量。
  7. 监控：失败告警 + 每日冒烟。

选型口径：能用 API/开放 API 解决的，不上 UI 录制。录制只补足「无 API 或 API 能力不足」的环节。

1.3 工具横向对比与定位

区分两类工具：传统桌面/UI RPA，和 AI 工作流/Agent 编排。

工具 定位 免费档（已核实）
影刀 RPA 国产低代码 RPA，强电商/桌面 社区版免费（非商业、时长限制）
UiPath 国际老牌，Orchestrator 调度，MCP Server 2025 GA Community License 免费
Power Automate Desktop 微软桌面 RPA，Win11 自带，Office 集成 桌面版免费
实在 RPA 国产 RPA + AI，多平台采集 有免费试用（额度未逐一核实）
八爪鱼 采集器起家扩展 RPA 免费版 ¥0（100 任务数）
n8n 通用自动化工作流引擎，可搭 Agent 开源自托管免费
Dify LLM 应用平台，RAG/Agent 中台 开源自部署免费
Coze（扣子） 字节 AI Agent 无代码平台 免费版 0 元

面试对比口径：影刀、UiPath、PAD 属于传统桌面/UI RPA，八爪鱼是采集器/轻量 RPA，n8n/Dify/Coze 属于 AI 工作流与 Agent 编排，不操作 Windows 界面，但能调度 API 与模型，是「RPA + AI」融合的另一条路。

「API 优先、UI 兜底」原则：能对接平台 Open API / ERP API 就先对接，理由是 API 稳定、快、不易被风控。UI 录制易被前端改版、登录态、验证码打断。RPA（UI 自动化）作为「无 API 或 API 能力不足」时的补充。

1.4 OpenClaw（小龙虾）是什么

OpenClaw 俗称「小龙虾」「养龙虾」，是 2026 年初在国内爆火的真实开源 AI 智能体（Agent）/ 桌面 Agent 框架，让 AI「拥有手和脚」：读写文件、操作浏览器、执行系统命令，支持本地/云端一键部署。还有独立的 openclaw-rpa 开源项目（录制浏览器/Excel/Word/API 操作回放成独立脚本、无需大模型），以及阿里云 RPA 的「OpenClaw SKILL」企业能力。

问法 一句话答 追问
知不知道 OpenClaw 2026 爆火的开源 AI 桌面 Agent 框架，能让 AI 操作浏览器/文件/命令，也能和 RPA 结合做录制回放 它和我们公司用的系统什么关系
RPA 和 Agent 什么关系 RPA 跑固定规则流程，Agent 用 LLM 做决策编排；OpenClaw 这类给 RPA 加了「会思考的调度」 那是不是 Agent 会取代 RPA

聊 OpenClaw 不翻车的边界：只说它是真实存在的开源 AI Agent 框架、能操作浏览器/文件/命令、可与 RPA 结合（录制回放、企业 SKILL）。不要断言它和该公司内部某系统的绑定关系，查不到。

1.5 影刀企业版控制台能力（面试能展开）

企业版和社区版的分水岭在「集中管控」。控制台提供：

能力 用途
调度中心 / 高级任务计划 定时触发、依赖编排，不用自己写 cron
机器人管理 多机器人分账号、分店铺并发跑
任务监控 实时看运行状态、成功率、耗时
任务管理 启停、重跑、暂停单个流程
云元素库 团队共享稳定元素，降低单人维护成本
MCP 管理 接入模型上下文协议，给流程接 AI 能力

社区版没有这些集中能力，定时要靠系统计划任务 + 启动流程的曲线方案。面试被问「企业版值不值」，答：多人协作、统一调度监控、合规私有化，是团队规模化的前提。

1.6 影刀流程调试与排错思路

现象 排查顺序
元素找不到 看是否 iframe/弹窗 → 元素是否改版 → 用 AI 辅助定位重拾
运行卡住 看日志卡在哪步 → 是否等待超时 → 是否弹窗拦截
数据错 看字段映射 → 解析逻辑 → 去重键是否唯一
定时没跑 社区版看系统计划任务是否触发 → 企业版看控制台任务状态
登录失效 token/cookie 是否过期 → 重登流程是否通 → 转人工

排错铁律：先看运行日志和错误列表，再决定改选择器还是改逻辑，不盲改。

二、RPA 工程化与稳定性

这章最能显专业。面试官看的是你把「能跑」的脚本做成「敢放生产」的系统。

2.1 幂等与幂等键

幂等指同一输入重复执行，结果一致、不产生副作用（重复下单、重复付款、重复写 Excel 行都不该发生）。

要点 做法
幂等键 用业务唯一键做去重，订单下载用订单号，付款回传用交易流水号
幂等表/集合 处理前先查「已处理集合」（数据库表或本地 set/文件），命中就跳过，没命中就处理并写入
写 Excel 按订单号做合并去重，已存在的行更新而非追加
失败重跑 重跑整批时，已成功的行靠幂等键跳过，不会重复落库

2.2 重试与退避

网络抖动、临时弹窗、页面加载慢都会造成瞬时失败，重试是标配，但要防「重试风暴」。

策略 说明
指数退避 间隔随次数指数增长：1s、2s、4s、8s
加抖动 在退避基础上加随机量，避免多个机器人同时重试撞车
上限 设最大重试次数（如 5 次），超过转人工/告警，不无限重试
只对瞬时错重试 网络超时、元素暂未出现可重试；业务校验失败、数据错误不该重试

2.3 断点续跑与检查点

长流程跑了 80% 崩了，不该从头来。记录已处理游标/检查点，失败从中断处继续。

检查点类型 例子
已抓页码 分页抓取记下当前页，重启从该页继续
已处理主键 订单号集合持久化到文件/数据库，续跑跳过
阶段标记 下载完成→清洗完成→写入完成，每阶段落一个状态

2.4 UI 选择器脆弱性与缓解

录制生成的 XPath/CSS 易因前端改版、动态 id、iframe、懒加载失效，这是 RPA 最常见的半夜失败原因。

脆弱来源 缓解
动态 id 改用稳定属性：data-*、文本、相对锚点、相邻稳定元素
前端改版 元素锚点 + AI 辅助定位，减少裸 XPath 依赖
iframe/弹窗 显式切 iframe、等待弹窗出现再操作
懒加载 滚动到位再拾取，配合等待策略
登录态失效 token/cookie 复用，失效才重新登录，避免每次验证码

2.5 异常分层

别用一个大 try 包住全流程。按层捕获，每层给不同处理。

层 典型异常 处理
UI 层 元素未找到、弹窗 等待重试、AI 定位重拾、截图
IO 层 网络超时、HTTP 错 退避重试、熔断
数据层 字段缺失、校验失败 记录脏数据、跳过并告警
全局兜底 未捕获异常 截图 + 告警 + 人工兜底，绝不静默吞错

2.6 日志结构化与告警

关键节点记结构化日志：时间/步骤/输入/输出/耗时。失败自动截图，异常推送到钉钉/邮件/Webhook。

日志不打印敏感信息（账号密码、token、身份证）。

2.7 调度

场景 方案
轻量单机 系统 cron / Windows 任务计划
Python 内 APScheduler 定时；Celery（beat + worker）做分布式
企业 RPA 控制台集中调度、机器人管理、任务监控
云原生 容器 + K8s CronJob

APScheduler、Celery 是真实存在的库，能直接说名字。

2.8 并发与资源冲突

多机器人同时跑同一 Excel、同一账号会冲突。

冲突 解法
同文件写 文件锁、写前备份、串行化
同账号并发 账号分片，一个账号一个机器人
重复处理 工作队列 + 幂等表去重

2.9 版本与灰度

流程版本化（Git 或控制台版本），先小流量/单店铺验证再全量，准备回滚预案。改了选择器或字段映射，先在测试店铺跑通再推生产。

2.10 上线验收与每日冒烟

上线前在仿真/小批量数据跑回归，核对输出与手工结果一致，记通过率。建「冒烟流程」每日晨间校验：抽几条数据跑一遍核心链路，失败即告警。

2.11 合规边界

只做业务授权范围内的自动化。不绕过平台验证码/风控、不爬禁止数据、遵守 robots 与平台 API 条款。验证码优先走官方 API 或人工兜底，避免对抗式绕过。

问法 一句话答 追问
怎么保证 RPA 不重复处理 用业务唯一键做幂等，处理前查已处理集合，命中跳过 集合存哪
半夜跑失败怎么发现 失败截图 + 钉钉告警 + 断点续跑 + 晨间冒烟 重跑会不会重复下单
UI 老失效怎么办 用稳定属性定位、AI 辅助、降低对 UI 依赖，优先 API 没有 API 呢

2.13 灰度与回滚

改了选择器或字段映射别全量推。灰度：先单店铺/小批量验证，通过率达标再扩。回滚：控制台或 Git 保留上一版，出问题一键回退。本地脚本用 Git tag 锁版本。

阶段 动作

五、AI 应用（JD 加分项）

5.1 用 LLM 辅助编程的真实工作流

需求拆解 → 生成代码 → review（人工 + lint/test）→ 补单测 → 跑通 → 写文档。ChatGPT/Claude/Gemini 用来做调研、排错、写文档，但生成代码必须过单测和人工 review 才进库，不是直接贴进生产。

5.2 提示工程要点

清晰角色、任务、上下文、输出格式、约束。Few-shot 给样例。分步骤。让模型先思考（CoT）。避免歧义。给 RPA 写提示时把「可用的指令清单、字段名、输出 schema」写死，减少幻觉。

5.3 Function Calling / Tool Use

模型输出结构化「调用某函数 + 参数」，由宿主执行后把结果回传模型继续推理。这是 Agent 调用真实工具（查库存、发邮件、调 API）的基础。OpenAI/Anthropic/Google 都支持。

5.5 RAG 与评测指标

RAG 流程：文档切分 → embedding 向量化 → 存入向量库 → 召回 top-k → rerank → 拼进 prompt 生成。

指标 含义
Hit@k 前 k 个结果里是否命中相关内容
Recall@k 前 k 个结果召回的相关占比
MRR 首个相关结果排名倒数的均值
NDCG 考虑排序位置的增益

5.6 幻觉与护栏

幻觉是模型编造不实内容。缓解：RAG 给据、引用来源、约束输出、人工复核。护栏：输入校验、输出过滤、权限最小化、限流。

5.7 成本控制

缓存重复请求、按任务选小模型、限制 token、批量调用。长文本摘要用小模型，复杂推理用大模型。

八、逻辑思维笔试速成（博客空缺）

笔试是逻辑选择题 + 主观题。下面六类套路练熟，选择题不慌。

8.1 数字推理

题型识别：给一串数求下一个。套路：先算相邻差/比，再看平方/立方/递推/隔项。

  1. 2,5,8,11,? → 14（等差 +3）
  2. 3,6,12,24,? → 48（等比 ×2）
  3. 1,1,2,3,5,8,? → 13（斐波那契 aₙ=aₙ₋₁+aₙ₋₂）
  4. 1,4,9,16,? → 25（平方 n²）
  5. 2,6,12,20,? → 30（n×(n+1)）

限时：每题不超 40 秒，算不出先跳。

8.2 图形推理

题型识别：给图找规律。套路：旋转/翻转/平移、数元素个数/种类、对称/封闭/笔画、叠加求同求异、位置遍历。

  1. 每行图形依次旋转 90° → 缺失图是上一图再顺时针转 90°。
  2. ○个数 1,2,3,4 → 下一图 5 个○。
  3. 轴对称→中心对称→既是 → 按对称类型推进。
  4. 两图叠加去同存异 → 套规则得结果图。
  5. 小图形在大框内顺时针移动 → 按位置规律定位。

8.3 类比推理

题型识别：A : B = C : ?。套路：先定关系类型（功能/场所/组成/种属/反义/因果），再匹配。

  1. 医生 : 医院 = 教师 : 学校（职业:场所）
  2. 笔 : 写字 = 刀 : 切割（工具:功能）
  3. 苹果 : 水果 = 玫瑰 : 花卉（种:属）
  4. 部分 : 整体 = 叶 : 树（组成）
  5. 冷 : 热 = 静 : 动（反义）

8.4 逻辑判断

题型识别：充分必要、真假话、矛盾、三段论。套路：充分必要别颠倒。真假话用假设法/矛盾法。三段论看中项。

  1. 「下雨→地湿」。地湿了能推出下雨吗？→ 不能（肯定后件不成立）。
  2. A→B 中 A 是 B 的充分条件，B 是 A 的必要条件。
  3. 甲乙丙一人真两人假：「甲说乙假，乙说丙假，丙说甲乙都假」。→ 乙真（假设法逐一验证，仅乙真自洽）。
  4. 「所有鸟会飞」「有的鸟不会飞」→ 矛盾关系，必一真一假。
  5. 所有人会死，苏格拉底是人 → 苏格拉底会死（有效三段论）。

8.5 资料分析

题型识别：给数据算增长率/占比/平均。套路：先定位指标定义再算。

  1. 去年 100 万今年 120 万 → 增长率 **20%**（(120-100)/100）。
  2. A 占 30%、总量 500 → A=150。
  3. 同比=与上年同期比；环比=与上一周期比。
  4. 平均数=总量/个数；中位数=排序后中间值。
  5. 部分增速 > 整体增速 → 比重上升（增速差决定升降）。

8.6 情境判断（业务面常见）

题型识别：给工作场景问你怎么处理。套路：先止损/告警，再定位根因，再加固（幂等/备份/监控）。

  1. 流程半夜跑失败、业务早上才发现 → 加失败告警（钉钉/邮件）+ 自动重试 + 断点续跑 + 晨间冒烟。
  2. 两平台字段含义不同导致对账差异 → 建字段映射表 + 数据校验 + 差异告警人工确认。
  3. RPA 误删数据 → 操作前备份/软删除 + 幂等 + 权限最小化 + 审计日志。
  4. 平台限流导致抓取失败 → 退避重试 + 感知 429 降速 + 分时段错峰调度。
  5. 同事误改选择器导致全流程挂 → 版本回滚 + 灰度发布 + 关键选择器代码评审。

8.7 笔试时间不够怎么取舍

先抢「确定性高分」：数字/类比/资料分析这类有固定套路的题优先做。图形和情境判断卡住就跳。主观题别空着，按第九章模板写骨架就能拿分。选择题不会用排除法，别在单题磨超过 1 分钟。

8.8 各题型限时分配（笔试 60 分钟示例）

题型 建议题量占比 单题时限 策略
数字/类比/资料 40% 30-40 秒 有套路的先拿满
图形推理 20% 60 秒 卡住先跳，最后回头
逻辑判断 20% 60-90 秒 假设法/矛盾法稳做
情境判断 10% 90 秒 按「止损→根因→加固」答
主观题 10% 留 8-10 分钟 按第九章骨架写，不空

总原则：会的先写、不确定的跳、主观不空、单题不磨超过 1 分钟。

8.9 常见笔试误区

误区 正确做法
一道图形题磨 5 分钟 卡住先跳，最后回头，保其他确定分
主观题空着 按第九章骨架写，有结构就有分
逻辑判断靠语感 用假设法/矛盾法，别凭感觉
资料分析先算大数 先定位指标定义，再算，避免单位错
类比硬凑 先定关系类型（功能/场所/种属/反义），再匹配

笔试考的是「在规定时间里拿到最多确定分」，不是每题做对。策略比单题正确率更重要。

九、主观题模板（笔试主观题 + 面试开放题共用）

9.1 RPA 流程设计题

题目：「每天从 3 个平台后台下载订单汇总到 Excel」。答题骨架：

  1. 需求澄清：哪 3 个平台、有无 API、去重键（订单号）、输出 Excel 格式/路径、频率时限。
  2. 方案选型：先查 3 平台是否开放 API / 已有 ERP 对接；无 API 才用影刀 UI 自动化。
  3. 流程设计：登录（token/cookie 复用避免每次验证码）→ 分页抓取 → 统一字段映射 → 按订单号幂等合并去重 → 写 Excel（openpyxl）→ 失败重试 + 退避 → 完成通知。
  4. 稳定性：元素锚点/AI 定位、等待、异常捕获截图、断点续跑（记已抓页）。
  5. 调度：APScheduler/cron/影刀控制台定时；并发用账号分片防冲突。
  6. 验收：小批量对账无误再全量；每日冒烟。

9.2 需求澄清题

结构：5W1H + 边界。谁用、做什么、数据从哪到哪、频率、异常怎么算、成功标准、合规边界。先问清再动手，不急着写代码。

9.3 异常处理题

结构：分层 + 兜底。UI 层（元素/弹窗）→ IO 层（网络/超时）→ 数据层（校验）→ 全局（截图 + 告警 + 人工兜底）。强调幂等，避免重复下单/重复付款。

9.4 项目复盘题

STAR 精简：

  • S 背景：重复手工任务、易错。
  • T 目标：自动化 + 提效 + 降错。
  • A 行动：选型、设计、幂等、监控。
  • R 结果：没数据就写「效率显著提升、错误率下降」，不编造数字；有数据再量化。
  • 改进：下一步接 API、加告警。

9.5 文档与培训题

模块 要点
操作手册要素 前置条件（登录/权限）、分步截图、常见报错与自救、联系人/反馈渠道
培训流程 录屏 + 现场跟做一遍 + 留 Q&A 文档
受众导向 不用技术黑话，先讲「能帮你省什么」
边界说明 哪些自动处理、哪些要人工介入（如验证码）

9.6 职业规划题

短期：把影刀/RPA 工程化和 Python 基础打牢，独立交付一两个跨境场景自动化。中期：掌握 AI 辅助（LLM/Agent）把流程提效，研究 OpenClaw 等新技术。长期：成为能设计 RPA + AI 方案的自动化工程师，覆盖需求分析到上线运维。

9.7 反问环节清单

反问 目的
团队现在用影刀还是其他 RPA，版本企业版吗 确认技术栈与权限
跨境场景里最痛的自动化点是哪个 展示业务理解
这个实习岗的脚本会进生产吗，有 review 机制吗 确认工程严谨度
团队怎么看 AI（LLM/Agent）在 RPA 里的角色 对齐加分项
问法 一句话答 追问
设计题怎么答最稳 先澄清需求再选型，API 优先，再讲幂等/重试/调度/验收 没 API 怎么办
复盘没数据怎么写 写「效率显著提升、错误率下降」，不编数字 有数据呢
给业务培训注意什么 不讲黑话，先讲省什么，附截图和自救指南 他们不会用怎么办

9.8 安全与权限题

答题骨架：权限最小化（机器人只给必要账号/目录）、凭证不硬编码（走环境变量/密钥管理）、操作留审计日志、敏感字段不进日志、越权操作要审批。RPA 跑业务账号要和生产账号隔离，测试用测试店铺。

9.9 数据质量题

答题骨架：入库前校验（必填、类型、范围、格式）、去重（幂等键）、异常值隔离（脏数据入差异表不进主表）、对账（和源系统比数量与金额）、可追溯（每批带批次号和时间戳）。数据质量差比流程跑不通更危险，因为错数据会静默流进报表。

问法 一句话答 追问
自动化怎么保数据质量 入库前校验 + 幂等去重 + 脏数据隔离 + 对账 对账不平怎么办
RPA 账号怎么管 权限最小化、凭证不硬编码、测试生产隔离 凭证泄露谁负责
脏数据怎么处理 进差异表隔离，不污染主表，告警人工确认 误删了能恢复吗

十、项目追问链

把三个项目分别映射到本岗追问路径。STAR 精简，每条追问给一句话答法 + 一条翻车点。

10.1 踏浪 AI 中心（RAG 评测 / 分层会话记忆 / 单测有效性 / 变异验证）

STAR 精简：S 团队要建 RAG 知识库问答。T 保证回答质量与记忆连贯。A 做 RAG 评测、分层会话记忆、单测有效性、变异验证。R 单测能抓住改坏实现、记忆分层可用（无数字不编）。

追问 一句话答法 翻车点（不要说）
RAG 怎么评测 用 Hit@k/Recall@k/MRR 看召回质量 只说「准确率」不提指标
分层记忆怎么测 短期摘要 + 长期事实两层，测四类场景 把两层说成一层
单测有效性怎么证明 断言能抓住真实改动，空洞断言（is not None）重退 说「跑通就是有用」
变异验证是什么 注入变异看用例是否变红，验证真有效 和单测混为一谈
和本岗关系 RAG 评测思路能迁移到 RPA 异常日志归类 扯远不落地

10.2 VidDigest（Python + FastAPI + SQLite + SSE + Vue3）

STAR 精简：S 视频解析要加 AI 摘要。T 保证接口与流式输出稳。A 用 pytest 分库建用例、SSE 契约逐字段断言、密钥扫描、429 断言。R 回归能抓改动（无数字不编）。

追问 一句话答法 翻车点（不要说）
怎么测 SSE 按契约逐字段断 event/data/结束标记，不只看有无返回 只断「有返回」
分库用例怎么写 每用例独立临时库跑完销毁，避免互相污染 共用一个库导致串
密钥扫描查什么 扫代码里硬编码 token/密钥，进 CI 拦截 说没做过
429 怎么断言 触发限流断言返回 429 且有重试提示 忽略限流场景
和 RPA 关系 FastAPI 可做 RPA 结果回调服务，思路相通 否认后端经验

10.3 Vapor 优选（SpringBoot + MySQL + Redis + Lua + Kafka 秒杀）

STAR 精简：S 秒杀要防超卖和重复下单。T 保证一致性与幂等。A Redis+Lua 原子扣减、幂等、先更库后删缓存 + MQ 补偿。R 并发不超卖（无数字不编）。

追问 一句话答法 翻车点（不要说）
不超卖怎么实现 Redis+Lua 把资格校验与扣减压成一次原子执行 先查后扣不原子
重复下单怎么防 幂等键 + Lua 原子校验，超时重试只成一单 只说「加锁」
缓存一致性 先更库后删缓存 + MQ 补偿保证最终一致 只删缓存不补偿
Kafka 干什么 异步解耦下单与后续处理，削峰 说不清为什么用
和 RPA 关系 高并发一致性设计可迁移到订单同步防重复 认为用不上 Java

10.4 三个项目串成一条 RPA 故事线

面试时把三个项目讲成一条能力链，比孤立罗列更有说服力：

  1. Vapor 优选证明你会写「稳的后端」：一致性与幂等、并发不超卖，这是 RPA 落生产前的工程底子。
  2. VidDigest证明你会写「带契约的接口与测试」：SSE 逐字段断言、分库用例、429 断言，这是自动化脚本单测与校验的能力。
  3. 踏浪 AI 中心证明你会「用 AI 提效并验证 AI」：RAG 评测、单测有效性、变异验证，这是把 LLM 接进 RPA 前的评测与护栏能力。

一句话收尾：「我做过一致性的后端、带契约测试的接口、和 AI 评测，这三块正好对应 RPA 工程化里最难的落地、验证、和 AI 提效。」

问法 一句话答 追问
三个项目有什么关系 一条能力链：稳的后端 + 带测试的接口 + AI 评测 哪个最贴本岗
没跨境经验怎办 用一致性和测试经验迁移到订单同步防重复 业务不懂呢（先学 API）

十一、明天进门前 20 分钟

11.1 极简清单（最容易忘的点）

  1. RPA 适用边界：稳定规则 + 高频 + 有界面无 API。
  2. API 优先、UI 兜底。
  3. 影刀社区版免费但非商业、有运行时长限制；xbot 不能 pip 装。
  4. 幂等键用业务唯一键，处理前查已处理集合。
  5. 重试加指数退避 + 抖动 + 上限。
  6. 断点续跑靠检查点（页码/主键/阶段）。
  7. 异常分层：UI→IO→数据→全局兜底截图告警。
  8. UI 选择器用稳定属性 + AI 辅助，降低脆弱性。
  9. 合规：不绕验证码/风控，只做授权内。
  10. GIL：IO 密集多线程有效，CPU 密集用 multiprocessing。
  11. 3.13 free-threaded 是实验性，不上生产。
  12. 3.12 PEP 695 泛型写法 def f[T](x: T) -> T。
  13. Java 21 无 String Templates（已撤销），有虚拟线程/record/sealed。
  14. checked vs unchecked：IOException 强制处理，RuntimeException 不强制。
  15. MCP 是 2024-11-25 开源标准，影刀/UiPath 已接入。
  16. RAG 指标：Hit@k/Recall@k/MRR。
  17. LLM 提效 RPA 四法：生成流程、异常归类、OCR+LLM 抽单据、视觉兜底。
  18. 覆盖率别追 100%，优先核心逻辑与异常分支。
  19. OpenClaw 是真实开源 AI Agent 框架，不编内部绑定。
  20. 不会的就诚实说不会，给相邻经验 + 推导。

  • 我还做过秒杀后端，用 Redis+Lua 做原子扣减和幂等，对一致性和健壮性比较在意。

11.4 进场前心态与节奏

笔试时先扫一遍题型分布，确定高分确定题先做。主观题不空，按第九章骨架写。技术面被问到不会的点，用「诚实边界」那章的话术：说不会、给相邻经验、现场推导。业务面多聊跨境场景和你做过的项目，少背概念。

节奏：笔试前翻第八章。技术面前把第二、五、六章话术背上。进门先看第十一章清单。把「我会做、我做过、我能落地」三个信号稳定传出去，比每个知识点都答满分更重要。

十二、诚实边界

不会的怎么答：明确说不会，给相邻经验（「这个我没直接用过，但我做过类似的 X」），再现场推导思路（「如果是我，会先查 API 文档，再……」）。不编造影刀内部 API 名（如 xbot.orders.download() 这类没公开的方法）和业务数字（订单量、节省工时等没核实的不写）。

纠偏清单（面试别踩）：

错误说法 正确事实
GIL 让 Python 完全不能并发 IO 密集多线程有效，CPU 密集用 multiprocessing，3.13 实验性无 GIL
RPA 只能调 API / 只能点 UI RPA 含 UI、API、数据表、文件；优先 API，UI 是补充
Java 21 有 String Templates 已撤销，不是正式特性
xbot 能 pip 装 影刀内置包，仅流程内可用
OpenClaw 是骗局 2026 真实开源 AI Agent 框架
n8n/Dify/Coze 就是 RPA 是 AI 工作流/Agent 编排，不操作 Windows 界面
3.13 free-threaded 可上生产 实验性，生产谨慎
RPA 能绕验证码/风控 合规边界，不对抗安全机制

收尾：这份笔记偏「能答得上、聊得开」。进门先看第十一章，笔试前翻第八章，技术面把第二、五、六章的话术背上。和上一份软件测试笔记的关系是理论归理论、本文归工程化与 RPA 实战。祝你明天顺利。
