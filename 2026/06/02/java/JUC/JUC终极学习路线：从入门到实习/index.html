🎯 前言：JUC不是API手册，是并发思维的”心法”

为什么大学生必须学JUC？

校招面试 高频考点，命中率90%+ 算法题做出来也会被刷
入职初期 看懂部门代码的前提 CR时连”这行锁干嘛的”都问不出

🎯 核心心法：JUC的”三件套思维”

几乎所有JUC问题都能归到这三件事：

心法 核心问题 涉及知识域 真实场景举例
🔒 互斥 同一时刻只有一个线程能进 synchronized、Lock、AQS 账户扣款、库存扣减
🔄 协作 线程间如何等待/通知 wait/notify、Condition、CountDownLatch 主线程等子线程完成、限流
📡 共享 多线程如何安全访问同一份数据 volatile、CAS、并发容器、ThreadLocal 缓存、用户上下文、计数器

💡 面试黄金句式：回答任何并发问题，先说一句”这个场景本质是『互斥/协作/共享』问题“，然后展开，能瞬间提升逼格。

🧪 横向对比表：常见API到底该选谁？

锁的选择

场景 推荐方案 原因 备注
简单的临界区 synchronized 编译期优化好，简洁 详见§2.1
需要可中断/超时 ReentrantLock.lockInterruptibly() synchronized不支持 §2.3
读多写少 ReentrantReadWriteLock 读写分离提升性能 §2.4
极致性能 StampedLock (Java 8+) 乐观读无锁 §2.4
跨JVM互斥 分布式锁 (Redisson/Zookeeper) 不在JUC范畴 §1.1 案例

并发容器的选择

场景 推荐容器 不推荐 原因
高频读 + 少量写 ConcurrentHashMap Hashtable/Collections.synchronizedMap 分段锁/无锁读，吞吐高10倍以上
读极多 + 写极少 CopyOnWriteArrayList/Set Collections.synchronizedList 写时复制，读全无锁
排序+范围查询 ConcurrentSkipListMap/Set ConcurrentHashMap 跳表天然有序
阻塞队列 ArrayBlockingQueue/LinkedBlockingQueue ConcurrentLinkedQueue 是否需要阻塞/有界是核心
优先级任务 PriorityBlockingQueue 视情况 注意无界可能OOM

线程池的选择

场景 推荐线程池 核心参数 注意事项
CPU密集型 newFixedThreadPool 核心数=Ncpu+1 避免线程上下文切换
IO密集型 newFixedThreadPool 核心数=2*Ncpu 看具体IO耗时再调
短任务+大量 WorkStealingPool (ForkJoinPool) - 任务规模大才有优势
定时任务 ScheduledThreadPoolExecutor - 注意scheduleAtFixedRate的坑
高并发Web 自定义 + 队列限流 见第6章 必须有界队列+拒绝策略
Java 21+ Executors.newVirtualThreadPerTaskExecutor() 阻塞友好 详见第7章

工具类的选择

目标 选择 关键API
等所有任务完成 CountDownLatch countDown() / await()
等所有任务完成 + 可复用 CyclicBarrier await()
控制并发度 Semaphore acquire() / release()
多步骤异步编排 CompletableFuture thenCompose / thenCombine
多生产者-单消费者 BlockingQueue put() / take()

🎯 面试官的”三阶段考察法”

第一梯队：必问题（校招命中率95%）

🎯 这些题答不上 = 直接挂。

题目 标准答案要点 难度
synchronized 和 ReentrantLock 的区别？ 6点：实现/可重入/可中断/公平/条件/性能 ⭐⭐
volatile 的作用？能保证原子性吗？ 可见性+禁止重排序，不能保证原子性 ⭐
HashMap 为什么线程不安全？ 1.7头插死循环；1.8尾插数据覆盖 ⭐⭐
ConcurrentHashMap 的原理？ 1.7分段锁；1.8 CAS+synchronized+红黑树 ⭐⭐⭐
线程池的7个参数？拒绝策略？ core/max/keepAlive/unit/workQueue/threadFactory/handler ⭐⭐
线程池的执行流程？ 提交→核心→队列→最大→拒绝策略 ⭐⭐
线程池怎么设置参数？ CPU密集型 N+1；IO密集型 2N ⭐⭐
ThreadLocal 的原理？内存泄漏？ ThreadLocalMap+弱引用+清理 ⭐⭐⭐
wait() 和 sleep() 的区别？ 锁释放/不释放；所属类/中断响应 ⭐
Java 内存模型？happens-before 是什么？ JMM定义；8条规则 ⭐⭐⭐

💎 加分回答模板（以”线程池参数”为例）

普通回答（❌）：”corePoolSize是核心线程数，maximumPoolSize是最大线程数…”
加分回答（✅）：
“线程池参数有7个，包括corePoolSize、maximumPoolSize、keepAliveTime、unit、workQueue、threadFactory、handler。我之前在做XX项目时遇到一个坑：核心线程数设成CPU数，但队列用了无界LinkedBlockingQueue，结果高峰期任务堆积到几十万，触发了OOM。后来改成有界队列+CallerRunsPolicy做了限流，业务峰值QPS从8000降回5000但服务稳定了。这个经历让我意识到：线程池参数不是看公式，而是根据业务特点+压测数据调出来的。”

附录B：常见并发陷阱Top 10

⚠️ Top 10 必知陷阱

# 陷阱 表现 解决方案
1 SimpleDateFormat 非线程安全 多线程下日期错乱 用 DateTimeFormatter 或 synchronized
2 Executors.newFixedThreadPool 队列无界 任务堆积OOM 用 ThreadPoolExecutor 自定义有界队列
3 Executors.newCachedThreadPool 线程数无界 创建过多线程OOM 同上
4 ThreadLocal 不清理 内存泄漏 用 try-finally 调 remove()
5 synchronized 用 String/Integer 作锁 字符串常量池导致锁串了 用 new Object()
6 volatile 用于复合操作 i++ 仍然非原子 用 AtomicInteger
7 锁内调用外部方法 死锁/超时 缩小锁范围
8 双重检查锁定用 Lazy 写法 实例可见性问题 用 volatile 或 Holder 模式
9 异步任务里抛异常没处理 异常”消失” CompletableFuture.exceptionally
10 锁对象本身变化（如集合） 锁失效 锁对象用 final 修饰
