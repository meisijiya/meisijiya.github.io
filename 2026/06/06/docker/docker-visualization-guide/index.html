🧐 第一章：为什么 Docker 还需要”图形化”

1.1 痛点：纯命令行的”最后一公里”

当你的项目从 1 个容器涨到 5 个、10 个，就会遇到这些场景：

场景 纯 CLI 怎么做 图形化怎么做
看某个容器日志 docker logs -f --tail 200 容器ID 浏览器点开容器 → “Logs” 标签 → 实时滚动
看容器 CPU/内存占用 docker stats 一闪而过 Netdata 实时折线图（1 秒粒度）
改环境变量重启 docker run -e KEY=VAL ... 一长串 表单填 key-value，点”Deploy”
给同学开个账号 手动建用户、SSH 密钥、配 sudo Portainer 加个用户、配 RBAC
毕设答辩前展示 SSH 进去敲一堆命令 Portainer 首页直接打开给评委看
服务器半夜挂了 设 cron + 邮件 Netdata 阈值告警 + Slack 通知

💡 核心观点：CLI 是”开发期”工具，GUI 是”运维期”工具。毕设答辩、给导师汇报、管理实验室多人共用的服务器，图形化是不可或缺的。

4.2 模板 2：nginx + Flask + MySQL（全栈教学黄金模板）

适用：理解”前后端分离 + 反向代理 + 健康检查 + 密钥管理”的完整范例（强烈推荐第二个就跑这个）

完整文件（来源）：

5 个关键设计点（这个模板是教学宝库）：

  1. **healthcheck + condition: service_healthy**：传统 depends_on 只等容器”启动”，不等”就绪”；加上 healthcheck 才能保证 backend 起来时 DB 已能接受连接。

  2. **secrets: db-password**：密码放文件、不放环境变量。环境变量 docker inspect 就能看到，secrets 至少要进容器才能看。

  3. **双网络 backnet + frontnet**：DB 在 backnet 看不到 proxy，proxy 在 frontnet 看不到 DB。最小权限原则的实战范例。

  4. **expose vs ports**：expose 只在容器间可见，ports 暴露到宿主机。DB 用 expose、proxy/backend 用 ports。

  5. **build: target: builder**：多阶段构建。builder 阶段装编译依赖，最终镜像不含。完整 Dockerfile 在 backend/Dockerfile（示例）。

🖱️ 第五章：Portainer 完整部署 + UI 中文对照

5.1 Portainer 是什么？

Portainer CE（Community Edition） 是一个单容器形态的 Docker 图形化管理平台，定位是”让不会写命令的人也能用 Docker”。GitHub 38k+ star、37.6k fork、2.8k fork 数据来源。

📌 官方说明（README 第 5-9 行）：

“Portainer Community Edition is a lightweight service delivery platform for containerized applications that can be used to manage Docker, Swarm, Kubernetes and ACI environments. It is designed to be as simple to deploy as it is to use.”

5.5 Portainer UI 中文布局对照（截图级描述）

进入主页后，左侧导航长这样（实际是英文）：

5.5.1 📦 Containers（容器管理）— 最高频使用

顶部按钮：

  • + Add container：弹出表单，创建新容器
    • Name: 容器名
    • Image: 镜像名（如 nginx:alpine）
    • Port mapping: 点 “+ publish a new network port”
    • 下方 Advanced settings（滚动后看到）：Env、Volumes、Network、Restart policy、Healthcheck
  • 🗑️ Remove：批量删除（选中后激活）

列表字段：

列 含义
Name 容器名（点进去看详情）
State ● Running / ● Stopped / ● Healthy / ● Unhealthy
Quick actions ▶️ 启动 / ⏸️ 停止 / 🔄 重启 / 📜 日志 / 🖥️ 控制台 / 🗑️ 删除

容器详情页（点容器名进入）有 5 个 tab：

  • Logs：实时日志（”Follow logs” 开关打开）
  • Inspect：完整 JSON 配置（等同 docker inspect）
  • Stats：CPU/内存/网络实时折线（比 docker stats 好看 10 倍）
  • Console：/bin/sh 或 /bin/bash 命令行（**有终端界面，不用 docker exec**）
  • Environment：环境变量（只读）

5.5.2 📚 Stacks（Compose 部署）— 第二个高频

顶部按钮：

  • + Add stack：弹出大表单
    • Name: stack 名（决定文件夹/项目名）
    • Build method:
      • Web editor: 浏览器里直接粘贴 compose.yaml 内容（最简单）
      • Upload: 上传 .yml 文件
      • Repository: 填 Git 仓库 URL（自动 clone 部署）
      • Custom template: 用预定义模板
    • Environment variables: 点 “Add environment variable” 加 key-value
    • 点底部 Deploy the stack 即可

列表字段：

列 含义
Name stack 名
Status 容器总数 / 多少个 healthy
Actions ▶️ 启动 / ⏸️ 停止 / 🔄 重新部署 / 📝 编辑 / 🗑️ 删除

💡 杀手级特性：你可以把 awesome-compose 仓库里任意一个 compose.yaml 内容复制粘贴到 “Web editor” → 起个 stack 名 → Deploy。比命令行 docker compose up -d 还快，而且可以直接在网页上改环境变量、点 “Update” 重启。

5.5.3 🖼️ Images（镜像管理）

  • Pull image: 顶部输入 镜像名:tag → 拉取
  • 列表显示本机所有镜像（Name / Tag / Size / Created）
  • 点镜像名 → 看用了哪些容器、可直接起容器

5.5.4 💾 Volumes / 🌐 Networks

这两个 tab 让你不用 docker volume / docker network 命令，可视化地：

  • 看所有卷/网络
  • 创建新的（填名字、选 driver）
  • 删除孤儿卷/未用网络
  • 绑定到容器

5.5.5 📋 Templates（应用模板）

Portainer 内置一组”应用模板”，一键部署常见服务：

  • NGINX、MySQL、Redis、WordPress、Portainer Agent
  • 点模板 → 填表单（容器名、端口、密码）→ Deploy
  • 比 Docker Hub 的 “Run” 按钮还方便（因为所有配置都在 Portainer 里统一管理）

5.5.6 👥 Users / 🌍 Environments（多人协作 + 远程主机）

  • Users: 给实验室同学开账号（CE 限制基础 RBAC）
  • Environments: 加远程 Docker 主机（通过 Portainer Agent）
    • + Add environment → 选 Agent → 填远程主机 IP + Port（默认 9001）
    • 远程主机上要起一个 portainer/agent 容器
    • 加完后在左侧切 “local” / “remote-server-1” 就能切换管理目标
  • 典型场景：你的笔记本 Portainer 管理本机 + 实验室服务器（远程 Agent）

📊 第六章：Netdata 完整部署 + 容器监控 + 告警

6.1 Netdata 是什么？

Netdata 是一个 1 秒粒度的实时性能监控面板，用浏览器打开就能看到 CPU/内存/磁盘/网络/容器/数据库等指标的实时折线图。GitHub 78.9k star、6.4k fork 数据来源。

📌 官方说明（README 第 8-14 行）：

“You can create a new Agent container with docker run or docker-compose, then access the dashboard at http://NODE:19999.”

Netdata 的 3 个核心优势（对比 Prometheus）：

维度 Netdata Prometheus + Grafana
部署复杂度 一行 docker run / 一份 compose 多个组件 + PromQL + 配置告警规则
采样间隔 1 秒 15 秒（默认）
仪表盘 开箱即用，800+ 图表自动出现 自己画（或者找社区 dashboard）
告警 内置 300+ 阈值告警 写 PromQL + Alertmanager 配置
适合场景 单机/小集群实时观测 大规模时序数据存储 + 复杂告警

💡 大学生建议：毕设/课设/实验室服务器 → 直接用 Netdata。Prometheus 等到真需要管多台服务器再用。

6.2 Netdata 的”特权”与”挂载”要求

📌 官方原话（README 第 16-27 行）：

“The Netdata container requires specific privileges and mounts to provide full monitoring capabilities equivalent to a direct host installation.”

两个关键要求：

类型 项 作用
Capabilities SYS_PTRACE 监控进程（ps、进程名解析）
Capabilities SYS_ADMIN cgroups 网络接口映射
PID 模式 pid: host 看到主机的所有进程（不写就要加 init: true）
网络模式 network_mode: host 主机网络栈监控 + 监听 19999 端口
挂载 /proc:/host/proc:ro 主机 CPU/内存/进程
挂载 /sys:/host/sys:ro cgroups、网络接口
挂载 /var/run/docker.sock:/var/run/docker.sock:ro 关键：监控 Docker 容器
挂载 /:/host/root:ro,rslave 主机磁盘空间
挂载 /etc/os-release:/host/etc/os-release:ro 识别主机系统

6.10 Netdata vs Portainer 监控功能对比

维度 Portainer Netdata

🔧 第八章：常见问题排查（FAQ）

Q1：Portainer 启动后访问 9000 端口拒绝连接

原因：容器没起来 / 端口被占 / 防火墙

Q2：Portainer 5 分钟内没设账号，被锁

解决：删除数据卷重来

Q3：Netdata 启动报 “permission denied” 挂载错误

原因：SELinux / AppArmor 阻止挂载

Q4：Netdata 看不到 Docker 容器

原因：/var/run/docker.sock 没挂载进 Netdata

Q5：awesome-compose 模板跑起来后端口被占用

解决：改 compose 文件的 ports 配置

Q6：Docker Compose v1 (docker-compose) 和 v2 (docker compose) 区别？

特性 v1 (docker-compose) v2 (docker compose)
写法 短横线 空格
状态 ⚠️ 已废弃 ✅ 当前
安装 Python pip Docker 插件
卸载 卸载 Python 包 apt remove docker-compose-plugin

📌 本教程全部用 v2 写法（docker compose，无短横线）。

Q7：实验室服务器只有 IPv6 公网，Portainer 怎么访问？

Q8：为什么 Netdata 这么吃内存？

答：Netdata 默认 1 秒采样 ×800+ 指标 ×保留 1-3 天的内存数据。

  • 单机：吃 200-500MB 内存（合理）
  • 想减肥：调小 dbengine multihost disk space MB（默认 256）到 64
