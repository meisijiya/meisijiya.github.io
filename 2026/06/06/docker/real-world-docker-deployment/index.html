vaultwarden 是用 Rust 重写的 Bitwarden 兼容服务端（github.com/dani-garcia/vaultwarden，49.6k★）。比官方 Bitwarden 轻量 10 倍，单容器即可跑，SQLite 就够用。

大学生适用场景 🎓

  • 毕设密码管理后台：在实验室 4 人组里共享一套密码，避免明文记在群里
  • CTF / 安全课作业：演示 argon2id 哈希比 bcrypt 慢多少，体会”密码存储不是越快越好”
  • Web 课设学习：vaultwarden 是少见的全栈 Rust Web 项目—— Rocket 框架 + Diesel ORM + SQLite，看完够吹半年
  • 实习面试亮点：”我部署过 Rust 单二进制 Web 服务，知道怎么用 Argon2 哈希密码做管理员鉴权”

常见坑与排错 🐛

  1. DOMAIN 写成 http → 附件下载、邮件链接全坏。反代后必须写 https://
  2. 忘记改 SIGNUPS_ALLOWED=false → 被互联网扫号注册一堆马甲
  3. admin 页面忘关 → 写明文 ADMIN_TOKEN 被人 cat 到镜像日志。必须先 docker run hash 生成 argon2
  4. docker-compose.yml 里 $$argon2id$$ 写成 $$ 转义 → docker compose 会做变量插值，argon2 的 $ 必须写两个（详见 Discussion #6652）

依赖服务 🎯

没有外部依赖。SQLite 文件直接落在 ./vw-data/。这是它能单容器跑的核心原因。

资源要求 💻

  • CPU：单核够用（Rust 静态二进制，< 1% 闲置）
  • 内存：闲置 ~50MB，10 个活跃用户 ~150MB
  • 磁盘：SQLite 库 ~10MB + 附件按需

常见坑与排错 🐛

  1. ⚠️ NFS 文件系统不支持（官方明确警告）：SQLite 的文件锁机制在 NFS 上完全不可靠，会随机数据库损坏。必须用本地 ext4/btrfs/xfs
  2. 升级 v1→v2 没改端口 → v1 默认 3001，v2 也是 3001，没问题；但数据迁移要先备份
  3. Web 端 502 → 检查 UPTIME_KUMA_BIND 没被设成 127.0.0.1
  4. 钉钉/飞书通知收不到 → 通常是 Webhook URL 末尾多了空格/换行，复制粘贴必查

依赖服务 🎯

  • 没有外部依赖（SQLite 嵌入）

资源要求 💻

  • CPU：单核够用，50 个监控项约 5-10% CPU
  • 内存：闲置 ~200MB（Node 基础开销大），每加 50 个监控 + 20-30MB
  • 磁盘：应用 ~150MB，每条历史记录约 200 字节，1 万条 ~2MB

docker/production/Dockerfile 是教科书级多阶段构建：

大学生适用场景 🎓

  • 运维课设展示：”我自己搭了一个 Heroku”——直接进面试谈资
  • 学习 PHP 工业部署：s6-overlay 进程管理 + FPM dynamic 控制 + Cloudflared 集成
  • PaaS 内置教学：看 源码 docker/production/ 理解”如何让 Docker 镜像适合生产”

常见坑与排错 🐛

  1. /data/coolify 权限错 → 容器内 UID 9999 必须能写。chown -R 9999:root /data/coolify && chmod -R 700
  2. 端口 80/443 被占 → Coolify 强制要求这两个端口（HTTP-01 证书签发）。先停 Apache/Nginx
  3. 树莓派 2GB 内存 → 启动时数据库崩溃。官方建议至少 4GB。可以加 swap：fallocate -l 2G /swapfile
  4. acme.json 权限 → Traefik 必须 600，且 owner 是非 root。chmod 600 /data/coolify/proxy/acme.json

依赖服务 🎯

  • Redis 7（缓存 + 队列）
  • Soketi（自建 Pusher 协议，用于 WebSocket 实时通知）
  • Traefik（安装脚本自动启动，反代 + 自动 SSL）

资源要求 💻

  • CPU：2 核起步
  • 内存：4GB 起步（树莓派 4B 8GB 版勉强能跑）
  • 磁盘：20GB+（每个部署的应用都会占空间）

常见坑与排错 🐛

mastodon 是去中心化社交网络（github.com/mastodon/mastodon，49k★），Ruby on Rails + Node.js streaming + Sidekiq 异步任务。这是本文最复杂的范例——光看 docker-compose.yml 就知道什么叫”生产级”。

配套 Dockerfile 要点

Dockerfile 是史诗级多阶段构建，共 6 个 stage：

要点：

  • 6 个 build stage：Node、Ruby、libvips、ffmpeg、Bundler、Precompiler、运行时。终极多阶段构建范本

DB_POOL PG 连接池大小 25

大学生适用场景 🎓

  • 毕设社交网络：Mastodon 本身就是完整社交网络，改皮肤就是新项目（很多大学的”创新创业”项目就这样）
  • 学习 Rails Sidekiq Node.js 三件套：现代 SaaS 的标准后端组合
  • 学习 Docker 高级模式：双网络分段、shm_size、健康检查、internal: true 网络
  • 运维实战课：完整 5 服务+4 卷的工业级编排
  • 面试大杀器：”我部署过联邦社交网络 Mastodon”——含金量极高

常见坑与排错 🐛

  1. LOCAL_DOMAIN 改了就崩 → 联邦身份是写死的域名，改名会让所有 follow 关系全断
  2. POSTGRES_HOST_AUTH_METHOD=trust + 没设 DB_PASS → 启动后 PG 拒绝连接。两个必须配对（trust 模式下 DB_PASS 可以任意）
  3. shm_size 不设 → PG shared_buffers 报错。256MB 是底线
  4. 升级没跑 rails db:migrate → 表结构没升级，新代码连旧表直接 500
  5. 媒体卷 public/system 没共享给 web 和 sidekiq → 用户上传图片只有 web 容器看得到，sidekiq 缩略图失败。两个 service 都必须挂
  6. SMTP_* 没配 → 用户注册收不到验证邮件，管理员看不到自己实例

依赖服务 🎯

  • **PostgreSQL 14+**（必需）
  • **Redis 7+**（必需）
  • Sidekiq（异步任务，内置）
  • Streaming（Node.js WebSocket，内置）
  • Elasticsearch 7（可选，全文搜索）
  • S3 / 本地卷（媒体存储）

资源要求 💻

  • CPU：2 核起步，4 核推荐
  • 内存：4GB 起步（web 进程 1GB+、sidekiq 1GB+、streaming 500MB+、PG/Redis 各 500MB）
  • 磁盘：100GB+（媒体卷是主要占用）

7️⃣ gogs：单 Go 二进制 + s6-overlay 的轻量 Git 服务

项目简介

gogs 是”自托管 GitHub”（github.com/gogs/gogs，47k★），用 Go 写的单二进制 Git 服务。比 GitLab 轻 100 倍——256MB 内存就能跑，老师机也能玩。

完整 docker-compose.yml（来自 awesome-docker-compose.com + 官方 docker hub）

💡 Gogs 也能用 SQLite，直接去掉 db service 就行，体积更小。

配套 Dockerfile 要点

仓库根 Dockerfile 是3 阶段 + s6-overlay：

要点：

  • s6-overlay 做进程管理：PID 1 是 s6-svscan，自动拉起 gogs + sshd + crond，挂了自愈
  • **go build -tags "pam prod"**：编译时启用 PAM 认证（Linux 系统用户认证）
  • **-ldflags -X**：把构建时间/提交 hash 塞进二进制，运行时可通过 /api/v1/version 看到
  • socat 端口转发：自动把 links 的容器端口绑到 localhost（启动脚本里看 create_socat_links）

大学生适用场景 🎓

  • 毕设代码托管：4-6 人组队，自己人跑 gogs，告别”代码在我电脑能跑、老师那跑不了”
  • 课设代码评审：老师可以登录 gogs 看你的每次 commit，省去”演示现场翻历史”
  • 学习 Go 单二进制部署：gogs 编译后 ~50MB 静态二进制，没有运行时依赖——这是 Go 项目的标准形态
  • 学习 s6-overlay 进程管理：比 systemd 简单，比裸 CMD 健壮，K8s Pod 里也常用
  • **面试谈”轻量自托管”**：用 gogs + gitea 对比，展示你对”工具选择”的思考

常见坑与排错 🐛

  1. SSH 端口设错 → clone 时一直连不上。容器内 22，对外 2222（避宿主 SSH）
  2. git 用户 UID 不一致 → SSH key 读不到。宿主机 chown -R 1000:1000 gogs-data/
  3. 首次没禁用注册 → 被扫号机注册一堆机器人。Install 完立刻去控制面板 → Disable Registration
  4. Application URL 写成 http://...:2222/ → clone URL 全错。Application URL 用 HTTP 端口（3000），不是 SSH 端口
  5. SOCAT_LINK=true 在 K8s 下 → 报错。Kubernetes 里要 SOCAT_LINK=false

依赖服务 🎯

  • 可选 PostgreSQL（SQLite 模式下完全独立）
  • 不需要反向代理（自带 HTTP 服务，但生产建议用 Nginx/Caddy 终止 HTTPS）

资源要求 💻

  • CPU：单核
  • 内存：256MB 起步（Go 二进制 + s6-overlay，闲置 ~80MB）
  • 磁盘：应用 ~80MB，每个仓库按 git 仓库实际大小

🐛 #1 端口冲突

症状：bind: address already in use

原因：宿主机的 80/443/3000/5432 已被占用（Apache/Nginx/旧版项目）

修复：

预防：所有服务永远绑 127.0.0.1，反代用 80/443

🐛 #2 数据库连接失败

症状：FATAL: password authentication failed for user "xxx"

原因：compose 里 POSTGRES_PASSWORD 和应用 DB_PASS 不一致

修复：两边对一下。或用 env_file 让两边读同一份

🐛 #3 数据卷没挂载，容器重启后数据全没

原因：

  • 用了匿名卷（/var/lib/docker/volumes/<hash>/_data），docker compose down -v 时被删
  • bind mount 路径写错

修复：

预防：永远用命名卷（顶层 volumes: xxx: 声明）

原因：应用需要知道自己在 HTTPS 后面，要设 DOMAIN=https://... 或 URL=https://...
