操作系统是后端面试里最能拉开档次的一块。

别人讲 JVM 讲源码、讲 GC 参数，你能把手搓到 task_struct、VMA、epoll 红黑树那一层——面试官的评估就从”背过”跳到了”真跑过”。

但这块的坑在于：它不是靠背，是靠被追问。

面试官不会问”进程有哪几种状态”，他会问”你刚才说 D 状态 kill -9 杀不掉，那它到底卡在哪儿”。所以这篇不给你第二十三份知识点罗列，而是把 24 道高频题还原成真实的面试现场——每道题都是「面试官怎么问 → 你第一反应会怎么翻车 → 正确答法 → 追问怎么接」。

怎么用这篇：不要背”要点”，要背**”现场反应”**。左边那栏是面试官的问题，右边是你脑子里应该立刻蹦出来的东西。考前一小时扫”⚠️ 翻车点”那一行，性价比最高。

一、开场三连：进程与线程

面试开场永远从最”基础”的地方切，因为这里最能看出你是不是只会背。

1. 操作系统中的进程有哪几种状态？

🎬 面试现场

面试官（推了推眼镜）：进程有哪几种状态？

⚠️ 翻车点：张口就答”就绪、运行、阻塞”。这答案不算错，但会让面试官觉得你在背书，他要问的一定是这个。

📝 回答重点

  • 五态模型先答全：新建 → 就绪 → 运行 → 阻塞 → 终止，内存紧张时再多两个挂起态。

  • 就绪是条件够了在队列里等 CPU，运行是真在 CPU 上跑，阻塞是主动让出等事件。

  • Linux 用 ps aux 的 STAT 列就能对上号，自己平时排查也看这一列。

  • 调度器 6.6 起从 CFS 换成 EEVDF，vruntime 只是入场券，挑的是最早合格虚拟截止期。

📈 拔高

EEVDF 的入场资格看 lag：比公平份额少用的任务才够格，公平性在入场时就判完，截止期按请求长度算，交互任务能排到吞吐任务前面。

状态 含义
R Running，运行中或就绪
S 可中断睡眠，等的是”能被信号打断”的事件
D 不可中断睡眠，等的是磁盘 I/O 这类打不断的事件
Z 僵尸，子进程已死、父进程未 wait
T 停止，被信号挂起

💡 主动加分的追问准备

面试官追问 你的答案
为什么僵尸进程不吃 CPU 还要处理？ 它不占 CPU 不占内存，但 PID 和 PCB 还在。默认 pid_max 是 32768，约 3 万个僵尸才耗尽 PID，另有 RLIMIT_NPROC 兜底。父进程收 SIGCHLD 后 wait 回收
什么是孤儿进程？ 父进程先退出，内核把它托管给 PID 为 1 的 init 自动清理，本身无害
阻塞态能直接跳回运行态吗？ 不能，必须先回就绪态排队。状态机里没有这条边

❌ 千万别说的话

  • “阻塞态被唤醒后直接变成运行态”：必须过就绪态
  • “kill -9 能杀掉 D 状态进程”：它是不可中断睡眠，信号 pend 着，等 I/O 完成才会处理
  • “孤儿进程是异常”：内核会自动收尸

2. 线程和进程有什么区别？

🎬 面试现场

面试官：进程和进程的区别？

⚠️ 翻车点：背出”进程是资源分配单位、线程是调度单位”就停下了。这是 20 年前的标准答案，现在只值一半分——因为它没回答 Linux 上到底怎么实现的。

📝 回答重点

  • 经典定义是进程管资源分配、线程管调度执行，只答这句只值一半分。
  • Linux 上二者都是 task_struct，真正的区别只有一条：有没有独立地址空间。
  • fork 只传 SIGCHLD，mm_struct、fs_struct、files_struct 各自独立申请一份。
  • pthread_create 走 clone，一次传 9 个 flag，CLONE_VM | CLONE_FS | CLONE_FILES 共享三件套，还要 CLONE_THREAD、CLONE_SIGHAND 这类成组标记。
  • pid 是线程 ID、tgid 是进程 ID，getpid() 返回的是 tgid。

📈 拔高

内核线程 mm_struct 为 NULL，拿不到用户地址空间；反过来多线程进程里一个线程 exec，其余线程全被终止，信号处理器全组共享而信号掩码各管各的。

💡 主动加分的追问准备

面试官：那 coroutine 呢？

Go 的 goroutine 更轻，是因为它连内核都进不去——切换只是换栈指针和寄存器，栈初始才 2KB。快的原因有三：栈小、无系统调用、调度器用 work stealing + 本地队列免锁。只答”用户态不用系统调用”是不完整的。

❌ 千万别说的话

  • “Linux 为线程设计了一套轻量级进程机制”：没有，就是共享资源的 task_struct
  • “进程和线程是完全不同的东西”：Linux 上相同点远大于不同点
  • CLONE_VM/CLONE_FS/CLONE_FILES 三个 flag 的含义记反

3. 什么是用户态和内核态？

🎬 面试现场

面试官：用户态和内核态的区别？为什么需要区分？

⚠️ 翻车点：”用户态不能访问硬件”——这句话一说出口就减分，因为存在一堆合法例外。

📝 回答重点

  • 本质是 CPU 特权级：x86 看 CS 低两位的 CPL，内核态 0、用户态 3。
  • 切态三条路：系统调用、异常、硬件中断，前两个同步，中断异步。
  • x86-64 走 syscall 指令，调用号放 rax、参数放 rdi/rsi/rdx，结果回 rax，用 sysret 切回。
  • 分不分看架构取舍：宏内核性能高但驱动出事全崩，微内核稳但 IPC 贵。
  • 系统调用开销认三处：上下文切换、权限检查、缓存与 TLB 失效。

📈 拔高

syscall 入口那几步能讲出深度：指令按 LSTAR MSR 直接跳内核入口，先 swapgs 换段寄存器，再切到 KPTI 的内核页表。

类型 例子 同步性
系统调用 read/write/fork/open 同步
异常 除零、缺页、非法指令 同步
硬件中断 时钟、键盘、网卡 异步

💡 主动加分的追问准备

面试官：用户态就真的碰不到硬件？

有三条合法路径：

  1. iopl() / ioperm() 开放特定 IO 端口
  2. mmap() 直接映射设备内存，如显卡的 DRI
  3. DPDK 直接映射网卡内存，绕过内核协议栈

还有个细节能显水平：**System.currentTimeMillis() 在现代 Linux 上走 vDSO，在用户态直接读时钟，通常根本不产生系统调用**。

另外，内核态出 bug 不一定蓝屏——轻微 Oops 只杀当前进程，只有数据结构破坏、死锁、栈溢出才是 Kernel Panic。

❌ 千万别说的话

  • “用户态绝对无法访问硬件”：有 iopl、mmap 设备内存、DPDK
  • “系统调用就是函数调用”：它涉及特权级切换和寄存器上下文保存

4. 进程之间的通信方式有哪些？

🎬 面试现场

面试官：进程间通信有哪几种？

⚠️ 翻车点：报菜名式列一遍就停。面试官要的是每种方式的适用边界。

📝 回答重点

  • 不报菜名，我按消息语义和数据量圈适用边界。
  • 共享内存最快也最危险：页表指向同一块物理内存，同步全靠自己加锁。
  • 管道是字节流没有边界，一次写可能被分几次读走，要自己定分隔符。
  • 消息队列有边界，System V 用 msgget/msgsnd/msgrcv，新项目优先 POSIX。
  • Unix 域套接字不走网络协议栈，还能传文件描述符。

📈 拔高

同机大块数据走共享内存加信号量，要传 fd 或要双向控制走 Unix 域套接字；管道写满会阻塞到读端来取，单条消息超 msgmax 则直接 E2BIG 拒收。

方式 边界/消息语义 数据量 关键特性
管道 字节流，无边界 内核环形缓冲默认 64KB 匿名管道仅限亲缘进程，mkfifo 命名管道可跨无关进程
消息队列 有边界，支持按类型取 单条默认上限 8KB System V msgget/msgsnd/msgrcv，现代推荐 POSIX
共享内存 无语义 零拷贝，大数据量下明显快于管道 shm_open → ftruncate → mmap，内核不提供同步
信号量 无 无数据 本质是计数器，P 减一/V 加一，减到 0 阻塞
信号 无 不能带数据 纯异步通知，只传信号编号
Unix 域套接字 有边界 大 不走网络协议栈，且能传递文件描述符

💡 主动加分的追问准备

面试官：管道和消息队列的核心区别？

管道是字节流，一次 write 100 字节可能被对方分 3 次读完，需要应用自己定义分隔符；消息队列有消息边界，要么整条读完要么不读。

❌ 千万别说的话

  • 把”信号”和”信号量”混为一谈：一个是异步通知，一个是同步计数原语
  • 说共享内存”又快又安全”：它同时最快也最危险

5. 什么是 CPU 缓存一致性协议 MESI？

🎬 面试现场

面试官（Java 背景，通常从这里切进 JMM）：MESI 讲讲？为什么需要它？

⚠️ 翻车点：把 MESI 讲成”硬件层的东西，和 Java 无关”。这句话直接断掉你和后面 volatile 的联系。

📝 回答重点

  • 一句话：多核各存一份缓存，靠给缓存行打状态标签协商谁是正版。
  • 四态 MESI：改过且独占是 M，独占未改是 E，多份一致是 S，本地作废是 I。
  • E 态的意义是省一次总线广播，独占时改自己不用通知别人。
  • 协调靠嗅探，核一多改用目录协议，避免广播风暴。
  • Store Buffer 让本核先跑，于是出现”我改了别人还没看见”，这才是内存屏障的由来。

📈 拔高

变体按厂商分：AMD 的 MOESI 多一个 Owner 态允许脏数据直接共享，Intel 的 MESIF 多一个 Forward 态只让一个核响应读请求；volatile 写在 x86 上编成 lock 前缀指令，store buffer 里的新值立刻全局可见。

状态 含义 记忆法
M Modified 独占且已改，是脏数据，未写回主存 改过的，脏
E Exclusive 独占未改，与主存一致 我一个人有，没人改
S Shared 多核共享且一致 大家都有，都没改
I Invalid 本地失效，需重新拉取 作废了

💡 主动加分的追问准备

伪共享是这块的高频深挖题：

  • 缓存行通常 64 字节，两个毫不相关的变量落进同一行，会互相触发失效
  • Java 8 用 @Contended 解决（需加 -XX:-RestrictContended），JDK 内部的 LongAdder、Striped64 都用了

面试官：volatile 能保证原子性吗？

不能。它只保证可见性 + 禁止重排，i++ 这种读改写依然不原子。

❌ 千万别说的话

  • “volatile 保证原子性”：M/V 级别的经典错误
  • 把伪共享说成”两个线程竞争同一变量”：伪共享是不相关的变量互相拖累

二、调度、中断与 CPU 指标

进程状态讲完，面试官通常顺势切到”那谁决定哪个进程跑”，然后一路问到你答不出来为止。

6. 进程的调度算法你知道吗？

🎬 面试现场

面试官：进程调度算法有哪些？

⚠️ 翻车点：只背 FCFS/SJF/RR 三个。真正拉开差距的是 MLFQ、HRRN，以及 Linux 实际用的 CFS。

📝 回答重点

  • 按演进讲：FCFS 简单但队头大任务拖慢所有人，SJF 平均等待最短却得预知运行时间。
  • 优先级调度会饥饿，RR 用固定时间片保响应性，两者常配合成多级反馈队列。
  • MLFQ 三到五个队列，新进程进最高级，用完时间片降级，定期提回防饿死。
  • HRRN 用响应比 R =（等待 + 服务）/ 服务 兼顾长短任务，适合批处理。
  • CFS 不设固定时间片，6.6 前按 vruntime 挑最小，6.6 起选任务换成 EEVDF。
  • 实时任务是 SCHED_FIFO/SCHED_RR，队列非空就抢占 CPU，默认 95% 节流，普通进程饿不死。

📈 拔高

内核 6.6 起选任务换成 EEVDF，按虚拟截止时间挑，延迟参数只剩 sysctl_sched_base_slice 默认 0.7ms。

💡 主动加分的追问准备

优先级反转几乎必问：

低优先级进程持有锁，高优先级进程等锁时，被中等优先级进程抢占了，高优先级进程就间接被中等优先级卡住。

火星探路者号就是因为没做优先级继承出过事故。解决方案是优先级继承：让持锁的低优先级进程临时提升到等锁的高优先级进程同级别。

MLFQ 防 gaming 的细节也常追问：不能只看单次时间片有没有用完，现代实现（BSD、Solaris）按各队列累计运行时间超阈值才降级。

❌ 千万别说的话

  • “Linux 用时间片轮转”：Linux 用的是 CFS 的 vruntime 抢占，没有固定时间片
  • “SJF 最好所以都用 SJF”：需要预知执行时间，现实中不可用

7. 操作系统在进行线程切换时需要进行哪些动作？

🎬 面试现场

面试官：线程切换要做哪些动作？开销大吗？

📝 回答重点

  • 四步：存上下文到 TCB、改线程状态、调度器挑下一个、恢复目标线程上下文。
  • 上下文三块：CPU 寄存器（含 PC、SP）、PSW、用户栈加内核栈，内核栈不存调用链就断了。
  • TCB 就是 struct task_struct，线程状态、PC、SP、优先级、调度信息都在里面。
  • 快慢的根因在地址空间有没有换：线程共享 mm，TLB 不用刷。
  • 同进程切换比跨进程快一个量级，Linux 上典型 1~10 微秒，goroutine 只要几百纳秒。

📈 拔高

进程切换要换 CR3 并让 TLB 失效，一次 miss 几十到几百个周期；靠 PCID 可以只刷相关条目，不必整表清空，这也是现代内核把切换代价压下来的关键。

💡 主动加分的追问准备

追问 答案
跨进程的线程切换也快吗？ 不快，本质就是进程切换，地址空间变了页表和 TLB 都得换
怎么排查切换开销？ vmstat 看 cs 列，pidstat -w 看单进程。每秒几万次正常，几十万次通常是锁竞争激烈或线程过多
怎么优化？ 短临界区用自旋锁避免切换、CPU 亲和性绑定（DPDK）减少跨核缓存失效、批量处理（Netty EventLoop）降低切换频率

❌ 千万别说的话

  • “自旋锁是万能优化”：临界区长会白烧 CPU，单核上持锁线程根本没机会跑

8. 什么是软中断、什么是硬中断？

🎬 面试现场

面试官：软中断和硬中断有什么区别？

⚠️ 翻车点：答成”硬中断是硬件触发的，软中断是软件触发的”。这是最常见的错答——触发方和实现方是两回事。

📝 回答重点

  • 先说价值：中断把轮询变成被动唤醒，CPU 才腾得出手干别的。

  • 别按触发方分，要按谁检测谁分发分：外部设备、异常、INT 指令三者都走硬中断。

  • 硬中断由 CPU 在每个指令周期末采样中断向量表，记录在 top 的 hi 列。

  • 软中断由内核扫描标记位再分发，对应 top 的 si 列，常态在中断返回时内联跑，积压了才叫 ksoftirqd 兜底。

  • 拆上下半部的原因：硬中断处理要快，不然会长时间关中断，鼠标键盘都会迟。

    硬中断 软中断
    检测方 CPU 硬件 Linux 软件（中断返回内联跑，ksoftirqd 兜底）
    发现时机 每个指令周期最后一个周期采样中断向量表 轮询软中断标记位数组，某位为 1 就取对应处理函数
    top 中 hi 列 si 列

📈 拔高

网卡收包是典型两段式：上半部只置软中断标记，下半部进协议栈逐层解析；负载高时软中断会积压，si 涨、ksoftirqd 占 CPU 就是信号。系统调用的主流入口是 syscall 指令，INT 0x80 只是 32 位遗留慢路径。

💡 主动加分的追问准备

面试官：异常为什么也是硬中断？

因为异常是 CPU 自己给自己中断号，不存在外部设备参与，但检测和分发仍然由硬件完成。容易被误归到软件侧。

❌ 千万别说的话

  • “软中断是软件触发的中断”：那是 INT 指令；软中断的触发源仍是硬件事件，只是处理环节被软件化延迟执行

11. CPU 使用率和 CPU 负载指的是什么？

🎬 面试现场

面试官（可能结合运维场景）：CPU 使用率和 CPU 负载有什么区别？

⚠️ 翻车点：把 load average 当成”排队任务数”直接背。它是指数衰减平滑的结果，不是瞬时快照。

📝 回答重点

  • 使用率是时间窗口内 CPU 真干活的占比，数据在 /proc/stat，做差时 idle 和 iowait 都要扣掉。

  • 负载是排队加运行的任务数，分 1/5/15 分钟三个指数滑动平均，不是瞬时值。

  • 这两个必须一起看，组合才有意义。

    使用率 负载 结论
    高 高 计算能力瓶颈
    低 高 大量 I/O 密集任务或锁竞争
    高 低 调度良好，无积压
    低 低 资源未充分利用

  • 负载统计把 D 态也算进去，所以磁盘卡住会先把负载顶起来。

  • 多核要除以核数读，8 核负载 8 才是刚好打满。

📈 拔高

排查顺序是先 vmstat 1 看 b 和 wa 分清是 IO 还是 CPU，再 iostat -x 看 await 和 %util；注意 %util 到 100% 只对机械盘和单队列 SSD 有说服力，NVMe 多队列下这个数会失真。

💡 主动加分的追问准备

两个细节最能显水平：

  1. 负载统计包含 I/O 等待的任务——这就是”低使用率 + 高负载”的成因
  2. 多核要除以核心数解读：8 核机器负载 8.0 表示每核刚好一个任务，16.0 表示每核还排着一个

完整排查链路：

  1. 告警负载高但 CPU 才 30% → vmstat 1 5 看 b 列（等待 I/O 的进程数）和 wa 列（I/O 等待占 CPU 百分比）
  2. b=15、wa=65% 就是典型磁盘瓶颈
  3. 再用 iostat -x 1 看 await（正常个位数毫秒）和 %util（接近 100% 只对串行设备成立）
  4. iotop 定位具体进程

❌ 千万别说的话

  • “使用率高就是负载高”：线上 4 核机器使用率 20%、平均负载 8 的情况大量存在，此时系统已经出现瓶颈
  • 把 15 分钟负载当瞬时值——趋势比绝对值重要：15 分钟高于 1 分钟说明系统正在恶化

22. 听说过 CFS 吗？

🎬 面试现场

面试官（顺着调度深挖）：CFS 讲讲？

📝 回答重点

  • CFS 从 2.6.23 起替代 O(1) 调度器，用 vruntime 衡量欠了多少 CPU，红黑树最左节点就是下一个要跑的。

  • 调度循环：取最左 → 跑 → 更新 vruntime 再插回红黑树，插入删除都是 O(log N)。

  • 增量公式是实际运行时间乘 NICE_0_WEIGHT / 权重，NICE_0_WEIGHT 是 1024。

    nice 权重 相对 CPU
    -20 88761 ≈ 87 倍
    0 1024 基准
    19 15 ≈ 1/68

  • 替代 O(1) 的理由是它猜不准交互式进程，CFS 不猜，睡眠期间 vruntime 不涨，醒来天然靠左。

  • 长睡进程醒来会把 vruntime 拉到队列最小值附近，避免一觉醒来霸占 CPU。

📈 拔高

6.6 起主线换成 EEVDF，只在选任务算法上换了思路，红黑树这套数据结构没动；多核是每 CPU 一棵树，靠 load_balance 在阈值超了才迁移，避免频繁搬任务丢缓存。

💡 主动加分的追问准备

面试官：CFS 的最新进展？

Linux 6.6（2023-10）引入 EEVDF（最早虚拟截止时间优先）替代 CFS，为请求时间片小的任务算 deadline，改善延迟敏感场景的体验。

❌ 千万别说的话

  • “CFS 保证低延迟”：它目标是公平而非低延迟，硬实时得用 SCHED_FIFO/SCHED_RR
  • “死循环进程会卡死全系统”：时间片有上限，多核下还能分散到其他核

三、内存管理与地址空间

调度讲完，面试官通常会问一句”那进程是怎么拿到内存的”，顺势进入这块。这部分最能区分”看过源码”和”只背过书”。

9. 为什么要有虚拟内存？

🎬 面试现场

面试官：为什么要引入虚拟内存？

⚠️ 翻车点：答”为了隔离进程和扩大可用内存”。太表面，答不到 VMA 这一层。

📝 回答重点

  • 每个进程的 task_struct 挂一个 mm_struct，虚拟地址空间切成互不交叉的 VMA，vm_start/vm_end 界定区间。
  • 我会主动讲清 VMA 只是地址范围，物理页等实际访问触发缺页才向伙伴系统申请。
  • 查 VMA 的结构 6.1 起换成 maple tree，之前是红黑树加双向链表，保护它的锁 5.8 起叫 mmap_lock。
  • 缺页链路顺着代码说：find_vma 找到所属 VMA，handle_mm_fault 把参数收进 struct vm_fault，handle_pte_fault 再分流。
  • 页表层级 x86-64 默认 pgd/pud/pmd/pte 四级，内核通用划分还含 p4d，LA57 机型能开五级。

📈 拔高

缺页入口 6.5 起换成 lock_mm_and_find_vma，里面还是先 find_vma 再校验，说出这层版本差异是加分点。32 位单进程页表满配 4MB 只是上限，多级页表按需分配实际远小于此，顺带提没 PAE 才是两级。

💡 主动加分的追问准备

面试官：堆和栈的物理内存什么时候分配？

进程加载时只分配地址空间范围（VMA），物理页等实际访问触发缺页中断时才申请。所以申请了大数组但没写入，不会立刻占物理内存。

❌ 千万别说的话

  • 以为 malloc/申请内存时就分配了物理内存，实际只拿到一个 VMA 地址区间
  • 忽略 find_vma 这一步，缺了它就无法判断地址是否合法、是否属于当前进程

10. 什么是分段、什么是分页？

🎬 面试现场

面试官：分段和分页有什么区别？

⚠️ 翻车点：只会背”分段按逻辑结构、分页按固定大小”，历史演进和 Linux 实际做法都接不住。

📝 回答重点

  • 本质差异先说清：分段按程序逻辑结构划分，大小不固定、有外部碎片，分页按固定单位切，只有内部碎片。
  • 分页的动机就是碎片：装不下新程序只能整段换出，按 4KB 分页后换入用到的页就行。
  • 多级页表治的是页表自身浪费，32 位满配单进程 4MB 只是上限，实际按需分配。没 PAE 才两级，PAE 进第三级。
  • TLB 缓存最近用的页表项，命中率通常很高，随工作集和 TLB 大小波动，大页能明显提升。
  • 页面置换 Linux 用近似 LRU，anon 和 file 各分 active/inactive 四条链表，回收从 inactive 尾部取最久未用的页。

📈 拔高

进程切换不必全刷 TLB：PCID 下切 CR3 可以带 no-flush 保留条目，同一 mm 的线程切换不刷，内核线程走 lazy TLB。MGLRU 已在 6.1 合入，按代际扫页替代纯 active/inactive 链表，默认开不开看内核配置和发行版。

💡 主动加分的追问准备

分段与分页对照：

分段 分页
划分依据 程序的逻辑结构（代码/数据/堆栈） 固定大小物理单位
段/页大小 不固定 通常 4KB（可配大页）
碎片类型 外部碎片 内部碎片
用户可见性 对程序员可见（需指定段） 透明
  • 分段来自 8086：16 位寄存器加 20 位地址总线，段基址左移 4 位加段内偏移访问 20 位空间。一段只有 64KB，得不断换段基址
  • 80286 引入保护模式和 GDT：段寄存器改存选择子，用 RPL 和目标 DPL 比较判权限，实模式没有权限校验
  • 80386 起寄存器和地址总线都 32 位，分段失去意义，为兼容保留并把段基址全设 0，这就是平坦模式，Linux 照此运行
  • 大页 Linux 支持 2MB/1GB，1G 需要架构支持，页表项更少、TLB miss 更低，代价是内部碎片变大，数据库和虚拟机才用
  • 缺页中断与普通中断不同：普通中断处理完返回下一条指令，缺页中断处理完要重新执行触发它的那条指令

❌ 千万别说的话

  • “Linux 是段页式系统”：分段在 Linux 上是兼容遗留，实际按平坦模式运行，真正干活的是分页

21. 什么是物理地址，什么是逻辑地址？

🎬 面试现场

面试官：物理地址和逻辑地址的区别？地址转换是怎么做的？

⚠️ 翻车点：把翻译说成 OS 软件做的，或者答”进程切换就刷新 TLB”，PCID 这层接不住。

📝 回答重点

  • 物理地址是内存芯片上的真实位置，逻辑地址是程序看到的地址。
  • 翻译由硬件 MMU 依据页表完成，对程序透明，进程间天然隔离。
  • 拿例子走一遍：程序访问 0x000A1234，MMU 查页表得页框号，拼上页内偏移得物理地址。
  • 进程切换时 OS 把新进程页表基址写进 CR3，带 PCID 时 TLB 不必全刷。

📈 拔高

命中 TLB 直接出物理地址，miss 就走页表 walk，x86-64 四级每级一次访存共 4 次，五级 5 次，Page Walk Cache 还能缓存中间级。逻辑地址的好处我会主动讲：位置无关加载、野指针只触发缺页读不到别人、32 位程序能用 4GB 空间。

💡 主动加分的追问准备

  • 追问”为什么要引入逻辑地址”：位置无关加载、进程隔离、虚拟内存扩大可用空间
  • 追问”为什么进程切换要写 CR3”：CR3 换页表基址，带 PCID 时可以不刷 TLB，切换代价小很多

❌ 千万别说的话

  • “用户态程序可以访问物理地址”：Linux 的 /dev/mem 需要 root，生产环境一般禁用
  • 把”分段”当成 x86-64 的实际内存管理机制，分段已被架空

23. 负数的二进制如何表示？

🎬 面试现场

面试官（可能从 Java 类型转换切入）：负数的二进制怎么表示？

⚠️ 翻车点：只背”取反加一”，被追问减法怎么算、为什么最小值多一个就断片。

📝 回答重点

  • 负数用补码表示：正数按位取反加 1，正数的补码就是它本身，最高位是符号位。
  • 8 位例子：5 = 00000101 取反加 1 得 11111011，它就是 -5，加回 5 溢出位正好归零。
  • 补码让减法变加法，硬件只需一个加法器，数学上就是模 256 运算，-3 和 253 是同一个码。
  • 表示范围不对称：8 位是 -128 到 127，int 最小值取负还是自己，Java 里也一样。
  • 符号扩展 byte 转 int 负数补 1，byte b = -1; int i = b; 仍是 -1，想要无符号值用 b & 0xFF。

📈 拔高

位运算的差别要能接住：>> 算术右移保留符号位，>>> 逻辑右移补 0，C 没有 >>>，有符号右移行为依编译器。浮点数不走补码，IEEE 754 里负数只把符号位置 1，其余位不变。

💡 主动加分的追问准备

  • 追问”为什么最小值比最大值多一个”：0 的补码只有一套，省出来的编码落在最小值上
  • 追问”原码反码补码的关系”：原码是符号位加数值位，反码除符号位全取反，现代机器都用补码

❌ 千万别说的话

  • 认为浮点数用补码：浮点走 IEEE 754，负数只是把符号位置 1，其余位不变
  • 解释负数比正数多一个是”补码更聪明”：实际是 0 合并省下的编码落到了最小值上

13. I/O 是什么？

🎬 面试现场

面试官：讲讲你对 I/O 的理解？

⚠️ 翻车点

调度器还背成 CFQ、Deadline、Noop 这套 5.13 就删掉的老名字，或者把 InnoDB 默认 O_DIRECT 说成 8.0 也是。

📝 回答重点

  • 我先把定义给出来：I/O 是数据在内存和外部设备之间的搬运，设备分块设备和字符设备两类。
  • 延迟鸿沟这组数我背得很熟：CPU ~0.3ns、内存 ~100ns、SSD ~150µs、机械盘 ~10ms，CPU 跑一秒等于等机械盘一年。
  • 缓冲 I/O 走 Page Cache，读命中直接返回、写攒批刷盘；直接 I/O 用 O_DIRECT 绕过它，代价是缓冲区地址和长度得按设备逻辑块对齐。
  • InnoDB 要自己掌控刷盘时机：8.4 起 Unix 默认 O_DIRECT，8.0 默认还是 fsync，报版本别报错。
  • I/O 调度器重排请求省寻道：5.13 起 CFQ、noop 那批单队列调度器已删，现役是 mq-deadline、kyber、bfq，默认 mq-deadline。
  • 零拷贝三件套：mmap 映射免一次拷贝、sendfile 内核缓冲区直发 socket、splice 在 fd 间直搬，splice 要求一端是管道。

📈 拔高

对齐别背死数字，设备逻辑块是 512B 还是 4KB 可以用 STATX_DIOALIGN 查出来。调度器在 NVMe 上省不了寻道，内核常给它配 none 直通。

字符设备 键盘、串口 只能顺序字节流，读完即逝

💡 主动加分的追问准备

直接 I/O 一定比缓冲 I/O 快吗？ 不一定。随机小读命中 Page Cache 反而更快，直接 I/O 赢在可控，数据库这类自己管缓存的应用才需要它。sendfile 和 splice 怎么选？ 同机文件发 socket 用 sendfile，管道接管道、跨 fd 搬数据用 splice。

❌ 千万别说的话

  • “非阻塞就是异步”：非阻塞只解决数据没准备好，拷贝还得用户线程自己做
  • “所有 I/O 都必须经 Page Cache”：数据库这类应用恰恰要绕开它

14. 为什么网络 I/O 会被阻塞？

🎬 面试现场

面试官：为什么网络 I/O 会阻塞？

⚠️ 翻车点

只会说队列满了就丢包，说不出半连接队列和已完成队列溢出的默认行为完全不同，深度一眼见分晓。

📝 回答重点

  • 阻塞本质是等：等数据到、等缓冲区腾位置、等连接建立，OS 把进程挂起让出 CPU，唤醒时再付一次上下文切换。
  • 三类场景：读阻塞是接收缓冲区空，写阻塞是发送缓冲区满，连接阻塞是 connect 等握手、accept 等已完成队列。
  • 服务端走 socket、bind、listen、accept 四步，listen 的 backlog 在 Linux 只指已完成队列，还会被 somaxconn 上限截断。
  • accept 从已完成队列取出连接返回新 fd；客户端不用 bind，connect 时内核自动选源 IP 和随机端口。
  • write 慢常见于发送缓冲区满或对端窗口关零，用 fcntl 设 O_NONBLOCK 后条件不满足立刻返回 EAGAIN。
  • 队列溢出分两种：半连接队列满时默认 tcp_syncookies 发 cookie 兜底，SYN 不丢；已完成队列满时默认静默丢弃第三次 ACK，synack 重试耗尽才回 RST。

📈 拔高

溢出别光背结论，看 netstat -s 里的 ListenOverflows、ListenDrops 统计就能确认。想让已完成队列满时立刻回 RST，把 tcp_abort_on_overflow 置 1，默认是 0 所以才静默丢弃。SYN Flood 攻的就是半连接队列，syncookies 就是为它设计的兜底。

类型 触发条件
读阻塞 接收缓冲区为空
写阻塞 发送缓冲区已满
连接阻塞 connect 等三次握手、accept 等已完成队列

💡 主动加分的追问准备

backlog 到底填多大？ 它只描述已完成队列，实际能用的值还会被 somaxconn 截断，Linux 5.4+ 默认 4096，调大它两边都得改。线上怎么确认溢出？ netstat -s 找 listen overflow 相关计数，nstat -az | grep -i listen 看得更快。

❌ 千万别说的话

  • “backlog 是等待建立连接的请求总数”：Linux 下它只算已完成队列，半连接队列另有一套
  • “半连接队列满了 SYN 必被丢弃”：默认 tcp_syncookies=1，溢出时退化为发 cookie
  • “已完成队列满了服务端立刻回 RST”：默认静默丢弃第三次 ACK，要置 tcp_abort_on_overflow=1

15. I/O 模型有哪些？

🎬 面试现场

面试官：I/O 模型有哪几种？区别在哪？

⚠️ 翻车点：报出五种名字就停。核心差异是「等数据」和「拷贝数据」这两个阶段分别由谁完成——这句话是本题的得分锚点。

📝 回答重点

  • 拿到这题我先给分法：按等数据和拷贝数据两阶段由谁干，分阻塞、非阻塞、多路复用、信号驱动、异步五种。
  • 阻塞 I/O 一个连接一个线程，recvfrom 挂到拷贝完成为止，实现简单但连接一多线程先扛不住。
  • 非阻塞 I/O 数据没准备好立刻返回 EWOULDBLOCK，程序反复轮询，纯轮询白烧 CPU，实际都配多路复用用。
  • 多路复用 一次盯一批 fd，select、poll、epoll 都行，就绪了再自己发起读写，Redis、Netty 都是这套。
  • 信号驱动注册 SIGIO，数据就绪内核发信号，拷贝还得自己做，信号会丢、处理耗时，高速场景不用它。
  • 异步 I/O 请求进内核全包，Linux 原生 AIO 用 io_getevents 收结果或 eventfd 唤醒，信号通知那套是 POSIX AIO 的事。

📈 拔高

信号驱动最容易被说错的是阻不阻塞：SIGIO 到达时数据已就绪，之后的 read 不会阻塞，拷贝仍由用户线程同步完成。真正全程躺着的是异步 I/O，连拷贝都归内核。

模型 阶段① 等数据 阶段② 拷贝数据 代表
阻塞 I/O 用户线程等 用户线程同步拷贝 最基础
非阻塞 I/O 立刻返回 EWOULDBLOCK 用户线程同步拷贝 轮询
I/O 多路复用 select/epoll 统一等 用户线程同步拷贝 Nginx、Redis、Netty
信号驱动 内核等，就绪发 SIGIO 用户线程同步拷贝 较少用
异步 I/O 内核等 内核拷贝，完成后通知 Windows IOCP

💡 主动加分的追问准备

为什么说多路复用还是同步？ 内核只负责通知就绪，读写那次系统调用还是应用自己发的，拷贝也自己做。epoll 比 select 好在哪？ 每次调用只返回就绪的 fd，不用每轮把整批 fd 传进内核查，连接多了差距越拉越大。

❌ 千万别说的话

  • “非阻塞 I/O 就是异步 I/O”：前者要问状态加读数据两次系统调用，后者一次请求内核全包
  • “信号驱动全程无阻塞”：SIGIO 只通知数据就绪，内核到用户缓冲区的拷贝还得自己做

16. 同步和异步的区别？

🎬 面试现场

面试官：同步和异步有什么区别？

⚠️ 翻车点

把同步异步答成会不会多线程，或者以为 @EventListener 天生异步，这两个坑一踩分数直接掉一半。

📝 回答重点

  • 一句话：同步异步说的是谁等结果，同步等做完再往下，异步提交完立刻返回靠回调通知。
  • 落地常写成「任务 + 回调」：Callable 配 Consumer，线程里跑完任务再把结果喂给回调。
  • Spring 里是发布订阅，ApplicationEventPublisher 发事件，@EventListener 收。
  • CompletableFuture 的 thenApply 不回主线程，它由跑完上游任务那个线程顺带执行。
  • 想换线程就在方法后面加 Async，重新入池由另一个线程执行。

📈 拔高

@EventListener 默认同步，发布方会被监听方拖住，要并行得再加 @Async 并配好线程池；否则事件一多，发布线程自己就是瓶颈。

💡 主动加分的追问准备

@EventListener 默认是异步的吗？

不是，默认是同步的——发布线程会阻塞到所有监听器执行完。要真正异步必须再加 @Async。

❌ 千万别说的话

  • 以为 thenApply 会等主线程回来执行——它由完成上游任务的工作线程顺带执行
  • 认为 @EventListener 默认异步——发布方会被监听方拖住

17. 阻塞和非阻塞的区别？

🎬 面试现场

面试官：阻塞和非阻塞的区别？

⚠️ 翻车点

答成阻塞就是慢就废了，OS 调度状态和一次切换的代价说不出，这题等于没答。

📝 回答重点

  • 阻塞时 OS 把线程从运行态切到等待态并移出就绪队列，不消耗时间片但栈和内存照占，唤醒再切回来，一来一回 两次上下文切换。
  • 非阻塞立刻返回 EAGAIN，线程可以先干别的，代价是得自己处理返回状态，编程复杂度高。
  • 纯非阻塞得轮询，间隔短 CPU 空转，间隔长响应延迟高，所以极少单独用，基本都配 I/O 多路复用。
  • Java 这边传统 InputStream.read 是阻塞，NIO 用 configureBlocking(false) 加 Selector，底层就是 epoll，Netty 的根基。
  • 模型对应关系别答错：BIO 同步阻塞、NIO 同步非阻塞、AIO 异步，把 NIO 说成异步直接出局。

📈 拔高

非阻塞真正的用法是交给 epoll：线程只在 fd 就绪后回来读，等数据的这段时间归 epoll 管，少数线程盯一池连接就是这么来的。

阻塞 非阻塞
编程复杂度 低 高（要处理返回状态）
线程与连接关系 1 线程 : 1 连接 少量线程 : 海量连接
CPU 利用率 低 高

💡 主动加分的追问准备

阻塞 ≠ 挂起，这个区分很能显水平：

  • 阻塞：线程主动发起、自愿等待
  • 挂起：OS 强制，如内存不足把进程换出到磁盘，进程自己都不知情

高并发下阻塞为什么致命：10 万连接 = 10 万线程，Linux 线程栈默认跟 RLIMIT_STACK 走，常见 ulimit -s 8192 就是 8MB，10 万线程光栈要 800GB 虚拟内存，直接 OOM；上下文切换也会压垮 CPU。而 1~2 个线程 + epoll 就能监控 10 万连接。

❌ 千万别说的话

  • 把阻塞和挂起混为一谈
  • 认为 NIO 是异步的——它是”非阻塞 + 同步”

19. 到底什么是 Reactor？

🎬 面试现场

面试官：讲讲 Reactor 模式。

📝 回答重点

  • Reactor 就是一个线程用多路复用盯住一堆连接，来事件就分发给对应 Handler，特点是事件驱动、少量线程扛海量 I/O，基础事件就连接、读、写三种。

  • Reactor 是同步非阻塞，只通知数据来了，读写应用自己干。Proactor 是异步非阻塞，内核干完再回调。

  • 三种结构按线程分工区分：

    模型 结构 案例
    单 Reactor 单线程 一个线程全干 Redis 6.0 前命令执行单线程
    单 Reactor 多线程 主线程监听 + 工作线程池 —
    多 Reactor 多线程 Boss Group 接连接 + Worker Group 读写 Netty 默认

  • Netty 默认就是多 Reactor，常用配 1 个 Boss 加 CPU 核数乘 2 个 Worker。

  • 耗时业务别扔 Reactor 线程，Netty 里给 Handler 配 EventExecutorGroup 指到别的线程池。

  • Nginx 靠 epoll 跑同一个事件循环，官方口径是一万条空闲 keep-alive 约 2.5MB，十万并发视配置而定。

📈 拔高

EventLoop 就是 Reactor 线程本体：一个 EventLoop 绑死一个线程，内部跑 Selector 循环扫注册上来的所有 Channel。Windows 的 IOCP 是原生 Proactor，Linux 下 Boost.Asio 的 Proactor 也是拿 Reactor 套出来的。

❌ 千万别说的话

  • “把 Reactor 和 Proactor 说反”：Reactor 同步非阻塞，Proactor 异步非阻塞
  • 把耗时业务写在 Reactor 线程里
  • “Boss 线程堆到很多个”：一般只需 1 个，调优重点在 Worker 数

20. Select、Poll、Epoll 之间有什么区别？

🎬 面试现场

面试官：select、poll、epoll 有什么区别？

📝 回答重点

  • select 和 poll 每次调用都要全量拷贝加线性扫，epoll 只注册一次、只返回就绪 fd。

    select poll epoll
    数据结构 fd_set 位图 struct pollfd 数组 红黑树 + 就绪链表
    数量限制 FD_SETSIZE = 1024 无（受内存限制） 无
    每次调用 全量拷贝 + 全量扫描 全量拷贝 + 全量扫描 只遍历就绪链表，空则挂起
    注册时机 每次调用都要重传 每次调用都要重传 只注册一次
    复杂度 O(总数) O(总数) O(就绪数)

  • select 传三个 fd 集合，nfds 是最大 fd 加一，timeout 给 NULL 就一直等，给 0 立刻回。

  • poll 改用动态数组没数量上限，events 自己填、revents 内核回，timeout 按毫秒算。

  • epoll 分三步：epoll_create 建实例，epoll_ctl 增删改红黑树，epoll_wait 只扫就绪链表。

  • 触发模式两档：LT 水平触发没读完每次报，ET 边缘触发只在状态变化时报一次。

  • 十万连接一百活跃时，select 还是 O(10 万) 全量扫，epoll 只看这 100 个，实测快 10 倍以上。

📈 拔高

就绪事件是 copy_to_user 拷进用户态的，epoll 源码里根本没有 mmap，这说法是把别的优化记串了。ET 再配 EPOLLONESHOT，一个 fd 同时只被一个线程处理，多线程抢同一连接时靠它兜底。

追问 答案

24. 死锁是什么？如何预防和避免死锁？

🎬 面试现场

面试官：说下死锁，以及怎么处理。

📝 回答重点

  • 死锁就是两个进程各拿一把锁互等对方，谁也不放，没外力都走不动。

  • 四个必要条件必须同时成立，破坏任意一个就能预防，这是本题总纲。

  • 四个条件和含义对着表讲，重点看请求与保持行的不放 A：

    条件 含义
    互斥 资源同一时刻只能被一个进程占用
    请求与保持 持有 A 的同时等 B，且不放 A
    不剥夺 资源用完前不能被强行抢走
    循环等待 A 等 B、B 等 C、C 等 A

  • 应对按四条对号入座，最常用的是循环等待，先定死全局顺序：

    破坏的条件 方法 代价
    互斥 只读文件共享、打印机虚拟化成打印队列、数据库用 MVCC 适用面窄
    请求与保持 一次性申请所有资源，全拿或全不拿（acquire_all_locks） 资源利用率低、易饥饿
    不剥夺 带超时获取 lock.acquire(timeout=1) 可能误杀正常业务
    循环等待 全局锁顺序表（account=1、order=2、inventory=3、payment=4）按序加锁、逆序释放 需要人工维护约定

  • 银行家算法先算 need = Max − Allocation，试分配后找安全序列，不安全立刻回滚。

  • 检测靠等待图查环，恢复就终止进程或抢资源，MySQL 的 SHOW ENGINE INNODB STATUS 能看谁在等，innodb_lock_wait_timeout 默认 50 秒兜底。

📈 拔高

预防、避免、检测是三层：破坏必要条件挡在事前，银行家每次申请先算安全序列，等待图查环是事后兜底。真正天天在生产里跑的是固定加锁顺序加超时，矩阵试分配那套停在教科书。

  1. D 状态进程 kill -9 杀不掉
  2. 跨进程的线程切换 = 进程切换，不快
  3. Linux 不是段页式，分段已被架空
  4. Java NIO 是”非阻塞 + 同步”，不是异步
  5. glibc 的 POSIX AIO 是线程池模拟的，不是真异步
  6. free 低≠内存不足，看 Swap
  7. select/poll 每次全量拷贝扫描，epoll 只注册一次

五个数字

数字 含义
64 字节 缓存行大小，伪共享的根源
512 B ~ 150 µs L1 到 SSD 的延迟量级差
1024 select 的 FD_SETSIZE
4 KB 默认页大小
-20 ~ 19 nice 值范围

最后一句提醒：回答时先给定义，再给机制，最后给边界条件。面试官真正在听的是第三层——你知道这个机制在什么情况下会失效。
