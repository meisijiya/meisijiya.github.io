1. 元素有哪些常用操作方法？

🎬 面试现场

面试官（口语化）：找到元素之后，一般对它做哪些操作？Selenium 里对应哪些方法？

⚠️ 翻车点

容易只答 click 和 send_keys，漏掉五类操作里的获取属性（get_attribute、text）和校验状态（is_displayed、is_selected）。测试里大量断言就靠这两个。另一个高频坑是等待方式混用。网页加载时间可能不确定，需要显式等待（WebDriverWait）和隐式等待（implicitly_wait）配合元素加载完成。

📝 回答重点

  • 元素操作我按五类来记：查找、交互、取属性、等待、校验状态。
  • 查找用各种选择器定位元素，复杂结构里 XPath 和 CSS 选择器最好使。
  • 交互就是三板斧：click 点、send_keys 输入、clear 清空。
  • 取属性用 get_attribute("value") 拿输入框的值，.text 拿可见文本；输入框的值不能靠 .text，得取 value 属性。
  • 元素加载不确定时用显式 WebDriverWait 或隐式 implicitly_wait 等它就绪。
  • 校验状态用 is_displayed 看是否可见、**is_selected** 看是否选中，断言经常落在这俩。

📈 拔高

我按五类来组织而不是背方法名，这样面试官追问「为什么输入框的值取不到」我立刻能接：输入值存在 value 属性里，得用 get_attribute('value')，.text 只拿可见文本。把这点讲透，基本就过关了。

💡 主动加分的追问准备

面试官追问 你的答案
元素操作分哪几类？ 查找元素（find_elements(By.ID, ...)、find_elements(By.NAME, ...)、find_elements(By.XPATH, ...) 等）、交互操作（click、send_keys、clear）、获取属性（get_attribute、text）、等待元素（显式等待 WebDriverWait、隐式等待 implicitly_wait）、校验状态（is_displayed、is_selected）。
怎么判断元素是否显示出来了？ 用校验状态的方法，is_displayed 判断元素是否可见，is_selected 判断元素是否被选中。
页面加载慢怎么办？ 网页加载时间可能不确定，需要适当地等待元素加载：用显式等待 WebDriverWait 等待特定条件成立，或用隐式等待 implicitly_wait 设置全局等待时间。
属性值怎么拿来做断言？ 用获取属性的方法，get_attribute 获取指定属性的值，text 获取元素的文本内容，经常用来做验证。

❌ 千万别说的话

  • “找到元素之后只有点击和输入两种操作。” 除了点击和输入，还有取属性、等元素、校验状态等几类常用操作，断言经常靠 is_displayed 和 get_attribute。
  • “断言只能靠读文本。” 除了文本，属性值也能通过 get_attribute 拿到做验证。
  • “元素还没加载出来就重试几次就行。” 网页加载时间不确定，应该用显式等待或隐式等待来确保元素加载完成，而不是手动重试。

2. WebDriver 操作浏览器有哪些常用方法？

🎬 面试现场

面试官（口语化）：WebDriver 有哪些操作浏览器本身的常用方法？close() 和 quit() 有什么区别？

⚠️ 翻车点

最容易答错的是 close() 和 quit() 的区别：close() 仅关闭当前窗口，常用于有多个窗口的场景。quit() 则会关闭所有浏览器窗口并结束 WebDriver 进程，通常在测试完成时使用。另一个容易漏的是 navigate() 和 get(url) 的关系。navigate().to(url) 类似于 get(url)，但还提供 back()、forward()、refresh() 等功能。以及 manage() 里可以设置隐式等待时间、最大化窗口这类浏览器设置。

📝 回答重点

  • 浏览器层面：**get(url)** 打开页面，**navigate()** 管前进后退刷新，manage() 管窗口和超时。
  • 元素层面：**findElement(by)** 查单个元素，findElements(by) 查多个并返回列表。
  • 取状态用 getTitle() 拿标题、getCurrentUrl() 拿地址、getPageSource() 拿源码，调试时很有用。
  • 收尾用 close() 关当前窗口、**quit()** 关所有窗口并结束 WebDriver 进程。
    📈 拔高

我会特意把 close() 和 quit() 讲清：close() 只关当前窗口，多个窗口场景要小心；quit() 才真正退出 WebDriver 进程。还有 get 和 navigate().to 不是两回事，后者是前者的超集，多带历史导航能力。

💡 主动加分的追问准备

面试官追问 你的答案
close() 和 quit() 有什么区别？ close() 仅关闭当前窗口，常用于有多个窗口的场景。quit() 会关闭所有浏览器窗口并结束 WebDriver 进程，通常在测试完成时使用。
怎么验证页面加载对了？ 用 getTitle() 获取当前页面的标题来验证页面是否加载正确，用 getCurrentUrl() 获取当前页面的 URL 来验证页面跳转是否正确。
get(url) 和 navigate().to(url) 有区别吗？ navigate().to(url) 类似于 get(url)，但还提供 back()、forward()、refresh() 等功能，例如 driver.navigate().back() 返回上一个页面。
浏览器窗口大小和超时怎么管？ 通过 manage() 方法，它包含了很多有用的管理功能，比如 manage().timeouts().implicitlyWait(10, TimeUnit.SECONDS) 设置隐式等待时间，或 manage().window().maximize() 最大化窗口。

❌ 千万别说的话

  • “close() 和 quit() 效果一样。” close() 只关当前窗口，quit() 才关所有窗口并结束进程，两者差别很大。
  • “WebDriver 只能打开网页，找元素要换别的工具。” findElement(by) 和 findElements(by) 本身就是 WebDriver 的常用方法。
  • “调试时找不到某个元素文本，只能加打印。” getPageSource() 拿页面源码调试很方便，能直接看元素或文本在不在页面上。

3. WebDriver 如何操作鼠标？

🎬 面试现场

面试官（口语化）：WebDriver 怎么模拟鼠标操作？双击、右键、拖拽分别怎么写？

⚠️ 翻车点

最容易漏的是 perform()。Actions 类的方法只是把操作串成动作链，必须调用 perform() 才会真正执行。另一个坑是动作链的组合写法：clickAndHold()、moveByOffset()、release() 这些要链式调用后一次性 perform。容易被忽略的还有两点。无头浏览器（如 HtmlUnitDriver 或 Headless Chrome）中某些鼠标操作可能不完全支持。不同浏览器上 Actions 的行为可能有所差异。

📝 回答重点

  • 鼠标操作用 Actions 类，先 new Actions(driver) 建对象，再链式调方法，最后必须 perform() 才真正执行。
  • 常用方法：click()、doubleClick()、contextClick()（右键）、moveToElement()、clickAndHold()、release()、dragAndDrop()、moveByOffset()。
  • 复合动作把多步串成一条链，比如按住、移动、松开，最后一次性执行。
  • 操作前用 WebDriverWait 等 elementToBeClickable 确保元素可点，避免点到半截。
  • 无头浏览器（HtmlUnitDriver、Headless Chrome）里部分鼠标操作可能不完全支持，不同浏览器行为也可能有差异。

📈 拔高

我一般会补一句：鼠标操作为什么要先等 elementToBeClickable 再点，因为很多失败出在元素还没就绪就被点，脚本本身没错。无头环境部分动作不支持这点也主动提，显得踩过坑。

💡 主动加分的追问准备

面试官追问 你的答案
鼠标操作怎么实现？ 主要通过 Actions 类实现，创建 Actions 对象时传入 WebDriver 实例，然后用 click()、doubleClick()、contextClick()、moveToElement()、clickAndHold()、release()、dragAndDrop()、moveByOffset() 等方法，最后调用 perform() 执行动作链。
为什么要加 perform()？ Actions 类的方法是把操作组成动作链，调用 perform() 才会真正执行动作链。复合操作就是把多步操作组合在一起，然后通过 perform() 一次性执行。
元素还没准备好就点会怎样？ 元素的加载速度和时间存在不确定性，良好的实践是使用 WebDriver 的 WebDriverWait 类来进行等待，确保元素可操作，比如等待 elementToBeClickable 之后再操作。
鼠标操作在不同浏览器上行为一致吗？ 不同浏览器行为会有差异，跨系统、跨版本跑一遍能抓兼容问题。无头浏览器（HtmlUnitDriver、Headless Chrome）里有些鼠标动作不支持。

❌ 千万别说的话

  • “调用 actions.click(element) 就点下去了。” 必须调用 perform() 才会真正执行动作链。
  • “鼠标操作失败一定是脚本写错了。” 无头浏览器中某些鼠标操作可能不完全支持，也要考虑是否和浏览器类型有关。不同浏览器上行为也可能有差异。
  • “动作失败只能重跑。” 可以通过截图、日志等方式调试，有时还可以增加操作之间的等待时间。

4. Web 自动化测试中，WebDriver 如何开启和退出一个浏览器？

🎬 面试现场

面试官（口语化）：用 WebDriver 跑一个浏览器，从开起来到关掉，代码怎么写？quit 和 close 有区别吗？

⚠️ 翻车点

最容易翻车的是把 quit() 和 close() 混为一谈：quit() 关闭所有关联的窗口并且完全退出浏览器，close() 只关闭当前窗口，但如果只剩下一个窗口，它也会退出浏览器。另一个坑是忘了配驱动，Chrome 需要 chromedriver，并且要把路径加进系统环境变量，或者在代码里指定。还有人只答开启不答退出，以及把「无头模式」当成默认。无头是要通过浏览器选项显式配置的。

📝 回答重点

  • 浏览器启动我先建 webdriver.Chrome() 实例，再 driver.get(url) 打开网页，结束用 **driver.quit()**。
  • 退出要分清：**quit()** 关所有窗口并结束进程，**close()** 只关当前窗口（只剩一个时也会退出）。
  • 跑 Chrome 得配 chromedriver，把路径加系统环境变量或在代码里指定。
  • 不显示界面就配 Options 加 --headless，还能加 --disable-extensions 禁扩展。
  • 元素没加载完就用 WebDriverWait 等 expected_conditions；另外 driver.title 取标题、driver.save_screenshot() 截屏也是常用操作。

📈 拔高

我一般会补一句：很多人把 quit 和 close 混着说，其实多个窗口场景 close 只关一个，得用 quit 才退得干净。还有无头不是默认开的，得显式加 --headless，这点容易被当默认。

💡 主动加分的追问准备

面试官追问 你的答案
quit() 和 close() 有什么区别？ driver.quit() 关闭所有关联的窗口并且完全退出浏览器。driver.close() 关闭当前窗口，但如果只剩下一个窗口，它也会退出浏览器。
启动 Chrome 需要做什么准备？ WebDriver 需要一个对应浏览器的驱动程序来与浏览器进行通信，Chrome 需要 chromedriver，可以根据操作系统下载相应驱动程序，并把路径添加到系统环境变量。
怎么让浏览器跑起来不显示界面？ 通过配置浏览器选项来设置，比如用 Options 加 --headless 启用无头模式（即不显示 GUI 的模式），还可以加 --disable-extensions 禁用扩展。
元素还没加载出来就操作会怎样？ 自动化测试中元素加载时间不一致，需要处理这个问题，Selenium 提供了显式等待和隐式等待，显式等待通过 WebDriverWait 类实现，可以等待特定元素的出现。
WebDriver 还能做哪些常见操作？ 获取网页标题（driver.title）、查找页面元素（如 driver.find_element(By.NAME, 'q')）、截屏（driver.save_screenshot('screenshot.png')）等。

5. Web 自动化测试中，如何查找屏幕上是否显示了元素？

🎬 面试现场

面试官（口语化）：怎么判断页面上某个元素是不是显示出来了？找不到和显示不出来怎么区分？

⚠️ 翻车点

最容易答成「用 find_element 找到了就说明显示了」。找到元素不等于元素可见，is_displayed() 才是判断可见的那一步。第二个坑是只答一种情况：元素在 DOM 里存在但不可见（is_displayed() 返回 False）和元素根本不存在（抛异常）是两回事，脚本里通常要用 try/except 把「未找到」和「未显示」分开。还有人不用等待，直接查就断言，页面还没渲染完就判失败。

📝 回答重点

  • 先定位元素，再用 is_displayed() 判断它是否可见，这是「显示出来」的判定。
  • 页面没渲染完别直接断言，用 WebDriverWait 等 visibility_of_element_located 条件。
  • find_element 找不到会抛异常，元素在 DOM 里但不可见时布尔判定返回 False，脚本里常拿 try/except 把「未找到」和「未显示」分开。

📈 拔高

我一般强调 is_displayed() 只判断可见性、不判断存在性。很多人把「找到了」误当「显示了」，其实元素可能藏在 DOM 里不渲染，必须显式等 visibility_of_element_located 才算真可见。

💡 主动加分的追问准备

面试官追问 你的答案
怎么判断元素是否显示？ 先用 ID、类名、名称、XPath 或 CSS 选择器等定位方法定位到目标元素，再用 Selenium 提供的 is_displayed() 方法判断元素是否可见。
元素存在但不可见怎么办？ 可以使用 find_elements 方法返回一个列表，通过检查列表长度来判断元素是否存在，这样能区分「在 DOM 里存在但不可见」和「根本不存在」。
页面还没加载完就判断会怎样？ 页面加载需要时间，用隐式等待（implicitly_wait）或显式等待（WebDriverWait 和 expected_conditions）更好地处理页面元素加载问题，显式等待可以等到 visibility_of_element_located 条件成立。
用例里还能配合哪些操作？ 可以配合 Selenium 提供的导航方法 back()、forward() 和 refresh()，测试复杂的用户交互场景。也支持跨 Chrome、Firefox、Safari、Edge 等不同浏览器做测试。

❌ 千万别说的话

  • “找到元素就说明它显示出来了。” 定位到元素只是第一步，可见性要靠 is_displayed() 判断。
  • “元素不存在时会返回空。” 用 find_elements 才会返回列表（可以判断长度），单元素定位找不到会抛异常，脚本里要区分「未找到」和「未显示」。
  • “不用等，页面打开就能查。” 页面加载需要时间，应该用隐式等待或显式等待处理元素加载问题。

6. Web 自动化测试中，如何使用 Selenium 在文本输入框中输入文本？

🎬 面试现场

面试官（口语化）：用 Selenium 往输入框里打字并提交，完整流程是怎么走的？

⚠️ 翻车点

最容易答漏的是初始化 WebDriver 这一步。很多人直接答「找到输入框然后 send_keys」，但驱动实例、打开网页这两步缺一不可。第二个坑是只讲 find_elements(By.ID, ...) / find_elements(By.NAME, ...) 一种定位，页面结构复杂或元素动态生成时不够用，还得会用 find_elements(By.XPATH, ...)、find_elements(By.CSS_SELECTOR, ...)。第三个坑是只讲输入不讲等待，页面加载时间和 JavaScript 渲染时间会影响脚本稳定性。

📝 回答重点

  • 完整流程我先 pip install selenium，导入 webdriver 和 **Keys**，再建 webdriver.Chrome() 实例。
  • 用 get 打开目标网页，再用 find_elements(By.ID, ...)/find_elements(By.NAME, ...) 等找到输入框。
  • 往里 send_keys 打文本，提交表单就 send_keys(Keys.RETURN)。

📈 拔高

我一般提醒一句：输入框的值要用 send_keys 真实输入，而不是去改 value 属性，否则有些前端校验和事件不会触发。提交方式也看具体表单，是按钮点击还是回车更稳得实测。

💡 主动加分的追问准备

面试官追问 你的答案
往输入框输入文本的完整步骤是什么？ 安装并导入 Selenium 的必要模块（webdriver、Keys），初始化 WebDriver 启动浏览器实例，用 get 方法打开目标网页，找到输入框，再用元素的 send_keys 方法输入文本。
只用 id 和 name 定位够吗？ 不够，页面结构复杂或元素动态生成时不够用，还可以使用 find_elements(By.XPATH, ...)、find_elements(By.CSS_SELECTOR, ...)。善于构造 XPath 和 CSS 选择器可以极大提高脚本的稳定性和灵活性。
页面渲染慢导致输入不稳定怎么办？ 页面加载时间和 JavaScript 渲染时间会影响脚本稳定性，Selenium 提供了显式等待和隐式等待，显式等待可以让脚本等待直到满足某个特定条件才继续执行。
想在多个浏览器上跑这套用例怎么改？ Selenium 支持 Chrome、Firefox、Safari 等浏览器，只需要相应地配置 WebDriver，比如把初始化部分换成 driver = webdriver.Firefox()。

二、等待机制：显式等待、隐式等待与两者区别

9. 什么是显式等待？

🎬 面试现场

面试官（口语化）：显式等待是什么？它和固定 sleep 相比好在哪？

⚠️ 翻车点

容易答漏两点。其一，显式等待的行为描述：它会以固定的时间间隔检查是否满足了某个特定条件，一旦满足条件就会继续执行后续操作，否则会等待一段时间直到超时为止，不是”睡固定秒数”。其二，它和隐式等待的差别：隐式等待是全局性的，规定一个时间段，被用于查找所有元素的等待；而显式等待更加精确且能针对特定的条件进行等待。

📝 回答重点

  • 显式等待用 WebDriverWait + **ExpectedConditions**（常缩写 **EC**），以固定间隔检查某个条件，满足就继续，超时就抛异常，不是 sleep 固定秒数。
  • 和隐式等待的区别：隐式是全局性，被用于查找所有元素；显式更精确，针对特定条件。
  • 其他等待技术还有固定 sleep、等页面完全加载，复杂场景可以混合使用。

📈 拔高

我一般强调显式等待的超时不是 sleep：条件一旦满足就立刻继续，不会等满。把这点讲清，面试官就知道我理解的是按条件检查，不是固定延时。

10. 什么是隐式等待？

🎬 面试现场

面试官（口语化）：隐式等待是干什么的？设置之后 WebDriver 的行为是怎样的？

⚠️ 翻车点

容易答成”元素找不到就多等一会儿”，漏掉关键机制细节：设置隐式等待后，WebDriver 在尝试定位元素时，会在指定的时间内不断地重新尝试查找元素，一旦找到元素就立即执行接下来的操作，而不是等到时间结束。如果在指定时间内找不到元素，才会抛出 NoSuchElementException。另一个容易答漏的是作用域。隐式等待通常在用例一开始设置全局等待时间，应用于整个 WebDriver 的生命周期。

📝 回答重点

  • 隐式等待用 implicitly_wait 全局设置，WebDriver 在指定时间内反复查找元素，找到就立刻继续，超时抛 **NoSuchElementException**。

  • 适用页面加载时间稳定、很少需要特定条件的场景；页面变化频繁或需要特定条件时更推荐显式等待。

📈 拔高

  • 表格读取核心：定位表格 → 取行列表 → 取单元格。下标从 0 起算：第二行是 **rows[1]**，第二列是 **find_elements(By.TAG_NAME, 'td')[1]**；定位表格本身可以用 find_elements(By.ID, ...)、find_elements(By.NAME, ...)、find_elements(By.XPATH, ...)、find_elements(By.CSS_SELECTOR, ...) 等。
  • 动态表格用 WebDriverWait 等 presence_of_element_located 等加载完成，否则拿到空表。
  • 取行和取单元格都用标签名定位，遍历两层列表就能读出整张表的数据。

面试前 10 分钟速查

WebDriver 基本操作

  • 元素操作五类：查找元素（find_elements(By.ID, ...)、find_elements(By.NAME, ...)、find_elements(By.XPATH, ...)、find_elements(By.CSS_SELECTOR, ...)）、交互（click、send_keys、clear）、取属性（get_attribute、text）、等待（显式 WebDriverWait、隐式 implicitly_wait）、校验状态（is_displayed、is_selected）。
  • WebDriver 常用方法：get(url)、findElement(by)、findElements(by)、getTitle()、getCurrentUrl()、getPageSource()、close()、quit()、navigate()、manage()；navigate().to(url) 类似 get(url)，还提供 back()、forward()、refresh()。
  • close 与 quit 区别：close() 只关闭当前窗口，quit() 关闭所有关联窗口并结束 WebDriver 进程；driver.close() 只关当前窗口，若只剩一个窗口它也会退出浏览器。
  • 浏览器管理：manage().timeouts().implicitlyWait(10, TimeUnit.SECONDS) 设隐式等待，manage().window().maximize() 最大化；还可取标题 driver.title、截图 driver.save_screenshot('screenshot.png')。
  • 启动与退出：webdriver.Chrome() 创建实例后 driver.get("http://www.example.com")，结束用 driver.quit()；Chrome 需要 chromedriver 并把路径加入系统环境变量。
  • 无头与选项：Options 加 --headless 启用无头模式、加 --disable-extensions 禁用扩展，再 webdriver.Chrome(options=chrome_options)；无头不是默认开启的。
  • 鼠标 Actions：创建 new Actions(driver) 后链式调用 click()、doubleClick()、contextClick()、moveToElement()、clickAndHold()、release()、dragAndDrop()、moveByOffset()，最后必须 perform() 才真正执行。
  • 复合动作链：actions.moveToElement(element).clickAndHold().moveByOffset(50, 0).release().perform() 一步完成按住拖拽释放；无头浏览器（HtmlUnitDriver、Headless Chrome）中部分鼠标操作可能不完全支持。
  • 元素是否显示：先定位再 is_displayed() 判断可见；元素在 DOM 存在但不可见与根本不存在是两回事，用 try/except 把「未找到」和「未显示」分开。
  • 判断存在性：用 find_elements 返回列表并判断 len(elements) > 0；单元素定位找不到会抛异常，页面未渲染完时用显式等待 WebDriverWait(driver, 10).until(EC.visibility_of_element_located(...))。
  • 输入文本流程：pip install selenium 后导入 webdriver、Keys，初始化驱动、用 get 打开网页、找到输入框、send_keys('Hello, world!') 输入、send_keys(Keys.RETURN) 提交、driver.quit() 关闭。
  • 取元素文本：导入库、启动 WebDriver 并打开网页、定位元素、用 .text 取文本、关闭浏览器；输入框里的值要用 get_attribute('value') 取，多个元素用 find_elements(By.CLASS_NAME, ...) 返回列表。
  • 键盘与鼠标模拟：Selenium 用 sendKeys 或 Actions 类，Puppeteer 用 page.keyboard.type('Hello, World!') 和 page.mouse.move(100, 100)；操作失败常因元素不可见或被覆盖，可用 JavascriptExecutor 执行 arguments[0].scrollIntoView(true); 并切窗口焦点。

等待机制

  • 显式等待机制：WebDriverWait 以固定时间间隔检查某个特定条件，条件满足即继续，否则等到超时；实现靠 WebDriverWait 类配合 ExpectedConditions 类。
  • 显式等待写法：WebDriverWait(driver, 10).until(EC.presence_of_element_located((By.ID, "myElement"))) 表示最长等 10 秒直到该 ID 元素出现。
  • 隐式等待机制：driver.implicitly_wait(10) 后 WebDriver 在指定时间内不断重新尝试查找元素，找到即立即执行后续操作；超时找不到才抛 NoSuchElementException。
  • 隐式等待作用域：声明一次，整个 WebDriver 实例查找元素时都用这个等待时间，通常在用例一开始设置，作用于整个 WebDriver 生命周期。
  • 核心差异：显式等待针对特定元素设条件与最长等待时间，超时抛超时异常；隐式等待为 WebDriver 设定全局最长等待时间，不停检查 DOM 直到找到元素，找不到抛找不到元素异常。
  • 等待类型数量：Selenium 有三种等待——隐式等待、显式等待、自定义等待（Fluent Wait），后者是显式等待的变体，可设最大等待时间、轮询间隔及忽略特定异常。
  • 内置等待条件：elementToBeClickable、visibilityOfElementLocated、presenceOfElementLocated 等 ExpectedConditions 条件，配合显式等待比等固定时间更高效。
  • 混用与超时：显式与隐式等待可以同时使用，但可能引发复杂的等待时间计算问题，不建议混用；超时设过短等不够、过长浪费时间，需按应用实际加载时间评估。

表单与弹层操作

  • 下拉框三种选法：Select(driver.find_element(By.ID, 'dropdown_id')) 后用 select_by_visible_text('Option Text')、select_by_value('option_value')、select_by_index(1) 选择。
  • 多选下拉框：用 multiple 属性选择多个选项，取消选择用 deselect_by_visible_text('Option Text 1')；下拉内容动态加载时需显式等待或处理异步请求。
  • JS 弹窗：alert、confirm、prompt 由浏览器生成，用 driver.switch_to.alert 切换；alert 用 .accept() 确定，confirm 还可 .dismiss() 取消，prompt 先 send_keys("Input text") 再 accept() 提交。
  • 自定义弹层：属于网页内容的一部分，用 CSS 选择器或 XPath 找到关闭按钮点击，操作前用显式等待 EC.visibility_of_element_located((By.ID, "customPopup")) 确认可见。
  • 滚动方式：window.scrollTo(x, y) 跳到绝对坐标，window.scrollBy(dx, dy) 从当前位置做增量偏移，element.scrollIntoView() 让元素进入视窗；Selenium 侧可用 location_once_scrolled_into_view 或动作链。
  • 滚动条不需定位：滚动条是页面或元素的属性，实际依赖对目标元素位置和属性的操作；判断是否可见用 element.is_displayed()，不可见时先 scrollIntoView。
  • 文件上传：定位文件选择的 input 元素，upload_element.send_keys("C:/path/to/your/file.txt") 直接传路径，再点提交按钮；多文件用循环依次传路径。
  • 上传异常处理：上传前用 os.path.exists 检测文件是否存在，并考虑网络中断等异常；Cypress 用 cy.get('input[type="file"]').attachFile('path/to/file')。
  • 时间控件定位：find_element(By.XPATH, "//input[@type='date']")、find_element(By.CSS_SELECTOR, "input[type='date']")、find_element(By.ID, "timePicker")、find_element(By.CLASS_NAME, "time-picker-class") 四条路径。
  • 动态控件写法：元素动态生成或属性变化时用低敏感度写法 //*[contains(@class, 'date-picker')]、input[id^='time']，并用 WebDriverWait 等控件加载完成；控件常拆成日历按钮和输入框两部分需分别定位。
  • 修改元素属性：用 driver.execute_script("arguments[0].setAttribute('attribute_name', 'new_value')", element) 注入 JavaScript 改 DOM 属性，理由是满足测试用例需要、绕过前端限制、增强脚本对不同 DOM 结构的适应性。

页面与窗口

  • 代理重定向原理：代理服务器在客户端和目标服务器之间充当中间人，接收并处理或修改请求后转发，响应也经代理回传，因此可实现请求层重定向而不是改代码里的 URL。
  • BrowserMob Proxy 三步：Server("/path/to/browsermob-proxy") 启动并 server.create_proxy()，用 chrome_options.add_argument("--proxy-server={0}".format(proxy.proxy)) 塞给浏览器，再 proxy.rewrite_url("http://example.com", "http://newexample.com") 写规则。
  • 其他拦截工具：Puppeteer 用 interceptRequest 做请求拦截与重定向；Mitmproxy 作为交互式抓包工具和 Python 库可精细修改请求与响应。
  • iframe 四步：定位 iframe 元素 → driver.switchTo().frame(iframe) 切上下文 → 像普通页面一样操作内部元素 → driver.switchTo().defaultContent() 切回主页面。
  • iframe 切换方式：嵌套 iframe 需逐层切换（先 switchTo().frame("first_iframe_id") 再切嵌套）；也可按索引 driver.switchTo().frame(1) 或直接传 WebElement 切换；定位不唯一会抛 NoSuchElementException。
  • 导航命令三类：打开网页 driver.get(url)、刷新页面 driver.navigate().refresh()、历史前后退 driver.navigate().back() 与 driver.navigate().forward()。
  • 导航后配套：多窗口用 driver.switchTo().window(windowHandle) 切换、句柄用 driver.getWindowHandles() 获取；会话状态用 driver.manage().getCookies()、driver.manage().addCookie(cookie)；导航后用显式等待并断言页面状态。
  • 历史来回浏览：先打开第一个 URL 再打开第二个 URL 制造历史，driver.back() 后退、driver.forward() 前进；等价写法 driver.execute_script("window.history.go(-1)") 与 window.history.go(1)。
  • 等待优于 sleep：历史导航中用 time.sleep() 简单但不稳定，实际项目推荐 WebDriverWait(driver, 10).until(EC.presence_of_element_located((By.ID, "some-element-id")))。
  • 四种刷新方式：driver.navigate().refresh()、driver.get(driver.getCurrentUrl())、用 Actions 的 sendKeys(Keys.F5).perform()、执行 ((JavascriptExecutor)driver).executeScript("location.reload()")；刷新后要等页面加载，多窗口需先切到正确标签页。
  • 窗口切换步骤：用 driver.window_handles 取全部句柄、driver.switch_to.window(windows[1]) 切换、操作完 driver.switch_to.window(windows[0]) 切回；新窗口有延迟时用 WebDriverWait(driver, 10).until(EC.new_window_is_opened(windows))。
  • 关闭后句柄失效：driver.close() 关闭当前窗口后必须重新获取窗口句柄列表并切到剩余窗口；窗口间传数据可用 JavaScript 的 window.dataToSend 与 opener.dataToSend。

细节补充

  • 各浏览器专用驱动：Chrome 用 chromedriver、Firefox 用 geckodriver、Edge 用 msedgedriver，对应 System.setProperty("webdriver.chrome.driver", "path/to/chromedriver") 等设置；驱动必须与浏览器版本匹配。
  • Safari 特殊：不需要设置驱动路径，只需在 Safari 中开启开发者菜单并允许远程自动化。
  • 驱动路径与远端：也可把驱动路径加入系统环境变量（如 Windows 的 PATH）省去 System.setProperty；用 Selenium Grid 或 BrowserStack、Sauce Labs 可在云端或集群按不同操作系统和浏览器组合执行测试。
  • 启动选项：ChromeOptions/FirefoxOptions 加 --headless 实现无头运行，还可配置窗口大小、禁用插件。
  • Firefox 启动代码：pip install selenium 后下载 GeckoDriver 并加进环境变量，driver = webdriver.Firefox(executable_path='/path/to/geckodriver')，用 Options 设 options.headless = True 可无头运行，结尾 driver.quit()。
  • 兼容性兜底：确保 GeckoDriver 版本与 Firefox 浏览器和 Selenium 库版本匹配，并捕获 WebDriverException 增强健壮性。
  • findElement 与 findElements：findElement() 匹配到多个只返回第一个，找不到抛 NoSuchElementException；findElements() 返回所有匹配元素组成的列表，找不到返回空列表不抛异常。
  • 返回类型与选法：findElement() 返回 WebElement，findElements() 返回 List<WebElement>；验证元素存在用 findElements() 判断列表是否为空，批量处理一组复选框或列表项也用它。
  • 表格读行：先 table = driver.find_element(By.ID, 'example-table')，再 rows = table.find_elements(By.TAG_NAME, 'tr')，第二行是 rows[1]，rows[1].find_elements(By.TAG_NAME, 'td') 取单元格文本列表。
  • 表格读列：列索引用 td 列表 0 起算且不含表头行，第二列即 row.find_elements(By.TAG_NAME, 'td')[1]，遍历所有行收集文本。
  • 表格动态加载：数据由 JavaScript 动态生成时用 WebDriverWait(driver, 10).until(EC.presence_of_element_located((By.ID, 'example-table'))) 等表格出现再取，否则拿到空表。
