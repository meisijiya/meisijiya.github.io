1. 如何使用 JMeter 测试文件上传接口？

🎬 面试现场

面试官（口语化）：文件上传接口用 JMeter 怎么测？

⚠️ 翻车点

最容易翻车的是漏掉 Use multipart/form-data for POST 这个复选框。不勾它，文件根本传不上去，报错时很难第一时间想到是这个开关。第二个坑是只做单次上传就收工。文件路径、文件名在项目里是会变的，不做参数化脚本就没有复用性。第三个坑是不加断言。响应返回了不等于上传成功，不加断言就无从判断。还有个常见疏漏是没加监听器，跑完根本看不到响应结果。看到报错信息跟上传八竿子打不着时——先回头查这个复选框勾没勾，往往比改 URL 省时间。

📝 回答重点

  • 文件上传我用 HTTP Request 采样器，请求方法选 POST，URL 和路径填上传接口。
  • 主线三级是 Test Plan → Thread Group → HTTP Request，Body Data 里必须勾 Use multipart/form-data for POST。
  • 然后点 Add 加一个文件类型元件、选中要上传的文件，漏勾复选框文件根本传不上去。
  • 跑完挂 View Results Tree 看响应，判断成功加 响应断言 校验状态码和内容，响应回来不等于上传成功。
  • 路径和文件名在项目里会变，我用 CSV Data Set Config 参数化，脚本才有复用性。要压测配多个线程和不同调度策略。
  • 返回数据要后续验证，用 JSON Extractor 或 Regular Expression Extractor 提取。上线命令行跑脚本接 Jenkins，插件还能补数据处理和报告能力。

📈 拔高

我一般会先手动跑通单个上传，确认 multipart 开关和断言都对了，再补参数化和压力测试。最容易被忽略的就是那个 multipart 复选框——不勾的话服务端正文解析不到文件，报错信息还不一定指向这里。跑压测前我还会回头核对断言和监听器有没有跟着参数化一起改，不然换一批数据就把断言跑挂了。

💡 主动加分的追问准备

面试官追问 你的答案
用 JMeter 测文件上传接口的步骤？ 加 HTTP Request，勾 multipart，Add 选文件。
为什么要勾 multipart/form-data？ 不勾提交形式不对，文件传不上去。
多个文件路径怎么处理？ 用 CSV Data Set Config 读路径和文件名。
怎么确认上传真的成功了？ 加响应断言，校验状态码和响应内容。
返回的数据还要拿来做别的验证怎么办？ 用 JSON Extractor 或正则提取器提取。
想在流水线里跑怎么搞？ 命令行跑脚本，接 Jenkins 这类 CI/CD。

❌ 千万别说的话

  • “传文件就是在 Body Data 里填个路径就行。” 错，得勾 Use multipart/form-data for POST，再用 Add 按钮加文件类型元件选文件。
  • “响应返回了就说明上传成功了。” 错，得加断言组件，用 Response Assertion 验证状态码和响应内容才算成功。
  • “文件路径写死在脚本里最省事。” 错，路径和文件名会变，用 CSV Data Set Config 参数化才能复用。

2. 对于 POST 请求需要传递 JSON 格式数据，如何在 JMeter 中实现？

🎬 面试现场

面试官（口语化）：用 JMeter 发 POST 带 JSON，具体怎么配？

⚠️ 翻车点

最容易翻车的是只贴了 JSON 却不设 Content-Type。服务端按表单解析，字段全丢，现象是参数没传过去。第二个坑是找不到发送参数处这个勾选项。JSON 是在 HTTP 请求取样器里往下滚到发送参数处、勾选 HTTP 请求主体数据之后才有的入口，不是随便往文本框粘。第三个坑是不做断言。请求发出去了不代表业务成功，要用响应断言校验返回数据——顺序上我会先查 Header，再查勾选，最后才怀疑断言。

📝 回答重点

  • 我一般先建测试计划、加线程组（右键”添加” -> “线程（用户）” -> “线程组”），再加 HTTP 请求 取样器，方法选 POST，填好服务器名称或 IP、端口号和具体路径。
  • JSON 不粘参数栏。在取样器里往下滚到 发送参数处、勾选 HTTP 请求主体数据 后，把 JSON 贴进文本框。
  • 还要告诉服务端是 JSON，右键”配置元件”加 HTTP Header 管理器，条目名称 Content-Type、值 application/json。
  • 结果要校验，右键”断言”加 响应断言，看返回数据是否包含或等于预期值。调试挂查看结果树看请求和响应细节。
  • 数据里有动态值或要接上一请求的返回，用内置的 正则表达式提取器 或 JSON 提取器提取前一请求响应的值，后续请求里用变量引用。
  • 要发多组数据，加 CSV 数据文件集配置元件 参数化，HTTP 请求的数据部分用变量引用 CSV 里的数据。

📈 拔高

我一般先手动跑通一条再补断言，最容易漏的就是 Content-Type 和发送参数处那个勾选。JSON 贴错位置服务端会按表单解析，字段全丢，现象是参数没传过去。我排查的顺序一般是先看 Content-Type，再看那个勾选——最后才怀疑断言写错了。

💡 主动加分的追问准备

面试官追问 你的答案
用 JMeter 发 POST 带 JSON 的完整步骤？ HTTP 请求选 POST，JSON 走 Body Data。
JSON 数据粘在哪里？ 发送参数处勾 HTTP 请求主体数据后粘贴。
为什么要设 Content-Type？ 加 HTTP Header 管理器设 application/json。
怎么确认 POST 的结果符合预期？ 加响应断言，查返回数据。
数据里有动态值或要串上一个请求的返回？ 用正则表达式提取器或 JSON 提取器取值。
要测多组数据怎么办？ 加 CSV 数据文件集配置元件，变量引用。

❌ 千万别说的话

  • “JSON 贴到参数栏，再加个 header 就行了。” 错，JSON 要在发送参数处勾选 HTTP 请求主体数据后粘贴，并且必须用 HTTP Header 管理器加 Content-Type 为 application/json。
  • “请求发出去没报错就说明成功了。” 错，得加响应断言，检查返回数据是否包含或等预期值。
  • “多组数据只能一条条改。” 错，用 CSV 数据文件集配置元件参数化，在 HTTP 请求数据部分用变量引用 CSV 里的数据。

3. 如何在 JMeter 中测试 GET 请求接口？

🎬 面试现场

面试官（口语化）：拿 JMeter 测一个 GET 接口，整个流程你走一遍给我看看。

⚠️ 翻车点

最容易漏掉的是监听器和参数化。只把请求发出去、不挂 View Results Tree 看结果，等于没测——很多人就是跑到这里以为自己测完了。只测一组固定路径，也不叫覆盖。另外线程组的三个参数（线程数、Ramp-Up Period 秒、循环次数）不是可选项，不填就等于压测参数没定义。

📝 回答重点

  • 我先点”文件” -> “新建”建一个测试计划，右键”添加” -> “Threads(Users)” -> “Thread Group”，把线程属性设好：线程数（Number of Threads）、**Ramp-Up Period (秒)**、循环次数（Loop Count），这三个决定并发量和执行轮次。
  • 线程组下右键”添加” -> “Sampler” -> HTTP Request，协议填 http 或 https，服务器名称或 IP、端口、路径按 GET 接口填。
  • 只发请求不看结果等于没测，我再”添加” -> “Listener” -> View Results Tree，保存运行后在结果树里看响应数据。
  • 路径参数要变，加 “Config Element” -> User Defined Variables 定义变量，路径、参数处直接引用。多组数据用 CSV Data Set Config 从外部 CSV 读参。
  • 校验返回用断言：响应断言、JSON 断言都行，检查响应数据是否包含特定文本或 JSON 路径。看性能用 Aggregate Report 看累计结果。
  • 大并发用分布式测试，主从模式跑多个 JMeter 实例模拟大量并发用户。要上线就命令行（非 GUI）跑接 CI/CD，插件还能补图表、复杂协议和更多监听器类型。

📈 拔高

我通常先手动跑通一条 GET 再看结果树和断言，确认对了才补参数化和聚合报告。最容易被忽略的是线程组的三个参数，不填并发量就没定义。压测前我还会把 GUI 里的结果监听器开销降下来，树开太大反而拖慢结果。

💡 主动加分的追问准备

面试官追问 你的答案
路径里有一堆固定参数，每次改都要动采样器吗？ 加 User Defined Variables，路径参数直接引用。
想用多组数据跑同一个 GET 接口怎么办？ 用 CSV Data Set Config 从外部 CSV 读。
怎么确认返回结果是对的？ 加响应断言或 JSON 断言，查文本和路径。
大并发怎么压？ 分布式测试，主从模式拉多实例。

❌ 千万别说的话

  • “发一次请求没报错就算测完了。” 错，只发请求不看结果没有意义，要挂监听器（如 View Results Tree）查看响应数据，并用断言校验响应是否符合预期。
  • “线程数、循环次数随便填就行。” 错，线程数、Ramp-Up Period (秒) 和循环次数是线程组的核心属性，直接决定并发量和执行轮次。
  • “JMeter 只能手动点运行。” 错，除 GUI 模式外还支持命令行模式（非 GUI 模式），对 CI/CD 流水线里的自动化测试很有帮助。

  • 必须配 HTTP Header Manager（”添加” -> “Config Element”），加一条 Header，名称 Content-Type、值 application/json，否则服务端可能按表单解析。

5. 如何在 JMeter 中测试 SOAP 请求？

🎬 面试现场

面试官（口语化）：SOAP 接口用 JMeter 怎么测，跟普通 HTTP 请求有什么不一样？

⚠️ 翻车点

两个高频失误。一是采样器选错，SOAP 要用 SOAP/XML-RPC 请求 采样器，不是普通的 HTTP Request。二是忘配 Content-Type，SOAP 请求体是 XML，Header 里要加 Content-Type: text/xml;charset=UTF-8，否则服务端不认。还有人把 XML 粘到 Parameters 里，那不是正文位置。

📝 回答重点

  • 我一般用 SOAP/XML-RPC 请求 采样器（不是普通 HTTP Request），URL 填 SOAP 服务地址，把 SOAP 请求的 XML 粘到它的数据输入框里，不是粘到 Parameters。
  • Header 必须配：HTTP Header Manager 加 Content-Type: text/xml;charset=UTF-8，否则服务端不认。
  • 校验用断言：响应断言 检查返回的 HTTP 状态码、响应消息里的文本内容。要按固定节奏压就加恒定定时器，让每个请求之间保持固定间隔模拟用户操作。
  • 响应数据往下传用后置处理器（如 正则表达式提取器），发请求前做准备用前置处理器（如”用户定义的变量”）。
  • 看性能加”聚合报告”和”图形报告”实时监控结果，分析性能瓶颈。通用参数用 HTTP Request Defaults 这类配置元件统一设。
  • JMeter 不止测 HTTP/HTTPS，还支持 JDBC（数据库连接）、JMS（Java 消息服务）、LDAP（轻量目录访问协议），复杂场景还有插件生态可以扩协议、加报告。

📈 拔高

我一般先把采样器和 Header 配对跑通一条，再补断言和定时器。最容易错的就是拿 HTTP Request 发 SOAP——服务端会因为 Content-Type 不对直接拒。

💡 主动加分的追问准备

面试官追问 你的答案
SOAP 请求的 Header 要怎么配？ Header 管理器配 text/xml;charset=UTF-8。
怎么校验 SOAP 响应对不对？ 响应断言查状态码和消息文本。
想按固定节奏压 SOAP 接口呢？ 恒定定时器控制请求间隔。
响应里的数据要传给下一个请求怎么办？ 正则表达式提取器提取后再引用。

❌ 千万别说的话

  • “SOAP 接口直接用 HTTP Request 采样器发就行。” 错，JMeter 为 SOAP 提供专门的 SOAP/XML-RPC 请求 采样器，XML 内容粘贴到它的数据输入框里。
  • “SOAP 请求不用设置 Content-Type。” 错，要配置 HTTP Header Manager，添加 Content-Type: text/xml;charset=UTF-8。
  • “JMeter 只能测 HTTP 接口。” 错，除了 HTTP/HTTPS，JMeter 还支持 JDBC、JMS、LDAP 等多种协议。

6. 如何在 JMeter 中进行参数化？参数化类型有哪些？

🎬 面试现场

面试官（口语化）：同一个接口要跑很多组不同的数据，JMeter 里参数化有哪几种做法？

⚠️ 翻车点

容易混的是四种参数化手段的适用场景。CSV Data Set Config 面向大量数据，User Defined Variables 面向全局常量，Configuration Elements（如 HTTP Request Defaults）面向通用请求参数，函数和变量面向动态生成或引用。另一个坑是作用域。User Defined Variables 一旦定义就在其层级下全程生效、不能运行时动态改，而函数与 ${VarName} 引用是可以动态取值的。

📝 回答重点

  • JMeter 参数化我主要用四种，按场景选。大量数据用 CSV Data Set Config：添加元件后配文件路径、变量名称、分隔符，从外部 CSV 读参数，比如用户名密码列表。
  • 全局常量（如 API 的 base URL）用 User Defined Variables，在 Test Plan 或线程组下加，需要的地方 ${VAR_NAME} 引用。
  • 通用请求参数（服务器地址、端口）用 Configuration Elements 里的 HTTP Request Defaults，配好默认值，子级 HTTP 请求自动引用。
  • 动态生成或引用用 函数和变量：内置函数 __Random() 生成随机数，${VarName} 引用已定义的变量。
  • 验证参数化：设个迭代数看读取，或挂 Debug Sampler 看变量替换。
  • 参数化的好处是覆盖更全、用例可复用、维护更省事，只改参数文件不动脚本。参数文件大就分模块放不同 CSV，用 Git 管版本。

📈 拔高

我一般按数据量选手段。几万条账号走 CSV，固定常量走 User Defined Variables，能动态变化的值才交给函数。最容易踩的是把 User Defined Variables 当动态值用，它定义后在作用域内就不变了。

💡 主动加分的追问准备

面试官追问 你的答案
几万个账号密码怎么喂进去？ CSV Data Set Config 读账号密码。
base URL 这种固定值也要放 CSV 里吗？ 不用，User Defined Variables 管全局常量。
怎么确认参数真的替换进去了？ 迭代数看读取，Debug Sampler 查替换。
参数值想每次随机生成呢？ __Random() 生成随机数，或自定义函数。

❌ 千万别说的话

  • “参数化就是把所有数据塞进一个 CSV。” 错，CSV Data Set Config 只是其中一种。User Defined Variables 管全局常量，Configuration Elements 管通用请求参数，函数和变量用来动态生成或引用。
  • “User Defined Variables 可以在脚本运行中被改掉。” 错，它定义之后在整个作用域内保持不变，属于静态配置。需要动态变化的值应该交给函数和变量那一类做法。
  • “参数化之后维护脚本更麻烦。” 错，参数化使脚本维护更容易，只需修改参数文件，不用更改测试脚本，还能提高用例重用性。

7. 如何使用 JMeter 进行 POST 请求测试？

🎬 面试现场

12. 如果接口的请求参数需要加密处理，你们使用的是什么加密方式？你是如何处理加密的？

🎬 面试现场

面试官（口语化）：接口参数要加密，你们用的什么算法，加密这块怎么处理的？

⚠️ 翻车点

最容易被追问倒的是密钥怎么安全地送到服务端。对称加密速度快但密钥必须保密，常见做法是用 RSA 加密 AES 密钥，再把加密后的密钥和密文一起发。另一个坑是把密钥硬编码在代码里或者把摘要、密文混在一起不区分。那样既没有完整性保护，也埋了安全隐患。

📝 回答重点

  • 参数加密我分两种：对称用 AES（支持 128、192、256 位密钥），非对称用 RSA（公钥加密、私钥解密）。常见做法是 AES 加数据、RSA 加 AES 密钥，把加密后的密钥和密文一起发。
  • 流程走四步：生成随机 AES 密钥 → AES 加密请求参数（填充方式如 PKCS7Padding，保证数据块大小合规） → 用 RSA 加密这把 AES 密钥 → 服务器先用 RSA 私钥解开 AES 密钥，再解密数据。
  • 选 AES 是因为它对数据块逐块加密、处理大量速度快，多轮置换代换提供的安全性也很高。RSA 是一对密钥，公钥可以公开分发、验证身份，还能做数字签名。
  • 保证完整性：对请求参数做 SHA-256 哈希生成摘要，和加密数据一起发，防止被篡改。
  • 密钥不能硬编码在代码里，摘要和密文要分开。性能上只对敏感信息加密，整体通信走 HTTPS 再加一层保障。

📈 拔高

我一般把 AES 加数据、RSA 加 AES 密钥分清楚，再加 SHA-256 做完整性。最容易踩的是把密钥硬编码进代码，或者把摘要和密文混在一起不区分。

  • 手动加就点 Add 填名称、值、域、路径，服务端下发的 Set-Cookie 它也自动带到后续请求。
  • 只想给单个请求带 Cookie 就挂那个 HTTP 样本下面，挂计划层面就对整个测试计划的请求生效。

  • 配套还有 HTTP Header 统一加头，Cache Manager 管缓存，做请求定制优化。

16. 如何在 JMeter 中进行断言？

🎬 面试现场

面试官（口语化）：接口返回的结果怎么判断对不对，JMeter 里的断言是怎么加的？

⚠️ 翻车点

两个常见误区。一是只加一种断言，JSON 接口还用响应断言去匹配关键字，XML 接口不用 XPath 断言，定位能力很弱。二是忽略断言之间的关系。同一个请求节点下挂多个断言时，它们是 AND 关系，所有断言都必须通过，这条请求才算成功，漏配一个就可能把失败请求放过。

📝 回答重点

  • 加断言就三步：找到请求节点，右键”添加（Add）” -> “断言（Assertions）”，挑断言类型，再配参数（匹配内容、模式、响应时间这些）。
  • 响应内容里查关键字、正则或响应码，我用 响应断言（Response Assertion），最常用，比如看返回 JSON 里有没有某个关键字。
  • 返回是 JSON 就上 JSON 断言，校验特定字段和值，精确核对数据结构。返回是 XML 就用 XPath 断言，用 XPath 表达式定位检查文本，web 服务的 XML 特别吃这套。
  • 卡响应时间的场景用 Duration Assertion（响应时间断言），确保服务器在规定时间内返回。
  • 校验逻辑复杂就写自定义断言：BeanShell Assertion 或 JSR223 Assertion，用 Groovy、BeanShell、JavaScript 脚本做复杂校验。
  • 同一请求下挂多个断言是 AND 关系，全部通过才算成功，漏配一个就可能放过失败请求。

📈 拔高

选断言我按响应格式走——JSON 用 JSON 断言、XML 用 XPath 断言，别拿响应断言硬匹配。多断言挂一起时记得是 AND，有一个挂整条请求就算失败。

18. 如何在 JMeter 中处理 HTTPS 证书？

🎬 面试现场

面试官（口语化）：测 HTTPS 接口的时候证书这块你们怎么处理的？

⚠️ 翻车点

最容易漏的是证书的信任链位置。只生成了 CA 证书却不导入浏览器的受信任的根证书颁发机构存储区，HTTPS 流量照样抓不到、照样报错。另外协议与端口要配对。HTTP 请求采样器里协议要设成 https，服务器和端口也要对应，否则前面的证书都白配。还有人以为 JMeter 内置机制能自动信任任意证书，那是不成立的。

📝 回答重点

  • 抓 HTTPS 流量第一步是生成 JMeter CA 证书：启动 HTTP(S) 测试脚本记录器，它会自动生成一个用来捕获 HTTPS 流量的 CA 证书。
  • 证书文件在 $JMETER_HOME/bin 下，叫 ApacheJMeterTemporaryRootCA.crt，还要导入你执行测试那个浏览器的受信任的根证书颁发机构存储区，这步漏了流量照样抓不到。
  • 请求侧也要配对：HTTP 请求采样器里”协议”设成 https，目标服务器和端口填准。
  • 测试环境用自签名证书很常见，配系统属性 javax.net.ssl.trustStore 和 javax.net.ssl.trustStorePassword 指向可信存储就行。
  • 环境里证书链多就靠别名和信任链分开管，keytool 命令行工具能批量导入证书、管密钥库。
  • 对安全性有要求就调 https.default.protocol 和 https.socket.protocols 指定 TLS 版本和加密算法。证书过期是自动化里的常见坑，要么设系统参数，要么执行前检查更新证书。

📈 拔高

我一般把”生成 CA、导浏览器、协议设 https”当成固定三步走，最常漏的就是导浏览器那步。自签名证书别想着自动信任——指到 trustStore 才稳。

面试前 10 分钟速查

JMeter 请求配置

  • POST 参数位置：POST 参数写在 HTTP 请求采样器的 “Body Data” 选项卡，键值对格式，例如 username=admin&password=123456；写成 Parameters 里拼在 URL 上虽能通，但与真实调用形态不一致。
  • POST 发 JSON：HTTP 请求采样器里往下滚到”发送参数处”，勾选”HTTP 请求主体数据”后粘贴 JSON；再用 “HTTP Header Manager” 加一条 Content-Type 值为 application/json，否则服务端按表单解析、字段全丢。
  • JSON 请求体与请求头分离：请求体中的 JSON 写在 “Body Data” 里（不是 Parameters），Content-Type 必须通过 “Config Element” -> “HTTP Header Manager” 显式设为 application/json，漏配常表现为接口返回 415 或解析成空对象。
  • 文件上传接口：在 “Body Data” 部分勾选 “Use multipart/form-data for POST”，再点 “Add” 添加文件类型的元件选择要上传的文件；路径与文件名会变，用 CSV Data Set Config 参数化，并加响应断言校验状态码与响应内容、挂 “View Results Tree” 看结果。
  • GET 接口测试：测试计划下加 Thread Group，设定线程数、Ramp-Up Period (秒)、循环次数 (Loop Count)，再加 HTTP Request 配置协议、服务器名称或 IP、端口号与路径；路径里的固定参数放到 “Config Element” -> “User Defined Variables” 里用 ${VAR_NAME} 引用。
  • SOAP 请求：用专门的 “SOAP/XML-RPC 请求” 采样器而不是普通 HTTP Request，XML 粘在它的数据输入框；再用 “HTTP Header Manager” 配 Content-Type: text/xml;charset=UTF-8。
  • 参数化的四类：CSV Data Set Config 面向大量数据（文件路径、变量名称、分隔符），User Defined Variables 面向全局常量（定义后作用域内不变、不能运行时动态改），Configuration Elements（如 “HTTP Request Defaults”）面向通用请求参数，函数和变量用于动态生成或引用（如 __Random()）。

JMeter 数据处理

  • JMeter 没有加密元件：加密靠 “JSR223 PreProcessor”（语言选 Groovy）或 “JSR223 Sampler” 写脚本，脚本里必须 vars.put 把密文回写成 JMeter 变量，再在 HTTP Request 里用 ${encodedParameter} 引用，否则请求带出去的仍是原始参数。
  • Base64 与 AES 脚本写法：Base64 用 import org.apache.commons.codec.binary.Base64 调 encodeBase64String；AES 用 javax.crypto.Cipher 与 javax.crypto.spec.SecretKeySpec，密钥需 16 字节。
  • 密文响应的断言方式：不能拿明文关键字去匹配密文，先用 “JSR223 PostProcessor” 或 “BeanShell PostProcessor” 调 prev.getResponseDataAsString 解密并存进变量（如 ${decryptedResponse}），再用 “Response Assertion” 把 “Apply to” 选成 “JMeter Variable” 并填该变量名。
  • 提取上一步的加密数据：用”正则表达式提取器”配置引用名、正则表达式、模板 $1$、匹配数字 1、默认值 NOT_FOUND，下一个请求用 ${引用名} 显式引用；标准 JSON 用 JSON 提取器配 JSON 路径 $..encryptedData，XML 用 XPath 提取器配 //encryptedData/text()。
  • 跨线程组传参：普通 JMeter 变量作用域仅限当前线程组，要动态跨组用全局属性对象 props——一组里 props.put(“variableName”, “value”)，另一组里 props.get(“variableName”)；用户定义的变量虽全组可访问但运行中不可动态变化，CSV Data Set Config 适合大量参数不适合单参数。
  • 加密方案选型：用 AES 加密业务数据（AES 支持 128 位、192 位和 256 位密钥），用 RSA 加密 AES 密钥后与密文一起发送，密文接口还要用 SHA-256 摘要校验完整性、密钥不得明文存放在代码或日志中。
  • 密文接口的测试维度：解密后与期望数据比对、特殊字符与长字符串边界、密文泄露与重放风险、AES256 通常比 AES128 更安全、加密模式 GCM 自带完整性检验、性能上加解密开销。

JMeter 校验与通知

  • Cookie 管理：HTTP 样本下右键 Add -> Config Element -> HTTP Cookie Manager，点 Add 填名称、值、域、路径；它默认自动处理服务器下发的 Set-Cookie 并带到后续请求，可用 Clear Cookies each iteration 选项在每次迭代时清掉，Policy 默认是标准浏览器行为。
  • Header 的两种加法：多个请求共享同一 Header 用 “HTTP Header Manager”（默认 Header 只在请求未显式指定时才生效），单个请求的定制需求直接写在 HTTP 请求的”头部信息”部分；动态值可用 User Defined Variables、CSV Data Set Config 或 BeanShell PreProcessor、JSR223 PreProcessor 动态设置。
  • 断言类型：响应断言（字符串、正则、响应码）、JSON 断言（按 JSON 路径和值精确校验）、XPath 断言（XML 响应）、响应时间断言（限定响应时长）、自定义断言（BeanShell Assertion 或 JSR223 Assertion，写 Groovy、BeanShell、JavaScript）。
  • 多断言是 AND 关系：同一请求节点下添加的多个断言必须全部通过，该请求才算成功；只配一种断言会让定位能力偏弱。
  • 自动发结果邮件：用内置的 SMTP Sampler，填 SMTP 服务器地址、用户名、密码、发件人与收件人，并在目标监听器上设条件（如测试执行完毕时发送）；能否发出取决于网络访问权限与服务器配置，Gmail 要先开两步验证、再用应用专用密码（App Password）登录。
  • 报告与 CI/CD：用”聚合报告”或”图形结果”收集统计信息，配合 “Beanshell Sampler” 或 “JSR223 Sampler” 生成报告内容；也可把 JMeter 集成到 Jenkins，用 Jenkins 自带的邮件插件在每次代码更新后自动触发并反馈结果。

JMeter 安全与代理

  • HTTPS 证书三步：启动 HTTP(S) 测试脚本记录器生成 JMeter CA 证书，把 $JMETER_HOME/bin 目录下的 ApacheJMeterTemporaryRootCA.crt 导入浏览器的受信任的根证书颁发机构存储区，再把 HTTP 请求采样器的协议设为 https 并配准服务器与端口。
  • 自签名证书：配置系统属性 javax.net.ssl.trustStore 与 javax.net.ssl.trustStorePassword 指向自签名证书的可信存储；JMeter 内置机制并不会自动信任任意 HTTPS 站点。
  • 证书链与 TLS 版本：多证书链场景用不同别名管理并用 keytool 批量导入、管理密钥库；通过 https.default.protocol 与 https.socket.protocols 指定 TLS 版本与加密算法；证书过期会影响测试结果，需用系统参数或在执行前检查并更新。
  • 代理录制流程：选 Fiddler、Charles Proxy 或 Burp Suite，配置监听端口（Fiddler 通常监听 8888，改端口前确认未被占用），把浏览器/移动端 WiFi/代码请求指向该端口（Fiddler 通常监听 8888；Python 里用 requests 库的 proxies 参数），录完导出（Charles Proxy 可导出 HAR 文件）重放成脚本。
  • HTTPS 流量解密：要解密必须安装代理工具提供的证书，例如在浏览器的信任证书管理中安装 Fiddler 根证书，只配端口不解密只会录到握手失败。
  • HTTPS 接口的验证范围：确认 URL 以 https 开头、请求方法与请求头按接口文档配置；自签名证书在工具内加信任配置，更推荐把证书加载到客户机信任存储，而不是长期用 verify=False；除功能外还要做安全性测试，可用 OWASP ZAP 或 Burp Suite 做漏洞扫描和渗透测试。

Requests 基础

  • 七种请求方法：requests.get、requests.post、requests.put、requests.delete、requests.head、requests.patch、requests.options；head 与 GET 类似但不返回响应体、仅返回响应头，options 用于获取服务器支持的 HTTP 方法。
  • 常用参数：超时要显式设置（如 requests.get(url, timeout=3)）避免程序卡死；认证用 HTTPBasicAuth；文件上传用 POST 的 files 参数（如 files = {‘file’: open(‘report.xls’, ‘rb’)}）；大文件用流式请求 requests.get(url, stream=True) 配合 response.iter_content(chunk_size=1024) 逐块处理以改善内存使用。
  • JSON 接口四步：requests.post(url, headers=headers, data=json.dumps(data))，headers 里 Content-Type 设为 application/json，响应判 status_code == 200 并调 response.json()，异常分别捕获 HTTPError、ConnectionError、Timeout、RequestException 并配 logging 记录请求与响应。
  • 请求头：headers 必须以字典形式传，一个头名对应一个值；常用 Content-Type、Accept、Authorization、Cookie；想确认实际发出的头可用 response.request.headers 回读。
  • 带 Cookie 的三种写法：构造字典作为 cookies 参数传、或在 headers 里手工拼 ‘Cookie’ 字符串、或用 requests.cookies.RequestsCookieJar 以 jar.set 设置 domain 与 path 处理复杂场景；已知一批 Cookie 也可用 requests.utils.cookiejar_from_dict() 构造后赋给 session.cookies。
  • Session 与 Cookie 持久化：用 requests.Session() 贯穿全流程，登录请求返回的 Cookie 自动保存、后续请求自动携带；长时间跑的测试可把 session.cookies 用 pickle 序列化存文件再载入；requests 不受浏览器 Same-Origin Policy 限制，跨域靠设定合适头部解决；账号密码等敏感数据走环境变量或密钥管理服务。
  • HTTPS 证书三种处理：verify=False 忽略验证（只在可信的开发/测试环境用）、verify='/path/to/ca-bundle.crt' 指定 CA 证书文件或完整证书链、cert=('/path/client.crt', '/path/client.key') 提供客户端证书；更精细的 TLS 版本与密码套件控制靠 requests.Session 设置自定义 SSLContext。

接口自动化工程化

  • 用例间参数传递：在 conftest.py 里用 @pytest.fixture 定义返回共享参数的 fixture，测试函数按参数名声明就能拿到（不要用全局变量硬传）；作用域可选 function、class、module、session，作用域越大创建和销毁次数越少；fixture 之间还能互相依赖构建数据依赖链。
  • 用例数据管理：数据与脚本分离，存放在 Excel、JSON、CSV 文件或数据库表中，按功能或模块分成测试套件，用 Git 做版本控制；设计要覆盖正常情况、异常情况（传非法参数看错误信息）与边界情况（空值、最大最小值）。
  • 签名与 Token：签名是按特定算法（如 HMAC、MD5）对请求数据与密钥做哈希，用 hmac.new(secret_key.encode(), message.encode(), hashlib.sha256).hexdigest() 得到十六进制串，参数按 key 排序拼成 key=value&key=value 作为 message；Token 由授权服务器用用户名密码认证获取，要考虑有效期与刷新机制；请求头分别放 Signature 与 Authorization: Bearer {token}。
  • 数据驱动的落地方式：Java 用 JUnit 的 Parameterized 配 Apache Commons CSV 遍历 CSV；Python 用 unittest 配 pandas 读 Excel（pd.read_excel 后 iterrows 逐行断言）；Web 用 Selenium 配 TestNG 的 DataProvider 从 Excel 取数。
  • 参数化类型与实现方法：类型分值参数化、文件参数化、数据库参数化、环境变量参数化、API 参数化；实现上可在代码里硬编码（不推荐）、读测试数据文件（Excel 用 Apache POI、CSV 用 OpenCSV）、用配置文件或环境变量、用框架自带的数据驱动功能（TestNG 的 DataProvider、JUnit 的 Parameterized）、或直接用 JDBC 查库并缓存结果。
  • 随机数据生成：random.randint 生成整数、random.uniform(1.5, 6.5) 生成范围内浮点数，random.seed(42) 固定种子保证可重复（调试与回归必须），随机字符串用 string.ascii_letters 配 random.choice 拼出指定长度（如 8 位），需要更复杂的随机能力时改用 numpy（np.random.randint、np.random.uniform）。
  • 流水线接入：用例框架如 RestAssured、Postman、JMeter、Robot Framework 结合 Jenkins、CircleCI 做定时执行与结果报告，代码提交后立即跑测试以快速反馈。
