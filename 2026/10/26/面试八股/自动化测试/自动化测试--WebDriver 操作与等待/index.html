1. 元素有哪些常用操作方法？

🎬 面试现场

面试官（口语化）：找到元素之后，一般对它做哪些操作？Selenium 里对应哪些方法？

⚠️ 翻车点

容易只答”click 和 send_keys”，漏掉五类操作里的获取属性（get_attribute、text）和校验状态（is_displayed、is_selected）——测试里大量断言就靠这两个。另外一个高频坑是等待方式混用：网页加载时间可能不确定，需要显式等待（WebDriverWait）和隐式等待（implicitly_wait）配合元素加载完成。

📝 现场作答

  • 在进行 Web 自动化测试时，元素常用的操作方法主要包括以下几类：
    1. 查找元素：通过不同的选择器来查找页面上的元素，例如 find_element_by_id、find_element_by_name、find_element_by_xpath 等。
    2. 交互操作：对元素进行点击、输入文本、清除文本框等操作，例如 click、send_keys、clear。
    3. 获取属性：获取元素的属性值，例如 get_attribute、text。
    4. 等待元素：等待页面元素加载完成，例如显式等待 WebDriverWait 和隐式等待 implicitly_wait。
    5. 校验状态：验证元素是否可见、是否显示、是否选中等，例如 is_displayed、is_selected。
  • 每一类的具体写法：
    • 查找元素：在 Selenium 中，通过不同的方式来定位页面元素是基础操作。常见的方法有：find_element_by_id 通过元素的 ID 属性查找；find_element_by_name 通过元素的 name 属性查找；find_element_by_xpath 通过元素的 XPath 路径查找，在复杂的页面结构中尤其有用；find_element_by_css_selector 通过 CSS 选择器查找，灵活且简洁。
  • 交互操作：找到元素之后，可以对其进行各种交互操作，click 是点击元素，send_keys 是输入文本，clear 是清空输入框。
  • 获取属性：在测试中，经常需要获取元素的属性来进行验证，get_attribute 获取指定属性的值，text 获取元素的文本内容。
  • 等待元素：网页加载时间可能不确定，因此需要适当地等待元素加载，显式等待是 WebDriverWait，等待特定条件成立；隐式等待是 implicitly_wait，设置全局等待时间。
  • 校验状态：可以验证元素的不同状态来确保测试的准确性，is_displayed 判断元素是否可见，is_selected 判断元素是否被选中。

怎么判断元素是否显示出来了？ 用校验状态的方法，is_displayed 判断元素是否可见，is_selected 判断元素是否被选中。

2. WebDriver 操作浏览器有哪些常用方法？

🎬 面试现场

面试官（口语化）：WebDriver 有哪些操作浏览器本身的常用方法？close() 和 quit() 有什么区别？

⚠️ 翻车点

最容易答错的是 close() 和 quit() 的区别：close() 仅关闭当前窗口，常用于有多个窗口的场景；quit() 则会关闭所有浏览器窗口并结束 WebDriver 进程，通常在测试完成时使用。另一个容易漏的是 navigate() 和 get(url) 的关系——navigate().to(url) 类似于 get(url)，但还提供 back()、forward()、refresh() 等功能；以及 manage() 里可以设置隐式等待时间、最大化窗口这类浏览器设置。

📝 现场作答

  • WebDriver 是 Selenium 提供的用于操作浏览器的核心工具，常用方法有：
    1. get(url)：打开指定的 URL。
    2. findElement(by)：根据某个条件查找单个元素。
    3. findElements(by)：根据某个条件查找多个元素，返回一个列表。
    4. getTitle()：获取当前页面的标题。
    5. getCurrentUrl()：获取当前页面的 URL。
    6. getPageSource()：获取当前页面的源代码。
    7. close()：关闭当前窗口。
    8. quit()：关闭所有关联的窗口，退出 WebDriver。
    9. navigate()：用于浏览器导航，含有前进、后退、刷新等功能。
    10. manage()：用于管理浏览器的一些设置，比如窗口大小、超时设置等。
  • 每个方法的典型用途：
    • **get(url)**：这是通常用来打开特定网页的方法，例如 driver.get("http://example.com")，会让浏览器直接跳转到指定的 URL。
    • **findElement(by) 和 findElements(by)**：这两个方法用于查找网页元素，比如按钮、输入框等。使用方式多种多样，可以通过 ID、类名、标签名、XPath 等多种方式查找。例如 driver.findElement(By.id("submit")) 或 driver.findElements(By.className("items"))。
    • **getTitle()**：页面标题通常用于验证页面是否加载正确。例如 assert "Google" in driver.getTitle()。
    • **getCurrentUrl()**：获取当前页面的 URL 可以验证页面跳转是否正确。例如 assert "dashboard" in driver.getCurrentUrl()。
    • **getPageSource()**：获取页面源代码对于调试很有帮助，可以检查特定元素或者文本是否在页面上。
    • **close() 和 quit()**：close() 仅关闭当前窗口，常用于有多个窗口的场景；quit() 则会关闭所有浏览器窗口并结束 WebDriver 进程，通常在测试完成时使用。
    • **navigate()**：navigate().to(url) 类似于 get(url)，但还提供 back()、forward()、refresh() 等功能。例如 driver.navigate().back() 返回上一个页面。
    • **manage()**：这个方法包含了很多有用的管理功能，比如 manage().timeouts().implicitlyWait(10, TimeUnit.SECONDS) 设置隐式等待时间，或 manage().window().maximize() 最大化窗口。

3. WebDriver 如何操作鼠标？

🎬 面试现场

面试官（口语化）：WebDriver 怎么模拟鼠标操作？双击、右键、拖拽分别怎么写？

⚠️ 翻车点

最容易漏的是 perform()——Actions 类的方法只是把操作串成动作链，必须调用 perform() 才会真正执行。另一个坑是动作链的组合写法：clickAndHold()、moveByOffset()、release() 这些要链式调用后一次性 perform。容易被忽略的还有两点：无头浏览器（如 HtmlUnitDriver 或 Headless Chrome）中某些鼠标操作可能不完全支持；以及不同浏览器上 Actions 的行为可能有所差异。

📝 现场作答

  • WebDriver 操作鼠标主要通过 Actions 类来实现。Actions 类提供了一系列的方法，可以模拟鼠标的各种操作，例如点击、双击、右键单击、拖拽等。
  • 使用步骤：
    1. 创建 Actions 对象：需要传递一个 WebDriver 实例作为参数。
    2. 使用 Actions 类的方法：例如 click()、doubleClick()、contextClick()、moveToElement()、clickAndHold()、release()、dragAndDrop()、moveByOffset() 等等。
    3. **调用 perform()**：将上述操作加上 perform() 方法执行动作链。
  • 相关要点：
    • 复合操作：Actions API 不仅支持单个操作，还支持链式调用进行复合操作。例如，可以将多步操作组合在一起，然后通过 perform() 一次性执行。
  • 等待条件：在实际测试中，元素的加载速度和时间存在不确定性，所以良好的实践是使用 WebDriver 的 WebDriverWait 类来进行等待，确保元素可操作。
  • 无头浏览器：在无头浏览器（如 HtmlUnitDriver 或 Headless Chrome）中，某些鼠标操作可能不完全支持。因此在自动化测试中，如果鼠标操作不正常，可以考虑是否与浏览器类型有关。
  • 鼠标操作的调试和捕获错误：在鼠标操作频繁的场景下，可能会遇到操作失败或异常，这时可以通过截图、日志等方式进行调试。有时，还可以尝试增加操作之间的等待时间。
  • 跨平台操作：尽管 Selenium 的 Actions 类较好地模拟了各种操作，但不排除在不同浏览器上行为有所差异。在不同操作系统或浏览器版本进行测试，有助于发现潜在兼容性问题。

4. Web 自动化测试中，WebDriver 如何开启和退出一个浏览器？

🎬 面试现场

面试官（口语化）：用 WebDriver 跑一个浏览器，从开起来到关掉，代码怎么写？quit 和 close 有区别吗？

⚠️ 翻车点

最容易翻车的是把 quit() 和 close() 混为一谈：quit() 关闭所有关联的窗口并且完全退出浏览器，close() 只关闭当前窗口，但如果只剩下一个窗口，它也会退出浏览器。另一个坑是忘了配驱动，Chrome 需要 chromedriver，并且要把路径加进系统环境变量，或者在代码里指定。还有人只答开启不答退出，以及把「无头模式」当成默认——无头是要通过浏览器选项显式配置的。

📝 现场作答

  • 开启和退出浏览器通常需要以下步骤：
    1. 开启浏览器：首先创建一个 WebDriver 实例，例如要启动 Chrome 浏览器，可以通过 webdriver.Chrome()。
  1. 退出浏览器：通常使用 driver.quit() 或者 driver.close()。这两者有细微的差别：driver.quit() 关闭所有关联的窗口并且完全退出浏览器；driver.close() 关闭当前窗口，但如果只剩下一个窗口，它也会退出浏览器。
  • 相关的几个点：
    1. 浏览器驱动：WebDriver 需要一个对应浏览器的驱动程序来与浏览器进行通信。对于 Chrome 来说，需要 chromedriver，可以根据操作系统下载相应的驱动程序，并且将其路径添加到系统环境变量。
    2. 浏览器选项：可以通过配置浏览器选项来设置浏览器的一些属性，例如禁用扩展、无头模式运行（即不显示 GUI 的模式）。
  1. 等待机制：在自动化测试中，需要处理元素加载时间不一致的问题。Selenium 提供了显式等待和隐式等待来应对此类情况；显式等待通过 WebDriverWait 类来实现，可以等待特定元素的出现。
  1. 浏览器的其他操作示例：获取网页标题用 driver.title；查找页面元素如 driver.find_element(By.NAME, 'q')；截屏用 driver.save_screenshot('screenshot.png')。

5. Web 自动化测试中，如何查找屏幕上是否显示了元素？

🎬 面试现场

面试官（口语化）：怎么判断页面上某个元素是不是显示出来了？找不到和显示不出来怎么区分？

⚠️ 翻车点

最容易答成「用 find_element 找到了就说明显示了」——找到元素不等于元素可见，is_displayed() 才是判断可见的那一步。第二个坑是只答一种情况：元素在 DOM 里存在但不可见（is_displayed() 返回 False）和元素根本不存在（抛异常）是两回事，脚本里通常要用 try/except 把「未找到」和「未显示」分开。还有人不用等待，直接查就断言，页面还没渲染完就判失败。

📝 现场作答

  • 在 Web 自动化测试中，通常使用一些测试框架（如 Selenium）来查找并验证页面上的元素是否存在并显示出来，具体步骤：
    1. 定位到目标元素：可以使用 ID、类名、名称、XPath 或 CSS 选择器等定位方法。
    2. 检查元素是否可见：Selenium 提供了 is_displayed() 方法，可以用它来判断元素是否可见。
  • 其他相关的方法和技术：
    1. 等待元素：有时候页面加载需要时间，使用隐式等待（implicitly_wait）或显式等待（WebDriverWait 和 expected_conditions）更好地处理页面元素加载问题。

⚠️ 翻车点

最容易答漏的是两者异常类型不同：显式等待在超时时间内条件满足就继续执行，否则抛出超时异常；隐式等待在指定时间内找不到元素，抛出找不到元素异常。另一个高频坑是”两种等待可以同时使用”——虽然可以同时使用，但这样有可能会引发复杂的等待时间计算问题，不建议混用。

📝 现场作答

  • 显式等待（Explicit Wait）和隐式等待（Implicit Wait）是 Selenium WebDriver 中的两种等待策略，用于网络测试时处理元素加载问题，二者的主要区别如下：
    1. 显式等待：为某个特定的元素设置一个条件（Condition）和最长等待时间。在这个时间内，WebDriver 会每隔一定的时间检查条件是否满足。如果在超时时间内条件满足了，那么程序继续执行，否则抛出超时异常。例如，等待一个按钮变为可点击状态。

最容易只答「隐式等待和显式等待两种」——实际是三种：隐式等待、显式等待、自定义等待（Fluent Wait），后者是显式等待的一种变体。第二个坑是说不清作用域：隐式等待是全局设置的，查找元素时统一等这么久；显式等待针对某个元素、等某个条件成立。第三个坑是忽略内置条件：Selenium 提供了多种内置的 ExpectedConditions，比如 elementToBeClickable、visibilityOfElementLocated、presenceOfElementLocated，配合使用才有效率。还有人只等固定时间，而不是配合具体的 ExpectedConditions 条件。

📝 现场作答

  • 在 Selenium 中，主要有三种类型的等待：隐式等待（Implicit Wait）、显式等待（Explicit Wait）和自定义等待（Fluent Wait）。
  • 三者的区别：
    1. 隐式等待（Implicit Wait）：这是全局设置的等待方式，即在设置这个等待时间后，WebDriver 会在查找元素时等待该时间的到达。每次查找元素时，WebDriver 都会等待指定的时间，直到找到元素或超时。隐式等待的好处是设置简单，但不够灵活。

    1. 显式等待的条件：Selenium 提供了多种内置的 ExpectedConditions，例如 elementToBeClickable、visibilityOfElementLocated、presenceOfElementLocated 等等，可以与显式等待一起使用。对于一些需要等待页面加载完毕或某个按钮可点击的场景，利用这些条件非常有效。
    2. 等待的最佳实践：优先选择显式等待而不是隐式等待，因为显式等待能够提供更加精确和灵活的控制；使用显式等待时最好与具体的 ExpectedConditions 条件结合使用，而不是单纯等待固定时间；通过调试和分析，尽量减少不必要的等待时间，以提高脚本的运行速度和效率。

27. Web 自动化测试中，findElement() 和 findElements() 有什么区别？

🎬 面试现场

面试官（口语化）：findElement() 和 findElements() 有什么区别？什么时候用哪个？

⚠️ 翻车点

最容易漏掉异常行为这一条，这是两个方法最本质的差别：findElement() 找不到会抛 NoSuchElementException 异常，findElements() 找不到返回空列表而不抛异常。第二个坑是返回类型说糊——一个是 WebElement 对象，一个是 List<WebElement> 对象。第三个坑是选错方法：验证页面上是否存在某个元素时，findElements() 更合适，只需要判断列表是否为空；页面结构复杂时应尽量使用定位更精确的策略，以提高查找效率。

📝 现场作答

  • findElement() 和 findElements() 是 Web 自动化测试中用于定位页面元素的重要方法，但它们有一些关键的区别：
    1. **findElement()**：用于根据指定的定位策略（如 ID、Class Name、XPath 等）找到页面上的单个元素。如果匹配到多个元素，它只返回第一个；如果一个都找不到，它会抛出 NoSuchElementException 异常。
    2. **findElements()**：根据指定的定位策略返回页面上所有匹配的元素，组成一个列表。如果找不到任何元素，它会返回一个空列表，而不会抛出异常。
  • 延伸的几点：
    1. 返回类型：findElement() 返回的是一个 WebElement 对象；findElements() 返回的是一个 List<WebElement> 对象。
    2. 异常处理：使用 findElement() 时，如果找不到元素，程序会抛出异常，需要注意异常捕获；使用 findElements() 时，不需要捕获异常，但需要判断返回的列表是否为空，以避免后续代码因空列表而出错。
    3. 性能考虑：在需要验证页面上是否存在某种元素时，findElements() 会更适合，因为我们只需要判断返回的列表是否为空，而不需要处理异常；在页面结构复杂的情况下，尽量使用定位更精确的策略，以提高查找效率。
    4. 实际案例：在表单自动化测试中，常常需要检查表单中是否有特定的输入框或者按钮，使用 findElement() 可以方便地进行快速定位并操作，比如点击一个按钮或填写一个输入框；在需要检查某个页面上多处存在的重复元素（如一组复选框或者一组产品列表项）时，findElements() 可以帮助我们获取所有匹配的元素，进而进行批处理操作。

WebDriver 基本操作

  • 元素操作五类：查找元素（find_element_by_id、find_element_by_name、find_element_by_xpath、find_element_by_css_selector）、交互（click、send_keys、clear）、取属性（get_attribute、text）、等待（显式 WebDriverWait、隐式 implicitly_wait）、校验状态（is_displayed、is_selected）。

等待机制

  • 显式等待机制：WebDriverWait 以固定时间间隔检查某个特定条件，条件满足即继续，否则等到超时；实现靠 WebDriverWait 类配合 ExpectedConditions 类。
  • 显式等待写法：WebDriverWait(driver, 10).until(EC.presence_of_element_located((By.ID, "myElement"))) 表示最长等 10 秒直到该 ID 元素出现。
  • 隐式等待机制：driver.implicitly_wait(10) 后 WebDriver 在指定时间内不断重新尝试查找元素，找到即立即执行后续操作；超时找不到才抛 NoSuchElementException。
  • 隐式等待作用域：声明一次，整个 WebDriver 实例查找元素时都用这个等待时间，通常在用例一开始设置，作用于整个 WebDriver 生命周期。
  • 核心差异：显式等待针对特定元素设条件与最长等待时间，超时抛超时异常；隐式等待为 WebDriver 设定全局最长等待时间，不停检查 DOM 直到找到元素，找不到抛找不到元素异常。
  • 等待类型数量：Selenium 有三种等待——隐式等待、显式等待、自定义等待（Fluent Wait），后者是显式等待的变体，可设最大等待时间、轮询间隔及忽略特定异常。
  • 内置等待条件：elementToBeClickable、visibilityOfElementLocated、presenceOfElementLocated 等 ExpectedConditions 条件，配合显式等待比等固定时间更高效。
  • 混用与超时：显式与隐式等待可以同时使用，但可能引发复杂的等待时间计算问题，不建议混用；超时设过短等不够、过长浪费时间，需按应用实际加载时间评估。

表单与弹层操作

  • 下拉框三种选法：Select(driver.find_element_by_id('dropdown_id')) 后用 select_by_visible_text('Option Text')、select_by_value('option_value')、select_by_index(1) 选择。
  • 多选下拉框：用 multiple 属性选择多个选项，取消选择用 deselect_by_visible_text('Option Text 1')；下拉内容动态加载时需显式等待或处理异步请求。
  • JS 弹窗：alert、confirm、prompt 由浏览器生成，用 driver.switch_to.alert 切换；alert 用 .accept() 确定，confirm 还可 .dismiss() 取消，prompt 先 send_keys("Input text") 再 accept() 提交。
  • 自定义弹层：属于网页内容的一部分，用 CSS 选择器或 XPath 找到关闭按钮点击，操作前用显式等待 EC.visibility_of_element_located((By.ID, "customPopup")) 确认可见。
  • 滚动方式：window.scrollTo(x, y) 跳到绝对坐标，window.scrollBy(dx, dy) 从当前位置做增量偏移，element.scrollIntoView() 让元素进入视窗；Selenium 侧可用 location_once_scrolled_into_view 或动作链。
  • 滚动条不需定位：滚动条是页面或元素的属性，实际依赖对目标元素位置和属性的操作；判断是否可见用 element.is_displayed()，不可见时先 scrollIntoView。
  • 文件上传：定位文件选择的 input 元素，upload_element.send_keys("C:/path/to/your/file.txt") 直接传路径，再点提交按钮；多文件用循环依次传路径。
  • 上传异常处理：上传前用 os.path.exists 检测文件是否存在，并考虑网络中断等异常；Cypress 用 cy.get('input[type="file"]').attachFile('path/to/file')。
  • 时间控件定位：find_element_by_xpath("//input[@type='date']")、find_element_by_css_selector("input[type='date']")、find_element_by_id("timePicker")、find_element_by_class_name("time-picker-class") 四条路径。
  • 动态控件写法：元素动态生成或属性变化时用低敏感度写法 //*[contains(@class, 'date-picker')]、input[id^='time']，并用 WebDriverWait 等控件加载完成；控件常拆成日历按钮和输入框两部分需分别定位。
  • 修改元素属性：用 driver.execute_script("arguments[0].setAttribute('attribute_name', 'new_value')", element) 注入 JavaScript 改 DOM 属性，理由是满足测试用例需要、绕过前端限制、增强脚本对不同 DOM 结构的适应性。

页面与窗口

  • 代理重定向原理：代理服务器在客户端和目标服务器之间充当中间人，接收并处理或修改请求后转发，响应也经代理回传，因此可实现请求层重定向而不是改代码里的 URL。
  • BrowserMob Proxy 三步：Server("/path/to/browsermob-proxy") 启动并 server.create_proxy()，用 chrome_options.add_argument("--proxy-server={0}".format(proxy.proxy)) 塞给浏览器，再 proxy.rewrite_url("http://example.com", "http://newexample.com") 写规则。
  • 其他拦截工具：Puppeteer 用 interceptRequest 做请求拦截与重定向；Mitmproxy 作为交互式抓包工具和 Python 库可精细修改请求与响应。
  • iframe 四步：定位 iframe 元素 → driver.switchTo().frame(iframe) 切上下文 → 像普通页面一样操作内部元素 → driver.switchTo().defaultContent() 切回主页面。
  • iframe 切换方式：嵌套 iframe 需逐层切换（先 switchTo().frame("first_iframe_id") 再切嵌套）；也可按索引 driver.switchTo().frame(1) 或直接传 WebElement 切换；定位不唯一会抛 NoSuchElementException。
  • 导航命令三类：打开网页 driver.get(url)、刷新页面 driver.navigate().refresh()、历史前后退 driver.navigate().back() 与 driver.navigate().forward()。
  • 导航后配套：多窗口用 driver.switchTo().window(windowHandle) 切换、句柄用 driver.getWindowHandles() 获取；会话状态用 driver.manage().getCookies()、driver.manage().addCookie(cookie)；导航后用显式等待并断言页面状态。
  • 历史来回浏览：先打开第一个 URL 再打开第二个 URL 制造历史，driver.back() 后退、driver.forward() 前进；等价写法 driver.execute_script("window.history.go(-1)") 与 window.history.go(1)。
  • 等待优于 sleep：历史导航中用 time.sleep() 简单但不稳定，实际项目推荐 WebDriverWait(driver, 10).until(EC.presence_of_element_located((By.ID, "some-element-id")))。
  • 四种刷新方式：driver.navigate().refresh()、driver.get(driver.getCurrentUrl())、用 Actions 的 sendKeys(Keys.F5).perform()、执行 ((JavascriptExecutor)driver).executeScript("location.reload()")；刷新后要等页面加载，多窗口需先切到正确标签页。
  • 窗口切换步骤：用 driver.window_handles 取全部句柄、driver.switch_to.window(windows[1]) 切换、操作完 driver.switch_to.window(windows[0]) 切回；新窗口有延迟时用 WebDriverWait(driver, 10).until(EC.new_window_is_opened(windows))。
  • 关闭后句柄失效：driver.close() 关闭当前窗口后必须重新获取窗口句柄列表并切到剩余窗口；窗口间传数据可用 JavaScript 的 window.dataToSend 与 opener.dataToSend。

细节补充

  • 各浏览器专用驱动：Chrome 用 chromedriver、Firefox 用 geckodriver、Edge 用 msedgedriver，对应 System.setProperty("webdriver.chrome.driver", "path/to/chromedriver") 等设置；驱动必须与浏览器版本匹配。
  • Safari 特殊：不需要设置驱动路径，只需在 Safari 中开启开发者菜单并允许远程自动化。
  • 驱动路径与远端：也可把驱动路径加入系统环境变量（如 Windows 的 PATH）省去 System.setProperty；用 Selenium Grid 或 BrowserStack、Sauce Labs 可在云端或集群按不同操作系统和浏览器组合执行测试。
  • 启动选项：ChromeOptions/FirefoxOptions 加 --headless 实现无头运行，还可配置窗口大小、禁用插件。
  • Firefox 启动代码：pip install selenium 后下载 GeckoDriver 并加进环境变量，driver = webdriver.Firefox(executable_path='/path/to/geckodriver')，用 Options 设 options.headless = True 可无头运行，结尾 driver.quit()。
  • 兼容性兜底：确保 GeckoDriver 版本与 Firefox 浏览器和 Selenium 库版本匹配，并捕获 WebDriverException 增强健壮性。
  • findElement 与 findElements：findElement() 匹配到多个只返回第一个，找不到抛 NoSuchElementException；findElements() 返回所有匹配元素组成的列表，找不到返回空列表不抛异常。
  • 返回类型与选法：findElement() 返回 WebElement，findElements() 返回 List<WebElement>；验证元素存在用 findElements() 判断列表是否为空，批量处理一组复选框或列表项也用它。
  • 表格读行：先 table = driver.find_element_by_id('example-table')，再 rows = table.find_elements_by_tag_name('tr')，第二行是 rows[1]，rows[1].find_elements_by_tag_name('td') 取单元格文本列表。
  • 表格读列：列索引用 td 列表 0 起算且不含表头行，第二列即 row.find_elements_by_tag_name('td')[1]，遍历所有行收集文本。
  • 表格动态加载：数据由 JavaScript 动态生成时用 WebDriverWait(driver, 10).until(EC.presence_of_element_located((By.ID, 'example-table'))) 等表格出现再取，否则拿到空表。
