05 Go 接口与隐式实现

Go 的接口不需要 implements 关键字：只要方法对得上，类型就自动满足接口——这套「编译期检查的鸭子类型」是 Go 最有辨识度的设计。

5.1 接口只描述行为，不描述数据

Go 的接口是一个具名的方法集合：不关心实现者的字段和类型名，只声明”能干什么”。

对比三种语言里接口的”长相”：

维度 Go 接口 Java 接口 Python（鸭子类型）
满足方式 隐式：方法齐了自动满足 显式 implements 纯约定，运行期才检查
检查时机 编译期 编译期 运行期（AttributeError）
能否带字段 不能，只能有方法签名 可带常量 不适用
默认方法 没有（Java 8 有 default） 有 不适用
多接口组合 嵌入接口 extends 多个 不适用
空接口 any（零方法） Object（带一堆方法） object

最容易忽略的是「检查时机」这一行。很多人以为 Go 和 Python 一样”运行期才知道对不对”，其实不是：

Go 的鸭子类型是编译期检查的。Python 里 thing.speak() 写错要等线上跑到那一行才炸，Go 里按下 go build 的那一刻就报错了：类型安全你拿到了，接口解耦的灵活性你也要到了。

还有三点要记牢：接口不是类（没有构造函数和析构函数，不持有资源）；接口里放不下数据字段（一旦有字段，它就退化成结构体的泛化版）；接口没有继承层级（Go 用”嵌入接口”组合方法集，而不是父子类关系）。

也别让接口知道谁实现了它：

要区分具体类型，用类型断言（5.4）；要额外的公共行为，用子接口组合。Firetruck 是 Car 的超集，普通轿车完全不用理会消防车的事。

5.1.1 嵌入结构体会把方法”提升”出来

Go 没有继承，但结构体嵌入会把被嵌入类型的方法提升到外层，于是外层类型自动满足相应的接口：

这也是 Go 里”组合替代继承”的实际落地方式：想要复用行为就嵌入结构体，想要多态就定义窄接口，两件事互不冲突。

5.2 隐式实现：没有 implements 关键字

Dog 和 Robot 之间没有任何继承、也没有任何声明，满足 Speaker 只因为各自定义了 Speak() string。这就是隐式实现（implicit implementation）。Java 里同样的需求必须写 class Dog implements Speaker。

省掉的不只是几个字符：Java 里实现方”主动认领”接口，形成名义依赖；Go 里是实现方”被动暴露”能力，依赖方向反了过来——消费者依赖抽象，提供者不依赖抽象。

因为满足关系是隐式的，光看代码不容易确认某个类型满不满足某个接口，Go 社区的惯用法是加一条空的编译期断言：

它什么都不干，只在编译期被看一眼：Speak 一改名就立刻失败，而不是等下游包构建时才炸。

5.2.1 三种语言写”多态”的差别

Go 的写法比 Java 少一行，比 Python 少一整类运行期错误。命名上也有惯例：Go 的接口名通常带 -er 后缀且只描述一件事（Reader、Writer、Closer、Speaker），一个接口叫 Speaker 就只该有 Speak 这类方法，别做成 SpeakerAndWriterAndCloser。

接口该由谁定义？ Go 社区和 Java 的一个关键分歧是：接口定义在使用方，而不是实现方。使用方声明自己要哪一两个方法，实现方根本不用引用这个接口，签名对得上就能传进来。规则反过来，耦合就会漏回实现侧，Java 项目里那种”接口膨胀”的痛苦就是这么来的。

5.3 接口值：一个装着「类型 + 值」的盒子

Go 的接口变量在运行时同时记录两样东西：这个值实际是什么类型（动态类型），以及这个类型的具体数据（动态值）。

%T 打印的永远是动态类型，不是接口类型本身。这就是”多态在运行时决定”的落地方式。

底层上，一个接口值由两个机器字组成：第一个字指向 itab（接口方法表，记录”这个接口要哪些方法 + 具体类型怎么实现”），第二个字指向具体数据。这个”两个字”的结构解释了很多现象，最经典的就是 == nil 的判定——接口值为空要求两个字都为空（5.6 展开）。

小接口原则。 Go 社区有句老话：接口越大，抽象越弱。接口是实现者要签的合同，条款越多愿意签字的人越少，最后往往变成”只有原始类型能实现”的摆设。标准库几乎全是小接口：

接口 方法数 方法
io.Reader 1 Read(p []byte) (n int, err error)
io.Writer 1 Write(p []byte) (n int, err error)
fmt.Stringer 1 String() string
error 1 Error() string
sort.Interface 3 Len / Less / Swap

io.Reader 只有一个方法，所以你随手写个类型就能满足它，标准库因此能接受任何”能读字节流”的东西——文件、网络连接、压缩包全都接得上。

由此推出两条准则：接口定义在消费方，且只包含消费方真正用到的方法（哪怕实现方有二十个方法，接口上也只留你要调的那两个）；接受接口，返回结构体——入参用窄接口方便替换和 mock，返回值用具体结构体让调用方能访问全部字段。

5.4 类型断言与类型 switch

当接口里装着一个具体类型，而你要把它取出来时，就需要类型断言。

v, ok := s.(T) 里的 ok 表示断言是否成功，失败时 v 是目标类型的零值，不会 panic。

写法 语义 失败时行为
v, ok := s.(T) 带 ok 的断言 ok == false，v 为零值，不 panic
v := s.(T) 直接断言 panic：interface conversion: main.Dog is not main.Robot
switch v := s.(type) 类型 switch 走 default，不 panic
s.(I)（I 是接口） 断言到另一个接口 看动态类型是否实现了 I

断言到接口类型也合法，用来检查动态类型的”隐藏能力”（如 if w, ok := s.(io.Writer); ok { ... }）。要分支处理多种类型，用类型 switch：

5.5 空接口 any：万能容器与它的账单

type any = interface{}（Go 1.18 起的别名，与 interface{} 完全等价）。any 是零方法接口，因此所有类型都满足它。

维度 Go any Java Object Python object
是否所有类型满足 是（零方法） 只对引用类型，基本类型要装箱 是（一切皆对象）
自带方法 一个都没有 一堆（toString、equals…） 一堆（__str__、__eq__…）
取出具体类型 类型断言 / 类型 switch 强制类型转换 isinstance + 转型

Java 里 (String) obj 转错了编译期就报错；Go 里 s.(string) 写错了编译期完全发现不了，只会在运行到那一行时 panic。

代价有三笔：类型安全丢失（传进去的东西对不对，只能等运行期断言才知道）；装箱分配（把非指针类型、尤其结构体赋给接口变量时，Go 要为这份数据在堆上分配空间，再把指针塞进接口的两个字里，传指针或小整数则没有额外分配）；取值必须断言（每个读取点都要写 v.(T)，写错就是运行期 panic）。

any 适合真正的”任意类型”场景：fmt.Println 的参数、encoding/json 的解码目标、运行期才决定类型的容器。它不适合当万能参数类型——Go 1.18 之后想要”通用 + 类型安全”应该用泛型（第 14 篇会专门讲）。

5.6 经典坑：接口值非 nil，却装着 nil 指针

回到 5.3 的”两个字”模型：

itab 字（动态类型） data 字（动态值）
var s Speaker = nil nil nil
var p *User = nil; var s Speaker = p 非 nil（指向 *User 的方法表） nil（数据指针为空）

s == nil 要求两个字同时为 nil，这里动态类型是 *User（非 nil），只有数据是 nil，所以整个接口值不等于 nil。更糟的是调用它：

5.7 动手练

练习一：让两个无关类型满足同一接口。 定义 type Describer interface { Describe() string }，让 Product（字段 Name、Price）和 User（字段 Name、Level）都实现它，不写任何实现声明；再写一个函数接收 []Describer 并依次打印描述。验收点：方法签名要完全一致，少一个都不行。

练习二：用类型 switch 处理混合数据。 写 func summarize(v any) string，用类型 switch 分别处理 nil、int、string、[]byte、error。验收点：case nil 要单独写；多类型分支里变量是 any 类型，还得再断言一次。

练习三：复现并修掉 nil 指针陷阱。 写 func FindUser(id int) Speaker，找不到时先返回 var p *User; return p（制造 bug），用 s == nil 验证它是 false；再用修法二改成真正的 return nil，验证它变成 true。验收点：能说清”两个字”里分别是什么。

练习四：为标准库接口提供实现。 给 Product 实现 String() string 使其满足 fmt.Stringer，用 fmt.Println(p) 和 fmt.Printf("%v|%s", p, p) 观察差异；再给一个结构体实现 sort.Interface 并排序。验收点：%v 会自动调用 String()，%d 不会——这能帮你理解 fmt 怎么”嗅探”接口。

5.8 常见错误清单

错误写法 现象 正确做法
把 nil 指针装进接口后判 s == nil 永远 false，调用方法 panic 返回具体指针类型，或显式 return nil
用 any 当万能参数 编译期查不出，运行期断言才炸 定义窄接口；要通用性用泛型
接口里加 IsFiretruck() 这类标记方法 接口膨胀，实现者被迫加无用方法 用类型断言探测，或用子接口组合
断言写成 v := s.(T) 不带 ok 失败直接 panic，请求处理中断 一律用 v, ok := s.(T)
以为 Go 和 Python 一样是运行期鸭子类型 误以为编译期不检查 Go 编译期就检查，方法对不上直接编译错误
指针接收者的方法用值类型实现接口 编译错误：method has pointer receiver 统一接收者形态：全指针或全值
接口里塞字段（type X interface { ID int }） 编译错误 接口只放方法，数据放结构体
把接口值当 map key 动态类型不可比较时 panic 用具体类型做 key
用 case nil 抓”装着 nil 指针的接口” 匹配不上 分开判断：接口本身为 nil vs 动态值为 nil

Go 的接口只有一句话：定义行为，不定义实现；消费方定义，生产方满足。而后面所有的坑，几乎都来自同一个根因——接口值是两个机器字，多数人只记住了其中一个。
