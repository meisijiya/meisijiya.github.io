02 Go 变量、基本类型与零值

变量声明看着只是几行代码，却藏着 Go 最核心的设计取舍：类型系统、零值语义，以及「绝不隐式转换」的倔强。

2.1 三种声明方式，以及它们和 Java 的根本分歧

Go 里声明变量只有三条路：var x T（类型写在前面）、x := v（类型由编译器推断，只在函数内可用）、const x = v（编译期常量）。

和你的老朋友摆在一起：

维度 Go Java Python
声明写法 var x int / x := 1 int x = 1; x = 1
局部变量必须先赋值 否，自动取零值 是，might not have been initialized 不适用
交换两个变量 a, b = b, a 得靠临时变量或工具类 a, b = b, a
函数多返回值 原生 (v, error) 得自己造包装类 返回 tuple + 解包
整数默认宽度 int，随平台变化 int 恒 32 位 任意精度
隐式数值转换 一律禁止 窄化禁止、宽化一般允许 需显式 int()

Java 要求局部变量声明时就有确定值，Go 把「成员变量默认值」那套逻辑推广到了所有变量。

2.1.1 := 的两条铁律

铁律一：左边必须至少有一个新变量。

铁律二：:= 声明的变量，作用域从该语句结束开始，到最内层代码块结束。

2.2 基本类型：为什么默认是 int 而不是 int64

类型 宽度（64 位平台） 零值 说明
bool 1 字节 false 不可为 nil
int 8 字节（32 位平台 4 字节） 0 默认整数类型
int8 / int16 / int32 / int64 1 / 2 / 4 / 8 0 固定宽度，跨平台一致
uint / uint8 / uint16 / uint32 / uint64 8 / 1 / 2 / 4 / 8 0 无符号，下溢会绕回
uintptr 8 字节 0 只在 unsafe 里有意义
byte 1 字节 0 uint8 的别名，不是新类型
rune 4 字节 0 int32 的别名，一个 Unicode 码点
float32 / float64 4 / 8 0 默认浮点类型是 float64
complex64 / complex128 8 / 16 0 复数，工程里用得极少
string 16 字节（字符串头） "" 只读字节序列，约定 UTF-8

为什么默认是 int？ Go 想让「最常见的那次运算」永远是最快的那次。int 就是平台字长：64 位机器 8 字节，32 位机器 4 字节。若默认定成 int64，32 位平台上算术都得靠编译器模拟。

代价是同一份代码在 64 位和 32 位平台上 int 宽度不同。所以惯例是：int 用于下标、计数、循环变量；int64 用于时间戳、文件大小、数据库主键等。

byte 与 rune 都不是新类型，只是别名：byte 就是 uint8，[]byte 表示一串原始字节，读文件、读网络包用得上；rune 就是 int32，装得下一个 Unicode 码点，for range 遍历字符串拿到的就是它。所以 func f(b []byte) 能直接接收 []uint8。

2.3 零值语义：声明即初始化

Go 有一条硬规则：每种类型都有零值，任何变量在声明时就已经被初始化。

类型 零值
bool false
所有数值类型 0
string ""
指针、func、interface、map、slice、chan nil
struct / 数组 各字段、各元素各自的零值
error nil

后两行体现 Go「零值即可用」的理念：Java 的 ReentrantLock 必须 new。

内存视角上，零值意味着 Go 分配的每块内存都被清零了。 栈上变量由编译器保证，逃逸到堆上的对象由运行时保证，这直接消灭了 C/C++ 里「未初始化变量」那一整类 bug。

想亲眼看内存布局可以借 unsafe：unsafe.Sizeof(int(0)) 在 64 位平台上是 8，unsafe.Sizeof("") 是 16——string 只存字符串头（指针 + 长度）。

2.4 多变量声明与交换

Go 规定：赋值语句先把右边的表达式全部算完，再一次性写回左边，所以 a, b = b, a 天然安全。Java 则得先 int tmp = a; 再依次赋值；Python 原生支持同样写法，但那是引用别名、只是换绑定。

多返回值是这套设计的杀手锏：n, err := strconv.Atoi("42") 一行拿到值和错误。Java 没有多返回值，想表达「要么值要么错误」只能自己造 Pair / Result 类，而 Go 把 (value, error) 做成了语言级惯例。

2.7 数值溢出与类型转换：Go 绝不帮你猜

2.7.1 没有隐式转换

C/C++ 的「整型提升」会悄悄帮你统一类型，Go 取消了这套规则：类型不匹配直接编译报错。

2.7.2 溢出：常量溢出编译报错，运行时溢出静默绕回

无符号类型更极端：var u uint8 = 0; u-- 会得到 255。这种「静默溢出」不 panic、不报错，只是让数字变得离谱。

2.8 动手练与常见错误清单

2.8.1 动手练

  1. 实现一个 swap 函数，输入两个 int，用两个返回值吐出交换结果。再回忆：Java 写同样的功能，需要 int[] 包装还是第三方工具类？
  2. 统计中文字符串：分别打印 len(s)、utf8.RuneCountInString(s)、len([]byte(s))，再用 for i, r := range s 打印字节下标与码点，确认「字符数 ≠ len」。
  3. **用 const + iota 定义 KB / MB / GB**，写断言验证 KB == 1024 && MB == 1024*1024。再故意把第一行写成 _ = iota，看结果怎么变；然后给 Permission 加一个 PermAdmin 位，思考当 p 只有 PermAdmin 时 p&PermRead != 0 该返回什么。

最该带走的一句话是：Go 把「初始化」「类型」「转换」全部做成了显式、可在编译期检查的规则。 零值兜住初始化，静态类型兜住运算，禁用隐式转换兜住数值边界——代价是多写几个字符，换来的是编译期就挡掉一大类运行时事故。
