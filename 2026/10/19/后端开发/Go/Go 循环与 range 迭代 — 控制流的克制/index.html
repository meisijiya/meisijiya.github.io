Go 循环与 range 迭代 — 控制流的克制

07 Go 循环与 range 迭代

Go 只保留了一个循环关键字，这既是克制也是自由——这篇讲透 for / range / 标签，以及 Go 1.22 那个改变了无数老代码的循环变量变更。

7.1 for 的三种形态

Go 删掉了 while 和 do-while，只留 for。这不是图省事，是统一：一个关键字覆盖全部循环形态，gofmt 才能把 for 排得整整齐齐。

三条规则：init 里声明的变量作用域只在 for 语句内；省略条件等价于条件恒为真，for { } 就是 for true { }；post 语句在循环体执行完之后才执行，continue 也会走 post。

Go 没有 do-while，「先执行一次再判断」写成 for { doSomething(); if !cond { break } }，好处是循环体中间可以随时 return。

需求 Go Java Python
计数 for i := 0; i < n; i++ {} for (int i = 0; i < n; i++) {} for i in range(n):
条件 for cond {} while (cond) {} while cond:
无限 for {} while (true) {} while True:
遍历集合 for i, v := range xs for (T v : xs) for i, v in enumerate(xs)

7.2 range 遍历数组与切片

四个细节，每个都对应一类线上事故：

  1. u 是元素值的拷贝，不是引用。要改元素得写 users[i] = "x"；切片是 []*User 时 u 是指针拷贝，改 *u 影响原对象，改 u 不影响。
  2. range 表达式只求值一次，for _, u := range loadUsers() 只会调用一次 loadUsers()。
  3. 只写一个迭代变量时，range 不去索引切片本身，只产生下标，for i := range s 因此少一层边界检查。最后一个迭代变量写成 _ 等价于不写它。
  4. range 一个数组值会拷贝整份数组，大数组用 arr[:] 或 &arr 绕开这次拷贝；nil 切片则是遍历 0 次，不 panic。
写法 拿到下标 拿到值 说明
for i, v := range s ✅ ✅ 值是拷贝
for i := range s ✅ ❌ 最常用
for _, v := range s ❌ ✅ 只要值
for range s ❌ ❌ 只计数

Java 的增强 for 拿不到下标，Python 也没有「只要下标」的写法。Go 把这几种组合都做进了语法里。

7.3 range over int 与字符串的 rune

Go 1.22 起，for 可以直接 range 一个整数：

n 是整数类型或整型常量时，迭代值是 0 到 n-1，**n <= 0 时一次都不迭代**。编译器在 1.22 之后会把 range 10 和 for i := 0; i < 10; i++ 优化成几乎一样的代码，但前者语义更直白。

字符串的 range 更值得留意：

i 是字节下标，不是字符序号。 这是中文场景最大的坑：Python 的 s[0] 是第一个字符，Go 的 s[0] 是第一个字节（”你”占 3 字节）。Java 字符串底层是 UTF-16，emoji 会被拆成两个 char。遇到非法 UTF-8 序列时第二个值是 0xFFFD，且只前进 1 个字节。

只要字符用 for _, r := range s，只要字节位置用 for i := range s，要字符个数用 utf8.RuneCountInString(s)。

7.4 循环变量的语义变更（Go 1.22）

这是 Go 1.22 最重要的行为变更之一，面试也最爱问。

旧行为（Go 1.21 及以前）：for 循环里用 := 声明的变量整个循环共用一份，每轮只是把值改掉，闭包捕获它就总拿到最后一个值：

新行为（Go 1.22 起）：每轮迭代都新建一份循环变量。range 循环相当于循环体开头自动执行了 k := k; v := v；三段式 for 同理（规范里的例子会打印 1 3 5 而不是 6 6 6）。

关键门槛：新语义由 go.mod 里的 go 指令决定，不由你装的新工具链决定。go.mod 里写着 go 1.19 的老项目，即使拿 Go 1.25 编译，循环变量仍是旧的共享语义；只有声明 go 1.22 及以上的模块才启用新语义。

语言 / 写法 循环变量作用域 闭包捕获到的值
Go 1.21 及以前（range 与三段式 for 一样） 整个循环共用一份 全部是最后一个值
Go 1.22+（range 与三段式 for 一样） 每轮新建一份 每轮各拿各的值
Java 增强 for for (T v : xs) 每轮新建一份 每轮各拿各的值
Java 普通 for for (int i = 0; ...; i++) 整个循环共用一份 全部是最后一个值
Python for v in xs 函数作用域，循环后仍存在 全部是最后一个值

Java 的增强 for 从来没这个坑，但普通 for 里的 i 依然中招。Python 也有同样的坑且修法不同：for v in xs: v = v 没用，得用默认参数绑住值，如 [lambda v=v: v for v in xs]。

新语义下仍有两个残留坑：取地址仍然会变（m[&v] += v 这类写法每轮 &v 都不同，map 会多出条目，解法是显式写 v := v）；性能上只有取地址或被闭包捕获的循环会变，可能多一次堆分配。

迁移建议：老项目动 go.mod 之前，先用 go vet 跑一遍 loopclosure 检查器人工过一遍。

7.5 range 遍历 map

map 遍历有三条必须记住的规则。

第一，顺序是随机的，而且是被规范保证的随机。 规范写得很直接：map 的迭代顺序未指定，也不保证两次迭代相同。Go 团队是故意这么设计的——顺序一旦被程序依赖，就会有人写出「只在某个版本或某台机器上碰巧正确」的代码。需要稳定顺序就把键收集到切片排序后再遍历。

第二，遍历中删除是安全的，遍历中新增是「看运气」的。 规范原话是：还没遍历到的条目被删除就不会产出；遍历中新建的条目可能被产出，也可能被跳过。所以「边遍历边 delete」是官方认可的标准写法；而新增 key 是危险动作——给已有 key 赋值没问题，给新 key 赋值会触发致命错误 fatal error: concurrent map iteration and map write：

第三，nil map 可以遍历，但不能赋值。var m map[string]int 遍历 0 次不报错，m["a"] = 1 直接 panic。

需求 Go Java Python
遍历键值 for k, v := range m for (var e : m.entrySet()) for k, v in m.items()
只要键 for k := range m for (K k : m.keySet()) for k in m
只要值 for _, v := range m for (V v : m.values()) for v in m.values()
顺序 故意随机 HashMap 随机，LinkedHashMap 保序 3.7+ 保持插入序

「只要值」Go 没有直接语法糖：Go 1.23 起标准库提供 maps.Values(m)，返回迭代器 iter.Seq[V]；1.21、1.22 时代返回的是切片。

7.6 标签与控制流跳转

Go 保留了 label，但限制得很死：label 只能贴在 for、switch、select 语句上。

continue outer 则跳到外层循环的下一轮，常用于「整行都不合格就跳过这行」的场景。

Go 的 break 语义要特别小心：它终止的是最内层的 for、switch 或 select。写在 switch 里的 break 只跳出 switch，不会跳出外面的 for——这点和 Java 一致；但也正因如此，「跳出双层循环」必须用 label。Java 的 label 能贴在任意语句上，break label; 可以跳出被标记的块；Go 的 label 范围更窄，但语法几乎一样，从 Java 迁过来最容易想当然。

更 Go 味的做法是把双层循环抽成函数，用 return 跳出：

Go 鼓励「小函数 + 早返回」。Go 也有 goto，但限制到几乎不可用：不能跳过变量声明，也不能跳进块里。

7.7 常见写法

遍历下标：优先 for i := range s，别手写 for i := 0; i < len(s); i++——前者表达「我要下标」，后者把边界甩给写代码的人。

跳过元素用 continue 写卫语句，让主逻辑保持扁平；提前退出则能用 break / return 就别套 if，Go 的 if 支持带初始语句，判断和取值可以写在一起：

查找与排序：Go 1.21 起标准库 slices 包有现成的，别手写。slices.Index(users, "bob") 找不到返回 -1，slices.Contains(users, "bob") 给布尔判断，slices.Sort(names) 就地排序，slices.Reverse(s) 就地反转。

分组统计：map + range 是最常见的聚合写法，byTag[a.Tag] = append(byTag[a.Tag], a) 一行就够。

分页遍历：for i := range 只能给下标，分页得自己算边界，start := page * pageSize，end := min(start+pageSize, len(items))，其中 min 是 Go 1.21 起内置的。

7.8 动手练

  1. 迁移练习：把一段 Java 的双层 for + break 改写成 Go，分别用 label 写一版、用抽函数 + return 写一版，比较哪种更好维护。
  2. 复现闭包陷阱：go.mod 写 go 1.21 时跑一段 range 里 append 闭包的代码，再改成 go 1.22 跑一次，对比两次输出。
  3. 统计与清理：实现 wordCount(text string) map[string]int，再用「边遍历边 delete」删掉只出现一次且长度大于 3 的词。
  4. 中文下标：写一个函数把字符串按 rune 切成切片，验证 for i, r := range s 里的 i 是字节下标。

7.9 常见错误清单

# 错误写法 / 错误想法 后果 正确做法
1 写 while cond {} 编译不过 for cond {}
2 range 里改 v 以为改了切片 白改一场 v 是拷贝，要改写 s[i]
3 range 一个大数组 整份数组被拷贝 先 arr[:] 或用 &arr
4 老项目 go.mod 低于 1.22 闭包捕获仍是旧语义 升 go.mod，先跑 go vet
5 依赖 map 遍历顺序 结果随机、难复现 收集键后排序再遍历
6 range map 时新增 key 运行时 fatal error 先收集再写，或只用 delete
7 以为 switch 里的 break 能跳出 for 只跳出 switch 用 label，或抽函数 return
8 把 range 字符串的 i 当字符下标 中文、emoji 场景切错 i 是字节下标
9 给 nil map 赋值 panic: assignment to entry in nil map 先 make(map[K]V)

Go 的循环只有一种关键字，range 把「遍历什么」表达得比 Java 和 Python 更直白，Go 1.22 的循环变量变更则填平了一个流传多年的老坑。记住三条：遍历 map 别依赖顺序，range 拿到的值是拷贝，循环变量的新语义由 go.mod 决定。
