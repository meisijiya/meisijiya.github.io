Go 函数设计 — 多返回值、命名返回与可变参数

03 Go 函数设计

Go 没有异常、没有 try/catch，函数的返回值就是它全部的控制流——多返回值、命名返回、defer 与可变参数，外加与 Java / Python 的写法差异。

3.1 定义与调用：签名本身就是契约

3.1.1 func 签名长什么样

Go 的函数是包级声明，没有类，也没有”构造器”：

调用方用 value, err := divide(10, 4) 接住，err != nil 就提前返回。三个必须记住的点：

  • 参数名可以整个省略：func check(int, string) (bool, error) 合法；但同组里只要有一个写了名字，其余都得写。
  • 返回值可以合并：func f() (int, error) 等价于 func f() (a int, b error)。
  • 没有重载，也没有默认参数：可选参数要么多写一个函数，要么用可变参数，要么收一个 options 结构体。

3.1.2 多返回值与「必须表态」

多返回值按顺序解构：

声明了 err 却完全不看它，编译器直接报 declared and not used。Go 强制你表态，不强制你处理——Java 的 checked exception 强制捕获或声明 throws，Python 完全不强制。

3.1.3 函数是值

Go 没有 lambda。add 不加括号就是函数值，类型是 func(int, int) int：

函数值只能和 nil 比较。对照三门语言：Go 的函数值类型必须完全一致，Java 8 之后 lambda 是对象、要塞进 Function 接口，Python 完全不做签名检查。

3.1.4 保护子句：把嵌套拍成清单

Go 的错误处理天然催生保护子句（guard clause）：每个失败分支直接 return，把嵌套拉平。

差别不在行数，而在认知负荷：第一版要遍历整棵条件树，第二版是一张清单。

3.2 多返回值替代异常

3.2.1 error 就是一个普通返回值

error 是标准库里的一个接口：type error interface { Error() string }。任何实现了 Error() string 的类型都能当 error 用——这是 interface 在语言层面的第一次现身。

关键观念：错误在 Go 里是一个值，不是一段控制流，可以被包装、比较、存进结构体、原样往上传。

3.2.2 错误处理方式对比

维度 Go Java Python
机制 返回 error 值 抛异常（checked / unchecked） 抛异常
捕获方式 if err != nil try / catch / finally try / except / finally
编译器 强制表态，不强制处理 checked 强制捕获或声明 完全不强制
不可恢复错误 panic + recover Error + throw BaseException

3.2.3 panic 的边界，和错误怎么往上传

分工很清楚：预期内的失败（文件不存在、网络超时、参数非法）返回 error；程序员的错误（越界、空指针）才 panic。recover 只能在 defer 里生效，所以「捕获 panic」天然和 defer 绑在一起。

裸返回一个 err 会丢掉上下文，惯例是用 fmt.Errorf("读取配置 %s 失败: %w", path, err) 包装一层。%w 把底层错误串进错误链：errors.Is(err, os.ErrNotExist) 判哨兵错误，errors.As(err, &target) 把链里某个具体类型捞出来。

3.3 命名返回值：省代码还是埋坑

3.3.1 语法与两条硬限制

写法是 func parsePort(raw string) (port int, err error)，函数体里可以直接读写它们。两条硬限制：

  • 要么全命名，要么全不命名。func f() (int, err error) 是语法错误，编译不过。
  • 命名后它们就是普通局部变量，能读能写，也能被 defer 修改。

3.3.2 裸 return 的语义

裸 return 只有一条语义：把当前这些命名结果变量的值原样返回，不读源码、不推类型。

3.3.3 为什么别到处裸 return

  1. 可读性：读者看到 return 不知道返回了什么，得翻回函数头。
  2. 静默漂移：改了函数头的名字或顺序，裸 return 跟着变，显式 return 反而会编译报错。显式 return 是编译期检查，裸 return 是运行时行为。

建议：命名返回值只用在两种场景——需要 defer 修改返回值，以及需要在出口统一处理错误。其余一律显式 return。

3.4 defer：注册时机与执行时机

3.4.1 三个时间点

一句 defer 背后有三个时刻：

  1. 注册时刻：defer 语句被执行的那一刻，函数被登记进待执行列表。
  2. 求值时刻：实参在这一刻就全部求值完毕，函数体还没跑。
  3. 执行时刻：外层函数即将返回时，函数体才真正跑。

3.4.2 LIFO：后进先出

同函数里注册多个 defer，执行顺序是后进先出：defer fmt.Println("第 1 个")、"第 2 个"、"第 3 个" 三行连写，输出是「函数体 / 第 3 个 / 第 2 个 / 第 1 个」——后打开的资源先关掉。

3.4.3 参数立即求值 vs 闭包延迟求值

输出顺序是「闭包：2」先、「直接传参：1」后。规则很短：直接传参立即求值，包一层闭包就延迟到返回时求值。

3.4.4 资源释放的标准姿势

defer 最大的价值是：不管从哪个分支返回，清理动作一定发生。

锁同理，mu.Lock() 之后立刻写 defer mu.Unlock()，少一行就可能在早返回路径上死锁。常见场景：文件句柄、数据库连接、http.Response.Body、锁、临时文件。

3.5 可变参数

3.5.1 本质是切片，调用靠展开

parts 在函数体内的类型是 []string——可变参数不是独立语法糖，它就是”最后一个参数声明成切片”。parts... 是展开语法，把切片元素铺平传进去。fmt.Println 本身就是典型，签名是 func Println(a ...any) (n int, err error)。

⚠️ 展开时不复制底层数组：f(parts...) 传进去的切片和调用方共享底层数组，被调方 append 可能改到调用方的数据。Python 的 f(*parts) 每次新建 tuple，Java 的 varargs 也总是新建数组——只有 Go 是共享的。

3.5.2 可变参数对比

维度 Go Java Python
语法 func f(parts ...string) void f(String... parts) def f(*parts)
接收到的类型 []string（切片） String[]（数组） tuple
传切片进去 f(parts...)，共享底层数组 直接传数组引用 f(*parts)，总是新建 tuple

3.5.3 几条硬规则

  • 可变参数必须放最后，且一个函数只能有一个；混用时普通参数在前，如 func logf(format string, args ...any)。
  • 想要多个”传了就生效”的可选参数，用 options 结构体（functional options 模式）。
  • Go 没有关键字参数，f(a, b) 只能按位置传；想要可读性就传 struct。

3.6 函数作为值与高阶函数入门

3.6.1 把函数传给别人

Go 允许你给函数类型起名字（type Handler func(name string) (string, error)），标准库的 http.HandlerFunc 就是这个套路。接受函数作为参数的函数叫高阶函数：sort.Slice(slice, func(i, j int) bool { ... })、slices.SortFunc、中间件链 func(next http.Handler) http.Handler 都是。

注意 Go 的函数值类型是精确匹配的：func(int) int 传不到 func(int, int) int 的位置，没有协变也没有逆变。

3.6.2 闭包的预告

函数捕获了外层变量就成了闭包：counter() 返回的函数会一直持有外层的 n，两个闭包各有一份独立的 n。闭包捕获的是变量本身，不是快照——这正是 3.4.3 里”defer 闭包延迟求值”的底层机制，第 10 篇展开。

3.7 动手练

四个递进的小任务，都能 go run 验证：

  1. 多返回值 + 错误：实现 func divide(a, b float64) (float64, error)，除零返回 ErrDivideByZero；再写一个 mustDivide，出错就 panic。
  2. 可变参数：实现 func sum(nums ...int) int，再写一个只吃切片的 sumSlice(nums []int) int，用 sum(numsSlice...) 调起来；再验证”共享底层数组”是否成立。
  3. defer 时机：同时注册 defer fmt.Println(...) 和一个闭包版 defer，中间改变被捕获的变量，打印实际顺序和值。
  4. defer 修返回值：用 3.3.4 的 parsePort 骨架，让 parsePort("abc") 返回 err 而不是 panic。

跑之前记得 gofmt -w . 和 go vet ./...。

症状 根因 修法
错误被静默吞掉 n, _ := f() 或拿到 err 不判断 err 必须判断；确实不需要就显式 _ 并写注释
循环里句柄耗尽 defer f.Close() 写在循环体内 抽成独立函数，让 defer 随函数走

Go 的函数设计只有一条主线：签名说清楚契约，错误走返回值，清理交给 defer，剩下的交给类型系统。把这四条内化之后，再看 goroutine、channel、泛型，就不算另一门语言了。
