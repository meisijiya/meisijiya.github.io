10 Go 高阶函数与闭包

函数在 Go 里就是普通变量，闭包能装住状态——这一篇把「函数是一等公民」讲透，并把循环变量、defer 这两个经典坑一次讲清。

10.1 函数是值：一等公民到底是什么意思

「一等公民」其实就是一句话：函数和 int、string 一样，是可以被赋值、传参、返回的普通值。

1. 函数类型只看签名。 func(int, int) int 只看参数和结果的类型，参数名不参与判断，所以 add 和 mul 类型相同，能互换着传给 aggregate。Go 不支持函数重载，也源于此。

2. 函数值不可比较。 规范里写得很直白：函数值只能和 nil 比，所以不能把函数当 map 的 key（key 必须可比较），但可以当 value 存起来。

3. 方法也能变成函数值，这叫「方法值」：以 type Counter struct{ n int } 上的 Inc()/Get() 为例，inc := c.Inc 之后 inc() 就等价于 c.Inc()。它绑定的是接收者的一份副本，所以 get := c.Get 之后再改 c.n，get() 看到的仍是旧值。

Go / Java / Python 的函数一等性对比

维度 Go Java（8+） Python
函数是值 ✅ op := add ✅ 方法引用 Math::max ✅ op = add
函数作参数 / 返回值 ✅ 原生支持 ✅ Function / Consumer ✅ 任意形参与返回值
捕获并修改外层变量 ✅ 直接赋值 ❌ 只能捕获 effectively final ✅ 需 nonlocal
函数值可比较 ❌ 只能和 nil 比 ✅ 引用相等可判 ✅ 函数对象可判

Java 同学最容易卡住的是「捕获并修改」那行：Java 的 lambda 捕获的是值，想在闭包里累加计数得包一个 AtomicInteger；Go 捕获的是变量本身。

10.2 闭包：捕获的是变量，不是值

闭包 = 一个函数 + 它从外层捕获的那份环境。关键在于，捕获的是变量的引用（本体），不是某个时刻的快照。

每调用一次 concatter() 就造出一个全新独立的 doc。反直觉的推论是：闭包捕获的变量，在外层函数返回之后依然存活。

闭包语义速查

场景 Go Java（lambda） Python
捕获语义 变量本体（引用） 值（effectively final 快照） 变量（cell 引用）
能否修改捕获值 ✅ 直接赋值 ❌ 需可变包装类 ✅ 需写 nonlocal
循环变量捕获（≤1.21） 共享同一个变量 需 final 副本 共享同一个变量
循环变量捕获（≥1.22） 每轮新建，已修复 — 仍共享，需 i=i 规避

Python 的 nonlocal 在 Go 里是多余的：Go 不区分「赋值」和「重新绑定」，闭包内直接写 doc += word，改的就是外层那个 doc 本身。反过来也有代价——闭包会把本该栈上分配的东西拖到堆上。

10.4 装饰器思想在 Go 里的样子

Python 的 @decorator 在 Go 里没有语法糖，但思想完全一样：装饰器就是一个接受函数、返回新函数的函数。

Logging 接收一个 http.Handler，返回一个新的 http.Handler**，新 handler 在干活前后多做了些事再转交出去——这就是装饰器。链式组合 Logging(Auth(HealthHandler))` 的顺序是由外向内的：请求先进 Logging，再进 Auth，最后到 HealthHandler。

Go 没有装饰器语法的原因很实在：它不支持函数重载，也不支持默认参数，「包装器」只能显式规定自己的类型签名。

10.6 defer 与闭包：两个必须分清的坑

Go 的 defer 有两个特性叠在一起：参数在 defer 语句执行时立即求值，函数体在外层函数返回时才执行。闭包一掺和，输出就反直觉。

Go 1.22+ 的输出：

Go 1.21 及更早的输出：

  • defer fmt.Println("A:", i) 里 i 是参数，在 defer 那一行就求值，依次存下 0、1、2；defer 按后进先出执行，于是打印成 2、1、0。
  • defer func(){...}() 里 i 是闭包捕获的变量。Go 1.22 之前循环结束后 i 已是 3，三个闭包读到的都是 3；1.22 之后每轮有独立的 i，拿到 0、1、2，同样按后进先出打印。

要打印 defer 那一刻的值就用 defer fmt.Println(i)，要打印函数返回那一刻的值就用 defer func(){ fmt.Println(i) }()。

第二个坑更隐蔽：defer 绑定的是函数，不是循环体。在循环里 defer 释放资源，关闭动作会被推迟到函数返回时，句柄被一路攥到底，数量多了直接撞上限——循环里直接写 defer f.Close()，N 个文件要等到函数结束才关。修法是把单次处理抽成独立函数：
