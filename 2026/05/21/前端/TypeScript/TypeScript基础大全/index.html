1. TypeScript 是什么？

1.1 一句话理解 🔑

TypeScript = JavaScript + 类型系统

TypeScript（简称 TS）是微软开发的开源编程语言，它是 JavaScript 的超集（Superset）。

超集意味着：所有合法的 JavaScript 代码，都是合法的 TypeScript 代码。你可以把一个 .js 文件直接改名为 .ts，它就变成 TypeScript 了。

1.2 为什么需要 TypeScript？🤔

JavaScript 是动态类型语言，变量的类型在运行时才确定：

TypeScript 加入了静态类型检查，在写代码时就能发现问题：

对比维度 JavaScript TypeScript
类型检查 运行时 编译时（写代码时）
IDE 提示 弱 强（属性智能补全）
重构安全性 低 高
大型项目维护 困难 容易
学习曲线 低 中

1.3 核心设计理念

  1. 类型声明是可选的：可以加，也可以不加，不加时 TS 会自动推断
  2. 编译时检查，运行时消失：类型只在编译阶段存在，编译成 JS 后全部擦除
  3. 渐进式采用：可以在 JS 项目中逐步添加 TS，无需一次性全部迁移

⚠️ 重要区分：TypeScript 代码分为两层——**”值代码”**（运行时执行的 JS 逻辑）和 **”类型代码”**（编译时的类型标注）。编译过程就是删除所有”类型代码”，只保留”值代码”。

11. 特殊类型：any / unknown / never / void

11.1 any 类型 🚨

any 表示关闭类型检查，可以赋任意值，做任意操作：

🚨 any 的危害：

  • 会”污染”其他变量（any 可以赋值给任何类型）
  • 丢失所有 IDE 智能提示
  • 让 TypeScript 变成 “AnyScript”

仅在以下场景使用：

  1. 迁移旧 JS 项目时的临时方案
  2. 确实无法确定类型的极端情况

11.2 unknown 类型 ✅（any 的安全替代）

unknown 也是”未知类型”，但必须先做类型判断才能使用：

特性 any unknown
可以赋任意值 ✅ ✅
赋值给其他类型 ✅（危险） ❌（安全）
直接调用方法 ✅（危险） ❌（安全）
需要类型判断 ❌ ✅

📌 黄金法则：永远优先用 unknown 替代 any！
