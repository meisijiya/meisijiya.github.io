1. 并发容器概述

并发容器是Java并发编程中用于多线程环境下安全访问的数据结构。与同步容器（如Vector、Hashtable）不同，并发容器通过更精细的锁策略、无锁算法或写时复制等技术，在保证线程安全的同时提供更高的并发性能。

1.1 为什么需要并发容器

同步容器（如Collections.synchronizedList）通过在每个方法上加synchronized关键字实现线程安全，但存在以下问题：

  • 性能瓶颈：所有操作都竞争同一把锁，高并发下性能差
  • 功能缺失：缺少复合操作的原子性保证（如”检查-再-操作”）
  • 迭代风险：迭代过程中需要手动加锁，否则可能抛出ConcurrentModificationException

并发容器通过以下方式解决这些问题：

  • 分段锁：将数据分成多段，每段独立加锁（如ConcurrentHashMap JDK1.7）
  • 无锁算法：使用CAS操作实现线程安全（如ConcurrentLinkedQueue）
  • 写时复制：读操作无锁，写操作复制底层数组（如CopyOnWriteArrayList）

3.5 使用场景与优缺点

适用场景：

  1. 读多写少：监听器列表、配置信息缓存
  2. 并发读取：不需要强一致性的场景
  3. 小数据量：写操作时复制整个数组，数据量大时性能差

优点：

  • 读操作完全无锁，性能极高
  • 迭代器不会抛出ConcurrentModificationException
  • 线程安全，无需额外同步

缺点：

  • 写操作需要复制整个数组，内存开销大
  • 数据实时性差，读取的可能是旧数据
  • 不适合大数据量场景

8. 并发容器与同步容器的区别

8.1 同步容器

同步容器通过在每个方法上加synchronized实现线程安全，包括：

  • Vector
  • Hashtable
  • Collections.synchronizedList()
  • Collections.synchronizedMap()
  • Collections.synchronizedSet()

特点：

  1. 简单粗暴：所有操作竞争同一把锁
  2. 性能差：高并发下成为瓶颈
  3. 迭代风险：需要手动加锁，否则可能抛出ConcurrentModificationException

8.2 并发容器

并发容器通过更精细的锁策略或无锁算法实现线程安全。

特点：

  1. 细粒度锁：如ConcurrentHashMap的分段锁或CAS+synchronized
  2. 高性能：读操作通常无锁
  3. 迭代安全：迭代器基于快照，不会抛出异常
  4. 功能丰富：提供原子操作、批量操作等

10. 面试常见问题及答案

Q1: ConcurrentHashMap在JDK1.7和JDK1.8中的实现有什么区别？

答案：

  • JDK1.7：使用分段锁（Segment），每个Segment是一个小型HashMap，拥有独立的锁。默认16个Segment，支持16个线程并发写。
  • JDK1.8：抛弃分段锁，使用CAS + synchronized。锁粒度更细，只锁链表或红黑树的头节点。引入红黑树优化长链表查询。

Q2: CopyOnWriteArrayList的实现原理是什么？有什么优缺点？

答案：
原理：

  1. 读操作：直接读取底层数组，无锁
  2. 写操作：复制底层数组，在新数组上修改，然后替换引用

优点：

  • 读操作性能极高，无锁
  • 迭代器不会抛出ConcurrentModificationException
  • 线程安全

缺点：

  • 写操作需要复制整个数组，内存开销大
  • 数据实时性差，读取的可能是旧数据
  • 不适合大数据量场景

使用场景：读多写少，如监听器列表、配置信息缓存

Q3: BlockingQueue有哪些实现类？各有什么特点？

答案：

  1. ArrayBlockingQueue：基于数组的有界队列，按FIFO排序
  2. LinkedBlockingQueue：基于链表的可选有界队列，默认无界
  3. PriorityBlockingQueue：基于数组的优先级无界队列
  4. SynchronousQueue：不存储元素的队列，每个插入等待移除
  5. DelayQueue：支持延迟获取的无界队列

选择建议：

  • 固定大小生产者-消费者：ArrayBlockingQueue
  • 不确定大小：LinkedBlockingQueue
  • 优先级任务：PriorityBlockingQueue
  • 直接传递：SynchronousQueue
  • 定时任务：DelayQueue

Q4: ConcurrentLinkedQueue是如何实现无锁的？

答案：
使用CAS（Compare-And-Swap）算法：

入队操作：

  1. 获取当前tail节点
  2. 创建新节点
  3. CAS设置tail.next = newNode
  4. CAS设置tail = newNode

出队操作：

  1. 获取当前head节点
  2. CAS设置head = head.next
  3. 返回原head的item

特点：

  • 无锁，高性能
  • 无界队列
  • 不支持阻塞操作

Q5: 并发容器和同步容器有什么区别？

答案：
同步容器：

  • 实现：每个方法加synchronized
  • 锁粒度：方法级别
  • 性能：高并发下性能差
  • 迭代：需要手动加锁

并发容器：

  • 实现：细粒度锁或无锁算法
  • 锁粒度：更细或无锁
  • 性能：高并发下性能好
  • 迭代：基于快照，安全

选择建议：

  • 低并发：同步容器（简单）
  • 高并发：并发容器（性能好）

Q7: 如何选择合适的并发容器？

答案：
根据使用场景选择：

场景 推荐容器 原因
读多写少 CopyOnWriteArrayList 读无锁
读写均衡 ConcurrentHashMap 细粒度锁
生产者-消费者 LinkedBlockingQueue 阻塞等待
有序Map ConcurrentSkipListMap 跳表实现
无锁队列 ConcurrentLinkedQueue CAS算法
延迟任务 DelayQueue 支持延迟

选择原则：

  1. 优先考虑并发性能
  2. 根据读写比例选择
  3. 考虑数据量大小
  4. 是否需要阻塞操作
  5. 是否需要有序性

Q8: ConcurrentHashMap的扩容机制是怎样的？

答案：
JDK1.7：

  • 每个Segment独立扩容
  • 扩容时只锁当前Segment
  • 扩容因子：0.75

JDK1.8：

  • 支持多线程协同扩容
  • 扩容时创建新表，迁移数据
  • 使用ForwardingNode标记已迁移的桶
  • 扩容因子：0.75

JDK1.8扩容流程：

  1. 创建新表（大小为原表2倍）
  2. 分配迁移任务给多个线程
  3. 每个线程迁移自己负责的桶
  4. 使用ForwardingNode标记已迁移的桶
  5. 迁移完成后替换table引用
