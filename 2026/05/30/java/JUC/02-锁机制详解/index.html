1. synchronized 关键字

1.1 基本概念

synchronized 是 Java 内置的关键字，提供了一种排他式的同步机制。当一个线程获取锁后，其他线程必须等待该线程释放锁才能继续执行。

1.5 synchronized 的特性

特性 说明
互斥性 同一时刻只有一个线程能持有锁
可重入性 同一线程可以多次获取同一把锁
非公平性 不保证等待时间长的线程优先获取锁
自动释放 线程退出同步块或方法时自动释放锁
不可中断 等待获取锁的线程无法被中断

7. 面试常见问题

Q1：synchronized 和 ReentrantLock 的区别？

答：

  1. 实现层面：synchronized 是 JVM 关键字，ReentrantLock 是 API 层面的实现
  2. 使用方式：synchronized 自动获取释放，ReentrantLock 需手动 lock/unlock
  3. 功能差异：
    • ReentrantLock 支持公平锁
    • ReentrantLock 支持可中断获取
    • ReentrantLock 支持超时获取
    • ReentrantLock 支持多个条件变量
  4. 性能：JDK 6 后差距不大
  5. 选择建议：简单场景用 synchronized，需要高级功能用 ReentrantLock

Q2：synchronized 的锁升级过程？

答：

  1. 无锁：没有线程获取锁
  2. 偏向锁：第一个获取锁的线程，对象头记录线程 ID
  3. 轻量级锁：有其他线程竞争，使用 CAS 自旋等待
  4. 重量级锁：竞争激烈，未获取锁的线程被阻塞

Q3：volatile 关键字的作用？

答：

  1. 可见性：修改后立即刷新到主内存，其他线程可见
  2. 有序性：禁止指令重排序
  3. 不保证原子性：不能替代 synchronized

适用场景：

  • 状态标志（一写多读）
  • DCL 单例模式（禁止重排序）
  • 读取计数器

Q4：什么是死锁？如何避免？

答：

死锁条件（四个同时满足）：

  1. 互斥条件：资源独占
  2. 请求与保持：持有资源的同时请求新资源
  3. 不可剥夺：已获取的资源不能被强制剥夺
  4. 循环等待：线程之间形成环形等待

避免死锁的方法：

  1. 固定加锁顺序：所有线程按相同顺序获取锁
  2. 使用 tryLock：超时后释放已持有的锁
  3. 使用定时锁：设置锁的超时时间
  4. 避免嵌套锁：减少锁的嵌套使用

Q5：CAS 是什么？有什么问题？

答：

CAS（Compare And Swap）：比较并交换，是一种无锁的原子操作。

原理：

问题：

  1. ABA 问题：值从 A 改为 B，再改回 A，CAS 检测不到变化
    • 解决：使用 AtomicStampedReference（带版本号）
  2. 自旋开销：竞争激烈时 CPU 空转
    • 解决：限制自旋次数，或使用重量级锁
  3. 只能保证一个变量的原子操作
    • 解决：使用锁，或合并变量

Q6：AQS 是什么？

答：

AQS（AbstractQueuedSynchronizer）：抽象队列同步器，是 JUC 中很多同步组件的基础。

核心思想：

  • 使用 volatile int state 表示同步状态
  • 使用 FIFO 双向队列管理等待线程

实现原理：

  1. 线程通过 CAS 修改 state 获取锁
  2. 获取失败的线程加入等待队列
  3. 持有锁的线程释放时唤醒队列中的线程

基于 AQS 的组件：

  • ReentrantLock
  • ReentrantReadWriteLock
  • CountDownLatch
  • Semaphore

Q7：锁的优化策略有哪些？

答：

  1. 减小锁的范围：只同步必要的代码
  2. 减小锁的粒度：使用读写锁替代排他锁
  3. 锁分离：将一个锁拆分为多个锁
  4. 锁粗化：JVM 自动合并相邻的锁操作
  5. 锁消除：JVM 通过逃逸分析消除无竞争的锁
  6. 使用无锁数据结构：如 ConcurrentHashMap、Atomic 类

Q8：ReentrantLock 的公平锁和非公平锁？

答：

公平锁：

  • 严格按 FIFO 顺序获取锁
  • 不会产生线程饥饿
  • 吞吐量较低（需要维护等待队列）

非公平锁：

  • 允许新来的线程插队
  • 可能产生线程饥饿
  • 吞吐量较高（减少线程切换）

默认：ReentrantLock 使用非公平锁

Q9：什么是可重入锁？

答：

可重入锁：同一线程可以多次获取同一把锁，避免自己持有锁时再次请求锁导致死锁。

Q10：Condition 和 wait/notify 的区别？

答：

对比项 wait/notify Condition
所属 Object 类 Lock 接口
使用 synchronized 块内 Lock 配合使用
等待队列 只有一个 可以有多个
精确唤醒 notifyAll 唤醒所有 signal 唤醒指定条件
超时等待 wait(timeout) await(time, unit)

Condition 优势：

  • 支持多个条件变量
  • 可以精确唤醒特定条件的线程
  • 支持不可中断等待（awaitUninterruptibly）
