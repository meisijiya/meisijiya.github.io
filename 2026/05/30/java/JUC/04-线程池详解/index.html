🎯 一、线程池的概念和优势

1.1 什么是线程池

线程池（Thread Pool）是一种基于池化思想管理线程的工具。它维护着多个线程，等待监督管理者分配可并发执行的任务。这种做法避免了为处理短生命周期任务而频繁创建和销毁线程的开销。

线程池的核心优势：

优势 说明 重要性
降低资源消耗 通过复用线程，减少线程创建和销毁的开销 ⭐⭐⭐⭐⭐
提高响应速度 任务到达时无需等待线程创建即可立即执行 ⭐⭐⭐⭐⭐
提高线程可管理性 统一管理、调优和监控线程 ⭐⭐⭐⭐
提供更多功能 定时执行、定期执行、并发数控制等 ⭐⭐⭐

1.3 线程池的应用场景

典型应用场景：

  1. Web服务器处理请求：如Tomcat使用线程池处理HTTP请求
  2. 数据库连接池：复用数据库连接，减少连接创建开销
  3. 异步任务处理：后台任务、消息处理、日志写入
  4. 并行计算：大数据处理、图像处理、科学计算
  5. 定时任务调度：使用ScheduledThreadPool执行定时任务

2.2 七个核心参数详解

2.2.1 corePoolSize（核心线程数）

定义： 线程池中保持活动状态的最小线程数，即使线程处于空闲状态也不会被回收（除非设置allowCoreThreadTimeOut）。

参数特点：

  • 核心线程在创建后会一直存在，直到线程池被关闭
  • 默认情况下，核心线程即使空闲也不会被销毁
  • 可以通过allowCoreThreadTimeOut(true)设置超时回收

设置建议：

  • CPU密集型任务：核心线程数 = CPU核心数 + 1
  • IO密集型任务：核心线程数 = CPU核心数 × 2
  • 混合型任务：根据任务类型比例调整

2.2.2 maximumPoolSize（最大线程数）

定义： 线程池中允许的最大线程数。当工作队列满了，且当前线程数小于最大线程数时，会创建新的线程。

参数特点：

  • 最大线程数必须大于等于核心线程数
  • 当任务数超过核心线程数且队列已满时，会创建新线程直到达到最大线程数
  • 超过最大线程数的任务会被拒绝

设置建议：

  • 根据系统资源和任务特性设置
  • 通常设置为CPU核心数的2-4倍
  • 需要考虑系统内存和上下文切换开销

2.2.3 keepAliveTime（线程空闲时间）

定义： 非核心线程空闲存活时间。当线程空闲时间超过此值时，非核心线程会被回收。

参数特点：

  • 默认只对非核心线程有效
  • 可以通过allowCoreThreadTimeOut(true)让核心线程也受此参数影响
  • 时间单位由unit参数指定

2.2.4 unit（时间单位）

定义： keepAliveTime参数的时间单位。

常用时间单位：

2.2.5 workQueue（工作队列）

定义： 用于保存等待执行的任务的阻塞队列。

常用队列类型：

队列类型 特点 适用场景
ArrayBlockingQueue 基于数组的有界队列，FIFO 任务量已知，需要限制队列长度
LinkedBlockingQueue 基于链表的可选有界队列，FIFO 任务量不确定，可设置容量限制
SynchronousQueue 不存储元素的队列，直接传递 任务执行快，需要立即处理
PriorityBlockingQueue 支持优先级排序的无界队列 任务有优先级区分
DelayQueue 延迟获取元素的无界队列 定时任务、缓存过期

2.2.6 threadFactory（线程工厂）

定义： 用于创建新线程的工厂。可以自定义线程名称、优先级、是否为守护线程等。

自定义线程工厂：

2.2.7 handler（拒绝策略）

定义： 当线程池和工作队列都满了，对新提交任务的处理策略。

四种拒绝策略（下一节详细讲解）：

  • AbortPolicy：直接抛出异常（默认策略）
  • CallerRunsPolicy：由调用线程执行任务
  • DiscardOldestPolicy：丢弃队列中最老的任务
  • DiscardPolicy：直接丢弃任务，不抛出异常

🚫 四、四种拒绝策略

4.1 AbortPolicy（中止策略）

默认策略，直接抛出RejectedExecutionException异常。

适用场景： 需要快速失败，及时发现系统过载。

4.2 CallerRunsPolicy（调用者运行策略）

由调用线程（提交任务的线程）执行被拒绝的任务。

输出示例：

适用场景： 不希望丢失任务，且可以接受任务由调用线程执行。

4.3 DiscardOldestPolicy（丢弃最老任务策略）

丢弃工作队列中最老的任务，然后重新提交当前任务。

适用场景： 允许丢失部分任务，且希望保留最新的任务。

4.4 DiscardPolicy（丢弃策略）

直接丢弃任务，不抛出任何异常。

适用场景： 允许丢失任务，且不希望影响主流程。

🏭 五、线程池的创建方式

5.1 Executors工具类

Java提供了Executors工具类来创建常见的线程池。

5.1.1 newFixedThreadPool（固定大小线程池）

特点：

  • 核心线程数 = 最大线程数
  • 使用LinkedBlockingQueue（无界队列）
  • 线程不会被回收，即使空闲
  • 适用于任务量已知且稳定的场景

5.1.2 newSingleThreadExecutor（单线程池）

特点：

  • 只有一个核心线程
  • 使用LinkedBlockingQueue（无界队列）
  • 保证任务顺序执行
  • 适用于需要顺序执行任务的场景

5.1.3 newCachedThreadPool（缓存线程池）

特点：

  • 核心线程数为0，最大线程数为Integer.MAX_VALUE
  • 使用SynchronousQueue（直接传递队列）
  • 空闲线程会被回收（60秒超时）
  • 适用于任务量波动大、执行时间短的场景

5.1.4 newScheduledThreadPool（定时线程池）

特点：

  • 支持定时执行和周期性执行
  • 可以设置核心线程数
  • 使用DelayedWorkQueue
  • 适用于定时任务、周期性任务

⚠️ 六、为什么阿里规范要求使用ThreadPoolExecutor创建线程池

6.1 阿里开发规范要求

阿里开发规范明确要求： 线程池不允许使用Executors去创建，而是通过ThreadPoolExecutor的方式，这样的处理方式让写的同学更加明确线程池的运行规则，规避资源耗尽的风险。

6.2 Executors创建线程池的隐患

6.2.1 FixedThreadPool和SingleThreadExecutor的问题

问题分析：

  • 使用LinkedBlockingQueue（无界队列）
  • 任务堆积会导致内存溢出
  • 无法控制队列大小

6.2.2 CachedThreadPool的问题

问题分析：

  • 最大线程数为Integer.MAX_VALUE
  • 可能创建大量线程，导致系统资源耗尽
  • 线程上下文切换开销大

6.3 ThreadPoolExecutor的优势

ThreadPoolExecutor的优势：

  1. 参数可控：可以精确控制核心线程数、最大线程数、队列大小等
  2. 资源可控：避免无界队列和无限线程数导致的资源耗尽
  3. 行为可控：可以选择合适的拒绝策略
  4. 监控友好：提供丰富的监控方法

🔒 九、线程池的关闭

9.1 shutdown方法

shutdown方法特点：

  • 不再接受新任务
  • 等待已提交的任务完成
  • 不会中断正在执行的任务
  • 调用后isShutdown()返回true

9.2 shutdownNow方法

shutdownNow方法特点：

  • 不再接受新任务
  • 尝试中断正在执行的任务
  • 返回未执行的任务列表
  • 调用后isShutdown()和isTerminated()都返回true

🎯 十一、面试常见问题及答案

11.1 基础概念问题

Q1：什么是线程池？为什么使用线程池？

答案：
线程池是一种基于池化思想管理线程的工具，它维护着多个线程等待执行任务。使用线程池的主要原因：

  1. 降低资源消耗：复用线程，减少创建和销毁开销
  2. 提高响应速度：任务到达时无需等待线程创建
  3. 提高线程可管理性：统一管理、调优和监控
  4. 提供更多功能：定时执行、并发数控制等

Q2：ThreadPoolExecutor的七个核心参数是什么？

答案：

  1. corePoolSize：核心线程数，线程池中保持活动状态的最小线程数
  2. maximumPoolSize：最大线程数，线程池中允许的最大线程数
  3. keepAliveTime：非核心线程空闲存活时间
  4. unit：keepAliveTime的时间单位
  5. workQueue：用于保存等待执行的任务的阻塞队列
  6. threadFactory：用于创建新线程的工厂
  7. handler：当线程池和工作队列都满了的拒绝策略

Q3：线程池的工作流程是什么？

答案：

  1. 提交任务到线程池
  2. 如果当前线程数 < 核心线程数，创建新核心线程执行任务
  3. 如果当前线程数 >= 核心线程数，将任务添加到工作队列
  4. 如果工作队列已满，且当前线程数 < 最大线程数，创建新非核心线程执行任务
  5. 如果当前线程数 >= 最大线程数，执行拒绝策略

11.2 高级特性问题

Q4：四种拒绝策略是什么？分别适用于什么场景？

答案：

  1. AbortPolicy：直接抛出异常，适用于需要快速失败的场景
  2. CallerRunsPolicy：由调用线程执行任务，适用于不希望丢失任务的场景
  3. DiscardOldestPolicy：丢弃队列中最老的任务，适用于允许丢失部分任务的场景
  4. DiscardPolicy：直接丢弃任务，适用于允许丢失任务且不希望影响主流程的场景

Q5：为什么阿里规范要求使用ThreadPoolExecutor创建线程池？

答案：

  1. 参数可控：可以精确控制核心线程数、最大线程数、队列大小等
  2. 资源可控：避免无界队列和无限线程数导致的资源耗尽
  3. 行为可控：可以选择合适的拒绝策略
  4. 监控友好：提供丰富的监控方法
  5. 风险规避：避免Executors工具类创建的线程池潜在问题

Q6：如何合理设置线程池参数？

答案：

  1. CPU密集型任务：核心线程数 = CPU核心数 + 1
  2. IO密集型任务：核心线程数 = CPU核心数 × 2
  3. 混合型任务：根据任务类型比例调整
  4. 队列选择：根据任务量选择合适的队列类型和容量
  5. 拒绝策略：根据业务需求选择合适的拒绝策略

11.3 实践应用问题

Q7：线程池中的异常如何处理？

答案：

  1. execute方法：未捕获的异常会导致线程终止，需要设置UncaughtExceptionHandler
  2. submit方法：异常会被封装在Future中，通过get()方法获取
  3. 自定义包装器：包装任务，统一处理异常
  4. 全局异常处理器：设置线程工厂的异常处理器

Q8：如何监控和调优线程池？

答案：

  1. 监控指标：活跃线程数、队列大小、已完成任务数、线程使用率等
  2. 调优策略：根据监控数据动态调整核心线程数和最大线程数
  3. 告警机制：设置阈值告警，及时发现线程池问题
  4. 日志记录：记录线程池状态变化，便于问题排查

Q9：如何优雅关闭线程池？

答案：

  1. shutdown方法：平滑关闭，等待已提交任务完成
  2. shutdownNow方法：立即关闭，尝试中断正在执行的任务
  3. 优雅关闭策略：先shutdown，等待超时后shutdownNow
  4. 资源释放：确保线程池关闭后释放所有资源

Q10：CompletableFuture与线程池的关系？

答案：

  1. 异步执行：CompletableFuture使用线程池执行异步任务
  2. 自定义线程池：可以指定自定义线程池，避免使用ForkJoinPool.commonPool()
  3. 组合操作：支持多个异步任务的组合和协调
  4. 异常处理：提供丰富的异常处理机制

11.4 源码原理问题

Q11：ThreadPoolExecutor的execute和submit方法有什么区别？

答案：

  1. execute方法：提交Runnable任务，无返回值，异常直接抛出
  2. submit方法：提交Callable或Runnable任务，返回Future对象，异常封装在Future中
  3. 实现原理：submit内部调用execute，将任务包装为FutureTask

Q12：线程池中的线程是如何复用的？

答案：

  1. Worker类：ThreadPoolExecutor使用Worker类封装线程
  2. 循环获取任务：Worker线程循环从工作队列中获取任务执行
  3. 任务完成后继续：一个任务执行完成后，继续获取下一个任务
  4. 线程保持活跃：核心线程会一直保持活跃，等待新任务

Q13：如何理解线程池的生命周期？

答案：

  1. RUNNING：正常接收新任务，处理工作队列中的任务
  2. SHUTDOWN：不接收新任务，但处理工作队列中的任务
  3. STOP：不接收新任务，不处理工作队列中的任务，中断正在执行的任务
  4. TIDYING：所有任务已终止，workerCount为0
  5. TERMINATED：terminated()方法执行完成

📚 十二、总结与最佳实践

12.1 线程池使用原则

  1. 避免使用Executors工具类：使用ThreadPoolExecutor创建线程池
  2. 合理设置参数：根据任务类型和系统资源设置参数
  3. 使用有界队列：避免无界队列导致的内存溢出
  4. 设置合适的拒绝策略：根据业务需求选择合适的拒绝策略
  5. 命名线程池：便于问题排查和监控
  6. 处理异常：确保异常得到正确处理
  7. 优雅关闭：确保线程池正确关闭，资源得到释放

12.2 常见陷阱

  1. 线程池大小设置不当：导致资源浪费或性能瓶颈
  2. 忽略异常处理：导致线程终止，任务丢失
  3. 不关闭线程池：导致资源泄漏
  4. 使用无界队列：可能导致内存溢出
  5. 在任务中阻塞：导致线程池性能下降

12.3 性能优化建议

  1. 根据任务类型选择线程池：CPU密集型、IO密集型、混合型
  2. 使用合适的队列类型：根据任务特性选择队列
  3. 监控线程池状态：及时发现和解决问题
  4. 动态调整参数：根据负载变化调整线程池参数
  5. 避免任务阻塞：减少任务中的阻塞操作
