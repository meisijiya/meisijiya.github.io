1. 线程与进程

1.1 进程 (Process)

定义：进程是操作系统进行资源分配和调度的基本单位，是程序的一次执行实例。

特点：

  • 🏗️ 进程是系统资源分配的基本单位
  • 📦 每个进程拥有独立的内存地址空间（堆、栈、代码段、数据段）
  • 🔒 进程间相互隔离，一个进程崩溃不会影响其他进程
  • 🔄 进程间通信（IPC）成本较高（管道、消息队列、共享内存、Socket等）

进程组成：

1.2 线程 (Thread)

定义：线程是进程中的一个执行单元，是CPU调度和分派的基本单位。

特点：

  • 🎯 线程是CPU调度的基本单位
  • 📊 同一进程内的多个线程共享进程的资源（内存空间、文件句柄等）
  • 💡 每个线程拥有独立的栈空间、程序计数器、寄存器
  • ⚡ 线程创建和切换的开销比进程小得多
  • 🤝 线程间通信更方便（共享内存）

并发性 多进程并发 多线程并发

1.4 为什么使用多线程？

优势：

  1. 提高CPU利用率：当一个线程等待I/O时，其他线程可以使用CPU
  2. 提高响应速度：UI线程不会被耗时操作阻塞
  3. 简化程序设计：将复杂任务分解为多个并行任务
  4. 利用多核CPU：真正实现并行计算

Java中线程的实现：

  • Java线程在JDK1.2之前使用用户线程（Green Thread）实现
  • JDK1.2及之后使用内核线程（Native Thread）实现
  • 一个Java线程对应一个操作系统内核线程

5.3 有序性 (Ordering)

定义：程序执行的顺序按照代码的先后顺序执行。

问题原因：

  • 指令重排序：编译器和处理器为了提高性能，会对指令进行重排序
  • 内存系统的重排序：缓存和写缓冲区可能导致操作顺序变化

指令重排序的三种情况：

  1. 编译器重排序：编译器在不改变单线程程序语义的前提下，可以重新安排语句的执行顺序
  2. 指令级并行重排序：处理器采用指令级并行技术将多条指令重叠执行
  3. 内存系统重排序：处理器使用缓存和读/写缓冲区，导致加载和存储操作看起来可能乱序执行

6. 线程同步的必要性

6.1 什么是线程安全？

定义：当多个线程访问同一个对象时，如果不用考虑这些线程在运行时环境下的调度和交替执行，也不需要进行额外的同步，或者在调用方进行任何其他的协调操作，调用这个对象的行为都可以获得正确的结果，那么这个对象就是线程安全的。

6.2 线程安全问题产生的原因

根本原因：

  1. 存在共享数据：多个线程访问同一份数据
  2. 存在多个线程修改共享数据：至少有一个线程在修改数据
  3. 没有有效的同步机制：缺乏对共享数据的保护

6.3 为什么需要线程同步？

8. 面试高频问题

8.1 基础概念类

Q1：线程和进程的区别是什么？

A：

  • 进程是操作系统资源分配的基本单位，拥有独立的地址空间
  • 线程是CPU调度的基本单位，共享进程的资源
  • 一个进程可以包含多个线程，线程是进程的执行单元
  • 进程间通信需要IPC机制，线程间可以直接共享内存
  • 进程创建和切换的开销比线程大

Q2：创建线程有哪几种方式？

A：Java中有四种创建线程的方式：

  1. 继承Thread类：重写run()方法，简单但Java单继承限制
  2. 实现Runnable接口：实现run()方法，推荐使用，支持多实现
  3. 实现Callable接口：实现call()方法，有返回值，可抛异常
  4. 使用线程池：生产环境推荐，资源复用，易于管理

Q3：run()和start()方法有什么区别？

A：

  • start()方法会启动新线程，JVM会调用该线程的run()方法
  • 直接调用run()方法只是普通方法调用，不会启动新线程
  • 同一个线程对象不能重复调用start()方法

8.2 线程状态类

Q4：Java线程有哪些状态？

A：Java线程有6种状态：

  1. NEW：新建状态，线程对象已创建但未启动
  2. RUNNABLE：可运行状态，已调用start()方法
  3. BLOCKED：阻塞状态，等待获取synchronized锁
  4. WAITING：等待状态，等待其他线程执行特定操作
  5. TIMED_WAITING：超时等待状态，有超时时间限制
  6. TERMINATED：终止状态，线程执行完毕或异常退出

Q5：BLOCKED和WAITING状态有什么区别？

A：

  • BLOCKED：等待获取synchronized锁，被动进入
  • WAITING：调用wait()、join()等方法主动进入，需要notify()/notifyAll()唤醒
  • BLOCKED是针对synchronized的，WAITING是针对Object.wait()等方法的

Q6：如何终止一个线程？

A：

  1. 使用标志位：设置volatile标志位，线程检查标志后退出
  2. 使用interrupt()方法：设置中断标志，线程检查后退出
  3. 不推荐使用stop()方法：已废弃，可能导致数据不一致

8.3 线程安全类

Q7：什么是线程安全？如何保证线程安全？

A：
线程安全是指多个线程访问同一个对象时，无论运行时环境如何调度，都能得到正确的结果。

保证线程安全的方法：

  1. 使用synchronized关键字：保证原子性、可见性、有序性
  2. 使用volatile关键字：保证可见性、有序性
  3. 使用Lock接口：更灵活的锁机制
  4. 使用原子类：如AtomicInteger、AtomicReference等
  5. 使用线程安全集合：如ConcurrentHashMap、CopyOnWriteArrayList等
  6. 使用ThreadLocal：线程局部变量，避免共享

Q8：synchronized和volatile的区别是什么？

A：

特性 synchronized volatile
原子性 ✅ 保证 ❌ 不保证
可见性 ✅ 保证 ✅ 保证
有序性 ✅ 保证 ✅ 保证
阻塞 ✅ 会阻塞 ❌ 不会阻塞
性能 较差 较好
使用场景 复合操作 简单读写

Q9：synchronized的原理是什么？

A：

  • synchronized基于Monitor（监视器/管程）机制实现
  • 每个Java对象都有一个Monitor
  • Monitor中有EntryList（锁池）和WaitSet（等待池）
  • 线程获取锁时，会尝试获取对象的Monitor
  • 获取成功则进入同步代码，失败则进入EntryList等待
  • 线程调用wait()方法会进入WaitSet等待

Q10：什么是volatile？它的作用是什么？

A：
volatile是一个轻量级的同步机制，有两个作用：

  1. 保证可见性：修改后的值对所有线程立即可见
  2. 禁止指令重排序：防止编译器和处理器对指令进行重排序

使用场景：

  • 状态标志
  • 双重检查锁定（DCL）单例模式
  • 一次性安全发布

注意：volatile不能保证原子性，复合操作仍需使用synchronized或原子类。

死锁是指两个或多个线程互相等待对方释放资源，导致所有线程都无法继续执行。

死锁的四个必要条件：

  1. 互斥条件：资源一次只能被一个线程使用
  2. 请求与保持条件：线程持有资源并请求其他资源
  3. 不剥夺条件：已获得的资源不能被强制剥夺
  4. 循环等待条件：存在线程的循环等待链

避免死锁的方法：

  1. 按顺序获取锁：所有线程按照相同的顺序获取锁
  2. 设置超时时间：使用tryLock()方法设置超时
  3. 避免嵌套锁：尽量避免同时持有多个锁
  4. 使用定时锁：使用Lock.tryLock(timeout)
