1. 原子操作的概念和重要性

1.1 什么是原子操作

原子操作（Atomic Operation）是指不会被线程调度机制打断的操作。这种操作一旦开始，就一直运行到结束，中间不会切换到另一个线程。

原子性是并发编程中最重要的特性之一。当一个操作是原子的，其他线程看到的只有两种状态：操作前和操作后，不存在中间状态。

2. CAS原理（Compare And Swap）详解

2.1 CAS基本概念

CAS（Compare And Swap）是一种无锁的并发算法，它包含三个操作数：

  • V（Value）：要更新的内存地址中的值
  • E（Expected）：预期原值
  • N（New）：新值

10. 面试常见问题及答案

Q1: 什么是CAS？它的优缺点是什么？

答：
CAS（Compare And Swap）是一种无锁的并发算法，包含三个操作数：内存值V、预期原值E、新值N。当V等于E时，将V更新为N，否则不做任何操作。

优点：

  • 无锁，避免线程阻塞和上下文切换
  • 性能通常优于synchronized
  • 不会死锁

缺点：

  • ABA问题（可通过AtomicStampedReference解决）
  • 自旋开销（竞争激烈时CPU空转）
  • 只能保证单个变量的原子性

Q2: 什么是ABA问题？如何解决？

答：
ABA问题是指一个值从A变为B，再变回A，CAS操作会认为值没有变化。

解决方案：

  1. AtomicStampedReference：使用版本号，每次修改版本号+1
  2. AtomicMarkableReference：使用布尔标记，表示是否被修改过
  3. 使用不可变对象（引用变化就是真正变化）

Q3: AtomicInteger的实现原理是什么？

答：
AtomicInteger通过Unsafe类调用CPU的CAS指令实现原子操作。

关键点：

  • 使用volatile保证可见性
  • 使用CAS保证原子性
  • 失败时自旋重试

Q4: LongAdder和AtomicLong有什么区别？什么时候用哪个？

答：

特性 AtomicLong LongAdder
实现原理 单变量CAS 分段CAS（Cell数组）
高竞争性能 差（频繁CAS失败） 好（分散竞争）
读取准确性 实时准确 最终一致（sum()）
内存占用 小 大（Cell数组）
适用场景 低竞争、需要精确值 高竞争、最终一致性

选择建议：

  • 低竞争、需要实时精确值 → AtomicLong
  • 高竞争、统计计数、可以接受最终一致性 → LongAdder

Q5: Unsafe类的作用是什么？为什么不推荐直接使用？

答：
Unsafe类提供底层内存操作能力，是Java原子类的实现基础。

主要功能：

  • CAS操作（compareAndSwapInt等）
  • 内存分配和释放（allocateMemory等）
  • 内存屏障（loadFence等）
  • 对象字段偏移量获取

不推荐使用的原因：

  1. 绕过JVM安全检查，可能导致JVM崩溃
  2. 可移植性差（依赖底层实现）
  3. JDK9+已移除对Unsafe的直接访问
  4. 使用不当会导致内存泄漏

Q6: 什么是内存屏障？在原子类中如何使用？

答：
内存屏障（Memory Barrier/Fence）是一条CPU指令，用于控制特定条件下的重排序和内存可见性。

类型：

  • Load Barrier：确保屏障前的读取操作在屏障后读取之前完成
  • Store Barrier：确保屏障前的写入操作对其他处理器可见

Q10: CAS和synchronized如何选择？

答：

维度 CAS synchronized
锁类型 无锁（乐观锁） 有锁（悲观锁）
性能 低竞争时好 高竞争时可能更好
复杂度 只能单变量 可以保护代码块
公平性 不公平 可配置
适用场景 简单操作、计数器 复杂逻辑、多变量

选择建议：

  • 简单的原子操作 → CAS（原子类）
  • 复杂的复合操作 → synchronized
  • 需要阻塞等待 → synchronized
  • 高竞争简单操作 → LongAdder

11. 总结

核心要点

  1. CAS是无锁并发的基础，通过比较并交换实现原子操作
  2. 原子类是CAS的封装，提供类型安全的API
  3. ABA问题是CAS的主要缺陷，通过版本号解决
  4. LongAdder在高并发下性能优于AtomicLong
  5. Unsafe类是CAS的底层实现，不推荐直接使用
  6. 选择原子类要根据场景：竞争程度、精度要求、内存限制
