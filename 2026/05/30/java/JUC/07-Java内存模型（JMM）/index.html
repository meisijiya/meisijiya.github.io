Java内存模型（JMM）详解

作者: 老江湖
日期: 五月 30, 2026  0:30:03
分类: java 并发与多线程

📖 本笔记系统梳理Java内存模型（Java Memory Model, JMM）的核心概念、内存语义规则及并发编程实践，适合深入理解和面试复习使用。

一、JMM的概念和作用

1.1 什么是JMM

Java内存模型（Java Memory Model, JMM） 是Java虚拟机规范中定义的一套规则，用于屏蔽各种硬件和操作系统的内存访问差异，使Java程序在各种平台下都能达到一致的内存访问效果。

JMM定义了：

  • 线程之间的共享变量如何存储和访问
  • 线程之间如何通信和同步
  • 指令重排序的规则和限制
  • happens-before关系的语义

⚠️ 常见误区：很多人将JMM的”主内存”等同于JVM的”堆”，将”工作内存”等同于JVM的”栈”，这是不准确的。JMM是一个抽象概念，主内存和工作内存并不对应具体的内存区域。

二、主内存与工作内存

2.1 模型结构

JMM规定所有变量都存储在主内存（Main Memory）中，每个线程有自己的工作内存（Working Memory）。

2.2 主内存

主内存是所有线程共享的内存区域，存储所有的实例变量、静态变量和数组元素。

  • 主内存是线程间通信的唯一媒介
  • 一个线程不能直接操作另一个线程的工作内存
  • 线程间的数据传递必须通过主内存

2.3 工作内存

工作内存是每个线程私有的内存区域，存储该线程使用到的变量的主内存副本。

  • 线程对变量的所有操作（读取、赋值）都在工作内存中进行
  • 不同线程之间无法直接访问对方的工作内存
  • 线程间变量值的传递需要通过主内存

四、happens-before规则详解

4.1 概念定义

happens-before是JMM中最核心的概念，用于判断数据是否存在竞争、线程是否安全。

如果操作A happens-before 操作B，那么：

  • A的结果对B可见
  • A的执行顺序排在B之前

注意：happens-before不是指时间上的先后顺序，而是一种可见性保证。

十一、面试常见问题及答案

Q1：什么是Java内存模型（JMM）？

答：Java内存模型是Java虚拟机规范中定义的一套规则，用于屏蔽各种硬件和操作系统的内存访问差异。它定义了：

  • 线程之间的共享变量如何存储和访问
  • 线程之间如何通信和同步
  • 指令重排序的规则和限制
  • happens-before关系的语义

JMM的核心目标是保证多线程环境下程序的正确性。

Q2：主内存和工作内存有什么区别？

答：

  • 主内存：所有线程共享的内存区域，存储所有的实例变量、静态变量和数组元素
  • 工作内存：每个线程私有的内存区域，存储该线程使用到的变量的主内存副本
  • 线程对变量的所有操作都在工作内存中进行，不能直接操作主内存
  • 线程间的数据传递必须通过主内存

Q3：volatile关键字的作用是什么？

答：volatile提供两个核心保证：

  1. 可见性：对volatile变量的读写总能获取到最新值
    • volatile写会立即刷新到主内存
    • volatile读会从主内存重新加载
  2. 有序性：禁止volatile操作前后的指令重排序
    • volatile写之前的语句不会重排到之后
    • volatile读之后的语句不会重排到之前

volatile不保证原子性，例如volatile++不是原子操作。

Q4：volatile和synchronized有什么区别？

答：

特性 volatile synchronized
原子性 不保证 保证
可见性 保证 保证
有序性 保证 保证
阻塞 不会 会
性能 较好 较差
适用场景 状态标志、DCL 临界区保护、复合操作

Q5：什么是happens-before规则？

答：happens-before是JMM中最核心的概念，用于判断数据是否存在竞争、线程是否安全。如果操作A happens-before 操作B，那么A的结果对B可见，A的执行顺序排在B之前。

八大happens-before规则：

  1. 程序顺序规则：同一线程内，代码顺序执行
  2. 锁规则：unlock happens-before 同一个锁的lock
  3. volatile规则：volatile写 happens-before volatile读
  4. 线程启动规则：start() happens-before 线程的任何操作
  5. 线程终止规则：线程的所有操作 happens-before join()返回
  6. 线程中断规则：interrupt() happens-before 中断检测
  7. 对象终结规则：构造函数结束 happens-before finalize()开始
  8. 传递性：A hb B，B hb C → A hb C

Q6：什么是指令重排序？

答：指令重排序是指编译器和处理器为了优化程序性能，对指令序列进行重新排序的行为。重排序分为三种：

  1. 编译器重排序：编译器改变语句顺序
  2. 处理器重排序：处理器改变指令执行顺序
  3. 内存系统重排序：由于写缓冲区导致的重排序

重排序在单线程环境下不影响程序结果，但在多线程环境下可能导致问题。

Q7：什么是内存屏障？

答：内存屏障是一种CPU指令，用于控制特定条件下的重排序和内存可见性。分为四种：

  1. LoadLoad屏障：确保Load1先于Load2执行
  2. StoreStore屏障：确保Store1先于Store2执行
  3. LoadStore屏障：确保Load1先于Store2执行
  4. StoreLoad屏障：确保Store1先于Load2执行（全能屏障）

volatile的内存语义就是通过内存屏障实现的。

Q8：DCL（双重检查锁定）为什么要用volatile？

答：instance = new Singleton() 不是原子操作，实际包含三个步骤：

  1. 分配内存空间
  2. 初始化对象
  3. 将引用指向内存空间

可能发生重排序为1→3→2，导致其他线程看到未初始化完成的对象。使用volatile可以禁止重排序，保证对象完全初始化后才被其他线程看到。

Q9：final字段的内存语义是什么？

答：final字段具有以下内存语义：

  1. 在构造函数内对final字段的写入，编译器会在之后插入StoreStore屏障
  2. 初次读取包含final字段的对象引用，编译器会在之后插入LoadLoad屏障

这保证了final字段在构造函数完成后对所有线程可见，可以安全发布。

Q10：如何保证多线程环境下的内存可见性？

答：有以下几种方式：

  1. volatile关键字：保证读写的可见性，适用于状态标志
  2. synchronized关键字：保证进入和退出同步块时的可见性
  3. final关键字：保证构造函数完成后字段的可见性
  4. 并发工具类：如Atomic类、锁、CountDownLatch等

选择哪种方式取决于具体场景和性能要求。

Q11：JMM与JVM内存结构有什么区别？

答：

  • JMM：抽象规范，定义线程间数据共享和同步的规则
  • JVM内存结构：具体实现，定义JVM运行时的内存区域划分

JMM的主内存和工作内存不对应具体的JVM内存区域，主内存可以对应堆和方法区，工作内存可以对应栈和寄存器。

Q12：什么是竞态条件？如何避免？

答：竞态条件是指多个线程同时访问和修改共享数据，最终结果取决于线程执行的精确时序。例如i++操作。

避免方式：

  1. 使用synchronized同步
  2. 使用Atomic原子类
  3. 使用Lock锁
  4. 使用volatile（仅适用于简单场景）
  5. 使用不可变对象
