一、Spring Cloud Alibaba 概述

1.1 什么是 Spring Cloud Alibaba

Spring Cloud Alibaba 是阿里巴巴开源的一套微服务解决方案，为微服务开发提供一站式解决方案。它提供了服务注册与发现、配置管理、服务治理、流量控制、分布式事务等分布式系统所需的核心功能。

与 Spring Cloud Netflix 那套生态相比，Spring Cloud Alibaba 更贴合国内互联网公司实际需求，组件国产化、社区活跃度高、文档中文友好。

1.2 Spring Cloud Alibaba 都有哪些组件

组件 作用 地位
Nacos 服务注册与发现 + 配置管理 替代 Eureka + Config
Sentinel 流量控制、熔断降级、系统保护 替代 Hystrix
Seata 分布式事务解决方案 行业标杆
Dubbo 高性能 RPC 框架 + 服务治理 替代 Feign（RPC 层）
RocketMQ 分布式消息引擎 替代 RabbitMQ/Kafka
Alibaba Cloud ACM 阿里云全局配置中心 商业化
Alibaba Cloud OSS 对象存储服务 商业化
Alibaba Cloud SchedulerX 分布式任务调度 商业化

1.3 Spring Cloud Alibaba 与 Spring Boot、Spring Cloud 版本关系

⚠️ 版本选择非常关键，版本不匹配会导致依赖冲突。建议在 start.aliyun.com 生成脚手架时选择对应版本。

二、服务注册与发现 —— Nacos

2.1 Nacos 是什么

Nacos（Name as Configuration Service）是一个更易于构建云原生应用的服务发现、配置管理和服务管理平台。它既可以替代传统的 Eureka 作为注册中心，也可以替代 Spring Cloud Config 作为配置中心。

核心能力：

  • 服务注册与发现（支持 CP/AP 两种模式）
  • 配置管理（配置变更、灰度发布、配置共享）
  • 服务管理（流量管理、权重路由）

2.2 Nacos 服务注册与发现原理

服务注册

当服务实例启动时，它会向 Nacos 服务器发送一个注册请求，请求中包含：

  • 服务名（spring.application.name）
  • IP 地址 + 端口号
  • 健康检查信息
  • 元数据（metadata）

2.3 Nacos 的 AP 和 CP 模式

Nacos 支持 CPA 理论中的两种一致性模式：

模式 全称 特点 适用场景
AP模式（默认） Availability + Partition tolerance 优先保证可用性，节点间数据可能短暂不一致 注册中心（服务发现）
CP模式 Consistency + Partition tolerance 优先保证一致性，写操作需同步到多数节点 配置中心（leader选举）

2.4 Nacos 的核心概念

概念 解释
Namespace 环境隔离，默认为 public，如 DEV、SIT、UAT、PROD
Group 项目隔离，默认 DEFAULT_GROUP，不同项目可用不同分组
Service 服务名称，唯一标识一个微服务
Cluster 集群隔离，同一服务在不同机房的节点可划为同一集群
Instance 服务实例，即服务Provider的某一个运行进程

三、流量控制与熔断降级 —— Sentinel

3.1 Sentinel 是什么

Sentinel（流量防卫兵）是阿里巴巴开源的高性能流量控制组件，以流量为切入点，从流量控制、熔断降级、系统负载保护等多个维度保护服务的稳定性。

3.2 为什么需要 Sentinel

在高并发场景下，如果服务A调用服务B，而服务B因故障导致响应极慢甚至不可用，继续让所有请求打到B上会导致：

  1. 级联失败：服务A的资源被耗尽，影响上游服务
  2. 雪崩效应：故障在服务链中蔓延，形成系统级故障

Sentinel 的解决方案：

  • 流量控制：限制单位时间内请求数量
  • 熔断降级：当失败率/响应时间超过阈值时，断开调用链
  • 系统自适应保护：根据 CPU/LOAD/响应时间等指标自动调节整体流量

3.3 Sentinel 与 Hystrix 的核心区别

对比项 Hystrix Sentinel
线程池隔离 ✅ 有，但资源消耗大 ❌ 无，采用信号量隔离
熔断策略 基于异常比例 基于 QPS / 异常比例 / 响应时间
规则配置 配置在代码中 运行时动态配置（推模式）
规则持久化 无内置 支持 Nacos、Apollo 等多种存储
控制台 Turbine 单机聚合 Sentinel Dashboard 可视化控制台
实时指标 仅聚合，无实时性 基于滑动窗口，实时准确

3.4 流量控制规则（Flow Rule）

Sentinel 支持以下几种流控效果：

效果 说明
直接拒绝（Default） 超出阈值的请求直接拒绝
冷启动（Warm Up） 逐渐预热到阈值，防止冷系统被突发流量击垮
排队等待（Queuely Waiting） 超出的请求排队等候，常用于削峰填谷

3.5 熔断降级规则（Degrade Rule）

Sentinel 的熔断器状态机：

Sentinel 支持三种熔断策略：

  1. 基于异常比例：每秒请求中异常比例超过阈值触发熔断
  2. 基于异常数：当每分钟异常数超过阈值触发熔断
  3. 基于响应时间：响应时间超过阈值触发熔断

四、分布式事务 —— Seata

4.1 为什么需要分布式事务

在微服务架构下，一个业务操作往往需要跨多个数据库或跨多个服务完成：

如果订单创建成功但库存扣减失败，单机事务无法覆盖两个数据库，此时需要分布式事务来保证要么全部成功，要么全部回滚。

4.2 Seata 是什么

Seata（Simple Extensible Autonomous Transaction Architecture）是阿里巴巴开源的易于使用的高性能微服务分布式事务解决方案。它提供了 AT、TCC、Saga、XA 四种事务模式。

4.3 Seata 的三种事务模式

模式 原理 优点 缺点 适用场景
AT（推荐） 基于本地事务 + 全局锁，自动生成回滚 SQL 对业务零侵入，代码零修改 需要支持 UNDO_LOG 表 大多数业务场景
TCC Try-Confirm-Cancel，预预留资源 性能高，无锁定 代码侵入，需实现三个方法 高性能要求场景
Saga 长事务编排，每个服务正向操作+补偿操作 支持长事务 补偿逻辑复杂 业务流程长、参与者多
XA 强一致性，基于两阶段提交 数据一致性高 性能差，锁定资源时间长 对数据强一致性要求高

4.4 AT 模式工作原理

AT 模式是 Seata 最推荐的模式，工作流程：

关键点：

  • TC（Transaction Coordinator）：独立的协调服务，维护全局事务状态
  • TM（Transaction Manager）：事务发起方，控制全局事务边界
  • RM（Resource Manager）：资源管理器，管理分支事务使用的资源

五、服务间通信 —— Dubbo

5.1 为什么选择 Dubbo 替代 Feign

对比项 Feign Dubbo
底层协议 HTTP（基于 RestTemplate） TCP（基于 Netty / 高性能 RPC）
序列化 JSON（较慢） Hessian / Protobuf（二进制，高效）
性能 较低 高（官方测试是 Feign 的 2-3 倍）
功能 轻量，仅 HTTP Client 服务治理（负载均衡、路由、熔断）
生态 Spring Cloud 生态 独立生态，但支持 Spring Boot

💡 在国内高性能场景（如电商、金融），Dubbo 仍然是主流选择。

策略 说明

六、分布式消息 —— RocketMQ

6.1 RocketMQ 核心概念

概念 解释
Producer 消息生产者，负责发送消息
Consumer 消息消费者，负责消费消息
Broker 消息代理，存储和转发消息
Topic 主题，消息的分类管理单位
Tag 标签，同一 Topic 下的消息二级分类
Message 消息内容
Group 消费组，同一消费组的消费者均分消息

6.2 RocketMQ 的消息类型

  1. 普通消息：发送即 forget，不保证可靠性
  2. 事务消息（Transaction Message）：先执行本地事务，根据本地事务结果决定是否提交消息，用于解决分布式事务问题

七、Gateway 网关

7.1 Spring Cloud Gateway 核心概念

Spring Cloud Gateway 是 Spring Cloud 的全新网关，替代了已经进入维护模式的 Zuul。

核心概念：

  • Route：路由定义，包含 id、uri、predicates、filters
  • Predicate：断言，用于匹配请求条件（如路径、请求方式、Header 等）
  • Filter：过滤器，在请求前后执行过滤逻辑

八、微服务架构常见面试问题

8.1 Nacos 和 Consul 在服务注册和发现方面有什么不同

对比项 Nacos Consul
一致性协议 AP/CP 可切换 CP（Consul 使用 Raft）
配置中心 内置 需额外集成 Consul Template
多语言支持 所有语言（HTTP） 所有语言（HTTP + DNS）
运维成本 中等 较高（Consul Agent 部署）
中国本地化 中文文档，社区活跃 英文为主

8.2 如何实现服务限流

在 Spring Cloud Alibaba 环境中，实现限流有几种方式：

  1. Sentinel + @SentinelResource（推荐）：

    • 基于 QPS / 并发线程数限流
    • 支持分布式限流（集群流控）

  2. Gateway + Redis + RequestRateLimiter：

  3. Nginx + lua + ngx_http_limit_req_module：

    • 网关层限流，适合入口流量控制

8.3 如何实现服务降级

服务降级的几种常见策略：

  1. Sentinel 降级：当接口响应时间超过阈值，自动触发降级，返回兜底数据
  2. Feign 降级（Hystrix）：配置 fallback 类，远程调用失败时返回兜底结果
  3. 重试机制：配合 Spring Retry，设置重试次数和退避策略
  4. 服务不可用时直接返回：通过熔断器状态自动实现

九、Spring Cloud Alibaba 与 Spring Cloud Netflix 对比总结

能力项 Spring Cloud Netflix Spring Cloud Alibaba
注册中心 Eureka Nacos（更强大）
配置中心 Spring Cloud Config Nacos（更易用）
服务调用 Feign Dubbo（更高性能）
熔断器 Hystrix Sentinel（更完善）
分布式事务 无内置 Seata（AT/TCC/Saga/XA）
消息队列 RabbitMQ / Kafka RocketMQ（国产优化）
网关 Zuul Gateway（性能更高）
文档/社区 英文为主，部分已过时 中文活跃
