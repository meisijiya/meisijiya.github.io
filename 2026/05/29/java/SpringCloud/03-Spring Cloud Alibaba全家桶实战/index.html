Spring Cloud Alibaba概述

1.1 什么是Spring Cloud Alibaba 🌟

Spring Cloud Alibaba是阿里巴巴开源的微服务解决方案，基于Spring Cloud，提供了微服务开发的一站式解决方案。

核心特性：

  • 服务发现与配置管理：Nacos
  • 流量控制与熔断降级：Sentinel
  • 分布式事务：Seata
  • 消息驱动：RocketMQ
  • 分布式任务调度：SchedulerX
  • 对象存储：OSS

1.2 为什么选择Spring Cloud Alibaba 🎯

与Spring Cloud Netflix对比：

组件功能 Spring Cloud Netflix Spring Cloud Alibaba
服务发现 Eureka（已停止维护） Nacos（活跃维护）
配置中心 Config（功能简单） Nacos（功能强大）
熔断降级 Hystrix（已停止维护） Sentinel（活跃维护）
API网关 Zuul（已停止维护） Gateway（官方推荐）
分布式事务 无 Seata（功能完善）
消息驱动 Stream（功能有限） RocketMQ（功能强大）

Spring Cloud Alibaba优势：

  1. 活跃维护：阿里巴巴持续更新
  2. 功能完善：覆盖微服务全场景
  3. 生产验证：经过双十一考验
  4. 中文文档：文档完善，社区活跃
  5. 性能优秀：经过大规模生产验证

Sentinel流量控制与熔断降级

3.1 Sentinel概述 🔥

Sentinel是阿里巴巴开源的流量控制与熔断降级组件，以流量为切入点，从流量控制、熔断降级、系统负载保护等多个维度来保护服务的稳定性。

核心功能：

  • 流量控制：控制请求速率
  • 熔断降级：防止服务雪崩
  • 系统负载保护：保护系统不被打垮
  • 热点参数限流：针对热点参数限流
  • 授权规则：黑白名单控制

Seata分布式事务解决方案

4.1 Seata概述 💰

Seata（Simple Extensible Autonomous Transaction Architecture）是阿里巴巴开源的分布式事务解决方案，提供了AT、TCC、Saga和XA四种事务模式。

核心功能：

  • 全局事务管理：管理分布式事务的生命周期
  • 分支事务管理：管理各个服务的本地事务
  • 事务协调：协调各个分支事务的提交或回滚
  • 资源管理：管理全局锁和资源

4.2 Seata架构 🏗️

核心组件：

  • **TC (Transaction Coordinator)**：事务协调者，管理全局事务
  • **TM (Transaction Manager)**：事务管理器，发起全局事务
  • **RM (Resource Manager)**：资源管理器，管理分支事务

面试常见问题与答案

Q1：Nacos与Eureka有什么区别？

答案：

对比维度 Nacos Eureka
开发公司 阿里巴巴 Netflix
维护状态 活跃维护 已停止维护
一致性模型 支持CP和AP 仅AP
配置管理 支持 不支持
健康检查 TCP/HTTP/MySQL 仅客户端心跳
负载均衡 权重/元数据 仅客户端负载均衡
多数据中心 支持 不支持
管理界面 功能完善 功能简单

Nacos优势：

  1. 同时支持服务发现和配置管理
  2. 支持CP和AP两种一致性模型
  3. 健康检查方式更多样
  4. 管理界面功能更完善
  5. 阿里巴巴持续维护更新

Q2：Sentinel与Hystrix有什么区别？

答案：

对比维度 Sentinel Hystrix
开发公司 阿里巴巴 Netflix
维护状态 活跃维护 已停止维护
隔离策略 信号量/线程池 线程池/信号量
流控模式 QPS/线程数 仅QPS
流控效果 预热/排队等待 快速失败
熔断策略 慢调用/异常比例/异常数 异常比例/异常数
热点限流 支持 不支持
系统保护 支持 不支持
管理界面 功能完善 功能简单

Sentinel优势：

  1. 流控模式更丰富
  2. 支持热点参数限流
  3. 支持系统保护
  4. 管理界面功能更完善
  5. 阿里巴巴持续维护更新

Q3：Seata的四种事务模式有什么区别？

答案：

事务模式 原理 适用场景 优点 缺点
AT模式 基于数据源代理，自动生成回滚SQL 大多数场景 无侵入，使用简单 性能损耗，需要代理数据源
TCC模式 手动编写Try/Confirm/Cancel方法 资金、库存等核心业务 性能好，无锁 代码侵入性强，开发成本高
Saga模式 长事务，正向操作+补偿操作 长流程业务 无锁，性能好 代码侵入性强，补偿逻辑复杂
XA模式 基于数据库XA协议 强一致性要求 强一致性 性能差，锁粒度大

选择建议：

  • 大多数场景选择AT模式
  • 资金、库存等核心业务选择TCC模式
  • 长流程业务选择Saga模式
  • 强一致性要求选择XA模式

Q4：Nacos配置管理的原理是什么？

答案：

Nacos配置管理原理：

  1. 配置获取：

    • 应用启动时，从Nacos Server获取配置
    • 配置格式支持：YAML、Properties、JSON、XML
    • 配置分组：支持多分组管理

  2. 配置监听：

    • Nacos Client监听配置变更
    • 基于长轮询机制（Long Polling）
    • 配置变更时，Nacos Server通知Nacos Client

  3. 配置更新：

    • Nacos Client重新获取配置
    • 应用动态刷新配置（@RefreshScope）
    • 支持配置版本管理

  4. 配置隔离：

    • 命名空间（Namespace）：环境隔离
    • 分组（Group）：业务隔离
    • 集群（Cluster）：区域隔离

Q5：如何保证微服务间的数据一致性？

答案：

分布式事务解决方案：

  1. 2PC/3PC：

    • 强一致性，性能差
    • 适合传统数据库事务

  2. TCC：

    • 最终一致性，性能好
    • 适合资金、库存等核心业务

  3. Saga：

    • 最终一致性，无锁
    • 适合长流程业务

  4. 本地消息表：

    • 最终一致性，可靠
    • 适合异步场景

  5. 事务消息：

    • 最终一致性，可靠
    • RocketMQ事务消息

  6. Seata：

    • 提供AT、TCC、Saga、XA四种模式
    • 根据业务场景选择合适模式
