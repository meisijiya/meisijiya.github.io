1. 架构设计：RAG全流程解析

💡 RAG是什么？

RAG（Retrieval-Augmented Generation） 是构建智能客服、企业知识库、产品问答助手的核心技术，让AI既能懂知识又能说人话。

🎯 使用场景

场景 说明 价值
企业知识库 技术文档、Wiki、告警手册 知识统一管理，避免流失
智能客服 产品FAQ、常见问题 7x24小时自动回答
运维助手 告警处理、故障排查 快速定位问题
产品问答 功能说明、使用指南 减少人工支持

🔄 RAG核心流程

📊 提问前：数据准备链路

1.1 分片（Chunk）：切分文档

目标：将原始文档切割为多个语义完整的片段

关键原则：

  • ✅ 每个片段语义完整，不切断句子
  • ✅ 片段大小适中（200-1000 tokens）
  • ✅ 相邻片段有重叠（overlap），避免信息丢失

1.2 索引（Embedding）：向量化

目标：用Embedding模型将分片后的文本转化为向量

向量数据库：存储向量与文本，支持相似性查询

1.3 存储：写入向量数据库

目标：将向量和原始文本存入Milvus，方便后续检索

📊 提问后：回答生成链路

1.4 召回（Retriever）：向量相似度搜索

目标：将用户问题向量化，用向量相似度算法找出Top N最相关片段

向量相似度算法：

算法 运算符 原理 特点
L2距离 <-> 计算两点直线距离 距离越小越相似
余弦距离 <=> 计算向量夹角 只看方向，不看长度
内积 <#> 向量点积 适合推荐系统

1.5 重排（Reranker）：精筛优先级

目标：用专门模型进一步筛选，从Top N中选出Top K最相关片段

为什么不直接召回3个？

1.6 生成（Generate）：让AI写出答案

目标：将重排后的相关片段与用户问题一起投喂给大模型，生成准确回答

5. 面试话术与总结

🎯 面试话术模板

面试官：”介绍一下你的知识库Agent是怎么设计的？”

你：

“我的知识库Agent采用RAG架构，分为提问前和提问后两个阶段：

提问前（数据准备）：

  1. 分片：按Markdown标题+段落边界切分，保持语义完整
  2. Embedding：调用DashScope API将文本向量化（1024维）
  3. 存储：写入Milvus向量数据库

提问后（回答生成）：

  1. 召回：问题向量化 → Milvus相似度搜索 → Top K结果
  2. 重排：Cross Encoder精筛（本项目暂未实现）
  3. 生成：相关文档+问题 → 大模型生成回答

亮点设计：

  • 统一知识中台：一次开发，对话Agent和运维Agent都能复用
  • @Tool注解封装：Agent通过Function Calling调用
  • 智能分片：按标题切分，overlap避免信息丢失”
