2. 架构设计：Plan-Execute-Replan 设计模式核心原理

🎯 什么是 Plan-Execute-Replan？

Plan-Execute-Replan 是Agent的结构化任务执行模式，核心是：先规划执行步骤，再按步骤行动，随时校准方向。

🏠 装修类比

🔄 Plan-Execute-Replan vs ReAct

对比维度 ReAct Plan-Execute-Replan
工作方式 边想边做 先规划后执行
任务类型 简单/单步骤 复杂/多步骤
结构化 无结构化 强结构化
动态调整 自动调整 显式重规划
适用场景 问答、简单查询 告警排查、复杂运维

3. 架构设计：运维Agent的核心流程解析

🎯 核心目标

将运维人员的告警处理经验转化为自动化流程，通过计划生成 → 工具执行 → 动态调整的闭环，替代人工完成重复性告警排查工作。

🏗️ 整体架构

3.1 计划生成（Planner）

目标：基于告警类型和召回的运维手册，生成可执行的多步骤排查计划

3.2 计划执行（Executor）

目标：集成监控/日志工具，自动执行计划中的步骤

3.3 动态重规划（Replanner）

目标：根据Executor的执行结果，判断是否需要调整计划

5. 面试话术与总结

🎯 面试话术模板

面试官：”介绍一下你的运维Agent是怎么设计的？”

你：

“运维Agent采用Plan-Execute-Replan架构，核心是让AI像工程师一样先规划、再执行、随时调整：

架构设计：

  • Planner（规划器）：基于告警类型和运维手册，生成JSON格式的结构化排查计划
  • Executor（执行器）：集成Prometheus、Loki等工具，自动执行计划中的每个步骤
  • Replanner（重规划器）：评估执行结果，决定继续、调整还是终止
  • Supervisor（调度员）：编排Planner和Executor的交互流程

核心价值：

  • 接管80%重复性告警排查工作
  • 响应速度从30分钟降到秒级
  • 排查流程标准化、可追溯
  • 经验自动沉淀，用得越久越准确

技术栈：Spring AI Alibaba + ReactAgent + SupervisorAgent + Prometheus + Loki”
