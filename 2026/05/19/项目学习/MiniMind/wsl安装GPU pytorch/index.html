一、项目概览：这到底是个啥

1.1 MiniMind 是什么

MiniMind 是一个开源超小型语言模型，仅 64M 参数（GPT-2 的 1/2，LLaMA-7B 的 1/100），主打极低成本训练和推理。

🍵 奶茶店类比：MiniMind 是”迷你奶茶机”——不是星巴克那种工业级，但够你学做奶茶的每个步骤。配方（架构）和商用版一模一样，只是量小不占地。

1.2 我想对这个项目做什么

  • 基座模型：MiniMind 已做过 SFT（监督微调），会正常聊天
  • LoRA 微调：注入 0.4M 额外参数，学会女朋友的语气：撒娇、短回复、表情符号
  • 数据量：231,147 条原始消息 → 清洗后 2566 条训练样本

1.3 为什么用 venv 虚拟环境

在你开始装任何东西之前，先搞懂 Python 的”包隔离”机制——

**venv 就是项目专属的”小房子”**。每个项目有自己的 .venv/ 文件夹，里面装 Python + 所有依赖包，和其他项目完全不互通。

你的项目文件夹长这样：

问题 答案
CPU 和 GPU torch 装在哪？ 都在 .venv/lib/python3.12/site-packages/，不出这个文件夹
新项目要重新下载吗？ uv 有全局缓存 ~/.cache/uv/，同名包秒装不重复下载
会污染系统环境吗？ 绝不可能。删掉 .venv/ 就干干净净，不用 sudo
怎么删干净？ rm -rf .venv/ 一行搞定

全局安装 = 所有奶茶杯在同一个水池里洗（串味碰撞）；venv = 每人自己的杯子（干净独立）。uv 缓存 = 共享原料仓库（珍珠椰果不用每次进货）。

5.1 为什么 GPU 对 LoRA 如此重要

LoRA 看起来只训练 0.4M 参数，但每个训练 step 的前向+反向传播仍然需要 64M 基础模型全部参与计算。

以 MiniMind 单层 self-attention 为例（hidden_size=768）：

这些全是矩阵乘法——GPU 的绝对主场。CUDA 的 cuBLAS/cuDNN 库高度优化了此类操作：

库 作用
cuBLAS GPU 加速的基础线性代数（矩阵乘法 A@B）
cuDNN 深层神经网络原语（Attention softmax, LayerNorm）
cuSPARSELt 稀疏矩阵运算（对低秩矩阵的优化）

5.3 环境配置

项目 详情
系统 Windows 11 + WSL2 Ubuntu 24.04
GPU NVIDIA GeForce RTX 4060 Laptop (8GB)
CUDA 版本 12.6
Python 3.12
包管理 uv

为什么选 WSL2？传统 Windows 做深度学习有三难：包依赖混乱、驱动映射困难、调试体验割裂。WSL2 通过微软+NVIDIA 的 GPU Paravirtualization Layer 解决了这些——性能损耗不到 5%，nvidia-smi 直接可用。

可参考的博文：https://blog.csdn.net/weixin_42393362/article/details/156369331

5.8 踩坑总结

# 坑 现象 根因 解决
1 网络超时 pip install torch --index-url download.pytorch.org 反复失败 服务器国内访问极慢 拆分安装：torch 走本地 wheel，nvidia 走清华镜像
2 libcusparseLt.so.0 import torch 直接报错 nvidia-cusparselt-cu12 遗漏未装 单独补装
3 LD_LIBRARY_PATH 包装好依然找不到 .so nvidia-* 的 lib 不在系统搜索路径 写入 venv activate，激活时自动设置
4 PyPI torch 是 CPU 版 清华镜像装 torch 后 CUDA 不可用 pypi.org 的 torch 是 CPU-only，GPU 版在 download.pytorch.org 区分两个来源

核心经验

  1. 先 CPU 跑通，再上 GPU：CPU 安装零门槛，验证数据+脚本没有问题
  2. 国内网络装 GPU torch：主包走本地 wheel，依赖走清华镜像 https://pypi.tuna.tsinghua.edu.cn/simple/
  3. nvidia-cusparselt-cu12 不要忘：torch 2.6 新依赖，容易遗漏
  4. LD_LIBRARY_PATH 必需：写入 venv activate，一劳永逸
  5. venv 是好朋友：删 .venv/ 即清零，环境永远不污染系统
