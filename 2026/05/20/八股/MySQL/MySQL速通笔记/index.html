MySQL 速通笔记

作者: 老江湖
日期: 五月 20, 2026  23:43:12
分类: 八股 MySQL篇

紧急冲刺？看这篇就够了。核心考点浓缩，30分钟过一遍 🚀

一、基础速通

执行流程（一条SQL的旅程）

  • 🔑 Server层+存储引擎层解耦架构
  • 查询缓存：MySQL 8.0 已删除（不是指 Buffer Pool）
  • 连接器权限：连接建立后修改权限不影响已建立连接

一行记录的存储（行格式 Dynamic）

组成部分 内容
变长字段长度列表 varchar 实际长度，逆序
NULL 值列表 NULL 标记位，逆序
记录头信息 删除标记、下条记录位置等
隐藏字段 row_id(6B) + trx_id(6B) + roll_pointer(7B)

表空间层级（由小到大）

  • 页是 InnoDB 磁盘管理最小单元、IO 读写基本单位
  • varchar(n) 的 n 是字符数，不是字节数
  • 行溢出：超 16KB 时，Dynamic 格式只存 20 字节溢出页指针

存储引擎对比

特性 InnoDB ✅ MyISAM ❌ Memory ⚡
事务 ✅ ❌ ❌
锁粒度 行锁 表锁 表锁
外键 ✅ ❌ ❌
崩溃恢复 ✅ ❌ ❌(重启丢数据)

二、索引速通

索引分类（一张表）

维度 类型
数据结构 B+Tree(默认)、Hash、Full-text
物理存储 聚簇索引(叶子存完整行)、二级索引(叶子存主键)
字段特性 主键、唯一、普通、前缀、联合
字段个数 单列、联合

B+树为什么是 MySQL 的答案

🎯 核心：磁盘 IO 远慢于内存，索引设计必须矮胖 + 支持范围查询

对比 缺点
二叉查找树 退化成链表
红黑树/AVL 二叉树高，IO 次数多
B 树 节点存完整数据，单页存索引少，范围查询需中序遍历
B+ 树 ✅ 非叶子只存索引→更矮胖；叶子双向链表→范围查询高效

🔥 面试必考清单

考点 一句话
最左匹配 联合索引 (a,b,c) 必须从 a 开始，不能跳过中间列
索引失效 like '%xx'、函数/计算、类型转换、!=/<>、is null/is not null(看情况)、or 部分列无索引
回表 二级索引查完主键后，再去聚簇索引查完整行 → 多一次 IO
覆盖索引 select 的列全在索引里 → 不回表，explain 显示 Using index
索引下推 存储引擎层先过滤索引条件再回表，减少回表次数
前缀索引 对长字符串取前 N 个字符建索引，减少空间，但无法 order by
主键自增 避免页分裂，B+树插入高效
区分度 选区分度高的列建索引（≈ count(distinct)/count(*)）

三、事务速通

ACID 及 MySQL 实现

特性 含义 MySQL 靠谁
原子性 要么全做，要么全不做 undo log 回滚
一致性 事务前后数据一致 其他三者共同保证
隔离性 事务间互不干扰 MVCC + 锁
持久性 提交后数据永久保存 redo log crash-safe

隔离级别与并发问题

隔离级别 脏读 不可重复读 幻读 实现
读未提交 ❌ ❌ ❌ —
读已提交 ✅ ❌ ❌ 每次查询新 Read View
可重复读(默认) ✅ ✅ ⚠️ 大部分解决 事务启动时一个 Read View
串行化 ✅ ✅ ✅ 读写互斥锁

MVCC 核心机制

可见性判断三规则：

  1. trx_id < min_trx_id → 可见（事务启动前已提交）
  2. trx_id >= max_trx_id → 不可见（事务启动后才开始）
  3. 中间值 → 在活跃事务列表里则不可见，否则可见
    → 不可见时沿 undo log 版本链回溯找可见版本

⚠️ RR 下仍可能幻读的场景

  1. 先快照读查不到 → 其他事务插入 → 本事务 update 该记录 → 再查可见（trx_id 变成自己的）
  2. 先快照读 → 其他事务插入 → 本事务当前读(select...for update) → 读到新记录

    解法：事务开启后立刻当前读，加 next-key lock 防插入

四、锁速通

锁的层级

锁类型 说明
全局锁 flush tables with read lock，整库只读
MDL 锁 自动加：CRUD→MDL读锁；DDL→MDL写锁，事务提交才释放
意向锁 加行锁前先加表级意向锁(IS/IX)，快速判断表是否有行锁
AUTO-INC 锁 自增主键专用，innodb_autoinc_lock_mode=2需配 ROW 格式 binlog

🔥 行锁加锁规则（面试核心，必须背）

加锁单位是 next-key lock，只对扫描到的索引记录加锁

场景 规则 锁退化
唯一索引等值-记录存在 退化为 Record Lock 只锁该行
唯一索引等值-记录不存在 退化为 Gap Lock 锁间隙防插入
唯一索引范围-等值部分存在 等值退化为 Record，范围加 next-key —
非唯一索引等值 记录加 next-key + 主键 Record Lock 最后一条不满足的退化为 Gap
非唯一索引范围 全部 next-key，不退化 —
无索引查询 全表扫描，锁全表！ 危险⚠️

死锁

  • 四条件：互斥、占有且等待、不可剥夺、循环等待
  • 避免：拆小事务、统一访问顺序、开启死锁检测、设锁等待超时

五、日志速通

三大日志一句话

日志 层级 类型 作用 写入方式
undo log InnoDB 逻辑日志 回滚 + MVCC 记修改前数据
redo log InnoDB 物理日志 崩溃恢复(crash-safe) 循环写，WAL 技术
binlog Server 逻辑日志 备份 + 主从复制 追加写

更新语句完整流程

两阶段提交（高频面试题）

🎯 目的：保证 redo log 和 binlog 逻辑一致，避免主从数据不一致

崩溃恢复：prepare 状态的 redo log，binlog 有对应 XID 则提交，否则回滚

关键参数速查

参数 值 含义
innodb_flush_log_at_trx_commit 1(默认) redo log 每次提交刷盘，最安全
2 写 OS page cache，OS 崩溃丢 1s
sync_binlog 1 binlog 每次提交刷盘，最安全
N 累积 N 个事务批量刷盘

组提交

合并多事务的 redo log/binlog 刷盘为一次 fsync，减少 IO 次数

六、内存速通

Buffer Pool（InnoDB 核心缓存）

  • 缓存：数据页、索引页、undo 页、锁信息等
  • 大小：**物理内存 60%~80%**，16KB 页为单位
  • 三大链表：
链表 作用
Free 链表 管理空闲缓存页
LRU 链表 young(热点) + old(默认37%)，防预读失效+Buffer Pool 污染
Flush 链表 管理脏页，后台刷盘

Change Buffer（写缓冲）

  • 缓冲非唯一二级索引的更新操作（唯一索引要立即判重）
  • 等索引页被读入 Buffer Pool 时批量合并，将多次随机 IO 转为一次

七、性能调优速通

explain 核心指标

指标 关注什么
type all(全表)→index→range→ref→eq_ref→const(最好)
key 实际使用的索引，NULL 表示没走索引
rows 预估扫描行数
extra Using filesort/Using temporary(要优化)；Using index(好)

常用优化手段

场景 方案
深度分页 子查询先取 id 再关联；游标分页(where id>上次最大)
大表计数 单独维护计数表；近似用 show table status
写性能 innodb_flush_log_at_trx_commit=2 + 组提交 + 拆小事务
索引选错 force index(idx_name)
防锁全表 sql_safe_updates=1

count 对比

  • count(*) ≈ count(1)（InnoDB 优化，选最小二级索引扫）
  • count(字段) 最慢（要判 NULL）
  • MyISAM 的 count(*) 最快（有元数据缓存），但不支持事务

八、架构速通

整体架构

主从复制

  • 异步(默认)：高性能，可能丢数据
  • 半同步：至少一台从库确认
  • 同步：全确认，几乎不用

九、思考题速记

update 是否自动开事务？

✅ InnoDB 默认 autocommit=1，单条 update 隐式开启独立事务，执行完自动提交。命中索引加行锁，无索引会降级锁全表。

全量 vs 增量备份

维度 全量 增量(binlog)
备份内容 全部数据 上次备份后的变化
速度快 慢 快
恢复快 快(一份恢复) 慢(全量+逐一回放)
工具 mysqldump / xtrabackup binlog 拷贝 / xtrabackup 增量

生产策略：每日全量 + 每小时增量 + 实时 binlog 同步
