WSL2 配置 VPN 代理的正确姿势

背景

VPN 客户端（Clash / V2Ray 等）运行在 Windows 侧，开启了 HTTP 代理（127.0.0.1:33210）和 SOCKS5 代理（127.0.0.1:33211）。需要让 WSL2 里的终端工具（curl、wget、apt、pip、git 等）也能走代理。

我的wsl配置：C:/user/<usrname>/.wslconfig

踩坑过程

❌ 误区一：用 Windows 宿主机 IP 替换 127.0.0.1

网上很多教程说 WSL2 是独立虚拟机，127.0.0.1 指向 WSL 自身，必须用宿主 IP 才行。于是查了 /etc/resolv.conf 里的 nameserver，拿到 10.255.255.254，替换后：

真相：WSL2 默认开启了 localhostForwarding，WSL 内访问 127.0.0.1 会被自动转发到 Windows 宿主机的 127.0.0.1。所以 直接用 127.0.0.1 就行，完全不需要折腾宿主 IP。

实测证明：

原因：VPN 代理只在 Windows 的 127.0.0.1 上监听，不在其他网口上监听。

❌ 误区二：用 ping 测试代理连通性

真相：ping 用的是 ICMP 协议（网络层 L3），而 HTTP/SOCKS 代理工作在上层（L4/L7），ICMP 流量根本不会走代理。

协议 层级 是否走代理
ICMP（ping） 网络层 L3 ❌ 永远不走
TCP（curl / wget） 传输层 L4 ✅ 走 http_proxy
UDP（DNS 等） 传输层 L4 ✅ SOCKS5 支持

❌ 误区三：开终端自动设代理

把 export http_proxy=... 直接写在 .bashrc 里，导致：

  • 不开 VPN 时，curl / apt 全部挂掉（代理端口不存在）
  • 每次都要手动 unset 才能恢复正常上网

关键知识点

  1. WSL2 的 localhostForwarding 默认开启，127.0.0.1 可在 WSL 中直连 Windows 服务
  2. ping 不走代理，用 curl -I 测试代理连通性
  3. 代理变量含 http:// / socks5:// 前缀，不能省略
  4. sudo 默认不继承代理变量，如需代理 apt 用 sudo -E apt update
  5. 大写/小写变量都要设，部分工具只认其中一种（http_proxy vs HTTP_PROXY）
